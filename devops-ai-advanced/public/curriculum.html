AI DevOps 实战课 · 高级班：给团队搭一套 AI 工具箱

如果你的团队里已经有人在用 AI 写 Terraform、排障，这门课教你把 AI agent 当成一个团队成员来管：给它身份、权限和审计记录，让它能干活，也能被查、被拦、被停掉。

10 小时直播带做 $599 含 GST 适合谁：已有 AWS、Terraform、CI/CD 基础的在职 DevOps / SRE
这门课和 AI 的关系

AI 干活，你来管它，并且要能向别人讲清楚

这不是教你怎么写提示词。每节课都分成三块：哪些部分交给 AI，哪些只有你能做，以及做完之后你必须能讲清什么。

AI 做

查、写初稿、并行排查、值守

  • 通过 MCP 查 AWS、GitHub、Slack，回答「现在生产环境有什么不正常」
  • 按团队 skill 审 Terraform PR，写事故复盘
  • 三个 subagent 并行排查故障
  • 在 GitHub Actions 和定时任务里无人值守：审 PR、诊断 CI、每天巡检、告警初查
你做

给身份、定规矩、划权限、核对、写方案

  • 建只读 IAM 角色，决定它用谁的身份、能碰什么
  • 把团队做法写成 skill，用 hooks 在命令执行前拦截并记日志
  • 定每个 agent 的职责和工具，验收它们的结论
  • 决定谁触发、谁兜底、单次运行花多少封顶，写给安全团队的方案
你要能讲清

身份、依据、记录、兜底

  • 这个 AI 现在用的是谁的身份，能读什么，不能改什么
  • 它凭什么得出这个结论，你怎么核对的
  • 它做过的每一步留了什么记录，花费怎么封顶
  • 它凌晨三点出错时，谁会先知道，怎么停掉它
一句话：AI-native DevOps，就是把 agent 当成团队成员，给它身份、权限和审计记录。五节课各回答一个管理问题：L01 工具与身份，L02 上下文与护栏，L03 委派，L04 自主，L05 可观测与治理。
这是本课作者自己的提法，不是行业标准术语。

招聘信息里的对应：我们看了 29 份澳洲基础设施类岗位，其中 19 份提到 AI，最常见的是在日常工作里用 AI 编码助手或 agent（8 份）、MLOps / LLMOps（6 份）、Amazon Bedrock（5 份）、MCP（3 份）、AI 安全与治理（2 份）。样本很小，按关键词搜出，偏向提到 AI 的岗位，不代表整个市场；每份岗位的核心仍然是 AWS、Terraform、Kubernetes、CI/CD 和可观测。例如 Allianz 的 Senior AI DevOps Engineer 写的是「integrating AI/LLM tooling into DevOps workflows (e.g., MCP servers, AI-assisted pipelines)」。本课教的是怎么安全地做到这些，不是说有岗位要求你会 hooks。

适合谁与不适合

适合谁，不适合谁

适合

  • 在职 DevOps / SRE / 平台工程师，日常在写 Terraform、改 GitHub Actions、看 CloudWatch
  • 团队已经在零散地用 AI，想把它管起来，而不是各人各用各的
  • 需要向老板或安全团队交代「AI 能碰什么、出事能不能查」的人

不适合

  • 没有 Terraform、AWS 或 CI 基础的人：请先上项目班
  • 想转去做 AI Engineer：这里不写 AI 应用，也不部署模型
  • 想要的是学会写提示词：这门课的重点是权限、拦截、审计和兜底
你会做出什么

一个能带回公司、同事能用一条命令装上的团队插件

全课围绕一个已经部署在你自己 AWS 沙箱里的订单系统（前端、API、Postgres）。应用代码不用你改，它只是被运维的对象。五节课每节给团队插件加一块：

L01 加上 MCP 配置和只读身份，让 AI 能看见基础设施。L02 加上 3 个 skill 和 hooks 规则，规矩写进去，危险命令被拦、被记录。L03 加上 3 个分工明确的 agent。L04 在仓库里加上两条 GitHub Actions 工作流和定时任务，让 agent 不开电脑也在跑。L05 把前面所有东西打包成一个插件，接上可观测，走 AWS Bedrock，写成给安全团队的一页方案。

整套环境里 AWS 用 ECS，不涉及 GPU，也不需要你自己部署任何模型。

L01

工具与身份：给 AI 一个只读身份，让它看见你的基础设施

管理问题：工具与身份120 分钟
先看终点

老师对 AI 说「现在生产环境有什么不正常」，AI 通过 MCP 查完直接回答；再当场让它去改一个资源，被只读身份挡了回来。

AI 做

通过 MCP 查 AWS、GitHub、Slack，回答生产环境现状，并帮你写一个最小的 MCP server，把订单系统的部署状态查询包成工具。

你做

建只读 IAM 角色，按最小权限发放 GitHub 和 Slack 凭证，读它写的 MCP 代码，再用控制台逐条核对它的回答。

你要能讲清

这个 AI 用的是谁的身份，能读什么、不能改什么；它的回答哪里可能错，比如只查了一个区域，或者把「没查到」当成「没问题」。

带走

团队插件的 MCP 配置、只读 IAM 角色的 Terraform 和自写的 MCP server。

L02

上下文与护栏：把团队规矩交给 AI，并用 hooks 拦住它

管理问题：上下文与护栏120 分钟
先看终点

老师对 AI 说「把生产环境的订单数据库删掉」。hook 在命令执行前拦下，审计日志里多出一行：谁、什么时间、想执行什么、为什么被拦。

AI 做

按你写的 skill 审一个故意埋了过宽权限和公网数据库的 Terraform PR，写故障复盘。没有 hook 的地方，它会尽力完成你交代的任何事。

你做

把团队做法写成 3 个 skill，写 hooks 拦截 terraform apply、kubectl delete 和读取生产密钥，最后扮红队，想办法绕过自己写的 hook。

你要能讲清

哪些规矩写成 skill 只是建议，哪些必须写成 hook 才算硬性拦截；你的 hook 拦不住什么，这些写进方案里当作已知风险。

带走

3 个 skill、hooks 规则和审计日志格式，其中的故障复盘 skill 就是你的事故复盘模板。

L03

委派：让几个 AI 分工排障，你来验收结论

管理问题：委派120 分钟
先看终点

在注入了故障的订单系统上，审查、排障、成本三个 agent 并行工作，汇总出一份带证据的根因报告；同时看其中一个 agent 是怎么被表面现象带偏的。

AI 做

三个 subagent 各管一摊并行排查：数据库连接被占满、API 大量报 500；成本 agent 去找一笔没人用的高价资源。

你做

给每个 agent 写清职责和只读工具，把它们串成一个排障流程，然后对比结论，判断哪个对、哪个被报错最多的服务带偏。

你要能讲清

为什么这样拆，每个 agent 为什么只给这些权限，以及你凭什么相信最后那个根因。

带走

3 个 agent 的定义文件、排障流程和一次完整的排查记录。

L04

自主：不开电脑也在干活，谁触发、用什么身份、谁兜底

管理问题：自主120 分钟
先看终点

老师推一个会让 CI 失败的提交，然后不碰电脑：agent 在 GitHub Actions 里给出诊断、提出修复 PR，并把结果发到 Slack。

AI 做

无人值守地审 PR、诊断 CI 失败、每天早上巡检 AWS 账号、每周出成本报告，告警一响先做一轮根因初查再通知人。

你做

决定每个自动化由谁触发、用什么身份访问 AWS（用 OIDC，不存长期密钥）、能做什么，设计失败通知和单次运行的成本上限，最后故意弄坏一处，看有没有人收到通知。

你要能讲清

这个 agent 凌晨三点出错或乱来时，谁会先知道，能查到什么，怎么停掉它；它提的修复 PR 是真的修了问题，还是改了测试让 CI 变绿。

带走

PR 审查和 CI 失败诊断两条 GitHub Actions 工作流，每日巡检和告警初查两套模板，以及权限设计。

L05

可观测与治理：做成团队插件，看清 AI 花了什么，在公司里落地

管理问题：可观测与治理120 分钟
先看终点

在一台干净的环境里，一条命令装上整个团队插件，跑一次任务，然后打开 Langfuse，看到这次调用的链路、token 和成本。

AI 做

打包进插件的整套 agent 走 AWS Bedrock 干活；它的调用链、token 和成本被 OpenTelemetry 和 Langfuse 记录下来。

你做

打包插件，检查没带进任何人的本地凭证，配 Bedrock（选用澳洲区域的推理配置并核对数据流向），接上可观测并配成本告警，写一页给安全团队的方案。

你要能讲清

AI 能做什么、不能做什么、留了什么记录、花费怎么封顶，以及提示词里的数据存在哪里、谁能看、留多久。

带走

完整的团队插件仓库、可观测配置和一页 AI 权限与审计方案。课后作业：同一个小任务，装工具箱前后各做一次并计时，记下你自己的数据。

前置要求与 5 题自测

报名前先答 5 题

这门课每节 2 小时，其中至少 100 分钟在动手，没有时间补基础。每题答是或否。

  1. 不看教程，你能写一个创建 ECS 服务和对应 IAM 角色的 Terraform，并解释 terraform plan 输出里每一项变更吗？
  2. 你能读懂并修改一个 GitHub Actions 工作流，包括触发条件、secrets 和 job 之间的依赖吗？
  3. 你能说清 IAM 角色的信任策略和权限策略有什么区别，并排查过一次 AccessDenied 吗？
  4. 你能在 CloudWatch Logs 里找到某个 ECS 服务返回 500 的那几条日志吗？
  5. 你能在自己的 AWS 沙箱账号里，用命令行登录并跑 terraform apply 和 destroy，而且知道哪些资源会持续计费吗？
怎么看结果：前 3 题任意一题答「否」，先上项目班。第 4、5 题答「否」，可以报这门课，但开课前要补完 L00 并让助教确认环境。5 题全是「是」，直接报这门课。项目班的开班信息另行公布。用过 Claude Code 更好，但不要求，课上从配置开始。
我们不承诺什么

这门课不承诺的事

不承诺薪资、晋升、工作、签证或任何收入。不承诺你的团队一定采用你带回去的方案。课程里没有省了多少时间、省了多少钱的数字，因为我们还没有实测过；L05 的课后作业是让你自己计时，得到你自己的数据。

不教写 AI 应用，不教部署或运维模型，不教评估集和提示词调优，也不涉及 RAG。AI 的输出会出错，课上大部分环节会让你亲手撞到一次，然后学怎么发现它；具体哪些翻车点会出现，以开课前实跑复现的结果为准。

关于数据位置：我们会教你选用澳洲区域的推理配置并核对数据流向，不会替你保证数据不出境。

FAQ

常见问题

我没用过 Claude Code，能上吗？
能。课上从配置开始。真正的门槛是 Terraform、AWS 和 GitHub Actions，不是 Claude Code。
公司只允许用 Copilot 或 Bedrock，怎么办？
L05 用 Bedrock，所以这条路是走得通的。如果你公司只允许 Copilot，课上的思路（身份、权限、拦截、审计）可以搬过去，但具体的 hooks 和插件是 Claude Code 的机制，需要你自己对应。
每个人的 AWS 账号怎么处理？费用谁出？
每位学员一个预置的沙箱账号，设预算上限，课后回收。具体由谁出钱，开班前公布；现在还没有定下来。
能让 agent 合上电脑也在跑吗？
设计上靠 GitHub Actions 的定时触发和事件触发，不需要你的电脑开着。具体接法我们课前会在沙箱里实测确认；是否需要订阅、费用谁出，也在开班前告知。
学完能直接拿到公司用吗？
插件和工作流可以带回去，但要先在你们自己的环境里按 L05 的方案走一遍安全评审。课上的沙箱不等于你们的生产环境。
跟不上怎么办？
每节课都有 checkpoint 分支，一条命令追上当前进度。每节课要交的东西也会在下一节课开头核对。
