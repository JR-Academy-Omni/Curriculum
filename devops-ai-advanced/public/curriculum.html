这门课和 AI 的关系

AI-native 不是边干活边用 AI，是把活重做成 agent 来干

cloud-native 不是把虚拟机搬上云；AI-native 也不是在 IDE 里多开一个聊天窗口。它是把工作重新设计成由 agent 执行，你负责 agent 周围的五件事。这门课每一节都在补其中一件，然后用数据看它有没有用。

意图

写要什么，和怎么算完成

任务写成结果加验收检查，不手写实现。说不清怎么验收的任务，先别交出去。

上下文

没写下来的，对 agent 不存在

团队约定、架构、runbook 写成它读得到的规则文件和 skill。每次失败都可能是一条该写下来的知识。

验证

生成便宜，确认对不对才贵

测试、plan 断言、策略检查是闸门，agent 必须一直改到通过，而且改不动闸门本身。

身份与边界

它是一个有权限的身份

独立 IAM 角色、默认只读、改动只走 PR、人工批准、CloudTrail 可查、一键停掉。

度量

用数说话

成功率、介入率、每任务用量和用时。每次失败写成复盘，写回上下文。

说明：这五件事的划分是本课作者自己的归纳，不是行业标准术语。工具（MCP、skills、hooks、云端 agent、OpenTelemetry、Langfuse）只在能提高你的成功率或守住边界时出现，这门课不带你逛工具。

适合谁与不适合

适合谁，不适合谁

适合

  • 没有 Terraform、AWS 或 CI 基础的人：请先上同系列的项目班

你会搭出什么

一条交给 agent 执行、由你掌控的团队流程

每位学员一个预置的 AWS 沙箱，里面已经跑着一个小型订单系统，连同它的 Terraform 和 GitHub Actions 仓库。agent 就是你自己的 Claude Code。全课只改造一条流程：基础设施变更与排障。

任务一

新建一个 S3 存储桶：不能公开，必须带成本标签

任务二

扩容订单 API，过程中健康检查不能掉

任务三

修好一次跑红的 CI，不准跳过测试

任务四

调查注入的 5xx 故障，提修复 PR

任务五

无停机轮换数据库密码

每个任务配一个验收脚本，退出码为 0 才算通过。比如任务一会读 plan JSON 检查公开访问和标签，部署后再用 AWS CLI 读回来核对；任务三会查 diff 里有没有删测试或加跳过标记。

L01

意图与上下文：把任务写成要什么和怎么验收，跑出你的基线

120 分钟
先看终点

老师打开自己课前跑的记录：同一组任务从基线一路重跑到最后一节，每次失败记了什么，改了哪一样东西之后哪个任务开始通过。

AI 做

先拿团队平时那样写的原始工单，无人值守地跑完 5 个任务，得到基线；再按你写的意图和上下文包重跑一遍。

你做

把 5 张原始工单改写成意图加验收，给一个验收脚本补一条断言；把团队约定、架构说明、部署与回滚 runbook 写成 CLAUDE.md、规则文件和 skill；给每次失败归类。

你要能判断

一次失败是意图没写清、缺上下文、没有验证、越权，还是环境问题；验收脚本会不会被"结果对、做法错"骗过。

本节重跑任务组

基线一开课就在后台跑；改完意图和上下文包后再跑一遍，逐个任务对比：哪个变了，能不能对应到你写下的某一条。

带走

5 份任务意图、团队上下文包、基线和第一次重跑的运行记录与失败归类。

L02

验证：搭起验收闸门，让 agent 一直改到通过

120 分钟
先看终点

同一个任务跑两次：没有闸门时，agent 交了一个带 0.0.0.0/0 入站规则的改动并说完成；有闸门时，它被拦下，读报错自己改，直到通过才报完成。

AI 做

改 Terraform 和代码，读闸门的报错自己修，循环到检查全部通过。

你做

搭四道闸：fmt 与 validate、plan JSON 断言（无公网入站、无公开存储桶、必须带标签）、policy-as-code、CI；再用 CODEOWNERS 和分支保护让 agent 改不动闸门。

你要能判断

闸门挡住了哪类风险、漏了哪类；agent 让检查变绿，是修对了，还是删了测试、放宽了策略。

本节重跑任务组

带上闸门重跑：哪些任务从失败变成通过，哪些多跑了几轮才过，有没有任务因为闸门变严反而失败。

带走

make verify 入口、plan 断言、策略文件、CI 检查工作流和防止 agent 修改闸门的仓库保护设置。

L03

身份与边界：agent 是一个有最小权限、审批、审计和停止开关的身份

120 分钟
先看终点

让 agent 直接改沙箱，CloudTrail 里出现它的角色收到的 AccessDenied，它转去提 PR；老师执行 kill switch，它当前会话的凭证马上失效。

AI 做

用自己的只读角色调查，所有改动只能推分支、提 PR，由 CI 部署角色在人工批准后执行。

你做

用 Terraform 建 agent 的 IAM 角色；设 GitHub environment 人工批准；写 CloudTrail 审计查询和 kill switch 脚本；用 hooks 拦危险命令；在日志和 PR 评论里埋指令当一次红队。

你要能判断

一个动作是被 IAM 挡住，还是只被 hook 挡住（hook 只是便利，不是边界）；出事时能不能还原它做过的每一步，多快能停掉它。

本节重跑任务组

换成 agent 自己的身份重跑，写操作走 PR 和批准。批准单独计数，不算介入；看收紧权限后哪些任务受了影响。

带走

agent 角色的 Terraform、审批与分支保护配置、审计查询、kill switch、hooks 规则、红队记录和一页 agent 身份说明。

L04

闭环：告警和 CI 失败自动叫醒 agent，调查、提修复、等你批准

120 分钟
先看终点

注入一次 5xx：CloudWatch 告警触发 GitHub Actions 里的 agent，它只读调查、写出调查记录、提修复 PR，检查通过后停下来等人。老师全程只点了一次批准。

AI 做

被告警或 CI 失败触发，无人值守地调查、提修复 PR、跑检查；定时巡检漂移、缺标签和公网暴露，发现问题开 issue。

你做

搭 CI 失败诊断和告警调查两条工作流，加一个定时巡检；定触发方式、运行身份、轮次和花费上限、失败通知和停止方式；故意弄坏一次，看有没有人知道。

你要能判断

它的修复 PR 修的是根因还是症状；夜里没人看着时它失败了，谁会知道，怎么停。

本节重跑任务组

修红 CI 和调查 5xx 两个任务改由事件触发、无人值守完成，看没人在场时结果有没有变。

带走

CI 失败诊断、告警调查、定时巡检三条工作流，以及它们的触发、身份、上限、通知和停止设置。

L05

度量与推广：给自己团队的 agent 装上仪表，用实测数字写方案

120 分钟
先看终点

老师打开课前实跑留下的看板，点进一次失败运行看它每一步做了什么，再看这次失败写回上下文包的那一处改动，和用这些数写成的一页方案。

AI 做

跑最后一次任务组，它的用量、调用记录和验收结果被自动采集。

你做

挑还没过的任务写复盘并写回上下文；打开遥测、启动最后一次重跑；趁它在跑，把 Claude Code 的 OpenTelemetry 指标接进 Grafana、把每次任务运行记进自托管的 Langfuse；写一页给老板和安全团队的方案。

你要能判断

5 个任务的数据能支撑什么结论、不能支撑什么；哪些失败该写回上下文，哪些说明这件事暂时不该交给 agent。

本节重跑任务组

最后一次重跑，画出从基线到现在的成功率和介入率曲线，标出每处变化对应的改动。

带走

整理好的团队 agent 套件仓库、指标看板配置、复盘记录和一页方案。

前置要求与 5 题自测

报名前先答 5 题

每节课 2 小时里至少 100 分钟在动手，没有时间补基础。你还需要自己的 Claude Code 使用额度，具体要求开班前公布。每题答是或否。

  1. 不看教程，你能写一个创建 ECS 服务和对应 IAM 角色的 Terraform，并解释 terraform plan 输出里每一项变更吗？
  2. 你能读懂并修改一个 GitHub Actions 工作流，包括触发条件、secrets 和 job 之间的依赖吗？
  3. 你能说清 IAM 角色的信任策略和权限策略有什么区别，并排查过一次 AccessDenied 吗？
  4. 你能在 CloudWatch 里定位某个服务开始返回 5xx 的时间段，并找到对应的日志吗？
  5. 你在工作中提过并合并过改动基础设施或流水线的 PR，并经历过评审吗？
怎么看结果：前 3 题任意一题答「否」，先上同系列的项目班。第 4 题答「否」，可以报这门课，开课前把 L00 做完并贴检查结果。第 5 题答「否」，说明你现在手上还没有能带回去改造的团队流程，方案部分会用不上，建议先上项目班或等工作中有这个场景再来。5 题全是「是」，直接报这门课。用过 Claude Code 更好，但不要求，L00 会带你配好。

FAQ

常见问题

agent 的成功率能做到多少？
我们不知道，也不预估。这门课的做法就是不靠感觉：同一组任务、同一套验收脚本，每节重跑一次，数字由你自己测出来。老师课前也会用同一组任务实跑一遍，第一节课上给你看完整记录，包括失败的那些。
我们公司用的不是 Claude Code，是 Copilot 或别的工具？
五件事的做法（意图、上下文、验证、身份与边界、度量）都能搬过去，任务组和验收脚本也和工具无关。但课上的 hooks、无人值守运行和 GitHub Action 是 Claude Code 的机制，换工具需要你自己找对应的做法。
公司要求模型调用走 AWS Bedrock，可以吗？
Claude Code 可以配置成走 Bedrock，我们会在开课前在沙箱里实测接法和推理区域，再告诉你能做到什么。核实之前，我们不写"数据不出境"。
我们跑的是 Kubernetes，不是 ECS，学了有用吗？
课上的沙箱用 ECS，因为建得快、成本低。课程教的是把一条流程交给 agent 并测出数据的办法，任务组和验收脚本是可以换的：回公司后，你把任务换成自己团队在 EKS 上的活，用同一套办法测。
AWS 和 Claude Code 的费用谁出？
每位学员一个预置的沙箱账号，设预算上限，课后回收。沙箱费用安排和你需要准备的 Claude Code 额度，开班前公布；现在还没有定下来。每节课重跑任务组会消耗额度，具体用量我们课前实测后告诉你。
跟不上怎么办？
每节课都有 checkpoint 分支，一条命令追上当前进度。任务组在后台运行，你可以一边跟老师讲评一边等结果。
