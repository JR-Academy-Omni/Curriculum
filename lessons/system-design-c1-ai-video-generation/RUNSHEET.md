# L03 讲师流程 · AI Video Generation

Lightman · 120 分钟（含 10 分钟休息）

## 开课准备

- 打开 P02，播放 v2 成片，再切到 v1 并拖至第 3–6 秒。首尾镜头一致，旧版中镜机身错误为红色，修订版回到深蓝。
- 下载并解开 FFmpeg 练习包。检查 Python 3.10+、ffprobe 和 FFmpeg（包含 VP9 与 H.264 编码支持）。在包目录内先运行 WebM 导出，再打开浏览器回放。
- 课堂用原创产品静帧，经 FFmpeg 推镜生成固定的输入片段，便于每组重跑。媒体后期链路真实运行，课件内模型生成步骤按架构与契约讲解。公开厂商长任务文档作为对照，课堂不消耗模型额度。

| 时间 | 讲师行动 | 学员行动与证据 |
|---|---|---|
| 00–15 · P01–P02 | 先播可下载的 v2 成片，再切旧版。对照原始参考图和版本表。 | 写出一个可观察的外观缺陷并定位到镜头。 |
| 15–45 · P03–P07 | 对比一次生成与逐镜生成，标出 model operation、审核和合成的状态来源。展开两份清单和取舍成本。 | 标哪个版本被选、哪个可保留。试算每条可用成片成本。 |
| 45–55 · P08 | 跑 ffprobe 看不同尺寸与帧率。投屏读 render_film.py 的 scale、pad、fps、concat 和字幕编码。 | 记下一项输入和一项输出规格。 |
| 55–65 · P09 | 从 v2 清单导出成片并回放。检查画面顺序、第二镜、字幕。示范 MP4 导出命令与 WebM 字幕轨的区别。 | 确认只换第二镜，打开当前成片核对选用记录。 |
| 65–75 | 休息。 | 保留 v1、v2 两份清单。 |
| 75–105 · P10–P11 | 发工作单，先让学员修正颜色错误，再加「合成阶段失败」条件。 | 改清单和架构，说明何种失败会消耗新的模型调用。 |
| 105–120 · P12–P13 | 以两个版本的差异和最终播放证据做评审。 | 交付图、选用清单和验证记录，给出一条停止重试的规则。 |

## 讲师参考与恢复

- v1 绑定 01-v1 / 02-v1 / 03-v1，v2 绑定 01-v1 / 02-v2 / 03-v1。两版都正常可播放，第二镜的创意质量不同。清单按版本保存，不篡改旧产物。
- 合成失败先查素材、字幕、编码或目标路径，复用已有选片。模型超时先查 operation ID，避免不确定时重复创建请求。
- FFmpeg 将三次 3 秒视频统一为 960×540、24 fps、yuv420p，再拼接。WebM 保留 WebVTT 字幕轨，网页播放器用同一字幕文件提供开关；本地课程命令也支持封装 MP4 的 mov_text。
- 若输出文件已存在，脚本提示换名。若模型输入规格或素材缺失，先用练习包里的原始版本恢复，再比较修改前后的探测结果。
- 阅读 [FFmpeg 滤镜和拼接](https://ffmpeg.org/ffmpeg-filters.html)、[ffprobe](https://ffmpeg.org/ffprobe.html) 和 [Google Cloud 视频生成长任务](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/video/generate-videos-from-text)。
