# Vibe Coding 大师课 · 第十四节蓝图

> 状态：DRAFT 1.1（2026-09-27）
> 课名：**《它能碰什么》**
> 主题：**给一个 agent 一套公司系统的权限、连接、技能与维护**
> 课型：**120 分钟线上直播动手课**（沿用 L13 的形式约束：无助教、救生艇、聊天框信号）
> 课堂硬产物：**一张学员自己公司的写权限表**（每行含"写到哪 / 谁批 / 批准立在什么上面"）、
> **一个当堂跑出 FAILED 而不是 0 的脚本**、**一份按十节写完的技能规范**。
>
> **内容库在 `VIBE_CODING_MASTER_L14_ARCH_BRIEFING.md`。本文指向它，不复述。**
> 本文定义课程结构、立论、教学决定、节奏与风险；交底模块定义讲什么。
> **两者冲突以本文为准。**

## 0. 立项决定

### 0.1 这一节为什么存在（以及它为什么必须在 L13 之后）

L13 让学员造出了一个会自己拦人的规则仓库。**但那个仓库现在没有消费者。**

学员回去第一天就会撞上的问题：

> 「我建好了。**然后呢？AI 在哪？它凭什么读我这些文件？它能改吗？谁拦着它？**」

L14 回答这个问题。

**顺序是故意的，而且是这两节课之间最重要的一句话：**

> **地基错了，上面那层越强越危险。**
> 一个规则写得糊涂的仓库，配上一个有写权限的 agent，**比没有 agent 糟得多。**

L13 的 P19 已经把这句话说过一次，L14 的开场回收它。

### 0.2 全节最重要的三句话

**立论**（第二幕点出）：

> **权限不是一个开关，是一张一行一行批出来的表。**

**反转**（第五幕，学员刚给自己的表加完审批人、最有安全感的时候翻）：

> **你加的那个人工审批，多半不是保障，是失效模式。**

**收口**（全程不许提前说）：

> **它最危险的时候，不是它做错了事，
> 是它什么都没做，而你以为它做了。**

**三句的链条，讲师必须能说出来：**

```
权限一行一行批        →  每一行都要记下「这项批准立在什么上面」
                      →  因为可核查的是依据，不是按钮
                      →  一个按钮产生不了任何可核查的东西
                      →  而不可核查的系统，最典型的失败不是做错事
                      →  是什么都没发生，而所有人以为发生了
```

**收口那句是全课的收束点，它同时收掉四样东西**（这是它比 L13 收口更"硬"的地方）：

| 课上哪一格 | 怎么被它收掉 |
|---|---|
| 四态结果模型（`failed` 绝不报 `0`） | 查询失败报成 0，你以为"本期无异常" |
| 连接失败必须自带修复步骤 | 连接过期没人知道，报告天天是空的 |
| 人工审批是失效模式 | 有人点了合并，但没人读过 |
| 权限漂移每周巡检 | 离职残留的授权一直在，只是没人看 |

**四件事是同一个形状：看起来发生了，实际没有。**

### 0.3 最重要的教学决定：这一节最大的风险是变成管理课，比 L13 严重得多

L13 有终端可以拉回来（每一步都跑一次检查）。
**L14 的内容天然更"纸面"** ：权限表、连接器清单、技能规范、维护制度，
四样里三样是在写表格。

**如果不做处理，这节课会变成一场治理研讨会，而且学员会觉得跟自己没关系。**

**定版：三次翻车全部是可以当场跑出来的，而且每一幕至少有一次终端输出。**

| 幕 | 学员在终端上做什么 |
|---|---|
| 一 | 跑一遍自己现有的 agent 配置，看它现在到底能碰什么 |
| 二 | 改权限白名单，**故意放一条危险的进去**，翻车① |
| 三 | **造一次查询失败，看它报 0 还是报 FAILED**，翻车② ⭐⭐ |
| 四 | 按十节把一个技能规范写完，跑一次它的验收测试 |
| 五 | 挂一个会阻塞的钩子，翻车③，然后改成不阻塞 |

**铁律：每一幕结束前，学员的终端必须有新输出。** 没有就是这一幕讲飞了。

### 0.4 第二个教学决定：三次翻车里，第二次最重要，而且它就是收口的地基

沿用 L13 的结构（三次形态不同、第二次最重要），但**内容选择是为收口服务的**：

| | 翻车① | **翻车②** ⭐⭐ | 翻车③ |
|---|---|---|---|
| 做什么 | 把白名单放宽，跑一条危险命令 | **把查询弄失败，看它报 0** | 让钩子阻塞会话 |
| 形态 | **认知错位**：以为白名单是安全边界 | **看不见**：它报了个 0，你以为没事 | **烦**：每次都要等它 |
| 感受 | 意外 | **后背发凉** | 想关掉它 |
| 指向 | 白名单是省事边界，不是安全边界 | **静默失败** | 阻塞式警告比它警告的问题更糟 |
| 讲轻的后果 | 学员回去把白名单当防护 | **收口没有地基，最后一句话落空** | 学员挂一堆阻塞钩子，一周后全删 |

**翻车②是全课唯一一个"学员看完会后背发凉"的时刻。** 它必须慢，必须让学员自己造。

### 0.5 第三个教学决定：全程不出现产品名

交底模块已经全程用「工单系统 / 聊天工具 / 邮箱 / 代码托管」写，**没有一个产品名**。

**这不只是脱敏，它是三重收益：**

| 收益 | |
|---|---|
| 脱敏 | 讲师的公司用什么，学员不需要知道（沿用 L13 §0.4 纪律） |
| **国内班海外班同一份课件** | 五问的结构对任何一套工具都成立，只换连接器清单。**这一页因此不需要"国产替代"专页** |
| **学员自己代入** | 学员公司用的东西跟讲师不一样是常态。讲产品名会让一半人觉得"这跟我没关系" |

> ⚠️ **讲师课上也不要说产品名。** 要举例就说"你们那个记事情的系统"。
> 这条比 L13 更要紧，因为 L14 通篇在讲外部系统。

### 0.55 单位沿用 L13：不一定是公司 ⭐ v1.1

**沿用 L13 §1.0 的操作定义，本节不重复，但有两处必须按小规模重读：**

| 本节哪一格 | 三人小组怎么读 |
|---|---|
| **三仓拓扑**（一幕） | 不用真建三个仓。**关键只有一条：哪一摊它绝对不许写。** 三人组通常就是"产品代码它只读" |
| **写权限表**（二幕） | 四列照填。**"谁批准的"那一栏对小组更容易填 ,就是你们仨里的某一个人** |

**而且有一格对小组反而更强：**

> 写权限表第三列"**批准立在什么上面**"，
> 大公司容易写成"某某流程规定"，看起来很正式，其实没人能重新打开来读。
> **三个人的组只能写实话：「上周三我们在群里说的」。**
> **那反而是一个可核查的依据 ,群记录翻得到。**

> ⚠️ 讲师注意：小组学员在第二幕会觉得"我们哪有什么审批"。
> **答案是：你们有，只是从来没写下来。** 谁能合主分支、谁能发版、谁去回客户，那就是审批。

```
L5   Skills          做一个技能            → L14 第四幕：一个技能要定义什么才算完整
L10  四象限协议      信息在谁那里          → L14 第二幕：只有人能按的那一下
L11  无人值守任务书  它不在场怎么做对      → L14 第三幕：什么时候根本不该让它不在场
L12  Hook            把规矩变成绕不过去    → L14 第五幕：一个钩子该不该阻塞
L13  规则仓库        造地基                → L14 全课：在地基上接东西
```

**L14 是系列第一次把五节课的东西同时用上**，而且不引入任何新工具。
**讲师要在开场说这一点**，因为它会让学员意识到前面几节不是孤立的。

### 0.7 承接句（开场用）

> L13 你造了一个会自己拦人的仓库。
> **但它现在没有消费者** ，没有任何 AI 在读它。
>
> 今天我们把 AI 接进来。
> 接之前先说一句上节课最后那句话：
> **地基错了，上面那层越强越危险。**
>
> 所以今天不是"怎么让它能干更多事"，是**"它能碰什么，以及你凭什么知道"。**

### 0.8 课程参数（沿用 L13 已确认的）

|---|---|
| 时长 | **120 分钟** `[proposed]` ，待讲师确认（见 §9-1） |

## 1. 核心框架

### 1.1 框架一：交底五问 ⭐⭐ 全节脊椎

**完整内容在 `VIBE_CODING_MASTER_L14_ARCH_BRIEFING.md`。本文只给骨架与顺序。**

| 幕 | 问 | 学员产出 | 分钟 |
|---|---|---|---|
| 一 | **有哪些仓？** 拓扑 + 为什么必须分开 | 自己公司的三仓图 + 一条"它绝不许写"的仓 | 0-18 |
| 二 | **给它什么权限？** 读什么 / 写什么 / 谁批 | **自己的写权限表** ⭐ 核心产物 | 18-46 |
| 三 | **接哪些外部系统？** 以及为什么不能定时跑 | 连接器清单 + 哪些能定时哪些不能 | 46-76 |
| 四 | **它有哪些技能？** 双层 + 十节 | 一份按十节写完的技能规范 | 76-98 |
| 五 | **怎么维护？** 检查怎么长 / 漂移 / 谁能改 | 三层自动化各挂一条 | 98-120 |

**五问有顺序，不能打乱：**
先有仓（东西放哪），才谈权限（谁能动），才谈连接（够不够得着外面），
才谈技能（会干什么活），最后谈维护（怎么不烂掉）。

### 1.2 框架二：写权限表 ⭐⭐ 全节核心产物

**一张表，四列。学员第二幕当堂填自己的。**

| 写到哪 | 谁批准的 | **批准立在什么上面** | 什么时候能升级 |
|---|---|---|---|
| 邮箱草稿 | | | |
| 仓库提交 | | | |
| 工单系统 | | | |
| 聊天通知 | | | |

**第三列是全课最值钱的一格，而且它反直觉：**

> 真正起作用的限制，**不在"谁按那个按钮"，在"这项批准立在什么上面"。**
> 后者读者可以核查，按钮不能。

**这张表允许出现强弱不同的两行，而且必须标出来：**

```
行 A  往工单系统写   依据：一封邮件，任何人都能重新打开来读
行 B  往聊天发通知   依据：一通电话，由提出这个需求的人转述
                     ⚠️ 这是一项批准在仍然算作批准的前提下，最弱的形式
```

**把 B 那行的弱标出来，比把它伪装成跟 A 一样，安全得多。**

### 1.3 框架三：静默失败的四种形状 ⭐⭐ 收口所依赖

**这四样在课上分布在四个不同的地方，第五幕才被合到一起。**

| 形状 | 出现在 | 表面上 | 实际上 |
|---|---|---|---|
| 查询失败报成 0 | 三幕（翻车②） | 本期无异常 | 什么都没查 |
| 连接过期没人知道 | 三幕 | 报告天天是空的 | 它早就够不着了 |
| 有人点了合并但没人读 | 五幕（反转） | 有审批流程 | 没有审查 |
| 离职残留的授权还在 | 五幕 | 权限清过了 | 只是没人看 |

**四件事是同一个形状：看起来发生了，实际没有。**

### 1.4 老师必须抓住的八个要点

1. **每一幕结束前学员终端必须有新输出。** 没有就是讲飞了。
2. **不说产品名。** 举例说"你们那个记事情的系统"。
3. **翻车②必须慢，而且必须学员自己造。** 它是收口的地基。
4. **写权限表第三列不许跳过。** 学员会想只填前两列。
5. **第三幕那条推论链要完整讲**（交互式登录 → 过期 → 空结果 → 读起来像没事）。
6. **反转是对"人工审批"的，不是对"审批"的。** 别让学员理解成"审批没用"。
7. **技能十节里第 10 条（验收测试）最容易被跳过，也最值钱。**
8. **收口要把四种静默失败合到一起**，不能只念最后那句话。

### 1.5 最容易出错的六类地方

| # | 出错长什么样 | 后果 |
|---|---|---|
| 1 | **讲成治理研讨会** | 比 L13 严重得多，因为这一节天然更纸面。靠 §0.3 那张终端表防 |
| 2 | 说了产品名 | 一半学员觉得跟自己没关系 |
| 3 | 翻车②被一句带过 | **收口落空**，全课最后一句话没有地基 |
| 4 | 反转讲成"审批没用" | 学员回去把审批全撤了 |
| 5 | 第四幕技能十节念成清单 | 二十秒念完，学员什么都没带走。必须当堂写一份 |
| 6 | 学员追问某个具体工具怎么配 | 答"那是那个工具的文档"，**不要现场调配置** |

## 2. 学员起点与入场券

### 2.1 学员应已具备

- **L13：已经有一个自己的规则仓库**（这是硬前提，见 §2.3）
- L12：挂过钩子
- L11：写过无人值守任务书
- L5：做过技能
- L10：写过开场四问

### 2.2 课前必须带来的东西（入场券）

> **两样：L13 那个仓库，和一件"你希望 AI 替你做的事"。**

**第一样 · L13 的仓库。** 至少要有 `rules/` 两个角色文件 + `check.mjs`。
**没有的用 L13 的 `rescue/step-6/`。**

**第二样 · 一件你希望 AI 替你做的事。** 三条硬要求：

1. **必须会产生一个对外可见的结果**（发消息、改工单、提交文件、发邮件）。
   纯读的事今天用不上，因为今天整节课在讲"它能碰什么"。
2. **必须是你们公司真的会做的事**，不是"如果有 AI 我就……"。
3. **说得出如果它做错了会怎样。**

**好例子：**

- 「每天把昨天没人跟的问题列出来发到群里」（小组也完全适用）
- 「有人提了需求，帮我建个工单」
- 「每周把逾期的事汇总，发邮件给负责人」
- 「有人问某个流程，让它照着我们的文档答」

**坏例子（当场退回，说清为什么）：**

- 「帮我写代码」← 没有对外可见结果，也不是这门课的题
- 「帮我做决定」← 今天会讲为什么这件事不在表上（§1.2 的禁令那一格）

### 2.3 没有 L13 仓库的学员怎么办

| 情况 | 处理 |
|---|---|
| 没上过 L13 | 用 L13 的 `rescue/step-6/`，**但要明说：你今天是在一个别人的地基上接东西** |
| 上过但没做完 | 同上 |
| 仓库里全是虚构内容 | **第二幕的写权限表会填不疼。** 让他换成真实的一件事（入场券第二样） |

## 3. 学习目标与过关证据

| # | 能做到 | 过关证据 |
|---|---|---|
| H1 | 画出自己公司的仓库拓扑，并指出 agent 绝不许写的那个 | 一张图，且那条禁令写进了指令文件 |
| H2 | **写出自己的写权限表，四列齐全** | 一张表，**第三列不许空** |
| H3 | 说出哪些不是"没批准"而是"不可批准" | 至少列出四条禁令 |
| H4 | 判断一件事能不能定时跑，并说出理由 | 对自己那件事给出判断 + 一句理由 |
| H5 | 写一个会报 FAILED 而不是 0 的脚本 | **终端输出** |
| H6 | 按十节写完一份技能规范 | 一份规范，**第 10 条不许空** |
| H7 | 说出人工审批什么时候是失效模式 | 一句话，能举出自己的例子 |
| H8 | 给自己的系统挂三层自动化各一条 | 钩子 / PR 检查 / 巡检各一条 |

**真正的过关线：**

> **H2 的第三列，和 H6 的第 10 条。**
> 这两格是全课唯一两个"想偷懒就会空着"的地方，
> 空着就说明这节课对这个学员没发生。

## 4. 非目标

- **不教某个具体工具怎么配。** 学员问具体配置，答"那是那个工具的文档"。
- **不讲 MCP 协议本身。** 只讲"它够不够得着外面、过不过期"。
- **不做组织设计。**
- **不重复 L13。** 规则怎么写、检查怎么写，全部当已知。
- **不出现产品名。**（§0.5）

## 5. 五幕设计意图

> **逐页口播在 RUNSHEET，内容细节在 `VIBE_CODING_MASTER_L14_ARCH_BRIEFING.md`。本节只写"这一幕为什么存在"。**

### 5.1 第一幕 · 它现在能碰什么（0 到 18）

**解决的问题：** 学员根本不知道自己那个 agent 现在的权限边界在哪。

| 段 | 分钟 | 做什么 |
|---|---|---|
| 1 | 0-6 | 承接句（§0.7）+ 一个问题：**你的 agent 现在能碰什么？** 聊天框回答 |
| 2 | 6-12 | 让他们跑一遍自己现有的配置，把实际能跑的命令列出来。**多数人会发现跟自己以为的不一样** |
| 3 | 12-18 | 画三仓图（`VIBE_CODING_MASTER_L14_ARCH_BRIEFING.md` §2），写下**哪个仓它绝不许写** |

**关键一击：** 第 2 段大概率会出现"它能跑的比我以为的多"。
**那就是这节课的起点** ，不是吓人，是让"边界"这个词第一次变成具体的东西。

**第 3 段的动作要落到文件上**：在指令文件里写死不许写的仓库名。
**这是全部权限设计里最便宜、收益最高的一条。**

### 5.2 第二幕 · 给它钥匙（18 到 46）⭐ 核心产物在这

| 段 | 分钟 | 做什么 |
|---|---|---|
| 1 | 18-24 | 读白名单：只放不改状态的命令。`fetch` 在里面，`pull` 不在 |
| 2 | 24-30 | **翻车①**：把白名单放宽，跑一条危险的。发现**白名单不是安全边界** |
| 3 | 30-40 | **写自己的写权限表** ⭐ 四列，第三列不许空 |
| 4 | 40-44 | 四条不可批准的禁令（不是"没批准"，是"不可批准"） |
| 5 | 44-46 | 草稿与发送那条线（三行一起讲） |

**立论在第 3 段点出：权限不是一个开关，是一张一行一行批出来的表。**

**第 3 段是全课核心动手，10 分钟，不许压。**
学员会想只填前两列。**第三列（批准立在什么上面）是这节课存在的理由。**

**第 5 段那三行必须一起讲**（自己邮箱里建草稿 = 起草 / 发送 = 禁止 / 往仓库提交 = 不触发通信禁令但受留存规则管）。
学员最容易犯的错是把第三行当第二行（不敢让它提交），或把第一行当第二行（不敢让它起草）。
**两种错都会让这套东西没法用。**

### 5.3 第三幕 · 它够得着外面吗（46 到 76）⭐ 全节高光

| 段 | 分钟 | 做什么 |
|---|---|---|
| 1 | 46-52 | 连接器清单，**按"它要干什么"排，不按产品名排** |
| 2 | 52-62 | **交互式登录撑不过定时任务** ，完整推论链 + 代价 |
| 3 | 62-70 | **翻车②** ⭐⭐：造一次查询失败，看它报 0 |
| 4 | 70-76 | 四态结果模型 + 连接失败必须自带修复步骤 |

**第 2 段的推论链要完整讲，一步都不能跳**（`VIBE_CODING_MASTER_L14_ARCH_BRIEFING.md` §4.2）。
**代价必须一起说：** 由人触发意味着技能追不上你。
兜底不是加定时器，是"下次有人来的时候，告诉他哪个已结束的周期没有报告"。

**第 3 段是全课最重要的六分钟。**

学员写一个小脚本去查点什么，然后**故意把路径写错 / 把连接断掉**，看它输出什么。
默认写法会输出 `0`。

三句，一句都不能省：

```
1. 它报了 0。这个 0 是什么意思？   →「没有」
2. 真的吗？它查到了吗？            →「……没查到」
3. 那它凭什么报 0                  →「0」和「我不知道」被写成了同一个字
```

然后给四态模型，改脚本，重跑，看到 `FAILED`。

> 🔥 **埋点：这一格是收口的地基。** 讲师这里要说一句
> 「**这一格今天最后会回来**」，然后走。

### 5.4 第四幕 · 它会干什么活（76 到 98）

| 段 | 分钟 | 做什么 |
|---|---|---|
| 1 | 76-82 | 双层结构（规范层 / 执行层）+ 单副本 + Windows 降级 |
| 2 | 82-94 | **按十节写一份技能规范** ⭐ 用入场券那件事 |
| 3 | 94-98 | 组合方向是反的（生产型技能放输出落地的地方，但总表仍要列它） |

**第 2 段是第二个核心动手，12 分钟。**
写的是**规范层**，不写代码，
这节课不是教做技能（L5 教过），是教**一个技能要定义什么才算完整**。

**第 10 条（验收测试）最容易被跳过，也最值钱。** 给四个可当场验证的例子打样。

**第 1 段的降级方案要说清它差在哪：**
单目录 + 一条一致性检查 **不是**符号链接的等价物，
它把"单副本"换成了"两副本加一条检查"。

### 5.5 第五幕 · 谁来维护，以及它什么时候骗你（98 到 120）

| 段 | 分钟 | 做什么 |
|---|---|---|
| 1 | 98-104 | 检查怎么长大（三条规矩）+ 三层自动化 |
| 2 | 104-108 | **翻车③**：挂一个会阻塞的钩子，烦，改成不阻塞 |
| 3 | 108-113 | **反转**：人工审批往往是失效模式 |
| 4 | 113-116 | 漂移检查只数数，以及它看不见什么 |
| 5 | 116-120 | **收口** |

**第 2 段接 L12**：那节教怎么挂钩子，这里给**一个钩子该不该阻塞**。
一个会阻塞会话的新鲜度警告，**比它警告的陈旧本身更糟**。

**第 3 段是反转，三条理由要完整讲**（`VIBE_CODING_MASTER_L14_ARCH_BRIEFING.md` §6.5），第三条最硬：
被扣住的合并会让仓库说谎。

> ⚠️ **反转是对"人工审批"的，不是对"审批"的。**
> 结论是：把关口放在"检查绿不绿"上，不要放在"谁点了合并"上。
> **检查是可核查的，按钮不是。**

**第 4 段那一格有个反直觉的收获**：因为账号映射不入库、不能按人查，
限制反而逼出了更强的检查形态（"一个不是组织成员的协作者"，
不需要知道那是谁就能抓到离职残留）。
**同样重要的是写清它看不见什么** ，高风险的残留恰恰在它看不见的地方。

### 5.6 收口（116 到 120，四分钟，一秒不能少）

**必须把四种静默失败合到一起，不能只念最后那句话。**

```
今天你给它开了权限、接了系统、写了技能、挂了检查。

现在回头看四样东西：
   查询失败报成 0       ， 你以为本期无异常
   连接过期没人知道     ， 报告天天是空的
   有人点了合并没人读   ， 你以为有审查
   离职残留的授权还在   ， 你以为清过了

四件事是同一个形状：看起来发生了，实际没有。
```

**停一秒，收口：**

> **它最危险的时候，不是它做错了事，
> 是它什么都没做，而你以为它做了。**

**作业（一句话）：**

> 这周就一件事：**回去看你那张写权限表的第三列。**
> 哪一行的依据你写不出来，**那一行就先关掉。**
