# P20 · 一个写对的会话启动钩子

> 第五幕（P20）用。**先跑一下，再装。**

**会话启动钩子** = 每次打开 agent 会话时自动跑一下的小脚本。

## 一、先跑一下

```bash
node check-freshness.mjs
```

三种结果**都是正常退出，它永远不拦你**：

| 情况 | 它说什么 |
|---|---|
| 落后了 | `你这份检出落后远端 N 个提交。要不要拉一下，由你决定。` |
| 是最新的 | `是最新的。` |
| **判断不了**（不是 git 仓 / 没设上游 / git 跑失败） | **`无法判断你落后多少 —— <原因>`**<br>**`这不代表没问题，只代表这条检查这次没覆盖到。`** |

> ⭐ **第三行是这个脚本最重要的部分，也是它和本课第三幕咬合的地方。**
>
> 一个判断不了、却一声不吭通过的检查，**和没有这条检查是一样的** ——
> 那正是 P14 那个把失败报成 `0` 的脚本犯的错。
>
> **这个脚本的前一版就犯过这个错**：它只读一个环境变量，
> 喂它一个非法值会静默通过。**已经修掉了，但这件事值得记一下** ——
> **连写这门课的人都会掉进去。**

## 二、装上（配成 SessionStart 钩子）

在**规则仓**的 `.claude/settings.json` 里加：

```json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          { "type": "command", "command": "node .claude/hooks/check-freshness.mjs" }
        ]
      }
    ]
  }
}
```

> ⚠️ 先把脚本复制到你规则仓的 `.claude/hooks/` 下，`command` 里的路径按你实际位置改。

## 三、验证

**关掉会话，重新开一个。** 会话一开始就应该看到 `[新鲜度] ...` 那一行。

**看不到** → 检查三件事：路径对不对、`node -v` 有没有输出、JSON 有没有写坏。

## 四、卸载

把上面那段 `hooks` 删掉，重开会话。

---

## 为什么它必须「不拦」

一个**会阻塞会话**的新鲜度警告，**比它警告的陈旧本身更糟** ——
它每天拦你一次，拦的还都是你当下不打算处理的事。

**两天之内你会亲手把它关掉。然后连提醒都没有了。**

> 三层自动化里，**只有中间那层（提改动时的一致性检查）该拦人**。
> 启动钩子是提醒，每周巡检是巡检 —— **这两层都不该拦。**
