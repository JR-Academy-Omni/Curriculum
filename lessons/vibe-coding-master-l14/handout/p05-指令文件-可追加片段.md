# P05 · 往指令文件里加的那一段

> 第一幕（P05）用。**三分钟。这是整节课最便宜、收益最高的一条。**

**第一步：找到你那份指令文件 —— 很可能你还没有。**

它是 agent **每次进这个仓库都会先读**的那份项目规则文件，放在**规则仓的根目录**。

> ⭐ **上节课的八步里，指令层是排在最后的，所以多半你还没建。**
> **没有就现在建一个** —— 这正是今天这一步的意义。

**第二步：把下面这段追加到文件末尾。**

```markdown
## 这个 agent 绝对不许做的事

- 不许向产品仓写入任何内容。
  产品仓是指：<把你们的产品仓名字逐个列在这里>
- 读产品仓是对的，也应该鼓励；**写是禁止的**。
```

**填好之后长这样**（这是讲师今天演示用的那份，你换成自己的仓库名）：

```markdown
## 这个 agent 绝对不许做的事

- 不许向产品仓写入任何内容。
  产品仓是指：star-mansions
- 读产品仓是对的，也应该鼓励；**写是禁止的**。
```

**第三步：把 `<...>` 换成真实的仓库名。**

> 🔴 **写「产品仓」三个字不算 —— 它不知道哪个是产品仓。**

**第四步：保存，重开一个 agent 会话，确认它读到了。**

---

## 为什么这一条值这么多

禁止写产品仓**不是怕它写坏**。

是因为**权限边界要跟责任边界对齐** ——
产品仓有它自己的审查人，有它自己的检查。
**一个 agent 同时能写两边，等于把两套互不相干的审查制度短路了。**

而且这一条**不需要任何工具支持**，它只是一句写下来的话 ——
**但它是今天唯一一条你现在立刻就能做完的。**
