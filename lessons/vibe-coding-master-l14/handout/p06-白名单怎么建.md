# P06 · 白名单怎么建

> 第二幕（P06）用。**八分钟，当堂建一个。**

## 一、它在哪，长什么样

在你规则仓的 `.claude/settings.json` 里：

```json
{
  "permissions": {
    "allow": [
      "Bash(git status:*)",
      "Bash(git diff:*)",
      "Bash(git log:*)",
      "Read(**)"
    ],
    "deny": [
      "Bash(rm -rf:*)",
      "Bash(git push --force:*)",
      "Bash(git reset --hard:*)"
    ]
  }
}
```

**两个列表，作用完全不一样：**

| | 它决定什么 | 拦不拦 |
|---|---|---|
| `allow` | **要不要问你一声** | **不拦。** 不在里面的命令照样会做，只是先问一句 |
| `deny` | **能不能做** | **拦。** 列进去的直接不做，**`deny` 优先于 `allow`**。⚠️ 但它是**按命令文本匹配**的，不是操作系统级边界 |

---

## 二、先说一件不太舒服的事

**你现在那份 `allow`，多半不是你设计出来的。**

是你一路点**「总是允许」**，它自己攒出来的 ——
每次弹窗你嫌烦，点一下，它就往里加一条。

> **所以它才不是安全边界：没有人设计过它。**

**今天打开你那份看一眼。** 你多半会看到几条你完全不记得自己批准过的东西。

---

## 三、正经建，三件事

### ① `allow` 只放不动你工作区的

看状态、看差异、看历史、取远端更新。

> ⚠️ 严格说「取远端更新」不是零写入 —— 它会写 `.git` 里的远端引用。
> **判据是「它不碰你的文件」，不是「它什么都不写」。**
> 如果你们要求绝对零写入，那就连它也别放。

### ② `deny` 放真正危险的 ⭐ 今天最值钱的一条

```
Bash(rm -rf:*)
Bash(git push --force:*)
Bash(git reset --hard:*)
Bash(git clean:*)
```

一行配置，立刻生效。

> ⚠️ **别把它当护城河。** `deny` 是**按命令文本匹配**的 ——
> 换个写法（套一层 shell、用全路径、把命令拼出来）就可能不匹配同一条规则。
> **它挡得住手滑和顺手，挡不住绕路。**
>
> 但这不等于它没用：**事故绝大多数是手滑和顺手，不是蓄意绕路。**

### ③ 个人偏好放 `settings.local.json`，并且 gitignore 掉

你自己嫌烦想多放几条，放本地那份。**别把你的习惯塞给全队。**

---

## 四、现在动手（八分钟）

1. 打开你规则仓的 `.claude/settings.json`（没有就新建）
2. **给 `deny` 加三条你真的不想让它跑的命令**
3. 保存，**重开一个会话**让它生效
4. 聊天框打 `1`

> 🚨 **做完记住两件事，下一页会展开：**
> **① `deny` 挡得住手滑，挡不住绕路**（文本匹配，不是 OS 边界）。
> **② 它管的是工具调用。** 「发一封邮件」「改一条工单」走的是连接器，
> 归下一页那张**写权限表**和它背后的**凭据**管。
