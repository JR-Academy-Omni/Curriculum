# P20 · 三层自动化，三个写对的脚本

> 第五幕（P20）用。**三层各一个，都先跑一遍再装。**

课上讲的三层，这里三个脚本一一对应：

| 层 | 什么时候跑 | 脚本 | 它能不能拦你 |
|---|---|---|---|
| 第一层 | **每次开会话** | `check-freshness.mjs` | **永远不拦** |
| 第二层 | **每次提改动** | `check.sh` | ⭐ **唯一真正会拦的一层** |
| 第三层 | **每周一次** | `access-drift.sh` | **不拦**，只出报告 |

**三个里只有中间那个该拦人。** 这不是实现上的偷懒，是这一页的论点本身 ——
全设成会拦，天天红，**然后没人再看**。

---

# 第一层 · 会话启动钩子（`check-freshness.mjs`）

**会话启动钩子** = 每次打开 agent 会话时自动跑一下的小脚本。

## 一、先跑一下

```bash
node check-freshness.mjs
```

三种结果**都是正常退出，它永远不拦你**：

| 情况 | 它说什么 |
|---|---|
| 落后了 | `你这份检出落后远端 N 个提交。要不要拉一下，由你决定。` |
| 是最新的 | `是最新的。` |
| **判断不了**（不是 git 仓 / 没设上游 / git 跑失败） | **`无法判断你落后多少 —— <原因>`**<br>**`这不代表没问题，只代表这条检查这次没覆盖到。`** |

> ⭐ **第三行是这个脚本最重要的部分，也是它和本课第三幕咬合的地方。**
>
> 一个判断不了、却一声不吭通过的检查，**和没有这条检查是一样的** ——
> 那正是 P14 那个把失败报成 `0` 的脚本犯的错。
>
> **这个脚本的前一版就犯过这个错**：它只读一个环境变量，
> 喂它一个非法值会静默通过。**已经修掉了，但这件事值得记一下** ——
> **连写这门课的人都会掉进去。**

## 二、装上（配成 SessionStart 钩子）

在**规则仓**的 `.claude/settings.json` 里加：

```json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          { "type": "command", "command": "node .claude/hooks/check-freshness.mjs" }
        ]
      }
    ]
  }
}
```

> ⚠️ 先把脚本复制到你规则仓的 `.claude/hooks/` 下，`command` 里的路径按你实际位置改。

## 三、验证

**关掉会话，重新开一个。** 会话一开始就应该看到 `[新鲜度] ...` 那一行。

**看不到** → 检查三件事：路径对不对、`node -v` 有没有输出、JSON 有没有写坏。

## 四、卸载

把上面那段 `hooks` 删掉，重开会话。

---

## 为什么它必须「不拦」

一个**会阻塞会话**的新鲜度警告，**比它警告的陈旧本身更糟** ——
它每天拦你一次，拦的还都是你当下不打算处理的事。

**两天之内你会亲手把它关掉。然后连提醒都没有了。**

> 三层自动化里，**只有中间那层（提改动时的一致性检查）该拦人**。
> 启动钩子是提醒，每周巡检是巡检 —— **这两层都不该拦。**

---

# 第二层 · 提改动时的一致性检查（`check.sh`）

**这一层是三层里唯一真正的硬政策** —— 它红了，改动就进不来。

它查的是**第十四节今天产出的东西**，不重复第十三节那套。

## 一、先跑一下

```bash
bash check.sh          # 它会自己回到仓库根再查，从哪个目录调起来都行
```

| # | 查什么 | 红了拦不拦 |
|---|---|---|
| 1 | **第十三节那个 `check.mjs` 还跑不跑得过** | **拦** |
| 2 | **写权限表第三列「批准立在什么上面」不许空** | **拦** |
| 3 | **技能规范十节不许缺**（尤其第 10 条验收测试） | **拦** |
| 4 | 全仓还剩多少处待补 | **不拦，只提示** |

**第 1 条是这一层存在的理由。** 第十三节那套检查是**手动跑的** ——
你不跑它就不说话。这一层做的事只有一件：**把它从「手动跑」变成「不绿就合不进去」。**

> ⭐ **第 4 条才是这个脚本要教的东西。**
>
> 「全仓还剩 N 处待补」是一个你**想知道**、但**不想每天被它拦一次**的数字。
> 所以它走 `note`，不走 `bad`。
>
> 这两个函数的区别只有一行 —— `bad` 把 `fail` 置成 1，`note` 不置。
> **「硬失败和提示必须分开」，落到代码上就是这一行。**

## 二、两个它自己踩过、已经修掉的坑（都值得看一眼）

**① 没有 `node` 的时候，第 1 条报的是 `FAIL`，不是跳过。**
一台装不了 node 的机器上，「这条没能跑」和「这条通过了」**是两回事** ——
这就是第三幕那个 `0`，换了个地方。

**② 表格里的空白行差点被当成分隔行跳过去。**
识别 Markdown 分隔行的那条正则原来不要求有 `-`，结果 `|  |  |  |  |`
也匹配上了 —— **一个本该全红的空白表，静悄悄地通过了。**
正则已经改成必须含 `-`。**写这门课的人自己又掉进去一次。**

## 三、装上

复制到你规则仓的 `.claude/scripts/check.sh`，在 PR / push 时跑它。
**退出码非 0 就不许合。**

## 四、自己验证它真的会拦

拿你今天填的那张写权限表，**把某一行的第三列清空**，再跑一次。
应该看到 **`FAIL ... 第 N 行第三列是空的`**，**退出码 1**。

**看到了，这一层才算装好了。**

> ⚠️ **第十三节建的是 `rules/<角色>.md` 单文件 + `rules/INDEX.md` 登记**，
> 真系统长大之后是 `roles/<角色>/charter.md` + `roles/README.md`。
> **这个脚本不替你判哪种对** —— 角色那两条由第 1 条里你自己的 `check.mjs` 管。

# 第三层 · 每周权限漂移巡检（`access-drift.sh`）

比对**实际权限**和**规矩里写的权限**，每周一次。

## 一、先跑一下（不用配任何东西）

```bash
bash access-drift.sh
```

**没配组织名的时候，它报的是：**

```
FAILED：没有配置组织名或仓库名。
  这次运行没有覆盖任何东西。
```

**退出码 1。**

> ⭐ **这就是今天第三幕那一格，在第五幕又出现了一次。**
>
> 一个查不到数据的巡检，**最容易写成「发现 0 处漂移」** —— 看起来是个干净的结果，
> 实际上是它根本没查。
>
> **「本次没有答案」和「答案是零」是两回事。** P14 那个脚本错的就是这个，
> 这个脚本对的也是这个。

## 二、配上去

按脚本头部的注释填组织名和仓库名，再跑一次。
需要 `gh`（GitHub CLI）并且已经登录。

## 三、它看不见什么

**这条很重要，P22 会专门讲一页：** 它数得到的是**还在组织里的人的权限**。
**它看不见的是**：个人访问令牌、机器账号、第三方应用的授权、
以及已经离开组织但凭据还在外面的那些 ——
**而高风险的残留，恰恰多半在它看不见的那一边。**

所以这一层的产出是**一份要人看的报告**，不是一个绿灯。
