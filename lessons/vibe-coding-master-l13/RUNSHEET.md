## A3. 线上无助教的五条纪律 ⭐⭐ 比逐页口播还要紧

**纪律一 · 你看不见他们在写什么，别假装看得见。**
所有"巡场""看到有人…""念一个写得好的"全部删除。**你只有聊天框。**

**纪律二 · 学员只贴终端输出，不贴文件内容。** 课上明说一次（第 28 分钟，P08 结束时）：

> 「等下让你们贴东西的时候，**只贴终端里那几行输出**，别贴文件内容。
> 　你写的是你们那儿真实的东西，那是你的，不用给我看。
> 　终端输出只有文件名和一句'疑似写了名字'，**它本身就是脱敏的**。」

**纪律三 · 卡住的人不要在直播里单独调，那一格改成看你投屏。** 见 §A4。**不发救生艇。**

**纪律四 · 等待点必须有话说。** 线上沉默比线下煎熬十倍。三段常备话术：

> **话术①（等跑通，60 到 90 秒）：**
> 「还没绿的先别急，两件事你可以核一下：一是你在不在仓库根目录跑的，
> 二是文件名是不是 `.mjs` 不是 `.js`。
> 　实在不行，把 `step-1/` 整个覆盖过去，**这不算作弊，这是让你跟上节奏。**
> 　顺便说一句，你可能觉得第一条检查特别蠢，『目录非空』谁会搞错。
> 　等下你会看到，蠢的检查抓到的，正好是人眼扫不出来的那类错。」
>
> **话术②（等造红，45 秒）：**
> 「你现在在做的事，一句话：**故意把它弄坏，看它会不会喊。**
> 　一个从来没红过的检查，跟没有检查是一样的，你根本不知道它在不在工作。」
>
> **话术③（等写东西，90 秒以上）：**
> 「写不出来是正常的。卡住的那一格，**先原样留着别填**，
> 　等下我们专门讲那一格该怎么办。」

**纪律五 · 不要点名。** 线上点名会让所有人闭麦。要例子就用你自己的（K.2）。

## A5. 有人问"我们就三个人" ⭐ 一定会有人问，答案要背下来

**不要答"那你可以简化一下"。那等于说他不配做这套东西。**

**照念：**

> **规模决定形态，不决定要不要做。**
>
> 而且说实话，**三个人的组收益最快。**
> 因为小组最吃亏的那条，是第五句：**只有一个人知道那件事怎么做。**
> 那个人请假、离职、或者只是那天忙，整摊就停了。
>
> **规则文件正是这件事最直接的解药。**

**然后给形态（附录 A0 那张表，一句话带过，不展开）：**

> 三个人：**一个仓，`rules/` 一个目录，三到五条检查。记录就用你们已经在用的那个工具，别另建。**
> 十个人：规则和记录分开，记录一个 git 仓够用。
> 五十人：已有工单 / IM 当写入面，git 只做快照锚点。
>
> **今天课上八步走的就是三人形态。**
> 所以规模大的回去往上加，**规模小的就停在今天这个样子 ,**
> **你不是做了个简版，你做完了。**

> 🚨 **最后那句"你做完了"必须说出口。** 小组学员全程会怀疑自己在做玩具，
> 　 这一句是他愿意回去真用的前提。

## P01 ｜ 0 到 5 分钟 ｜ 这五句，你们中了哪几句 · **埋点 1**

**开场不讲课。先让学员在聊天框认领一条症状。**

**照念（单位那段必须说出口，不许省）：**

> 「今天我会一直说『**你们那儿**』，不说『你们公司』。
> 　一家公司、一个部门、一个项目组、三个人的小队，
> 　**甚至只有你和你那几个 agent**，都算。
> 　判据只有一条：**有没有超过一个动作者，会碰同一批东西。**」

然后念五句，让聊天框打编号：

```
1. 没人看得见什么处在风险里          ← 偏大规模
2. 决策被提出，然后搁着
3. 问题被提出，然后悄悄淡掉
4. 有人绕开流程，直接找到了做事的人  ← 偏大规模
5. 只有一个人知道那件事怎么做        ← 偏小组
```

**读票（十秒，别做统计学）：**

| 票型 | 说明 | 你怎么调 |
|---|---|---|
| **5 票最多** | 这班偏小组 | 后面的例子全往三人组靠，§A5 提前准备好 |
| 1 / 4 票最多 | 这班偏大规模 | P07 记录选型那段可以多给三十秒 |

**⭐ 票最多那条记在你自己的纸上。收口（P27）第一句要用它。**

> **硬停：第 5 分钟。** 不要点评，不要展开，直接切 P02。

## P02 ｜ 5 到 8 分钟 ｜ 它写在三个地方，然后呢 🎬 **我现场跑**

**这一页做两件事，一页做完：演示 A 的台子，和第一幕到第二幕的桥。**

### 上半 · 跑之前

指着三个地方念完：

> 「这条规矩，写在**项目文档里**、写在**指令文件里**、**会上说过不止一次**。
> 　现在看它被破掉。」

**切终端，跑 K.1。**

> 🚨 **跑完不解释、不辩护、不说"平时不这样"。让沉默持续两秒。**

切回 deck，指着下半屏：

> 「三个地方都写了。**破它的时候，没有任何东西拦一下。**」

**然后这两句必须说（不说，学员会以为这是在黑 agent）：**

> 「顺带说一句：**这不是它的问题。**
> 　**换个人来做，结果一模一样。**」
>
> 「这条规矩我写过、说过、也提醒过。
> 　**这从来不是『没写下来』的问题。**」

### 下半 · 那个追问

> 「我想问的不是『为什么会有人破规矩』。
> 　是另一个问题 ——
> 　**在你们那儿，是什么东西保证一条规矩会被执行的？**」

**让聊天框答。他们会打出来：开会说 / 写进 wiki / leader 盯 / 大家自觉。**

收成一句：

> 「这四个是同一个答案：**靠人记得。**
> 　今天我们给规矩配一个**不靠人记得**的东西。
> 　它是一个仓库 —— **但在动手建之前，有一个问题最容易搞错。**」

> ⚠️ 最后那半句是唯一的前瞻，**刻意不说"八个问题"**。
> 　 路线图放这里，后面每一步的发现感全部消失（八步总表在附录 A1，课上不翻）。

> **硬停：第 8 分钟。**

## P03 ｜ 8 到 11 分钟 ｜ 那就写下来？ ⭐ **全课主链的入口 · 埋点 4**

**三拍有顺序，不能打乱。每一拍你自己问，自己答。**

```
① 「那就写下来？」   → 刚才已经试过了。写了三个地方，破的时候照样没人拦。
② 「那写进 wiki？」  → 谁都能悄悄改，而且改了没人知道。
③ 「那放进 git 仓？」 → 对。
```

**然后停，把第三拍的理由说完整 —— 这是全课的支点：**

> 「但**不是**因为 git 更专业、更规范、更工程化。
> 　是因为它有一个
> 　　　　**你改不了的远端**。
>
> 　wiki、共享文档、共享盘，都没有这个东西 ——
> 　**它们里面的每一条，都可以被有权限的人悄悄改成另一条。**」

> 🔥 **埋点 4。**「你改不了的远端」这句埋在这里，P20「本地的都可以改」整页展开它。
> 🚨 **这一页不许出现「CI」「分支保护」「第几级」。** 那是第四幕的东西。

> **硬停：第 11 分钟。**

## P04 ｜ 11 到 14 分钟 ｜ 这套东西长什么样（六层图）⭐ **埋点 5**

**这张图一次回答三件事：这系统是做什么的 / SOP 是什么 / 为什么今天不先写 SOP。**

从下往上念一遍，四秒一层：

```
L5  技能层   AI 怎么干活            ← 下一节
L4  流程层   SOP / 模板             ← SOP 在这里
L3  组织层   角色 / 花名册          ← 今天做
L2  治理层   谁说了算（最高权威）    ← 今天做
L1  入口层   人读的那一份
L0  指令层   AI 读的那一份          ← 最后做   ⭐
```

**念到 L0 那一行，停一下，把「最后做」的理由说掉（⭐ v3.2 讲师加的，不许省）：**

> 「注意最底下那一层的标是『**最后做**』，不是『今天做』。
> 　**它是唯一一份会反过来管住你这次施工的文件。**
> 　你写完它那一刻，**帮你建仓库的那个 agent 就开始受它管** ——
> 　它里面一旦有『规则目录的改动必须走 PR』这种话，
> 　**你后面每一步都要跟自己刚立的规矩打架，而且你可能已经没权限改它了。**
>
> 　所以顺序是：规则先定死、检查先跑绿、强制点先挂上，
> 　**最后才告诉 AI『这些是你要遵守的』。**」

> ⭐ **这是全课第一次出现「顺序本身也是设计」。** 它在 P24 生成器第 6 步还会回来一次。

**指着顶上那个空格：**

> 「**还差最上面一层。今天下半场才填。**」

> 🔥 **埋点 5。** 不要解释它是什么。**缺一块的图会让学员一直惦记，那是故意的。**
> 🚨 **不许在这里说"强制力"「执行层」「CI」。** 提前亮底，P21 的视觉重心就废了。

**然后 SOP 那段（学员真正的疑问在这儿）：**

> 「那 SOP 是什么？
> 　把『这件事该怎么做』写下来，**让换个人也能做**。
>
> 　**大多数公司的 SOP 失败，不是因为写得不好，
> 　是因为写完之后没有任何东西保证它被执行。**
>
> 　所以今天**不从写步骤开始**，从**『谁说了算』**和**『谁来拦』**开始。
> 　L4 站在 L2 和 L3 上面。**没有谁说了算，SOP 写出来也没人执行。**」

**最后白送一条（它不是话术，是这张图的结构本身在说话）：**

> 「⭐ 这张图还有第二重身份：**它是 AI 的检索路径。**
> 　每层一个位置，它才知道去哪找 ——
> 　**一个话题散在三个文件里，它必须三个都读完才敢答。**」

> **硬停：第 14 分钟。**

## P05 ｜ 14 到 18 分钟 ｜ 什么进得来 🎯 **全班动手**

**先建仓（三十秒，所有人一起）：**

```
mkdir my-ops && cd my-ops
git init
mkdir rules
```

**然后六样分拣，聊天框打编号：**

```
1. 谁审批超额支出
2. 上周三的会议纪要
3. 角色的职责边界
4. 今天谁在值班
5. 提交信息的写法要求
6. 这个 bug 的处理进度
```

> 🚨 **答案不上屏，你口播揭晓：1、3、5 进。**

**判据不是内容主题，是拿同一样东西问这三个问题：**

| 问这三个问题 | 该进来的 | 不该进来的 |
|---|---|---|
| 改一次要不要审？ | 要 | 不要 |
| 改错了多久能发现？ | 可能几个月 | 当天 |
| 写它的人会不会 git？ | 会 | 不一定 |

**结尾两句（都是下一页的钩子，一句都不能省）：**

> 「注意第三行那个『**不一定**』——**它后面藏着这一步真正的收获，下一页说。**」
>
> 「这两堆东西现在还没有名字。**名字也在下一页。**」

> ⚠️ **这一页不许给它们起名。**「规则 / 状态」这两个词在这页之前从没出现过，
> 　 而且「状态」跟下一页的「记录」打架 —— 不进的那三样里，会议纪要是**记录**，
> 　 值班和 bug 进度才是**状态**，两类混不进一个名字。

> **硬停：第 18 分钟。**

## P06 ｜ 18 到 21 分钟 ｜ 一个说「应该怎样」，一个说「当时怎样」· **埋点 6**

**拿这四件事去问，一行一行念：**

| | **规则** | **记录** |
|---|---|---|
| 它回答什么 | 现在的规矩是什么 | 当时发生了什么 |
| 内容能不能改 | 能改。规矩本来就会变 | 不能改。只能追加一条更正 |
| 谁写 | 少数人 | 所有人，包括不用 git 的 |
| **最怕什么** ⭐ | **改了，没人知道** | **写过的东西，被抹掉** |

**然后那一句（这一页的全部重量）：**

> 「**它们对保护的要求正好相反：**
> 　规则要的是**『改动可审』**，所以每次改都走 PR；
> 　记录要的是**『写入不可撤』**，所以**加东西要零摩擦，但加进去的抹不掉**。
>
> 　记录那边一旦也强制走 PR，追加就有了摩擦 ——**而有摩擦的记录没人写**
> 　（顺带把不用 git 的同事挡在门外）。」

> ⚠️ **「不会 git 的同事」是后果，不是理由。** 理由是"追加要零摩擦"。讲反了，学员回去会把记录也塞进 PR 流程。

**名字不对称那段必须说（这是 v3.1 的一刀）：**

> 「**注意这两个名字不对称，那是故意的：**
> 　规则**必须**放一个 git 仓 —— 我们刚证过，它需要一个你改不了的远端。
> 　**记录放哪还是个开放问题**，可能是仓、可能是数据库、可能两者 ——**下一页才回答。**」

**收尾：**

> 「至于『今天谁在值班』这种**当下**状态，它活在你们已经在用的工单系统里，这两个都不装。」
>
> 「**这两行『最怕什么』，后面那张开关表会回来收。**」

> 🔥 **埋点 6。** 🚨 **只说「后面那张」，不说页码。** deck 上写页码跟写分钟数一样脆。

> **硬停：第 21 分钟。**

## P07 ｜ 21 到 23 分钟 ｜ 被读，还是被数 ⭐

**学员课堂上不建记录，但回去第一天就要做这个选型，所以判据必须在正课。**

**判据只有一句，念出来：**

> 「**这条记录，是要被读，还是要被数？**」

| 拿这四件事去问 | 被读 → git | 被数 → 数据库 |
|---|---|---|
| 一年后翻出来干嘛 | 看当时怎么想的 | 算出现了多少次 |
| 形态 | 散文，价值在细微处 | 结构化，形状重复 |
| 一年产生 | 几十条 | 几千条 |
| 进不进 agent 的 context | 要，所以必须小 | 不要 |

```
进 git：决策记录 · 批准依据 · 破例记录 · 规则变更
进数据库：日更 / 站会 · 工单状态流转 · 检查命中记录 · 权限授予记录
```

**两句收尾：**

> 「**既要读又要数的**（比如破例记录）：**写进 git，让脚本去数。**
> 　几百条以内脚本数得动；超过了再拆 —— 结构化字段进库、理由文本留 git、用一个 id 挂起来。」
>
> 「**三个人的组：用你们已经在用的那个工具。不要为这门课另建一个仓。**」

> ⚠️ **判据为什么只有一句：** 混合方案的代价就是"这条记录该去哪"变成每天的判断。
> 　 判据不简单到能写进模板里，那个代价就还不起。完整三方案在附录 A8，**课上不翻**。

> **硬停：第 23 分钟。**

## P08 ｜ 23 到 30 分钟 ｜ 第一条检查：说给它听 🎯 **本节地基 · 埋点 3 / 7**

**先立一条规矩，全场通用：**

> 「从现在开始有一条规矩：**每加一条规则，当场给它加一条检查。**」

### 🚨 这一页是 v3 最大的改动：代码不是让学员抄的

**学员的动作是三步，页面上就是三栏：**

```
① 你说的话  →  ② 它写的东西  →  ③ 你判它对不对
```

**① 全班说同一句话（念一遍，让他们照说给自己的 agent）：**

> 「在 `check.mjs` 里加一条检查：**规则目录必须存在，而且不能是空的。** 空的就报失败。」

**这一句说完，把这两句补上 —— 这是整页真正的收获：**

> 「**你不用会写。** 你只需要把那条规矩说到**它不用猜**。」

> 🚨 **右边那段代码是给学员评判用的，不是给他抄的。你不许念它。**
> 　 一门 Vibe Coding 课让学员手敲 `readdirSync` 循环，本身就是跑题；
> 　 而且抄完的东西他两周后改不动。

**③ 判它对不对，两步：**

```
先红  ——  rules/ 现在是空的
建一个文件，再跑，绿了
```

**埋点 7（bad / note）—— 说完就走，不许展开：**

> 「骨架里有 `bad` 和 `note` 两个函数。
> 　**现在不用管为什么有两个 —— 等下你会非常需要这个区分。**」

**⭐ 第 28 分钟：全场同步点。绿了的打 `1`。**
**不到三分之二不推进**，念 §A3-话术①，让没跑通的覆盖 `step-1/`。

**埋点 3（这一页最后一句，必须说，而且说完就切页）：**

> 「最后说一件事：**目前没有任何东西自动跑它。**
> 　你今天不跑，它就今天不存在。」

**顺带把 §A3-纪律二那段脱敏规矩说掉（只说这一次）。**

> **硬停：第 30 分钟。第一次绿在这里，这是第一个硬判断点。**

## P09 ｜ 30 到 35 分钟 ｜ 他们不是没写裁决规则 ⭐

**开场一句把上一步接住：**

> 「第 1 步你有了一个目录。文件一多，它们会互相矛盾。到时候听谁的？」

**然后讲这个事故（虚构化叙述，照念，不加细节）：**

```
A · 治理文件   「这个仓库每次改动都走 PR，不需要审批人」
B · 角色文件   「合并审查绝不由作者自己做」
```

> 「两条前后差一天，都签字确认过。**不加范围读，不可能同时成立。**
>
> 　他们的裁决规则只写了一句：**『跟治理文件冲突时，治理文件赢』**
> 　而角色文件**不在治理目录里** —— 那条裁决规则够不着这个组合。
>
> 　后来有人去翻记录：**连着几个月，每一个改动都是提出的人自己批、自己合，没有一次例外。**
>
> 　在第一种读法下这是正常运行，在第二种读法下这是一串违规。
> 　而必需审批人数配置为 0，**无论按哪种读法，都没有任何东西会把差别暴露出来。**」

**收成一句（这是你必须点的那句）：**

> 「他们写了裁决规则。**但那张表漏了一格。**
> 　**漏掉的那一格，就是将来那场事故的位置。**」

> 🚨 **纪律 7：不出现精确计数。** 只说"连着几个月，没有一次例外"，
> 　 不说"N 个 PR 全部自合"—— 那种数字组合起来是可反查的指纹。

> **硬停：第 35 分钟。**（§J 二级砍法砍的就是这一页，降成一句话。）

## P10 ｜ 35 到 41 分钟 ｜ 裁决表 + 检查② 🎯 **全班动手**

**一句话给原则：**

> 「裁决表必须是**全序**：任意两个目录打架，都要有确定答案。」

**让他们写 `AUTHORITY.md`：**

```
# 权威优先级

冲突时，上面的赢。

1. governance/   谁决定、谁批准、什么禁止
2. rules/        每个角色答应什么
3. people/       这儿有谁
4. sops/         活怎么干
5. README.md     摘要。与上面冲突时，上面赢

## 例外
（暂无。加例外要同时加一条检查）
```

**一定会有人问"governance/ 和 sops/ 还不存在"—— 提前答掉：**

> 「**`governance/` 和 `sops/` 现在还不存在，先写进表里是对的：
> 　裁决表本来就该先于目录存在。**」

**然后检查②（还是"说给它听"）：**

> 「再加一条：**每个目录，都必须在 `AUTHORITY.md` 里有位置。** 没有的报失败。」

**价值那句必须点（它不是"找错"）：**

> 「它保证你以后**每新建一个目录，都必须先决定它在裁决表里的位置**，否则合不进去。
> 　**它把『别漏格』从『记得』变成了『绕不过去』。**」

**顺带两条，都是给 AI 读它用的（顺手给，不占独立时间）：**

> 「**一个话题只在一个文件里** —— 散在三个文件，它必须三个都读完才敢答，
> 　**漏一个就给你一个自信的错答案。**
>
> 　**例外必须和规则在同一个文件里** —— 所以上面那个『## 例外』是内嵌一节，**不是另一个文件。**」

**再顺带一条（回路三条之一，一句话）：**

> 「每条检查旁边写一句：**它是因为什么加的。** 不写，半年后没人敢删它。」

> **硬停：第 41 分钟。**

## P11 ｜ 41 到 50 分钟 ｜ 先记下有谁，再写谁答应什么 🎯 **全班动手**

> ⚠️ **本页不提「角色文件该怎么写」** —— 顺序上没必要提前，那条规矩在 P18 正面给。
> **v3.2 起这不再是「自毁按钮」**：P18 已经改成先讲规矩再跑，
> 你在这儿说漏嘴，最多是少一点意外，**不会整格作废**。
> 旧版把 P18 整格压在「那条检查会咬到学员自己」上面，**而那件事不保证发生**。

**一句话给要求：**

> 「**写你们那儿真实的情况，不要编一个好看的。**」

**① 先建花名册（顺序不能反）：**

```
# 花名册

- 张伟
- 李明
- 王芳
```

> 「中文英文都行。三个人的组就写三个，**不寒碜**。」
>
> 「⚠️ 这是你自己电脑上的文件，**不要贴到聊天框**。」

> ⚠️ **对学员的说法是「先记下有谁，再写每个角色答应什么」**，完全自然，
> 　 不会让任何人联想到后面那一刀。

**② 再写两个角色文件 `rules/<角色>.md`：**

```
# <角色名>

## 答应什么
（这个角色最终要对什么负责，两三条）

## 独自能决定什么
（不用问任何人）

## 什么必须报批，报给谁
（要报批的事，和报给谁）
```

> ⚠️ 第三段写成「什么必须报批，**报给谁**」—— **「报给谁」是故意的**，P13 那一问就落在这里。

**小组学员必须接住（不然他们会觉得这一步跟自己无关）：**

> 「三个人的组照样有角色：**谁管发布、谁管对外、谁能合主分支。**」

**这是全节最长的一个动手段（九分钟）。用 §A3-话术③ 填等待。**

> **硬停：第 50 分钟。**

## P13 ｜ 56 到 64 分钟 ｜ 那个数字，是谁定的 ⭐⭐

**三个问题，顺序不能换，一个都不能省：**

> 「① 刚才写『什么必须报批』的时候，**有多少人写了一个金额、一个天数？**」
>
> 「② **那个数字，是谁定的？**」

> 🚨 **第二问问完停两秒，不要马上接话。**

> 「③ 大概率是你刚才顺手写的 —— **因为不写显得没写完。**」

**追问分支（一定会有人答"老板定的"）：**

> 「答『老板定的』的人，我追一句：**你知道他是按什么定的吗？**」
>
> 答不上来 → 「**那也是一个空，在等的那个人就是老板。**」

**然后给三个标记：**

```
[confirmed]   锁定，有人确认过，带日期
[proposed]    待签字的建议
[to supply]   还没有人提供
```

**那条硬规矩（这是全节的价值观，念慢）：**

> 「**绝不用一个合理的猜测去填 `[to supply]`。**
>
> 　空着的缺口是信息。
> 　**编造的值是一个看起来像进展的缺陷** ——
> 　而且更糟，**因为它让所有人不再追问。**」

**两个对照，指着念：**

| | |
|---|---|
| ❌「超过 5000 元需老板审批」 | 看起来很专业。**没有人同意过。** |
| ✅「超过 `[to supply]` 需老板审批」 | 难看。**但它在等一个人。** |

**动手（三分钟）：**

> 「把每一个你答不上『谁定的』的数字，改成 `[to supply]`。」

> ⚠️ **纪律 7：不出现精确缺口数。** 不说"平均每人会有几处"。

> **硬停：第 64 分钟。**

## P14 ｜ 64 到 70 分钟 ｜ 标成 approved，跑 🎬 **第二次红 · 埋点 2 · 收口的地基**

> 🚨 **这一格是收口的地基。** 上一版没有这一步，导致「全节最重要的那条检查」
> 　 在课堂上从来没红过，学员只听过没见过。

**先加检查④（说给它听）：**

> 「再加一条：**标了 `approved` 的文件，不许残留 `[to supply]`。**
> 　还有，**顺便统计一共有多少处留白，但那个只打印，不算失败。**」

> ⚠️ 后半句是故意的：它让学员在没被命名的情况下，**第一次亲手用到 bad / note 的区分**。

**然后让他们触发：**

> 「挑一份你觉得已经写完了的，在最上面加一行 `Status: approved`，然后跑。」

**它会红。它会说一句话 —— 指着那行念：**

```
你还没写完。
```

> 🔥 **埋点 2。这次红，P27 收口要回收。**

**然后点破（v3 的关键一句，一字不改）：**

> 「**你刚才做的事有个名字。**
>
> 　『这份文件写完了吗』是**判断题**，机器判不了。
> 　『有没有残留 `[to supply]`』是**形状题**，机器一眼就判得出来。
>
> 　**你把一道判断题，换成了一道形状题。**」

> 🚨 **说完停。不要接着讲下一页。**

**第 68 分钟：看聊天框，红了的打 `1`。不到一半就投屏补造一次，这一格不能跳。**

## P15 ｜ 70 到 75 分钟 ｜ 它给了你一段跑得通的代码 🎬 **翻车①**

**放手让他们自己选（三分钟）：**

> 「现在你自己选一条**最该被查的**规矩，说给它听。三分钟。」

**一大半人会说出判断类的话。agent 不会拒绝，它会给一段跑得通但查错的代码。**

**三分钟后，投屏这张表：**

| 你说的 | 它写出来的 | 结果 |
|---|---|---|
| 「检查角色文件写得对不对」 | 它去数了字数 | 跑得通，查的不是你想查的 |
| 「检查这个审批额度合不合理」 | 它写了个区间判断，区间是它编的 | 跑得通，**而且编了一个数** |
| 「检查职责有没有划分清楚」 | 它检查了小节标题存不存在 | 跑得通，但那不叫清楚 |

**然后那段（v3 换过形态，这是静默失败，比"写不出来"危险得多）：**

> 「注意这次**不是它拒绝了你**。
> 　它给了你一段能跑的东西，**而你以为成了**。
>
> 　跑得通、不报错、CI 也是绿的 ——**而它查的根本不是那回事。**
>
> 　**这一类失败没有声音。**
> 　你不会发现，直到某天真出事，你回头看那条检查，发现它从来没在守什么。」

**收成一句：**

> 「所以问题不是『你会不会写代码』。是 ——**你那条规矩，说清楚了没有。**」

> ⚠️ **这一页不给"能 / 不能机械化"的表。** 那是下一页的事。

> **硬停：第 75 分钟。**

## P16 ｜ 75 到 79 分钟 ｜ 四道判断线 + 转化表 ⭐ **第三幕的骨架**

**先说清它是什么形状：**

> 「不是四个格子，**是一条链：前一道过不了，后面不用问。**」

| | 问什么 | |
|---|---|---|
| 第一道 | 这条规则能不能机械化？ | 能 → 立刻写成检查 |
| **第二道** ⭐ | **不能的话，能不能【转化】成能机械化的形状？** | **全节最实用的一格** |
| 第三道 | 这条检查该不该算失败？ | 不变式 → `bad` ／ 已知状态 → `note` |
| 第四道 | 这条检查是从哪来的？ | 从真发生过的错来，不从想象来 |

**转化表 —— 第二行要指出来："你刚才做过"：**

| 判断题（查不了） | 转化成形状题（查得了） |
|---|---|
| 这个审批额度合不合理 | 这个额度有没有人签过字（谁、什么时候） |
| **这份文件写完了吗** | **有没有残留 `[to supply]`** ← 你刚才做过 |
| 这个决定对不对 | 有没有记录是谁定的 |
| 这条 SOP 写得好不好 | 十三节齐不齐 |

**转化本身也能让它帮你做 —— 这句 prompt 要给出来，照念：**

> 「这条规矩我想查，但它是判断题。
> 　**有没有办法把它换成一个不动脑就能判的形状？**」

**最后那条红利（顺手给，不展开）：**

> 「⭐ 机械化的第二个红利（第一个是确定性）：
> 　**每一条你机械化掉的规则，都是 AI 以后不用再读的一条。**
> 　它不再需要被读懂、不再进 context、**不再有被误读的机会。**」

> **硬停：第 79 分钟。**

## P17 ｜ 79 到 87 分钟 ｜ 那就把能查的全查上 🎬 **翻车② ⭐⭐ 本幕支点 · 回收埋点 7**

> 🚨 **全节最容易被讲轻的一页。** 你觉得"提示不能当失败"很显然，**学员不觉得。**

**先接上一页：**

> 「既然判断类查不了，**那就把能查的全查上**，对不对？」

**你说的那一句（注意你没说"哪些不算失败"）：**

> 「再加一条：**索引里提到的文件，必须都存在。**」

**然后让他们造：**

> 「在索引里加三行，写三个你们那儿**还没写、但迟早要写**的角色。**文件不要建。** 跑。」

**满屏红。然后三句，一句都不能省，中间都要停：**

```
①  这是错吗？          →  不是。那几个角色本来就还没写。
②  那你明天还会跑它吗？  →  不会。你会关掉它。
③  一个天天红的检查，和一个不存在的检查，是同一个东西。
```

> 🚨 **第③句是本幕的支点。说完停两秒。**

**解药是一个词，让他们改一行：**

> 「把那条里的 `bad` 改成 `note`。」

**然后回收埋点 7（第 30 分钟那句"等下你会非常需要这个区分"）：**

| **硬失败 `bad`** | **提示 `note`** |
|---|---|
| 不变式被破坏 | 计划中的文件、缺口统计 |
| **退出码 1 · 合不了 PR** | 退出码 0 · 只是让你看见 |
| 「必须立刻修的错」 | 「一个已知的状态」 |

**分界线那句：**

> 「**没人负责的角色，是一条被破坏的不变式。还没建的文件，不是。**」

**这一页的结论：**

> 「**把什么当失败，是这个检查能不能活过两周的唯一决定因素。**」

**第 85 分钟：看聊天框有没有人说"红了一片"。没动静 → 你投屏跑一次，然后照问那三句。**

> 🚨 **铁律：翻车②和翻车③之间不许答疑。** 停下来答问题，P18 的突袭感就没了。

> **硬停：第 87 分钟。**

## P18 ｜ 87 到 93 分钟 ｜ 角色文件里只出现角色 🎬 **翻车③ ⭐⭐**

> # 🔄 v3.2 整页翻面（讲师）：**不要从反面说，直接正面说应该怎么做。**
>
> **旧版**是「这条检查我不解释，你先跑」——全部赌在**它会咬到学员自己**。
> **问题：每个人的仓库不一样，这一下不一定咬得到。**
> 学员今天只写了两个角色，而模板那三段（答应什么 / 独自能决定什么 / 什么必须报批）
> 并不天然招人名 —— **很多人跑出来就是绿的，那一格对他们完全是空的。**
>
> **只在学员恰好犯过错时才成立的教学点，不是教学点，是抽奖。**
>
> 所以现在的顺序是：**先给规矩 → 给理由 → 才跑 → 两种结果都有话说。**

**四层，顺序不能换。**

### 第一层 · 先把规矩正面说出来

**照念：**

> 「第六条。这一条我先讲清楚，再让你跑。
>
> 　**角色文件里，只出现角色，不出现人名。**
> 　人名**只活在花名册里**。
> 　角色文件里写『**谁管发布**』，不写『**张伟**』。」

### 第二层 · 为什么

> 「那个人离职的那天，**你要改的应该只有一份文件。**
>
> 　名字一旦散进角色文件，离职就变成一次**全仓搜索** ——**而搜索总会漏。**」

### 第三层 · 现在才跑

> 「现在把这条加进去，跑一次。」

说给它听那一句：

> 「再加一条：**角色文件里，不许出现花名册上的名字。**」

**⭐ 第 91 分钟：抓到打 `1`，没抓到打 `0`。**

> 🚨 **这是个命中率读数，不是过关线，也不再是这一格的支点。**
> 　 **全 `0` 也照常往下走。** 规矩已经正面给过了，这一跑只是验证。

**两种结果都要接住 —— 「没抓到」那一句是这一页新增的那一半，不许省：**

| | 你说什么 |
|---|---|
| **抓到了** | 「现在就改掉。**你早就破了这条规矩，而前五条检查一直是绿的 ——没有任何东西在查它。**」 |
| **没抓到** | 「**两种可能，别急着高兴：**你确实写对了，或者**你今天只写了两个角色，还没碰到**。**回去写第十个的时候会碰到。**」 |

> 🚨 **「没抓到」那格必须当场说。** 不说，那批学员会得出「这条跟我无关」的结论，
> 　 而他们回去写真的那个，一定会碰到。

### 第四层 · 你投屏自己的例子 ⭐ **现在它是主路径，不是备胎**

用 K.2 那条。**必须脱敏。**

> 「这是我自己那个仓库里的一条。写的时候我完全没觉得有问题。
> 　它在那儿躺了很久，**直到这条检查第一次跑起来。**」

**收成一句（第四道判断线的落点）：**

> 「所以这条检查**不是我想出来的**。**是它先咬了我一次，我才把它写下来的。**」

> ⚠️ **为什么这一层从"并行主路径"升成主路径：** 学员中没中是随机的，
> 　 **你中过是确定的。**「检查从哪来」这个点，只能压在确定的那一边。

> ⚠️ **检查⑥ 用花名册精确匹配，不用人名正则** —— 正则版在中文最自然的写法上全部漏掉
> 　（「由某某审批」后面紧跟汉字），还会把普通词误判成人名。

> **硬停：第 93 分钟。**

## P19 ｜ 93 到 99 分钟 ｜ 你们刚才被咬了三次 ⭐ **反转**

**三列并排，横着念（现象 / 感受 / 后果 / 解法）：**

| | 翻车① | **翻车②** ⭐⭐ | **翻车③** ⭐⭐ |
|---|---|---|---|
| 现象 | 卡住，写不下去 | 满屏红，而且红得有道理 | 全绿，然后抓到自己 |
| 感受 | 挫败 | **烦，马上想关掉** | **被抓包** |
| 后果 | 那条规矩永远停在最低一级 | **你会亲手关掉它** | 你以为守住了，其实没有 |
| 解法 | 承认边界，别假装 | **分开硬失败和提示** | **从真发生过的错反推** |

**然后兜底三级（判断不了的怎么办）：**

| 级 | | 怎么做 | 代价 |
|---|---|---|---|
| 一级 | **转化** | 把判断题改写成形状题 | 查的是「有没有人管过」，不是「管得对不对」 |
| 二级 | **降级** | 查不了内容，查「有没有人看过」 | 只保证被看了，不保证被看懂了 |
| 三级 | **明写** | 写成规则，承认这条只能靠人记得 | **但必须把「只能靠人记得」写在它旁边，不许假装它被守住了** |

> 🚨 **三级那句「不许假装」是硬的。** 学员最容易在这儿偷懒。
> ⚠️ **这里不许说「第 0 级」「最低一级」这类词** —— 阶梯还没出现，P21 才回收它。

**然后是反转，停一拍再念：**

> 「**检查挡得住的，
> 　只有你说得清的那部分。**
>
> 　说不清的，你能**转化**掉一部分 ——
> 　**剩下的必须承认它只能靠人记得，不许假装它被守住了。**」

**最后一句（这一页真正的刀）：**

> 「一个声称能查判断题的检查器，**只会在你最需要它的时候给你一个错误的绿灯。**」

> 🚨 **铁律：P19 到 P21 一口气到底。中间不许喝水不许答疑。**
> 　 停在这儿，学员带走的是"检查没用"。

**⭐ 第 99 分钟：第三幕硬判断点。超过 101 分钟立刻走 §J 一级砍法。**

> **硬停：第 99 分钟。**

## P20 ｜ 99 到 104 分钟 ｜ 本地的，都可以改 🎬 **我现场跑 · 回收埋点 4**

> 🚨 **全节最该有、上一版完全没有的一格。**

## P21 ｜ 104 到 110 分钟 ｜ 它还是要你记得跑 ⭐⭐ **全节视觉重心 · 立论 · 回收埋点 3 / 5**

```
L6  服务端拒绝 + 管理员也受约束    连最有权限的人也绕不过去
```

> 「⭐ 顺带把第一幕那张图缺的一层填上：**L6 执行层，就是这个阶梯。**」（回收埋点 5）

## P22 ｜ 110 到 119 分钟 ｜ 八行，跨过那条线 🎯 **全班动手**

**立场先给（沿用 L4，不然学员会怕）：**

> 「这些命令你早就让 Agent 干过了。**今天还是让它干，你只要知道要发生什么。**」

**八行 workflow —— 只讲最后一行：**

> 🚨 **runner / 缓存 / matrix 一律不讲。** 一开口这一页就变成 CI 课。

**然后造一个违规 PR：**


# C. 完整 check.mjs 终态（讲师参考，课上不投）

六条按课堂顺序累加之后应该长这样。**学员的版本会跟这个不一样**（角色名不同），
形状一致即可。

```js
#!/usr/bin/env node
import { readdirSync, readFileSync, existsSync } from 'node:fs';

let fail = 0;
const bad  = (m) => { console.log(`  FAIL  ${m}`); fail = 1; };
const note = (m) => { console.log(`        ${m}`); };
const hdr  = (m) => { console.log(`\n${m}`); };
const read = (p) => existsSync(p) ? readFileSync(p, 'utf8') : '';
const ls   = (p) => existsSync(p) ? readdirSync(p) : [];

const SKIP = (f) => f === 'INDEX.md' || f === 'README.md';

hdr('1. 规则目录存在且非空');
if (ls('rules').length === 0) bad('rules/ 是空的');

hdr('2. 每个目录都在 AUTHORITY.md 里有位置');
const auth = read('AUTHORITY.md');
for (const d of readdirSync('.', { withFileTypes: true })) {
  if (!d.isDirectory() || d.name.startsWith('.') || d.name === 'node_modules') continue;
  if (!auth.includes(`${d.name}/`)) bad(`目录 ${d.name}/ 没有出现在 AUTHORITY.md 里`);
}

const index = read('rules/INDEX.md');

hdr('3. 角色文件都被索引登记');
for (const f of ls('rules')) {
  if (SKIP(f)) continue;
  if (!index.includes(f)) bad(`rules/${f} 存在，但 INDEX.md 没登记它`);
}

hdr('4. 标了 approved 的文件不许残留 [to supply]');
let gaps = 0;
for (const f of ls('rules')) {
  if (SKIP(f)) continue;
  const body = read(`rules/${f}`);
  const n = (body.match(/\[to supply\]/g) || []).length;
  gaps += n;
  if (/^Status:\s*approved\s*$/m.test(body) && n > 0)
    bad(`rules/${f} 标了 approved 但还有 ${n} 处 [to supply]`);
}
note(`当前共 ${gaps} 处 [to supply]。这是故意的。`);

hdr('5. 索引登记的文件都存在');
for (const m of index.matchAll(/[a-z0-9-]+\.md/g)) {
  if (!existsSync(`rules/${m[0]}`)) note(`尚未创建: ${m[0]}`);   // ← 第 85 分钟从 bad 改过来的
}

hdr('6. 角色文件里不许出现花名册上的名字');
const roster = read('people/ROSTER.md')
  .split('\n')
  .map(l => (l.match(/^[-*]\s*(.+?)\s*$/) || [])[1])
  .filter(Boolean);
for (const f of ls('rules')) {
  if (SKIP(f)) continue;
  const body = read(`rules/${f}`);
  for (const n of roster)
    for (const line of body.split('\n'))
      if (line.includes(n)) bad(`rules/${f} 写了名字「${n}」：${line.trim().slice(0, 40)}`);
}

console.log(fail ? '\n有不一致项，见上面 FAIL。' : '\n通过。');
process.exit(fail);
```

**统计：5 条 `bad`（①②③④⑥）+ 2 处 `note` 输出（④的计数、⑤）。
其中第 5 条是学员在第 85 分钟亲手从 `bad` 改成 `note` 的。**

> ⚠️ **第 6 条为什么用花名册精确匹配，不用人名正则：**
> 　 正则版（姓氏 + 1 到 2 个汉字）在中文最自然的写法上会全部漏掉 ——
> 　 「由某某审批」「需要某某负责签字确认」后面紧跟汉字，边界断不开；
> 　 同时会把「这是黄色的」这类普通词误判成人名。
> 　 **花名册是已知集合，精确子串匹配中英文都成立，零误报。**

> **然后回主线。**
