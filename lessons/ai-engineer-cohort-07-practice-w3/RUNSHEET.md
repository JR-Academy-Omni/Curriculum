# W3 讲师流程

全课按 ADLC 五步推进：需求 → PRD → 开发 → 部署 → 反馈。每一步结束前确认产出和批准人，再进入下一步。

按 C7P03 的120分钟顺序进行；独立页码从1开始。课前先核查实际 starter 的启动和测试。本课件描述课程要求，不代表业务已实现。

- P02：把界面接成一条真正能用的业务流程 · 按 ADLC 五步排。
- P03：本周完整走一圈 ADLC · 需求 → PRD → 开发 → 部署 → 反馈；后面每一页都标出现在在哪一步。
- P04：不是养老专家，也能把需求做对 · 先承认不知道，再用可核查的来源补上；Claude 帮整理，不替代专家。
- P05：先分清谁买、谁用、谁受益、谁审核 · 画像按角色写；下面每一格都是待访谈验证的假设。
- P06：做产品的逻辑顺序 · 每一步的产出，都是下一步的输入。
- P07：本周只做这一条：从一位老人到一次确认 · vertical slice：从界面一路打通到数据库的一条完整流程，而不是每层各做一点。
- P08：三个端，共用一套 API 和数据库 · 从上往下讲：一线服务人员用护理端，院里管理人员用管理端，我们自己用平台端；三端都经过同一个 API 的四道检查，再写进同一个数据库。家属端以后再做。
- P09：按功能拆开：API 里有哪些模块 · P08 是高层视图，这页按功能逐个讲模块：做什么、用哪些表、谁在用；虚线部分只说从哪周开始，不展开。表名是示意，以 starter 为准。
- P10：AI 部分怎么接进来：Agent、RAG、记忆 · 本周不做，只讲各部分怎么连：Agent 在 Harness 里运行，通过工具用 RAG、记忆和业务 API，所有模型调用经路由；先有评估再写 RAG；AI 的结果只能是草稿，最后由人确认。W7、W9 在大纲里是占位，只按 W6、W10 的引用讲。
- P11：为什么要 Super Admin，它能做什么 · 先讲为什么：平台服务多家养老院，需要有人在所有养老院之上开通、配置、排查；再逐条讲 6 个功能。
- P12：每个架构决策，都写清为什么 · 决策 → 理由 → 本周怎么验收。
- P13：一条业务链，用一个例子走一遍 · 从老人档案到审核确认共 7 步：每一步是什么、谁来做、留下什么。
- P14：先核查项目的起步代码（starter） · starter：已经搭好登录、数据库、API、路由和测试框架的起步代码，先看清它有什么。
- P15：key 在哪台机器上，决定谁能改线上 · 本机的 Claude Code 能读到 .env：.env 里是哪套 key，它就能改哪套环境。
- P16：CI/CD：代码从你的电脑到线上的流水线 · 先讲两个缩写：CI 是每次提交自动检查，CD 是自动送到环境；持续交付上线前要人批准，持续部署自动上线。再沿两条泳道走一遍，强调两个人工关口（Code Review、上线审批）和失败就不能合并。GitHub Actions 只是例子，具体流水线以项目为准。
- P17：一条 workflow 是怎么跑的 · 沿流程图从左到右讲；再对着 yml 示意解释 on、job、needs、environment。yml 是示意，不是项目实际文件；实际 workflow 以项目仓库为准。
- P18：先让 Claude 出计划，你看过再动代码 · 在 Claude Code 里先用计划模式：只读代码、写计划，不改文件。
- P19：记录一条活动，要挂对老人、班次和任务 · 同一条活动，必须知道是给谁做的、哪个班、哪项任务。

课件到 P15 结束；之后按工作单带学员动手实操、测试与演示。
