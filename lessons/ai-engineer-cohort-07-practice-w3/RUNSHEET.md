# W3 讲师流程

按 C7P03 的120分钟顺序进行；独立页码从1开始。课前先核查实际 starter 的启动和测试。本课件描述课程要求，不代表业务已实现。

- P02：把 W2 UI 接成一条真实业务链。Claude 是开发工具；本周产品不调用 AI 模型。
- P03：先锁定唯一 vertical slice。范围由实际项目材料确认，不由模型自行扩大。
- P04：Resident 到 Confirm，要能一路走通。业务链每段都要保持正确对象关系和角色边界。
- P05：先核查老师提供的底座。文件路径、命令与已实现功能必须从真实 starter 取得。
- P06：让 Claude 先给出可审查计划。计划未经确认不进入大范围修改。
- P07：完成 repo 阅读和任务拆分。缺少底座时先补齐前置条件，不能宣称业务链跑通。
- P08：把活动放回正确的业务上下文。字段名和约束以实际 schema 为准；此页不定义虚构数据库表。
- P09：一次动作必须跨过三层。失败不能留下假成功提示；再次读取要看到预期结果。
- P10：连接 Resident 到 Care Activity。使用课程合成数据，不使用真实个人资料。
- P11：Progress Note 不能直接越过复核。谁可执行每一步、禁止哪些转换，写进契约并在服务端验证。
- P12：按钮隐藏不足以保护业务规则。具体角色名称与权限矩阵来自实际契约；不在课件中猜测。
- P13：实现文档状态与角色边界。记录实际请求与断言；不能只截图一个绿色状态。
- P14：确认针对哪一个文档版本。实现方式取决于真实模型；不要只在 UI 加一个 version 标签。
- P15：一次关键动作，留一条可追溯记录。Audit 不能泄漏密钥或真实个人资料；具体字段以工程契约为准。
- P16：错误路径也要写成验收动作。以上是需要核查的场景；处理策略由实际业务契约决定。
- P17：补齐版本、audit 和失败分支。先写预期，再执行；没有运行的检查标为未验证。
- P18：沿 UI → API → 数据库定位问题。不要把所有报错一次性交给模型，让它改完整仓库。
- P19：把 MVP 主路径写成浏览器验收。选择器、接口地址与测试命令从实际项目读取。
- P20：现场演示与限制清单。演示不能代替测试；测试也不能代替业务验收。
- P21：把可运行 MVP 交给下一周。本周不能把 Claude 帮忙写代码称作产品已经具备 AI 功能。
