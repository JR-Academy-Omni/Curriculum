# W1 工作单 · CareKind 项目启动

依据 [PRD](PRD.md) 与 [讲师流程](RUNSHEET.md)。本周完成产品契约、规则、任务和一次受控改动；真实 starter 的存在与可运行性需要课上核查。

## 1. 产品边界

- 机构购买、护理人员使用、老人受益：分别写出本周需要验证的一项需求。
- 写出目标、输入、输出和明确不做的功能。商业收费与拓展写为待验证假设。
- 用五步 ADLC 标出当前阶段：需求 → PRD → 开发 → 部署 → 反馈。

## 2. 规格与执行上下文

写一个可验收任务，包含用户角色、行为、成功结果与失败结果。将约束分别放入 PRD、Rules、CLAUDE.md，不用重复但矛盾的描述。

## 3. 拆分与受控改动

先核查实际仓库，再让 Agent 给出计划。并行时分配互不重叠的文件边界、接口和共享服务；worktree 不等于数据库隔离。执行一次明确的小改动，审查 diff，再自己运行验收。

## 交付与独立迁移

提交产品契约、规则路径、任务单、diff 和真实验收结果。找一个不同的小功能，独立写相同五项任务约束。未执行的步骤写未执行；没有 starter 时不声称实现成功。
