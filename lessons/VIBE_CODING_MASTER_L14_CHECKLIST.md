## A. 上完 L14，学员手上有什么（三件硬产物）

- [ ] **一张写权限表** ,, 四列：写到哪 / 谁批准的 / **批准立在什么上面** / 什么时候能升级
- [ ] **一个当堂跑出 `FAILED` 而不是 `0` 的脚本**
- [ ] **一份按十节写完的技能规范**

**外加三样落到文件上的小东西：**

- [ ] 指令文件里写死「不许写产品仓」+ 仓库名
- [ ] 四条「不可批准」的禁令
- [ ] 三层自动化各挂一条（会话钩子 / PR 检查 / 周巡检）

## B. 五问逐项覆盖明细

### 问 1 · 有哪些仓（0-18 分钟）

- [x] 三仓拓扑：规则仓 / 记录 / 产品仓
- [x] 为什么必须分三个（**规则和记录对分支保护的要求正好相反**）
- [x] agent 读产品仓应该鼓励，**写绝对禁止**（权限边界对齐责任边界）
- [ ] ❌ **记录仓怎么用** ,, 图上有它，但 agent 读它写它的规矩从没讲
- [ ] ❌ **留存规则** ,, §3.4 说「受另一条留存规则管」，**那条规则全文档不存在**

### 问 2 · 给它什么权限（18-46 分钟）⭐ 核心

- [x] 读权限白名单：只放不改状态的命令（`fetch` 在、`pull` 不在）
- [x] **白名单不是安全边界，是省事边界**
- [x] 写权限表四列 ,, **第三列「批准立在什么上面」是全课最值钱的一格**
- [x] 允许强弱不同的两行，**必须把弱的标出来**
- [x] 四条不可批准的禁令（不是「没批准」，是「不可批准」）
- [x] 草稿 / 发送 / 提交 三行一起讲
- [ ] ⚠️ **第四列「什么时候能升级，要什么证据」** ,, **开了列，没讲内容**
- [ ] ❌ **多人的时候这张表怎么办** ,, 一张共享还是每人一张，从没问过
- [ ] ❌ **个人覆盖**（`settings.local.json` + gitignore）**和共享规则冲突谁赢**

### 问 3 · 接哪些外部系统（46-76 分钟）

- [x] 连接器清单按「它要干什么」排，不按产品名排
- [x] **交互式登录撑不过定时任务**（完整推论链）
- [x] 四态结果模型：`ok` / `zero` / `partial` / `failed`
- [x] **分支判断看错误，不看结果集长度**
- [x] 连接失败必须自带修复步骤（三件事，第三件通常缺）
- [ ] ⚠️ **「宁可全部由人触发」这个结论认了一笔债** ,, 原话「**技能追不上你，没人开会话就没人被提醒**」,, **债没还**
- [ ] ❌ **服务凭据怎么弄** ,, 只说了「需要它」，没说下一步

### 问 4 · 它有哪些技能（76-98 分钟）

- [x] 双层结构：规范层（为什么）/ 执行层（怎么做），**单副本，符号链接**
- [x] Windows 降级方案，**并明说它是降级不是等价**
- [x] 执行层携带流程、指向规则、**绝不复述规则**
- [x] **技能十节**（trigger / 数据来源 / 必需输入 / 输出结构 / 人类审批人 / 允许的写 / 失败与重试 / **审计记录** / 隐私边界 / **验收测试**）
- [x] 第 10 条验收测试给了四个打样
- [x] 组合方向是反的（生产型技能放输出落地处，但总表仍要列它）
- [ ] ⚠️ **第 8 条「审计记录：这次跑了什么，留在哪」** ,, **一行字，从没展开**

### 问 5 · 怎么维护（98-120 分钟）

- [x] 检查是长出来的，三条规矩
- [x] 三层自动化：会话钩子（永远退出 0）/ PR 检查（**唯一硬政策**）/ 周巡检
- [x] 漂移检查「**只数数、不点名**」，以及**它看不见什么**
- [x] 谁能改规则 + **提案路径为什么不走 PR**（判据给了，不给结论）
- [x] **人工审批往往是失效模式**（三条理由，第三条：被扣住的合并会让仓库说谎）
- [x] 诚实是一种维护手段（缺口不许用猜测填）
- [ ] ⚠️ **「新检查从真发生过的错来」** ,, **事故 → 检查这条路径没定义**
- [ ] ❌ **「怎么改」这个动作本身** ,, §6.4 只回答了**谁**能改
- [ ] ❌ **「删」** ,, 全节、全系列，**一次都没提过**

## E. 身份：这套东西只做了两层

| 层 | 谁做的 |
|---|---|
| **角色**（这顶帽子答应什么） | L13 ✅ |
| **人**（名字属于 `people/`） | L13 ✅ |
| **执行者**（这一下是人做的 / 他的 agent 做的 / 一个定时任务做的） | ❌ **从没有过** |

**后果散在四处**：漂移检查看得见账号看不见执行者 · 个人覆盖被 gitignore 没人见过 ·
痕迹只要求「能核」不要求「知道是谁」· 变更记录署名的是提案人不是执行者。

## F. 汇总：系统还剩什么，以及它有多大

> **这一节是给 L15 划线用的。时长是我按 L13 / L14 的密度估的，不是猜的。**

| # | 剩什么 | 从哪来 | 估时 | 能不能砍 |
|---|---|---|---|---|
| 1 | **运行痕迹 + 证据**（审计记录展开） | C-1 / C-5 | **35 min** | ❌ 收口的地基 |
| 2 | **不可逆 + 回滚**（写权限表按「撤不撤得回来」重排） | B-问2 | **30 min** | ❌ L14 核心产物的另一半 |
| 3 | **升级三道门 + 真开定时任务** | C-2 / C-6 | **40 min** | ⚠️ 真开可砍，冷启动不可砍 |
| 4 | **事故回流**（事故 → 一条新检查） | C-4 | **20 min** | ❌ 回路闭合的唯一证据 |
| 5 | **L0 指令文件整份** | D | **26 min** | ⚠️ |
| 6 | **L1 入口层 + 两份怎么不打架** | D | **16 min** | ✅ 可压到 8 |
| 7 | **L4 SOP 十三节** | D | **38 min** | ❌ L13 明确延期的那条 |
| 8 | **加 / 改**（变更流程） | B-问5 | **24 min** | ⚠️ |
| 9 | **删**（删除三步） | B-问5 | **31 min** | ❌ |
| 10 | **身份第三层 + 多人** | E | **50 min** | ⚠️ 前三幕可压 |
| 11 | **留存规则** | C-3 | **10 min** | ✅ 可并进 1 |
| 12 | **服务凭据下一步** | B-问3 | **8 min** | ✅ 可并进 3 |

**合计约 328 分钟 ≈ 5.5 小时 ≈ 2.5 节 135 分钟的课。**

### 一节 135 分钟能装哪些（三种划法）

| 划法 | 装 1-4（+11+12） | 装 1-4 + 7 | 装 1、3、7、9 |
|---|---|---|---|
| 这一节讲什么 | **证据 + 定时任务**（现 L15 v2.1） | 证据 + 定时 + SOP | **痕迹 + 定时 + SOP + 删** |
| 时长 | 1-4 = **125**，**11+12 塞不下**（143 ✗）,, 实际 L15 只装 1-4，扩到 135 | **163 ✗ 超 28 分钟** | **144 ✗ 超 9 分钟** |
| 剩下留给后面 | 5-10 = **185 min**，加 11+12 共 203（两节） | 5/6/8/9/10（≈147 min，一节紧） | 2/4/5/6/8/10（≈166 min） |
| 代价 | 系统要三节才走完 | **砍不动，除非 SOP 只写五节** | **丢掉不可逆和回流 ,, 收口没地基** |

> **我的判断：第一种。** 第二、三种的超时都不是"压一压"能解决的 ,,
> 它们要砍的是 1 / 2 / 4 / 9 里的某一个，**而那四个每一个都是某条收口的地基**。
>
> **如果一定要两节走完**（L15 + 一节），可行的是：
> **L15 = 1+2+3+4（现在这版）· L16 = 5+6+7+8+9+10 压到 135**,,
> 代价是 L16 要砍掉身份那块的前三幕，**只保留离职清单**（≈ 从 50 砍到 18）。
> **那块砍了之后，第三层署名没人教，离职清单第 4 行就是空的。**
