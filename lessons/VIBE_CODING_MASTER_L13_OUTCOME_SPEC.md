## 1. 先算一笔账（这决定整节课的形态）

讲师目标：**学员能写出这样一个仓库，用于自己公司或项目的管理。**

参考系统的实际规模：

| | |
|---|---|
| 文件数 | 81 |
| 提交数 | 87，全部走 PR |
| 跨越 | 10 个工作日 |
| 体量 | 约 420 KB |
| 作者 | 一个熟手 + AI 全程参与 |
| 当前状态 | **仍然标着 draft, not in force**，265 处缺口未填，12 个 SOP 只写了 3 个 |

**一节 96 分钟的课不可能产出这个东西。** 谁说能，谁在骗人。

但这不等于目标做不到。**它等于：课堂产出的不能是那个仓库，必须是"能持续长出那个仓库的东西"。**

这就是 L13 的立项决定。

## 2. 把目标拆成可验收的出课能力

"能写出这样一个仓库"是个感觉。下面是它的可验收版本。
每一条都落在**产物形态**上，不落在标准答案上（系列惯例）。

### 2.1 必达（课堂内完成，当堂验证）

| # | 能做到 | 过关证据 |
|---|---|---|
| A1 | 判断一条内容属于**规则**还是**状态**，并说出它该进哪个仓库 | 给 10 条混合内容，分类正确 8 条以上，且能说出分不开时的三个判据 |
| A2 | 把一条口头规矩写成**五要素齐全**的规则 | 交一条：断言 / 标记加日期 / 权威归属 / 触发条件 / **强制点在第几级** |
| A3 | 说出自己那条规则**现在在强制力第几级**，以及升一级要做什么 | 一句话，且级别判断经得起追问 |
| A4 | 写出 3 到 5 条**可机械化**的不变式，并区分硬失败和提示 | `check.sh` 跑起来，**当堂红一次** |
| A5 | 把校验挂进 CI，提一个违规 PR **被挡住** | PR 页面截图，红 |
| A6 | 说出**为什么这条能机械化、那条不能** | 现场拿自己写的规则逐条分类 |

### 2.2 必达（课堂搭好，课后长出来）

| # | 能做到 | 过关证据 |
|---|---|---|
| B1 | 用一个**生成器 skill** 把自己公司的规则问出来、写成文件 | skill 能跑，产出 Tier 1 六个文件 |
| B2 | 生成器**拒绝编造**阈值、SLA、日期、人名 | 故意不告诉它 SLA，看它写 `[to supply]` 而不是"1 个工作日" |
| B3 | 建立一条**权威优先级全序**，任意两份文件冲突都有确定答案 | 一张表，且覆盖所有目录（不能像参考系统那样漏一格）|
| B4 | 设计分支保护的**五个开关**并说出每一个的理由 | 一张表，不许写"全开" |

### 2.3 进阶（依赖环境，课后作业）

| # | 能做到 | 过关证据 |
|---|---|---|
| C1 | 开分支保护，**三个动作实测**（两拒一放） | 三次实测记录 |
| C2 | 打开"管理员也受约束"，用管理员身份再试一次 | 仍然被拒 |
| C3 | 补出第二层：角色 charter + 第一条 SOP | 文件形态合规，校验器通过 |

### 2.4 明确的非目标

写进蓝图 §4，免得课程被撑爆：

- **不要求课堂产出 81 个文件。** 目标是 Tier 1 六个 + 一个生成器。
- **不教组织设计。** 不讨论该设几顶帽子、职责怎么划，那是学员公司自己的事。
- **不产出一个 web app。** 参考系统把"要不要做 app"刻意推迟到第三阶段，L13 沿用这个判断。
- **不把学员公司的真实治理内容当堂写进仓库。** 见 §5.3。

## 3. 交付设计：课堂产出"生成器"，不产出"仓库"

### 3.1 三个候选，为什么选第三个

| 方案 | 课堂产物 | 两周后的结果 |
|---|---|---|
| a 手写最小仓库 | 6 个文件 | **停在那 6 个文件**。第 7 个没人写 |
| b 发一套模板 | 一个 zip | **照抄别人公司的治理结构**，水土不服，没人填 |
| c **生成器 + 骨架 + 硬政策闭环** | 一个 skill + 6 个文件 + 一条红的 CI | 学员回去能**自己长出第二层、第三层** |

选 c。理由：这是 Vibe Coding 系列的原生答案，L5 已经教过"把反复用的套路固化成 Skill"，**L13 是那套能力第一次用在"造一套公司规则"上。**

### 3.2 生成器的核心张力（本节最值钱的一格）

让 AI 生成治理文件，会立刻撞上参考系统自己写下的那条铁律：

> 空着的缺口是信息。编造的值是**一个看起来像进展的缺陷**，
> 而且更糟，因为它让所有人不再追问。

**一个不设限的生成器会在 30 秒内吐出 81 个文件，每个阈值都很合理，每条 SLA 都很专业，
而且全部是编的。** 学员会觉得赚翻了，回去发给老板，老板照着执行，
然后在第一次真出事的时候发现那个数字从来没有人同意过。

**这是 L13 必须正面处理的事，也是本节的反转。**

所以生成器的规格里，最重要的不是"能生成什么"，是"**拒绝生成什么**"：

| 生成器必须 | 生成器绝不 |
|---|---|
| 生成**结构**（固定节、目录、索引、优先级表）| 生成**数值**（阈值、SLA、金额、天数）|
| 生成**问题**（这条谁批？触发条件是什么？）| 生成**答案**（"建议 1 个工作日"）|
| 把没答的写成 `[to supply]` 并保持可见 | 用"合理默认值"把空填上 |
| 生成**可机械化的检查** | 假装能检查判断类规则 |
| 写帽子 | 写人名 |

### 3.3 反转的完整表述（第四幕用，不许提前说）

> **生成器的好坏，看它留了多少空，不是填了多少。**

配一个当场可做的验证（B2）：故意不告诉它 SLA，看它写 `[to supply]` 还是写"1 个工作日"。
写了数字的，**当场删掉重做**。

### 3.4 闭环：为什么这个设计能让仓库"长出来"

四步，环环相扣，这是整节课的机械结构：

```
1. 生成器产出 Tier 1 骨架，满是 [to supply]
2. 校验器规定：标成 approved 的文件不许残留 [to supply]
3. 所以要把任何一条规则变成"在force"的，学员必须先去问真人
4. → 仓库逼着你去开那场从来没开过的对话
```

**第 4 步是这整套东西的真实功能。**
参考系统自己的立项动机，四句话，每一句都是"那场对话没发生"的症状：

> 没人看得见什么处在风险里 / 决策被提出然后搁着 /
> 问题被提出然后悄悄淡掉 / 客户最后直接找上了开发

**收口候选：**

> 这个仓库最大的产出不是文件，是它逼你去开的那几场对话。

## 4. 前置链条：L13 是前十二节的合流

这一节不引入新工具，它把已有的四样装到一起。**蓝图 §0.5 要写清楚这条线。**

| 来自 | 学员已有 | L13 用它做什么 |
|---|---|---|
| **L5 Skills** | 把反复用的套路固化成可调用能力 | **做生成器**。L13 是这个能力第一次用来造一套公司规则 |
| **L10 四象限协作协议** | 开场四问：信息在谁那里 | **做生成器的提问清单**。"哪些值只有老板知道" = 隐区 = `[to supply]` 的来源 |
| **L11 无人值守任务书** | 六段齐全的任务书 | **做 CI job 的规格**。无人值守的检查跟无人值守的任务是同一件事 |
| **L12 Hook** | 把"我跟它说过"变成"它绕不过去" | **强制力阶梯的 L2 那一级**，L13 把同一个立论从一个 agent 扩到一个团队 |

**L12 到 L13 的承接句（蓝图开篇用）：**

> L12 让一个 agent 绕不过去。L13 让**整个团队**绕不过去。
> 同一个立论，对象从一个 context 换成一群人。

**L10 的四象限在 L13 有个特别漂亮的落点：**
隐区（只有对方知道的信息）在这里就是**阈值、SLA、审批人、谁有权说不行**。
生成器问不出来的那些，正好就是 `[to supply]` 该待的地方。
**四象限不是比喻，它就是标记规则的来源。**

## 5. 一节课装不下的部分，怎么处理

### 5.1 课堂 96 分钟的现实预算

| 段 | 分钟 | 产出 |
|---|---|---|
| 一幕 规则 vs 状态，五要素 | 0 到 18 | A1 A2 |
| 二幕 强制力阶梯，写 check.sh 并跑红 | 18 到 46 | A3 A4 |
| 三幕 挂 CI，违规 PR 被挡 | 46 到 64 | A5 A6 |
| 四幕 做生成器，撞上"不许编造"的反转 | 64 到 88 | B1 B2 B3 |
| 五幕 分支保护五开关 + 收口 + 作业 | 88 到 96 | B4 |

**这个排布有风险**：四幕只有 24 分钟要做出一个生成器 skill。
缓解办法是发一个**半成品 skill**（结构齐全、约束清单留空），学员只写约束那一段。
**约束那一段恰好就是本节的知识点**，所以这个简化不掉价。
需要 dry run 验证，见 §7 V4。

### 5.2 课后四周养成路径（作业，带关卡）

课堂只到 Tier 1。剩下的用四周长出来，每周一个可验证的关卡：

| 周 | 做什么 | 关卡 |
|---|---|---|
| 1 | 把 Tier 1 六个文件里的 `[to supply]` **去问真人**，能填的填，填不了的留着并写清在等谁 | 缺口数下降，且**每个剩余缺口都有"在等谁"** |
| 2 | 补第二层：一顶帽子的 charter + 一条有 trigger 的 SOP | 校验器通过 |
| 3 | 开分支保护，三个动作实测 | 两拒一放的记录 |
| 4 | 加第二条机械化检查，来源必须是**这四周里真的发生过的错** | 检查能抓到那个错 |

> 第 4 周那条"来源必须是真发生过的错"是参考系统的规格 2。
> 凭想象加检查，加出来的是噪音；从事故反推，加出来的每一条都有人会维护。

### 5.3 脱敏是讲师的义务，不是学员的限制 ⭐ 已更正

> **更正记录：** 本节早先写的是"课堂上不许把自己公司的真实内容写进仓库"。**那是错的。**
> 讲师指出：约束的对象搞反了。

| 谁 | 约束 | 为什么 |
|---|---|---|
| **讲师** | 投屏、演示仓库、预录、讲义**全部脱敏** | 不能把自己公司的名字和同事的名字泄露给一屋子学员 |
| **学员** | **没有这条约束。写真名、真金额、真客户都对** | 系统在他们自己电脑上，是他们自己的东西，**不交给讲师，也不交给任何人** |

**为什么这个更正很重要，不只是措辞问题：**

学员如果编一个好看的虚构公司，**第 4 步（不许编造）就废了**。
那一步的全部张力来自"这个数是谁定的"这个问题当场答不上来，，
**编的公司，你想写多少写多少，永远答得上来，也永远不疼。**

所以让学员写真的，不是通融，是**教学必需**。

**那课堂上还有没有真正的数据边界要教？有，但它是另一件事：**

| | |
|---|---|
| 规则 | **个人标识符不进规则仓**：邮箱、账号 ID、handle、手机号 |
| 理由 | 不是"敏感"，是**单一权威源**。它们属于身份目录，存两份必然不一致 |
| 参考系统的说法 | **「列的定义进库，行不进库。」** 访问登记册长什么样写在库里，谁有哪个账号存在别处 |
| 教学位置 | 推 GitHub 之前那一刻（RUNSHEET P10），不在开课时 |

⚠️ **这条跟"角色文件不写人名"不是同一条。** 后者的理由是**可维护性**（离职只动一份文件），
前者的理由是**单一权威源**。两条都成立，讲的时候别混，混了学员会以为人名是隐私问题。

### 5.4 国产工具与平台替代（系列惯例，必须有一页）

| 需要的能力 | 需要验证的替代 |
|---|---|
| Claude Code 跑生成器 skill | 国内可用的 agent 工具，能不能读项目级指令文件、能不能装技能 |
| GitHub CI 挡 PR | Gitee / Coding / 自建 GitLab 的流水线 + 合并门禁 |
| 分支保护三开关 | 上述平台的等价配置，以及"管理员也受约束"有没有 |
| 完全内网 | 服务端 hook（pre-receive）演示同一个概念 |

**这页的结论必须是实测的，不能是推测。** 见 §7 V2。

## 6. 三个立论的分工（避免互相打架）

系列惯例：立论一句、反转一句、收口一句，且收口不许提前说。

| 位置 | 句子 | 作用 |
|---|---|---|
| **全节立论**（第二幕点出）| 一条规则如果没有强制点，它不是规则，是许愿 | 支撑强制力阶梯，解释为什么要写 CI |
| **反转**（第四幕）| 生成器的好坏，看它留了多少空，不是填了多少 | 打掉"AI 一键生成治理体系"的幻觉 |
| **收口**（第五幕，不许提前说）| 这个仓库最大的产出不是文件，是它逼你去开的那几场对话 | 回答"为什么要做这件事"，也把课后四周路径接上 |

三句之间是递进的：
**有强制点 → 强制点会卡住你 → 卡住你的地方，正是你从来没跟人谈妥的地方。**

### 7.2 需要你拍板

**Q11 · 课堂硬产物的最终定义，确认是不是这三样？**
(1) 一个生成器 skill，**带"拒绝编造"的约束清单**
(2) 它产出的 Tier 1 六文件骨架
(3) 一条红过的 `check.sh` + 一个被 CI 挡住的 PR 截图

我的推荐就是这三样。第 (1) 是带得走的机器，第 (3) 是当堂的爽点。

**Q12 · 四周养成路径以什么形式交付？**
(a) 写进 HANDOUT 的作业段
(b) 独立的四周打卡讲义
(c) 做成一个课后 skill，每周问学员一次进度

(c) 最符合系列调性（L11 教过定时任务），但会让课程尾巴变长。

**Q13 · 一人多帽那一格（设计文档 §3.4）放不放进课堂？**
上一轮我把它列成 Q9。现在目标定死是"学员用于自己公司"，
**这一格的权重上升了**：学员多半是小团队负责人，缺席代理不对称这件事他们一定会遇到。
但它偏组织治理不偏编码。我倾向**压缩成第五幕的一页**，只给那张不对称表，不展开。

**Q14 · 课程时长确认 96 分钟，还是要到 120？**
按 §5.1 的排布，96 分钟是紧的，且依赖"发半成品 skill"这个简化。
如果你希望学员当堂**从零**写出生成器，需要 120。
