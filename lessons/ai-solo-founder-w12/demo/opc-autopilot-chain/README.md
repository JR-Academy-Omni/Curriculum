# 一人公司自动化工厂 · 练习手册

OPC 创业营 W15 · 让生意自己运转。

这个仓库里有 **7 种自动化练习**，每种都很简单，但代表一种不同的自动化形态。它们共用同一套规则：

> 每一段做完必须交一张回执 `status.json`，状态只有三种：
> `done` 做完了 · `skipped` 按规则不该做 · `needs-human` 卡住了要你判断
>
> **宁可交回一句「我没做，因为 X」，也不要交回一个猜着做完的结果。** 什么都没交回来，脚本会自动记成 `needs-human`。

## 7 种练习一览

| # | 练习 | 自动化类型 | 一句话 | 难度 | 现场时长 |
|---|---|---|---|---|---|
| 1 | 每日行业简报 | 定时 · 单步 | 每天 8 点自己读信息源，写 3 件事给你 | ⭐ | 15 分钟 |
| 2 | 选题 → 文章 | 定时 · 两步接力 | 9 点排好选题，10 点按第 1 名写文章 | ⭐⭐ | 20 分钟 |
| 3 | 内容流水线上云 | 多步接力 · 代码上云 | 选题 → 文章 → 视频脚本 → 主编审稿，在 GitHub 上每天自己跑 | ⭐⭐⭐ | 30 分钟 |
| 4 | 竞品监控 | 巡检 · 有变化才报 | 每 6 小时看一次竞品定价页，变了才叫你 | ⭐⭐ | 15 分钟 |
| 5 | 审批闸 | 人在回路 | 主编通过后停下，等你点头才出发布包 | ⭐⭐ | 10 分钟 |
| 6 | 旧内容批量改写 | 批量 · 断点续跑 | 10 篇旧文改英文版，跑断了重跑不重复 | ⭐⭐ | 15 分钟 |
| 7 | 反馈闭环 | 闭环 | 读真实数据，建议怎么改选题打分规则 | ⭐⭐⭐ | 15 分钟 |
| 8 | 事件触发（挑战） | 事件 · webhook | 有新付款就起草上手邮件 | ⭐⭐⭐⭐ | 课后 |

**怎么选：** 所有人都做 0、1、2、3。之后按你的生意从 4–7 里选一个：

| 你的情况 | 选 |
|---|---|
| 有明确的竞品，或者产品页价格经常改 | 4 竞品监控 |
| 内容要对外发，怕 AI 乱说 | 5 审批闸 |
| 手上有一堆旧文章 / 旧帖子 / 旧课件 | 6 批量改写 |
| 已经发过 3 条以上内容，有阅读和点击数据 | 7 反馈闭环 |

## 两种跑法

| | A · Codex App（本机） | B · GitHub Actions（云端） |
|---|---|---|
| 怎么定时 | Codex App 里的 Automation | `.github/workflows/autopilot.yml` 里写好的时间表 |
| 费用 | 用你的 Codex 订阅 | 按 OpenAI API 用量计费 |
| 什么时候会跑 | 电脑醒着、Codex 开着 | 24 小时，电脑关着也跑 |
| 产物在哪 | 你电脑上的这个文件夹 | 自动存回 GitHub 仓库，有历史可查 |
| 练习 | 1、2、4、6 | 3、5、7 |

所有代码都由 Codex 写和改。你只需要用中文跟它说要做什么，下面每个练习都写好了「对 Codex 说」的原话，可以直接复制。

## 练习 0 · 填你的生意（10 分钟，所有人）

打开 `config/business.md`、`config/voice.md`、`config/sources.md`，按里面的提示填。信息源至少 5 个，要选你所在行业每天会更新的公开页面。

> **对 Codex 说：** 读 config/ 下的文件，告诉我哪里写得太空泛，会让后面的产出变得像谁都能写的东西。只提问题，不要替我编内容。

---

## 练习 1 · 每日行业简报（定时 · 单步）

**它在做什么：** 到点自己去看、自己写，你醒来直接读结论。这是最简单的一种自动化：一个触发，一个产出。

1. 在 Codex App 里打开这个文件夹，先手动跑一次：

   > **对 Codex 说：** 今天是（今天日期）。执行阶段 brief：先读 AGENTS.md，再读 stages/brief/TASK.md，严格按它做，最后写回执。

2. 打开 `runs/<今天>/brief/brief.md`，点开每个来源核对一遍。
3. 没问题就新建一个 Automation，时间设每天 08:00，指令用上面那段话，日期改成「今天的日期」。

**成功：** `brief.md` 里的 3 件事都附了来源，都写了「对我的用户意味着什么」；`status.json` 是 `done`。

**弄坏它：** 把 `sources.md` 全换成不存在的网址再跑一次。回执应该是 `needs-human`，而不是一份看起来很像样的简报。

---

## 练习 2 · 选题 → 文章（两步接力）

**它在做什么：** 第二步只读第一步的产物。第一步没做成，第二步就不做。这是「前后依赖」最小的样子。

1. > **对 Codex 说：** 今天是（今天日期）。执行阶段 topic-radar：先读 AGENTS.md，再读 stages/topic-radar/TASK.md，严格按它做，最后写回执。
2. 看 `runs/<今天>/topic-radar/topics.json`。**排序你同意吗？** 不同意，就改 `config/scoring.md` 里的权重，再跑一次。
3. > **对 Codex 说：** 今天是（今天日期）。先运行 python3 scripts/pipeline.py gate article（今天日期），如果输出 run=true，再执行阶段 article：读 AGENTS.md 和 stages/article/TASK.md，严格按它做，最后写回执。
4. 两个都满意，就建两个 Automation：09:00 跑 topic-radar，10:00 跑 article。

**成功：** 文章用的是 topics.json 里排第 1 的话题，开头第一段就给结论。

**弄坏它：** 把 `topic-radar/status.json` 里的 `done` 改成 `needs-human`，再让 article 跑。它应该被挡住，回执写着「上游状态是 needs-human」。

## 练习 3 · 内容流水线上云（多步接力）

**它在做什么：** 同一套任务卡搬到 GitHub 上，不靠你的电脑。代码负责定时、查上游、验回执、存档；Codex 只负责判断和写作。

1. > **对 Codex 说：** 帮我把这个文件夹建成一个新的私有 GitHub 仓库并推上去。然后告诉我在仓库设置里要加哪个 secret、去哪里加。
2. 在仓库的 Settings → Secrets and variables → Actions 里加 `OPENAI_API_KEY`。**这条路按用量计费**，先在 OpenAI 后台给这个 key 设一个每月用量上限。
3. Actions → Autopilot → Run workflow，按顺序跑 `topic-radar` → `article` → `video` → `review`，每跑完一个再跑下一个。
4. 回到仓库首页看 `runs/<今天>/`：四个文件夹、四张回执，外加一份日报 `DIGEST.md`。

跑通以后，它每天就会按 `autopilot.yml` 里的时间自己跑。墨尔本时间和 UTC 的换算写在那个文件开头。

**成功：** 四张回执都是 `done`，日报里有四个 ✅。

**弄坏它：** 在 GitHub 上删掉 `runs/<今天>/article/article.md`，保留 `status.json`，然后跑 `video`。把关脚本会发现「标了 done 却没有产物」，把 article 的回执改成 `needs-human`。**绿灯不等于做成了。**

---

## 练习 4 · 竞品监控（巡检 · 有变化才报）

**它在做什么：** 不是每次都写报告，只有和上次不一样才叫你。它要记住上一次看到了什么，这就是 `state/` 文件夹的用处。

1. 在 `config/watch.md` 里写 2–3 个要盯的页面，并写清楚「什么算变化」。
2. > **对 Codex 说：** 今天是（今天日期）。执行阶段 watch：读 AGENTS.md 和 stages/watch/TASK.md，严格按它做。
3. 第一次运行只会建快照，回执是 `skipped`（没有可以比较的上一次）。
4. 打开 `state/watch/` 下的一个快照，手动把价格改成一个假的旧值，再跑一次。

**成功：** 第二次运行发现了变化，`watch-report.md` 写出「旧值 → 新值」，回执是 `done`。

**弄坏它：** 页面没有任何变化时连跑两次。两次都应该是 `skipped`，不能每次都给你写一份「一切正常」的长报告。

## 练习 5 · 审批闸（人在回路）

**它在做什么：** 自动化做到草稿就停下，等你点头。你批准的方式只有一个：新建一个空文件。

前提：练习 3 已经跑完，review 的结论是「可以送审」。

1. 在 Actions 里跑 `publish-gate`。它不会做，回执写「等你批准」。
2. 打开 `runs/<今天>/review/review.md` 认真读一遍。同意的话，在 GitHub 上新建一个空文件 `runs/<今天>/review/APPROVED`。
3. 再跑一次 `publish-gate`。

**成功：** 第二次才出 `publish-pack.md`，每个平台一段，可以直接复制粘贴。**它不会替你发布。**

**想一想：** 你的生意里，哪一步必须等你点头？把这一步写进你的任务书。

---

## 练习 6 · 旧内容批量改写（批量 · 断点续跑）

**它在做什么：** 一次性的大活。重点不在改写，在于跑到一半断了，重跑时不重复、不遗漏。

1. 把 5–10 篇你自己的旧内容放进 `inbox/`，一篇一个 `.md` 文件。
2. 在 `config/batch.md` 里写清楚要改成什么。
3. > **对 Codex 说：** 执行阶段 batch：读 AGENTS.md 和 stages/batch/TASK.md，严格按它做。
4. 它一次最多做 5 篇。跑完看 `state/batch-progress.json`，再跑一次。

**成功：** 第二次只处理剩下的那些，`outbox/` 里没有重复的文件，全部做完后回执是 `done`。

**弄坏它：** 第一次跑到一半时在 Codex 里点停止，然后重新跑。已经写进 `outbox/` 的那几篇不应该再做一遍。

## 练习 7 · 反馈闭环（今天的结果影响明天的选择）

**它在做什么：** 读发出去之后的真实数据，判断你的选题打分规则哪里不准。**它只提建议，规则由你改。**

1. 在 `metrics/performance.csv` 里填至少 3 条你最近发过的内容的真实数据。
2. 在 Actions 里跑 `feedback`（或者在本机让 Codex 执行 feedback 阶段）。
3. 读 `scoring-proposal.md`：它建议改哪个权重，依据的是哪几行数据。

**成功：** 每条建议都能对上 performance.csv 里的具体某一行。你同意的，才去改 `config/scoring.md`，下周 09:00 的排序就会跟着变。

**弄坏它：** 只填 2 条数据。回执应该是 `skipped`（数据不足），而不是硬凑出一份建议。

---

## 练习 8 · 事件触发（挑战，课后）

GitHub Actions 的定时任务只能按时间跑。「有新付款就马上做事」需要一个能接收 webhook 的地方。

> **对 Codex 说：** 我想在 Stripe 有新付款时，自动起草一封给新客户的上手邮件（只起草，不发送）。先给我比较两三种能接收 webhook 的云端方案的费用和难度，等我选好再写代码。邮件草稿要用 AGENTS.md 里的回执规则。

## 仓库里有什么

| 路径 | 是什么 | 谁改 |
|---|---|---|
| `config/` | 你的生意、语气、信息源、打分规则、监控页面、批量要求 | 你 |
| `stages/<阶段>/TASK.md` | 每一段的任务卡：输入、做法、产出、完成判据 | 你（和 Codex 一起改） |
| `AGENTS.md` | Codex 在这个仓库里必须遵守的规则 | 一般不动 |
| `pipeline.json` | 有哪些阶段、谁是谁的上游、哪一段要等你批准 | 加新阶段时改 |
| `scripts/pipeline.py` | 把关脚本：查上游、查批准、验回执、出日报。不调用模型 | 不动 |
| `.github/workflows/autopilot.yml` | 云端定时 | 不动 |
| `runs/<日期>/<阶段>/` | 每天的产物和回执 | 自动生成 |
| `state/` | 需要「记住上一次」的练习存在这里（练习 4、6） | 自动生成 |
| `inbox/`、`outbox/` | 批量练习的输入和输出 | 你放 / 自动生成 |
| `metrics/performance.csv` | 发布后的真实数据 | 你 |

## 不要做

- 不要让任何阶段直接对外发布、发邮件或付款。对外的动作只写成草稿。
- 不要让 feedback 直接改 `config/scoring.md`。规则由你来改。
- 不要把 API key 写进任何文件，只放在 GitHub Secrets 里。
