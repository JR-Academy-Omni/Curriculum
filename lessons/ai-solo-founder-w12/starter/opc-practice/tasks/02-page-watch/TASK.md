# 02 · 竞品页面监控（巡检 · 有变化才报）

## 目标
检查下面的页面，和上一次的快照比较，只有实质变化才报告。

## 要盯的页面（练习前填 2 个）
| 页面名 | URL | 什么算变化 |
|---|---|---|
| | | 例：价格或套餐名变了 |
| | | 例：页面打不开 |

## 做法
1. 打开每个页面，提取关键信息（价格、套餐、主要卖点、能不能打开），写成简短的文本。
2. 和 `state/02-page-watch/<页面名>.md` 比较。第一次没有快照：只建快照，不算变化。
3. 用这次的结果覆盖快照文件。

## 产出
- `output/<今天>/02-page-watch/watch-report.md`：每个页面一行：无变化 / 有变化（旧值 → 新值）/ 打不开
- 更新后的 `state/02-page-watch/*.md`

## 完成判据
- `done`：至少一个页面有实质变化
- `skipped`：全部无变化，或者只是排版变化（第一次运行也是 skipped）
- `needs-human`：有页面打不开

---

**对 Codex 说：**
> 今天是（今天日期）。按 AGENTS.md 的规则，执行 tasks/02-page-watch/TASK.md，最后写回执。

**跑两次：** 第一次只建快照，回执是 `skipped`。然后打开 `state/02-page-watch/` 里的一个快照，把价格手动改成一个旧值，再跑一次，回执应该变成 `done`，报告写出「旧值 → 新值」。

**弄坏它：** 页面没变时再跑一次。它应该安静地交 `skipped`，而不是写一份「一切正常」的长报告。
