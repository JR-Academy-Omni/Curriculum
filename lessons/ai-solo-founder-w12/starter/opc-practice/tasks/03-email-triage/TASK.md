# 03 · 客户邮件分诊（事件）

## 目标
把一批客户来信分成三类，各起草回复。只起草，不发送。

## 输入
- 来信：`practice-data/emails/`，或者把你自己的 5 封来信（去掉姓名、电话、邮箱）存成 `.md` 放进去
- 我的 FAQ / 退款政策 / 价格：写在 `config/business.md` 里；没写到的，Agent 不能自己编

## 三类
| 类别 | 处理 |
|---|---|
| 使用问题 | 起草回复，只能引用 business.md 里有的信息 |
| 退款 / 投诉 | 不起草，标记「转人工」，写一句为什么 |
| 购买咨询 | 起草回复，并列出这位客户想要什么、下一步跟进什么 |

## 产出
`output/<今天>/03-email-triage/triage.md`：每封信一段：文件名、类别、理由、回复草稿（或转人工原因）、依据了 business.md 的哪一条

## 完成判据
- `done`：每封都分了类；每份草稿里的说法都能在 business.md 里找到依据
- `needs-human`：有一封信回答需要的信息 business.md 里没有，列出缺什么

---

**对 Codex 说：**
> 今天是（今天日期）。按 AGENTS.md 的规则，执行 tasks/03-email-triage/TASK.md，最后写回执。

**弄坏它：** 新建一封来信，问一个你的 business.md 里完全没写的问题（例如「你们支持新西兰的 GST 吗？」），再跑一次。它应该交 `needs-human` 并说缺什么信息，而不是编一个答案。

**真的接上邮箱：** 这是「有事发生就马上做」的事件型自动化，要接邮箱需要一个一直在线的云端服务，课后再做。
