# W15 · 自动化任务书（课堂硬产物）

每人交一份，写给你自己的生意（不是写给练习）。一件事一份；有几段接力，B 就写几张卡。这份写清楚了，换工具、换平台、换模型都还能用。

## A. 整条流水线

| 项 | 你的答案 |
|---|---|
| 这条流水线替我省掉的是哪件琐事？每周省多少分钟？ | |
| 第一段由什么触发？（时间 / 事件 / 监控到变化） | |
| 最后一段的产物交给谁？（我批准 / 自动发草稿 / 存档） | |
| 跑在哪里？（Codex App Automation / GitHub Actions / 云函数）为什么？ | |
| 每月预算上限（API 用量） | |

## B. 每一段一张卡（复制多份）

| 项 | 写什么 |
|---|---|
| 阶段名 + 时间 | 例：article · 每天 10:00 |
| 上游 | 读哪一段的哪个文件；上游不是 done 时怎么办 |
| 目标 | 一句话，写给 Agent 看 |
| 完成判据 | 怎么判断它做对了（可检查的条件，不写「写得好」） |
| 边界 | 它不许做什么（对外发布、改配置、编数据……） |
| 预答 | 它最可能来问你的 2 个问题，你提前写好的答案 |
| 出口 | 什么情况写 skipped，什么情况写 needs-human |
| 回执 | 产物文件名 + status.json |
| 重跑 | 同一天跑两次会不会出问题？不安全的话第一版只出草稿 |

## C. 练习 30 分钟的证据

截图发群里。证据放在哪，取决于你做的是哪一条：

| 你做的练习 | 正常那次的证据 | 弄坏那次的证据 |
|---|---|---|
| **主线：记忆仓库**（课上默认） | `topics/<今天>.md` + `evals/<今天>.md` | 加了违规句后 Eval 的回答：第一行 `状态：needs-human` |
| 本机 6 个小任务 | `output/<今天>/<任务>/` 里的产出 + `status.json` | 弄坏后的 `status.json`（skipped 或 needs-human） |
| GitHub 6 个小任务 | 任务 1、6：Issues 里的新 Issue；任务 2：`docs/INDEX.md` 的更新；任务 3：`briefs/<今天>.md`；任务 4：Issue 下的评论；任务 5：PR 页面 | Actions 运行日志里的状态行，或 Issue / 评论里的 needs-human |

## D. 这周的作业

让你设好的 Automation 自己跑满 7 天。每天早上只看一次日报，把 needs-human 的原因记下来，周日改任务卡。下周 Pitch 课 时，把 7 天的产出和回执当作「这门生意已经在自己运转」的证据。
