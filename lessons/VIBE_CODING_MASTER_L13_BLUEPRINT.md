## 0.1 这一节到底新在哪

前十二节交给学员的东西，全都是**给一个 agent 用的**。L12 的 hook 管的也只是你自己这台机器上的那个 agent。

**L13 第一次把对象换成人 ,而且第一次把「谁改得了它」当成问题。**

| | L12 | L13 |
|---|---|---|
| 管谁 | 一个 agent | **一群人，以及他们各自的 agent** |
| 强制点在哪 | 你本机的配置 | **一台你改不了的机器上** |
| 它能怎么绕 | 不读 / 读了不照做 | **把那条规矩本身改掉** |
| 谁写规矩 | 你 | 你，**但必须有人同意那些数字** |

第三行是 v3 新加的，也是这一节真正的新东西。

## 0.2 全节最重要的三句话

**立论**（第四幕，全节唯一一次点明）：

> **规矩的力量，不在它写了什么，在谁改得了它。**

**反转**（第三幕末，学员刚写完四道判断线、最有掌控感的时候翻）：

> **检查挡得住的，只有你说得清的那部分。**
> 说不清的，你能转化掉一部分，**剩下的必须承认它停在第 0 级 ,不许假装。**

**收口**（全程不许提前说）：

> **留白在等的那个人，就是你该去谈的那场话。**

> ⚠️ **v2 的「没有强制点就不是规则，是许愿」降级为第二幕的支撑句**，不再是立论 ,
> 它讲的是"没人执行"，而 v3 要讲的是"执行了也没用，因为规矩本身能被改"。
> ⚠️ **反转从第五幕前移到第三幕末。** 生成器那句「看留多少空」降成它的回声（同一条道理换个对象），
> **避免两个反转互相稀释**。

## 0.3 全课主链 ⭐⭐ v3 的核心，讲师必须能默写

```
规矩没人执行
      ↓
因为「靠人记得」
      ↓
那就写下来 ,不够。演示 A 已经证明：写了三个地方，照样没人拦
      ↓
写进 wiki？,谁都能悄悄改，而且改了没人知道
      ↓
放进 git 仓？,对。但不是因为 git 更专业，
               是因为它有一个【你改不了的远端】
      ↓
可是规则文件、检查脚本、给 agent 的指令，全都在本地，全都可以改
      ↓
所以本地跑检查是【给自己的便利】，不是【给别人的保证】
      ↓
唯一不在改动者机器上的执行点 = 远端 CI
      ↓
所以  ① 检查放 CI
      ② 规则的改动本身也要走 PR 被人看见
      ③ agent 每次先拉 origin ,防止它在被改过的规则下干活
      ↓
但 CI 只挡得住【你说得清的】
      ↓
说不清的：先试转化，转化不了就降级，再不行明写它停在第 0 级，不许假装
```

**这条链一口气回答四个 v2 没答的问题：**

| 问题 | 答案在第几行 |
|---|---|
| 为什么是 git 仓库不是 wiki | 4 到 5 |
| 为什么本地绿了还不够 | 6 到 8 |
| **哪里该有脚本** | 9 ,**哪里会被绕过，不是哪里容易出错** |
| `CLAUDE.md` 为什么要写拉取 | 9 ③ ,**完整性，不是新鲜度** |

## 0.4 教学决定一：两条线，不在同一层 ⭐ 这条最容易被误读

| | 是什么 | 出现在哪 |
|---|---|---|
| **八步**（§1.2） | **议程** ,今天依次做什么 | 贯穿全课，每步开头说"上一步留下什么问题" |
| **威胁模型链**（§0.3） | **论证** ,为什么必须这么做 | 第一幕（为什么是仓库）+ 第四幕（为什么 CI）。第四幕是它的高光 |

**威胁模型不改变八步中任何一步的顺序**，它只给第 1 步和第 6 步补了理由。
所以两条线不冲突 ,把论证误当成第二条脊椎，是 v3 起草过程中犯过并纠正的错。

## 0.5 教学决定二：脚本不是让学员抄的 ⭐⭐

| | v2 | **v3** |
|---|---|---|
| 学员在干什么 | 照着屏幕敲 `readdirSync` 循环 | **说一句话，让 agent 写成检查** |
| 核心技能 | 会写检查 | **判断哪里该有检查 / 说得够不够清楚 / 说不清的怎么兜** |
| 带走什么 | 六段代码 | **一套判断 + 一套让 agent 写对的说法** |
| 失败长什么样 | 语法错 | **它给了你能跑的代码，但查的不是你想查的** |

**deck 上代码的角色从「要抄的」变成「要评判的」**，统一三栏：

```
你说的话                          它写的东西        它抓到 / 漏掉了什么
「角色文件写得对不对」            一段能跑的代码    ❌ 查的不是你想查的
「每个角色文件都必须在索引里登记，  一段能跑的代码    ✅ 抓到了
 存在但没登记的报失败」
```

**这门课真正该留下的那句操作性的话：**

> **改你的说法，不是改代码。**

## 0.6 教学决定三：代词拆开，别用「它」 ⭐ v3 新增纪律

同一页里「它」曾经同时指四样东西（那条规矩 / 违反那个动作 / agent / 这件事），学员读到第三个就跟丢了。

| 指的是 | **必须用的词** |
|---|---|
| 那条规矩 | **这条规矩** |
| 违反那个动作 | **破规矩的时候** |
| 做事的那个人或 agent | **明确说出来，不许用「它」** |
| 这件事本身 | **这** |

**并且演示 A 跑完必须紧跟一句：**

> 这不是**它**的问题。**换个人来做，结果一模一样。**

这一句同时做三件事：把指代锁死、把对象从 agent 扩到人、**而且它是 L12 到 L13 唯一一处把承接做实的地方**（v2 里承接只在封面上有一句，正课没兑现）。

## 0.7 教学决定四：正面给规矩，不赌学员会犯错 ⭐⭐ v3.2 翻面

> **v2 到 v3.1 的做法：** 写角色文件那一页故意不说「不许写人名」，
> 后面那条检查抓到的是学员自己刚写的名字，抓到之后才讲为什么。
> **讲师一句好心提醒，整格作废** ,称为「本 deck 最大的自毁按钮」。

**讲师否掉了这个做法，理由是事实层面的：每个人的仓库不一样，这一下不一定咬得到。**

学员课堂上只写两个角色，而角色模板那三段（答应什么 / 独自能决定什么 / 什么必须报批）
**并不天然招人名** ,很多人跑出来就是绿的，**那一格对他们完全是空的**。

> **一个只在学员恰好犯过错时才成立的教学点，不是教学点，是抽奖。**

**现在的四层（顺序不能换）：**

| 层 | 做什么 | 保不保证发生 |
|---|---|---|
| 一 | **正面给规矩**：角色文件里只出现角色，人名只活在花名册里 | 必然 |
| 二 | **给理由**：那个人离职的那天，你要改的应该只有一份文件 | 必然 |
| 三 | **才跑**，验证 ,**抓到 / 没抓到都要有话说** | 必然 |
| 四 | **讲师投屏自己的例子** ,「检查从哪来」压在这里 | 必然 |

**「没抓到」那一句是新增的那一半，不许省：**

> 两种可能，别急着高兴：你确实写对了，或者**你今天只写了两个角色，还没碰到**。
> **回去写第十个的时候会碰到。**

不说，那批学员会得出「这条跟我无关」的结论。

**连带拆掉的：** 写角色那一页**不再是自毁按钮**，讲师说漏嘴不再整格作废。
**这同时消掉了一条「严重度：高」的结构性风险**（见 §14）。
第四层从「并行主路径」升成**主路径** ,学员中没中是随机的，**讲师中过是确定的**，
「检查从哪来」这个点只能压在确定的那一边。

检测用**花名册精确匹配，不用人名正则** ,正则版实测在中文最自然的写法上全部漏掉，还会把普通词误判成人名。
花名册版中英文通吃、零误报，而且「先建花名册再写角色」这个动作本身就在教**人和角色是两张表**。

## 1. 核心框架

### 1.0 这套东西的最小单位不是公司（v2 保留）

> 判据只有一条：**有没有超过一个动作者，会碰同一批东西。**
> 一家公司、一个部门、一个项目组、三人小队，**甚至只有你和你那几个 agent**，都算。

**三人组收益最快**，因为小组最吃亏的是「只有一个人知道那件事怎么做」。
课堂八步走的就是三人形态 ,**「你不是做了个简版，你做完了」这句必须说出口。**

### 1.1 全节立论

> **规矩的力量，不在它写了什么，在谁改得了它。**

五句症状（第 0 步用）：

```
1  没人看得见什么处在风险里            偏大规模
2  决策被提出，然后搁着
3  问题被提出，然后悄悄淡掉
4  有人绕开流程，直接找到了做事的人    偏大规模
5  只有一个人知道那件事怎么做          偏小组
```

五句都不是"我们没有文档"。五句都是同一个形状：**某件事本来该发生，但没有任何东西保证它发生。**

### 1.2 框架一：造系统的八个决定（议程脊椎，v2 保留）

| 步 | 要回答的问题 | 学员产出 |
|---|---|---|
| 0 | 我们到底疼在哪 | 认领一条症状 |
| 1 | 什么该进这个仓库 | 仓库骨架 + 检查① |
| 2 | 文件打架时谁赢 | `AUTHORITY.md` + 检查② |
| 3 | 谁答应什么 | 花名册 + 两个角色 + 检查③ |
| 4 | 我不知道的怎么办 | `[to supply]` + 检查④ + **标 approved 看它红** |
| 5 | 该查什么、不该查什么 | 三次翻车，检查活下来 |
| 6 | **怎么让它绕不过去** | CI 挡住 PR + 分支保护，**最后才写指令层** |
| 7 | 回去怎么复制这一套 | 生成器的约束段 |

**检查是累积的，每加一条规则就给它加一条检查。**
**学员要造四次红**：漏登记 · **标了生效但还有空** · 满屏红 · 抓到自己的名字
（⚠️ **第四次是条件红，不保证发生** ,见 §0.7）。

> ⭐ **第 6 步里的顺序也是设计：指令层排最后。** 理由见 §1.3 L0 那一行。

### 1.3 框架二：六层图 + SOP 的位置 ⭐ v3 新增

> 🔴 **只给六层，L6 留一个空格。** 七层里 L6 就是强制力阶梯，第一幕给全等于提前亮底。
> 第四幕阶梯那页把它补上，**缺一块的图会让学员一直惦记**。

```
     ┌────────────────────────────────┐
     │  ？？？                         │  ← 第四幕才填
     ├────────────────────────────────┤
L5   │  技能层    AI 怎么干活          │  → 下一节
L4   │  流程层    SOP / 模板           │  ← SOP 在这里
L3   │  组织层    角色 / 花名册        │  ← 今天做
L2   │  治理层    谁说了算（最高权威） │  ← 今天做
L1   │  入口层    人读的那一份         │
L0   │  指令层    AI 读的那一份        │  ← 最后做
     └────────────────────────────────┘
```

> ⭐ **L0 为什么排最后（v3.2 讲师）：它是唯一一份会反过来管住「这次施工」的文件。**
>
> 你写完 `AGENTS.md` / `CLAUDE.md` 的那一刻，**帮你建仓库的那个 agent 就开始受它管**。
> 它里面一旦有「规则目录的改动必须走 PR」「agent 不许写 governance/」这类条款，
> 你后面每一步都要跟自己刚立的规矩打架 ,**更糟的是，你可能已经没权限改那条规矩了。**
>
> 正确顺序：**规则先定死、检查先跑绿、强制点先挂上，最后才告诉 AI「这些是你要遵守的」。**
> 一句话：**指令层是对前面所有东西的引用。被引用的东西还没定，引用就是空的。**
>
> **落点：** P04 这张图的 L0 标「最后做」+ 一个红框讲理由 · P24 生成器第 6 步末尾明写「不许提前写」。
> **这是全课第一次出现「顺序本身也是设计」。**

**这张图一次回答三件事：**

| 问题 | 图怎么答 |
|---|---|
| 这个系统是做什么的 | 六层，每层一句话 |
| 什么是 SOP | **它是 L4** |
| 为什么今天不先写 SOP | **因为 L4 站在 L2 和 L3 上面。没有谁说了算，SOP 写出来也没人执行** |

最后一句是白送的 ,**它不是话术，是那张图的结构本身在说话**。

**SOP 定位取 B，课上一句话版：**

> 大多数公司的 SOP 失败，不是因为写得不好，
> 是因为**写完之后没有任何东西保证它被执行**。
> 所以今天不从「写步骤」开始，从「谁说了算」和「谁来拦」开始。

⭐ **这张图还有第二重身份，讲师要点出来：它是 agent 的检索路径。** 见 §1.7。

### 1.4 框架三：强制力阶梯（分界线重述）⭐ v3 改

```
L6  服务端拒绝 + 管理员也受约束
L5  分支保护
L4  CI 挂进 PR
─────────── 上面不在你机器上，下面在你机器上 ───────────
L3  本地校验脚本          ← 学员此刻在这
L2  会话启动钩子
L1  写进 AI 指令文件
L0  写在文档里            ← 开场那条规矩在这
```

| | v2 | **v3** |
|---|---|---|
| 分界线写的 | 上面是硬政策，下面是约定 | **上面不在你机器上，下面在你机器上** |
| 一句话 | 区别不是技术，是**谁来记得** | 区别不是谁记得，**是谁改得了** |

**改完之后 L0 到 L3 有了统一性质：它们全在你本地，全可以被改掉。** 学员一眼看懂那条线为什么在那儿。

### 1.5 框架四：四道判断线 + 兜底三级 ⭐⭐ v3 新增，第三幕的骨架

```
第一道  这条规则能不能机械化？
第二道  ⭐ 不能的话，能不能【转化】成能机械化的形状？
第三道  这条检查该不该算失败？
第四道  这条检查是从哪来的？
```

**第二道是全节最实用的技巧，转化表（课堂当场练）：**

| 判断题（查不了） | 转化成形状题（查得了） |
|---|---|
| 这个审批额度合不合理 | **这个额度有没有人签过字**（谁、什么时候） |
| 这份文件写完了吗 | **有没有残留 `[to supply]`** ← **课堂检查④就是这个** |
| 这个决定对不对 | **有没有记录是谁定的** |
| 这条 SOP 写得好不好 | **十三节齐不齐** |

> 转化本身可以让 agent 帮你做，这是可教的 prompt：
> 「这条规矩我想查，但它是判断题。**有没有办法把它换成一个不动脑就能判的形状？**」

**兜底三级，各有代价：**

```
一级  转化   把判断题改写成形状题          代价：查的是「有没有人管过」，不是「管得对不对」
二级  降级   查不了内容，查「有没有人看过」  代价：只保证被看了，不保证被看懂了
三级  明写   写成规则，承认停在第 0 级      代价：靠人记得
                                          【但必须写下来它是第 0 级，不许假装】
```

### 1.6 框架五：记录放哪 ⭐ v3 新增（正课 2 分钟，完整对比进附录 A8）

> **这条记录，是要被「读」，还是要被「数」？**

| | 被读 → **git** | 被数 → **数据库** |
|---|---|---|
| 一年后翻出来干嘛 | 看**当时怎么想的** | 算**出现了多少次** |
| 形态 | 散文，价值在细微处 | 结构化，形状重复 |
| 一年产生 | 几十条 | 几千条 |
| 进不进 agent 的 context | **要，所以必须小** | **不要** |

```
进 git（被读）                 进数据库（被数）
  决策记录：为什么这么定          日更 / 站会
  批准依据：那个批准立在什么上面   工单状态流转
  破例记录：这次为什么不适用       检查命中记录
  规则变更                       权限授予记录
```

**既要读又要数的**（比如破例记录）：写进 git，让脚本去数。
几百条以内脚本数得动；超过了再拆，结构化字段进库、理由文本留 git、用一个 id 挂起来。

**混合方案 = 分流 + 锚定**（完整版 A8）：数据库出快照提交进 git，
加一条对账检查 ,**数据库当前历史 vs git 快照序列，对不对得上**。
它补的正是数据库「策略性不可改写」那个洞。

**混合方案的真实代价必须讲：**「这条记录该去哪」变成每天都要做的判断。
**所以那条判据必须简单到能写进模板里 ,这就是它只有一句的原因。**

### 1.7 框架六：检索与 token ⭐ v3 新增，四条散进相应位置

**一、「一个话题一个权威源」的真正理由是检索，不是防漂移。**

> 一个话题散在三个文件里，agent 必须三个都读完才敢答；
> **漏一个，它就给你一个自信的错答案。**

**二、新铁律：例外必须和规则在同一个文件里。**

> agent grep 到规则，答了，**而例外写在另一个文件 ,它没看见。**
> 所以例外不许单独成文件，必须紧跟在它修饰的那条规则下面。

**三、规则仓的大小上限 = agent 还能不能一次读完。**

| | agent 整读的代价 |
|---|---|
| 最小规则仓（几个文件） | **一次读完，可接受** |
| 成熟规则仓 | **读不起**，必须真的靠导航 |
| 50 人一年的 git 记录 | **完全不可读**，任何跨记录的问题只能靠脚本 |

> **过了这条线，你的分层必须真的能导航 ,否则 agent 每次只能 grep，
> 而 grep 出来的片段是没有上下文的。**

**四、机械化的第二个红利（第一个是确定性）：**

> **每一条你机械化掉的规则，都是 agent 以后不用再读的一条。**
> 它不再需要被读懂、**不再进 context**、**不再有被误读的机会**。

### 1.8 老师必须抓住的十条

1. **主链（§0.3）要能默写。** 讲飞的时候回到那条链。
2. **八步是议程，威胁模型是论证，别混。**
3. **每一步结束跑一次检查。** 把课从管理研讨拉回动手课的唯一手段。
4. **写角色那一页不提人名规矩** ,顺序上没必要提前，规矩在 P18 正面给。**v3.2 起说漏嘴不再整格作废**（§0.7）。
5. **不用「它」。** 按 §0.6 拆词。
6. **演示 A 跑完必须说「换个人来结果一样」。**
7. **翻车②必须慢。**
8. **「改你的说法，不是改代码」要说出口。**
9. **反转是边界不是否定**，第三幕末一口气到底。
10. **收口四分钟一秒不能少。**

### 1.9 最容易出错的七类

| # | 出错长什么样 | 后果 |
|---|---|---|
| 1 | 讲成治理研讨会 | 靠铁律 3 防 |
| 2 | 写角色那页提醒了人名 | 翻车③整格作废 |

| 5 | 展开讲 CI/CD 语法 | 吃掉第五幕 |
| 6 | 学员问"我们就三个人"答"那你简化一下" | 见 §1.0，答反了 |
| 7 | 线上等待点空等 | 直播最致命的死场 |

## 7. 第三幕 · 说得清和说不清（56 到 99）⭐ 本节高光

| 段 | 分钟 | 页 | 做什么 |
|---|---|---|---|
| 7.1 | 56-64 | P13 | 那个数字是谁定的 + 三标记 + 留白 |
| 7.2 | 64-70 | P14 | 🎬 标 approved → **第二次红**，**并点破这就是「转化」的第一个例子** **埋点 2** |
| 7.3 | 70-75 | P15 | 🎬 **翻车①：你说得模糊，它给你一个跑得通但查错的东西** |
| 7.4 | 75-79 | P16 | **四道判断线 + 转化表** ⭐新 |
| 7.5 | 79-87 | P17 | 🎬 **翻车②：你没说哪些该算失败，它全算了** ⭐⭐ 本幕支点 |
| 7.6 | 87-93 | P18 | 🎬 翻车③：**正面给规矩** ,前五条一直全绿，而这条早就破了 |
| 7.7 | 93-99 | P19 | 三次并排 + **兜底三级** + **反转** ⭐新 |

**7.2 的关键一句（v3 新）：**

> 你刚才做的事有个名字。
> 「这份文件写完了吗」是**判断题**，机器判不了。
> 「有没有残留 `[to supply]`」是**形状题**，机器一眼就判得出来。
> **你把一道判断题，换成了一道形状题。**

**7.3 翻车①的新形态（v3 改）：**
不是"学员卡住写不出来"，是**"它给你一个能跑的东西，你以为成了"** ,
**这是静默失败**，它在第三幕就埋下了 L14 收口那句「它什么都没做而你以为它做了」。

**7.5 翻车②三句，一句都不能省：**
① 这是错吗（不是）② 那你明天还会跑它吗（不会）③ **一个天天红的检查，和一个不存在的检查，是同一个东西**。

**7.6 翻车③四层，顺序不能换（v3.2 翻面，见 §0.7）：**
**正面给规矩**（只出现角色，不出现人名）→ **给理由**（离职只动一份文件）→ **才跑**，
抓到 / 没抓到**都要有话说** → **讲师投屏自己的例子**（主路径，不是备胎）。

⚠️ **不要再用「这条检查我不解释，你先跑」。** 那个版本赌的是「它会咬到学员自己」,
**而每个人的仓库不一样，那件事不保证发生。**

**7.7 反转：**

> **检查挡得住的，只有你说得清的那部分。**
> 说不清的，你能转化掉一部分 ,**剩下的必须承认它停在第 0 级，不许假装。**
>
> 一个声称能查判断题的检查器，**只会在你最需要它的时候给你一个错误的绿灯。**

**7.7 还要顺带给机械化的第二个红利**（§1.7 四）：每机械化一条，就是 agent 以后不用读的一条。

**这一幕一格都不能砍。** 超时砍第四幕和第五幕。

## 8. 第四幕 · 谁改得了它（99 到 122）⭐ v3 改动最大的一幕

### 8.1 那个演示 ⭐⭐ 全节最该有、v2 完全没有的一格

**谁会绕过它：**

| 攻击者 | 动机 | 怎么绕 |
|---|---|---|
| 你自己 | 赶时间 | 本地改掉那条检查 |
| 你同事 | 对自己有利 | 把规则改宽了提交进来 |
| **你的 agent** | **你让它「把 CI 弄绿」** | **它去改检查，不改文件** |

**演示：跟 agent 说「把 CI 弄绿」，看它去改检查而不是改文件。**

> 本地的检查挡不住它 ,**因为检查也是本地文件。**

**这是 Vibe Coding 课独有的演示**，而且它续上 L12：
L12 讲「它可以不读，读了可以不照做」，**L13 讲「它还可以把那条规矩本身改掉」**。

> 🔥 **回收埋点 4**（P03 那句「你改不了的远端」）。

### 8.2 阶梯 + 立论

分界线改成「**上面不在你机器上，下面在你机器上**」（§1.4）。
**同时把六层图的 L6 补上** ,第一幕留的那个空格在这里填。

> 🔥 **回收埋点 3**（P08 那句「没有任何东西自动跑它」）。

### 8.3 CI 那一页的理由要换

| v2 | **v3** |
|---|---|
| 刚才它要你记得跑，现在它自己跑 | **刚才那个检查在你机器上，你改得了。现在它在一台你改不了的机器上** |
| 区别是谁来记得 | **区别是谁改得了** |

**推之前插数据边界（只插这一次）：** 个人标识符不进这个仓库 ,理由是**单一权威源**，
⚠️ **跟花名册那条检查不是同一件事**（那条是可维护性）。

### 8.4 五开关 + v3 新增的一格

**规则的改动本身也要被审。** 五开关表之外补一句：

> 你已经挡住了"违反规则的改动"。
> **但「把规则改宽」这个动作，本身也是一次改动。**
> 挡它的是同一套东西：PR + 必需检查 + 管理员也受约束。

## 12. 检查样例库（角色变了）⭐ v3 改

**v2 是"抄这段代码"。v3 是"这样说，它会写出这个"。**

每条样例三栏：**你该怎么说** / 它会写出什么 / **它抓得到什么、抓不到什么**。

| 类 | 不变式 | 课堂用 |
|---|---|---|
| A 存在性与引用完整性 | 角色文件都被索引登记 · 索引登记的都存在 · 每个目录在裁决表里有位置 | ✓ |
| B 格式与结构 | 必需表头字段 · 小节顺序固定 · 表头后无自由段落 | |
| C 派生值 | 派生值不许手写第二遍（**查的是动作，不是值**） | |
| D 禁用词与边界 | 角色文件不许出现花名册上的名字 · 个人标识符不进规则仓 | ✓ |
| E 状态一致性 | **标了生效的不许残留留白** · 缺口分布 · **Review date 过期报 note** ⭐新 | ✓ |
| F 权限与漂移 | 八条不需要身份就能查的不变式 | |
| **G 明确不该查的** | 权限划分对不对 · 阈值合不合理 · 职责该归谁 | **要讲** |
| **H 记录专用** ⭐新 | **没有任何一次提交修改了过去的记录文件**（append-only）· 数据库与 git 快照对账 | 附录 |

> **G 那一格的一句话：不假装，是这套东西能被信任的原因。**

### 13.2 A7 回路图

```

              ↑                ↓
              └────────────────┘
        被挡了几次 · 破例了几次 · 检查抓到了什么
```

**七层只画了「规则 → 执行」。** 回路是缺的那半边。

### 13.3 A8 记录存储三方案

| | 纯 git | 纯数据库 | 混合 |
|---|---|---|---|
| 抹不掉 | **结构性保证** | 策略性，能改的人可以不留痕 | git 那半是结构性的 |
| 查询聚合 | **几乎没有** | **强** | 分流之后各就各位 |
| 写入门槛 | 中 | **低** | 看分到哪边 |
| agent 读的代价 | 小量可整读，**大了读不起** | 不进 context | **被读的那半保持小** |
| 运维 | **零** | 要人管 | 要人管 |
| 规模上限 | 十人量级 | 无明显上限 | 无明显上限 |
| **最大风险** | **长大之后 agent 读不完，而它不会说** | **能改的人和定规则的人是同一批** | **分流判断做错** |

**混合 = 分流 + 锚定 + 一条对账检查。**
