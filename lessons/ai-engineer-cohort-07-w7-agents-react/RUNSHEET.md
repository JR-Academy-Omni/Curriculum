- 输出每次会有差异，这是正常的，正好说明路径不固定。讲的时候指真实输出，不要背固定结果。

- 只有 `01_control.py workflow` 和 `pytest` 不调模型，这两个每次输出一样。
- 全课只有三样东西：`01_control.py`（三种控制方式）、`agent.py`（一个 Agent，换场景）、`tests/test_failures.py`（失败路径）。讲的时候提一句：真实项目也是这样，一个 Agent，失败场景写成测试。

## 被问到时

- **为什么不用经典 ReAct 的 Thought**：课程要求不展示、不保存隐藏推理。排查和审计靠可见的 Action 和 Observation。
- **ReAct 和 extended thinking 有什么区别**：一句话：extended thinking 是“想清楚再说”，ReAct 是“去查了再说”。
  - ReAct 是循环的模式：跨多次模型调用，中间由代码执行工具，Observation 带回外部的新事实。它决定 Agent 能知道什么，由代码或 SDK 控制（循环、`max_turns`）。
  - Extended thinking 是模型的能力：在一次调用内部先推理再回答，只用上下文里已有的信息，不带来新事实。它决定模型把已知信息用得多好，由 API 参数控制（思考预算）。
  - 两者叠加，不冲突：思考可以发生在每轮的“决定”里，新模型还能在工具调用之间思考。原论文里写出来的 Thought，现在很大程度上变成了模型内部的思考。
  - 和课程规则的关系：开了 thinking，API 会返回 thinking 块。我们不展示也不保存它：`Printer.feed()` 只把工具调用、工具结果和模型的回复文字写进 Trace，thinking 块直接跳过。
- **Agent SDK 和 Claude Code 什么关系**：SDK 把 Claude Code 打包成库，所以有同样的 hooks、权限和 session。本课讲的是设计思想，不是 Claude Code 的用法。
- **为什么 agent.py 里 allowed_tools 了 issue_refund，还会被拦**：`allowed_tools` 只是自动批准。PreToolUse hook 在它之前运行。
- **hook 能不能代替工具内部检查**：不能。hook 配错或被绕过时，工具内部检查是最后一道线。第 44 页的测试演示的就是这点。
- **第 44 页是说模型真的会这样做吗**：不是。调用是伪造的，证明的是代码挡得住，不是模型一定会犯错。
- **幂等键谁来生成**：写操作最好由代码按业务生成。demo 里为了简单写在任务描述中，生产环境不要让模型随便编。
- **什么时候用 can_use_tool，什么时候用 hook**：`can_use_tool` 只在规则判定为“要询问”时触发，`allowed_tools` 放行的调用不经过它。要把关每次调用，用 PreToolUse hook。
- **resume 怎么用**：课上不演示。课后可以先跑一个场景，再跑 `uv run python agent.py --resume`，看它不调工具也答得出金额。
- **想看真实模型面对注入文字**：`uv run python agent.py --order A9216`。这条还没有实测，见 `QA.md`。
- **Google 的设计模式和这门课什么关系**：同一批概念，换了分类方式。那份指南也建议从单个 Agent 开始。只讲三个用到的模式，其余的 W8 再讲。
- **框架信息会过期吗**：会。本课按 2026-11 的文档和版本，见 `SOURCE_MAP.md`。
