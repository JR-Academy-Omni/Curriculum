# L02 讲师流程 · Video Streaming

Lightman · 120 分钟（含 10 分钟休息）

## 开课准备

- 打开 P03 和 P12，检查 Auto / 720p / 360p。确认 720p 实际解码 1280×720，360p 为 640×360。
- 下载并解开课件中的 FFmpeg 练习包。检查本地 FFmpeg 有 libx264；用 Bash 跑脚本。FFplay 可作为第二播放路径。
- 浏览器 Network 面板准备关注 m3u8 和 ts。用于讲画质切换的限制建议先设下载 750 kbps，延迟与上行分别记录。

| 时间 | 讲师行动 | 学员行动与证据 |
|---|---|---|
| 00–15 · P01–P03 | 先用 P02 复习 L01 的 5 步和本节新组件。再播放两档完成品，核对显示尺寸，指出它们是同一内容。 | 写下首次有画面与画质切换各如何验证。 |
| 15–45 · P04–P09 | 打开主列表和媒体列表。逐个说清转码、分片、CDN 缓存与 ABR。对照全员实时和 WebRTC 舞台加 HLS 观众的两个拓扑。用 P09 讲观看人数、弹幕和打赏各要多「准」，再用 P10 计算器现场改人数、码率和命中率。 | 标出主播上行、实时嘉宾链路、观看分发与回源。做一次出口估算。 |
| 45–55 · P11 | 用脚本生成两档 HLS，投屏查看 master、两个 index 与同序号片段。 | 用 ffprobe 核对两档分辨率，解释 24 fps、48 帧和 2 秒的关系。 |
| 55–65 · P12 | 播 720p，展示实际尺寸和片段。限速后切回 Auto 并重新播放，观察实际请求、缓冲和画质。 | 记录一条切片请求和当前解码尺寸。清掉限速后回看差异。 |
| 65–75 | 休息。 | 各组保留主列表或截图。 |
| 75–105 · P13–P14 | 发工作单，追加主播断线 8 秒。要求分别说嘉宾和观众会看到什么。 | 画两条媒体路径、算万人出口，给出一个恢复信号。 |
| 105–120 · P15–P16 | 比对两组拓扑和估算，复盘首帧、卡顿和直播延迟测量点。 | 在图上标出一个扩容瓶颈和一个应按地域分组的指标。 |

## 讲师参考与恢复

- 课堂 HLS 播放器的 36 秒素材由 FFmpeg 同一输入实际编码，使用可重播的 VOD 清单。一万观众和流量数字是设计负载。练习脚本的 --live 模式可跑 60 秒，另开窗口用 FFplay 或 local HTTP 读取滚动清单。
- 自适应需根据新下载和缓冲判断，降档并不必然发生在当前片段。若台上来不及重现，可固定切换 720p 与 360p，并用实际片段和尺寸证明可切换，再说明 Auto 的判断条件。
- 带宽参考为 0.4 × 3 + 0.6 × 1 = 1.8 Mb/s；10,000 人约 18 Gb/s 观众侧出口。回源估算需要缓存模型。
- FFmpeg 实操若打开空目录，检查目录生成权限和 master 路径；重跑时选择新的空输出目录。直播开始后等几个片段再开 FFplay。
- 阅读 [FFmpeg HLS muxer](https://ffmpeg.org/ffmpeg-formats.html) 与 [Amazon IVS 实时舞台接入直播频道](https://docs.aws.amazon.com/ivs/latest/RealTimeUserGuide/web-publish-subscribe.html)。
