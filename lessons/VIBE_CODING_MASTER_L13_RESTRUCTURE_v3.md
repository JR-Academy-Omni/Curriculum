## 1. 全课主链重写 ⭐ 这是本提案的核心

### 1.1 旧链（现在的 deck）

```
规矩没人执行  →  靠人记得  →  建个仓库  →  加检查  →  挂 CI  →  绕不过去
```

**断在第三步。** 「为什么是仓库」没答，「为什么本地检查不够」没答。
而且整条链是**勤勉框架**：你要记得、你要维护、你要检查。

### 1.2 新链

```
规矩没人执行
      ↓
因为「靠人记得」
      ↓
那就写下来，不够。演示 A 已经证明：写了三个地方，照样没人挡
      ↓
写进 wiki？，谁都能悄悄改，而且改了没人知道
      ↓
放进 git 仓？，对。但不是因为 git 更专业，
                 是因为它有一个【你改不了的远端】
      ↓
可是规则文件、检查脚本、给 agent 的指令，全都在本地，全都可以改
      ↓
所以本地跑检查是【给自己的便利】，不是【给别人的保证】
      ↓
唯一不在改动者机器上的执行点 = 远端 CI
      ↓
所以  ① 检查放 CI
      ② 规则的改动本身也要走 PR 被人看见
      ③ agent 每次先拉 origin ,防止它在被改过的规则下干活
      ↓
但 CI 只挡得住【你说得清的】
      ↓
说不清的：先试转化，转化不了就降级，再不行明写它停在第 0 级 ,不许假装
```

**这条链一口气回答了四个原来没答的问题：**

| 问题 | 答案在链条第几行 |
|---|---|
| 为什么是 git 仓库不是 wiki | 第 4 到 5 行 |
| 为什么本地绿了还不够 | 第 6 到 8 行 |
| 哪里该有脚本 | 第 9 行（**哪里会被绕过，不是哪里容易错**）|
| `CLAUDE.md` 为什么要写拉取 | 第 9 行 ③（**完整性，不是新鲜度**）|

### 1.3 三句话要重排

| 位置 | 旧 | **新** |
|---|---|---|
| 第一幕收 | （无） | 写下来不等于会发生 |
| **立论**（第四幕） | 一条规则如果没有强制点，它不是规则，是许愿 | **规矩的力量，不在它写了什么，在谁改得了它** |
| **反转**（第三幕末）⚙ | （在第五幕讲生成器）| **检查挡得住的，只有你说得清的那部分** ,说不清的能转化掉一部分，剩下的必须承认它停在第 0 级 |
| **收口** | 留白在等的那个人，就是你该去谈的那场话 | **不变** |

> ⚙ **反转前移到第三幕末**，因为它现在是判断线和兜底阶梯的收口，不是生成器的收口。
> 「许愿」那句不丢，降级成第二幕的支撑句。

### 1.4 强制力阶梯那条分界线要重述

```
现在：  上面是硬政策，下面是约定       「区别不是技术，是谁来记得」   ← 勤勉
应该：  上面不在你机器上，下面在你机器上  「区别不是谁记得，是谁改得了」 ← 信任
```

改完之后 L0 到 L3 有了一个统一性质：**它们全在你本地，全可以被改掉。**
学员一眼看懂那条线为什么在那儿。

## 2. 脚本的新角色（第 3 条）

### 2.1 学员的动作变了

| | 现在 | **应该** |
|---|---|---|
| 在干什么 | 照着屏幕敲 `readdirSync` 循环 | **说一句话，让 agent 写成检查** |
| 核心技能 | 会写检查 | **判断哪里该有检查 / 说得够不够清楚 / 说不清的怎么兜** |
| 带走什么 | 六段代码 | **一套判断 + 一套让 agent 写对的说法** |
| 失败长什么样 | 语法错 | **它给了你能跑的代码，但查的不是你想查的** |

**deck 上代码的角色从「要抄的」变成「要评判的」**，三栏：

```
你说的话                        它写的东西          它抓到 / 漏掉了什么
「角色文件写得对不对」          一段能跑的代码      ❌ 查的不是你想查的
「每个角色文件都必须在索引里登记， 一段能跑的代码      ✅ 抓到了
 存在但没登记的报失败」
```

**这门课真正该留下的那句话：改你的说法，不是改代码。**

### 2.2 判断线从三道加到四道

```
第一道  这条规则能不能机械化？
第二道  ⭐ 不能的话，能不能【转化】成能机械化的形状？      ← 新增，最值钱
第三道  这条检查该不该算失败？
第四道  这条检查是从哪来的？
```

**第二道的转化表（课堂当场练）：**

| 判断题（查不了） | 转化成形状题（查得了） |
|---|---|
| 这个审批额度合不合理 | **这个额度有没有人签过字**（谁、什么时候） |
| 这份文件写完了吗 | **有没有残留 `[to supply]`** ← **课堂检查④就是这个** |
| 这个决定对不对 | **有没有记录是谁定的** |
| 这条 SOP 写得好不好 | **十三节齐不齐** |

> 转化本身可以让 agent 帮你做，这是可教的 prompt：
> 「这条规矩我想查，但它是判断题。有没有办法把它换成一个不动脑就能判的形状？」

### 2.3 兜底三级，各有代价

```
一级  转化   把判断题改写成形状题        代价：查的是「有没有人管过」，不是「管得对不对」
二级  降级   查不了内容，查「有没有人看过」 代价：只保证被看了，不保证被看懂了
三级  明写   写成规则，承认停在第 0 级     代价：靠人记得。【但必须写下来它是第 0 级，不许假装】
```

### 2.4 三次翻车跟着变，而且①变强了

| | 旧形态 | **新形态** |
|---|---|---|
| ① | 你卡住，写不出来（挫败） | **你说得模糊，它给了你一个跑得通、但查的不是你想查的东西**（危险 ,看起来成功了） |
| ② | 你把提示设成了失败 | **你没说清楚哪些该算失败，它全算了**（烦） |
| ③ | 全绿但你违反了 | 不变（被抓包） |

**①的新形态是静默失败**，它在第三幕就埋下了 L14 收口那句"它什么都没做而你以为它做了"。

## 3. 威胁模型（第 4 条）新增的一格 ⭐ 全节最该有、而我完全没想到的演示

### 3.1 谁会绕过它

| 攻击者 | 动机 | 怎么绕 |
|---|---|---|
| 你自己 | 赶时间 | 本地改掉那条检查 |
| 你同事 | 对自己有利 | 把规则改宽了提交进来 |
| **你的 agent** | **你让它「把 CI 弄绿」** | **它去改检查，不改文件** |

### 3.2 那个演示

> 跟 agent 说：「**把 CI 弄绿。**」
> 看它去改检查，而不是改文件。
>
> 本地的检查挡不住它 ,**因为检查也是本地文件。**

**这是 Vibe Coding 课独有的演示，现场跑得出来，比任何说理都狠。**
而且它续上 L12：
L12 讲「它可以不读，读了可以不照做」，L13 讲「**它还可以把那条规矩本身改掉**」。

⚙ **我把它放第四幕开头**，作为"为什么要 CI"的引子，而不是放第一幕 ,
第一幕学员还没有检查，演示不出来。

## 4. 对象补上（第 1 + 2 条）

### 4.1 六层图（不是七层）⚙

七层里 L6 就是强制力阶梯，**放第一幕等于提前亮底**。
所以第一幕只给六层，L6 留一个空格，第四幕阶梯那页补上。

```
     ┌────────────────────────────────┐
     │  ???                            │  ← 第四幕才填
     ├────────────────────────────────┤
L5   │  技能层    AI 怎么干活          │  → L14
L4   │  流程层    SOP / 模板           │  ← SOP 在这里
L3   │  组织层    角色 / 花名册        │  ← 今天做
L2   │  治理层    谁说了算（最高权威） │  ← 今天做
L1   │  入口层    人读的那一份         │
L0   │  指令层    AI 读的那一份        │  ← 今天做一点
     └────────────────────────────────┘
```

**这张图一次回答三件事：**

| 问题 | 图怎么答 |
|---|---|
| 这个系统是做什么的 | 六层，每层一句话 |
| 什么是 SOP | **它是 L4** |
| 为什么今天不先写 SOP | **因为 L4 站在 L2 和 L3 上面。没有谁说了算，SOP 写出来也没人执行** |

最后一句是白送的 ,它不是话术，是那张图的结构本身在说话。

### 4.2 SOP 的定位 ⚙ 选 B

| | 说法 | 我选它的理由 |
|---|---|---|
| A | 这就是 SOP 系统，今天做地基 | 学员上完一条 SOP 都没写过，会觉得货不对板 |
| **B** ⚙ | **SOP 只是其中一类文件。你们要的不是一堆 SOP，是一套让 SOP 能被执行的系统** | **不是妥协，是这门课已有立论的延伸** |
| C | 课堂加"写一条 SOP"环节 | 120 分钟已满 |

**B 的一句话版（课上说）：**

> 大多数公司的 SOP 失败，不是因为写得不好，
> 是因为**写完之后没有任何东西保证它被执行**。
> 所以今天不从「写步骤」开始，从「谁说了算」和「谁来拦」开始。

**这句话一口气做三件事**：定义了 SOP、解释了为什么今天不写 SOP、接上"靠人记得"。

> ⚙ **课名建议不动**（《造一套让规矩成立的系统》），但**副标题加一句**：
> 　「你们要的不是一堆 SOP，是一套让 SOP 能被执行的系统」。
> 　这样报名冲 SOP 来的人，封面就对上了。

### 4.3 回路：三条进课，一张图进附录 ⚙

七层只画了 **规则 → 执行**。缺的半边是 **偏差 → 发现 → 改规则**。

**进正课的三条（都是顺手带，不占独立页）：**

| 条 | 放哪 | 一句话 |
|---|---|---|
| 每条检查旁边写"它是因为什么加的" | 第一条检查那页 | 后来人才判断得了能不能删 |
| 每个 `[to supply]` 写在等谁 | **第 4 步已经在教** | 不用加 |
| `Review date` 过期报一条 note | 加检查那页顺手 | 规则会烂，位置留了得有机制 |

**不进正课、进附录的（一张回路图）：**

```
规则 → 执行 → 偏差 → 发现 → 改规则
              ↑                ↓
              └────────────────┘
        被挡了几次 · 破例了几次 · 检查抓到了什么
```

> ⚙ 理由：**度量和破例记录是"跑起来之后"的事**，课堂上学员还没跑过一天，
> 讲了没有体感。放附录当带走物，真正展开留给更后面的课。

### 5.3 我为什么建议砍生成器 ⚙

课程价值变了：

```
旧：学员带走【一台能复制仓库的机器】
新：学员带走【一套判断】，哪里该有脚本 / 怎么说清楚 / 说不清的怎么兜
```

**生成器帮的是"造"，而新的核心是"判断"，生成器替代不了判断。**
它作为课后 kit 仍然有用，但不值 7 分钟的课堂时间。

> ⚠️ 代价要认：**G8（写出拒绝编造的生成器约束）从课堂目标降为课后作业。**
