## 24′ 经典多 Agent 架构
- 快速过。目的是让学员认得这些名字，面试被问到能接上。
- BDI：Rao 和 Georgeff 在 1990 年代形式化，来自 Bratman 的意图理论。要点：LLM Agent 的“信念”就是上下文里的工具结果，会过期，要写进 state、能追来源。
- Contract Net：Reid G. Smith，1980 年。今天的 roster 是固定的，所以不需要投标。
- Blackboard：CMU 在 1970 年代的 Hearsay-II 语音理解系统。
- 时间紧只读底下那句。

## 52′ 派活契约：W7 的交接单，反过来用
- 先回扣 W7：交接单是 Agent 停下以后交给人的；派活契约是协调者交给子 Agent 的。方向相反，标准一样：接手的一方不用回头问。
- 左表逐行读：W7 的字段在派活时变成什么。context 那行要强调：只给 ID，让子 Agent 自己读原件，不贴内容。每转述一次就可能走样，也多一份 token。
- 子 Agent 的回报本身就是一张小交接单：做了什么（draft_id）、没做成什么（NOT COVERED）、为什么（错误原文）、依据（observation ids）。
- 最后一行“W7 没有的”：工具、期限不写在消息里，写在 Agent 配置和我们的代码里，靠系统保证，不靠子 Agent 自觉。
- 💬 先读黄条那条差的派活，问学员缺了什么（30 秒）：缺班次、不知道“处理”是写还是查、不知道回报格式、不知道失败了怎么报。
- 右边是 prompts.py 里要求协调者写的格式，原文是英文。
