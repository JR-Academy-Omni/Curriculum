# AI Engineer 补充课 PRD 与课程大纲

## 1. 文档状态与课程定位

- 日期：2026-11-01；版本：v1.0。
- 课程名称：**从 AI Coding 到应用跑通：前端、API、后端与 AWS**。
- 归属：AI Engineer 工程基础衔接补充课。
- 时长：210 分钟，含 10 分钟休息。
- 当前交付：本地已完成 62 页 HTML 课件、配套资料与 HTTP 实操；浏览器证据和边界见 QA.md。未录制或部署。
- 排课建议：本期 W4 后、下一次依赖完整应用链路的实践前补课；后续新一期可放在首次完整项目实践前。具体日期、讲师与课程编号待排课，不改变现有 W4 标识、周次或后续课表。

## 2. 背景与问题

Owner 反馈：W4 中多名学员因前端、后端、Cloud 基础不完整而受阻。多数是在职人员，可能熟悉前端、后端或 DevOps 中的一部分，不能假定每个人都有全栈经验。多数代码可以借助 AI Coding 完成，因此本课应重点建立组件职责、API、数据流、运行环境与排障认知，减少语法和逐行代码讲解。

已查阅的本地课源：

- `curriculum/lessons/ai-engineer-cohort-07-practice-w4/PRD.md`：W4 沿用既有 CareKind 项目完成手工护理记录、审核与确认流程。
- `curriculum/lessons/ai-engineer-cohort-07-practice-w4/RUNSHEET.md`：W4 以继续开发和逐组排障为主，明确不重新讲架构与 W3 全套概念。

以上是课程设计背景，不代表已经逐组诊断出全部故障原因。实际卡点在课前收集，不能编造反馈人数、通过率或学习成效。

## 5. 范围与深度

### 必须亲手操作

- 在浏览器 Network 查看请求地址、方法、headers、输入、状态码和响应正文。
- 用一种接口工具独立验证同一 API；全班统一工具，避免同时教学多套工具。
- 保存并重新读取完整记录，检查失败反馈。
- 阅读脱敏后端日志，并与对应请求关联。
- 根据证据形成 AI Coding 修复指令，验证修复后的完整流程。

### 必须理解，课堂以演示为主

- 前端／后端的运行边界，API Contract，用户身份与业务权限。
- 网络地址、DNS、HTTPS、端口、CORS、本地与云端配置。
- AWS 资源地图、网络与 IAM，构建／运行／发布／回滚，Docker 基础。
- 外部 AI 调用的超时、限流、流式响应、重试与重复调用成本。

### 只需建立认识

- EC2、ECS/Fargate、Lambda 的不同计算模型。
- RDS 与 DynamoDB 的基本适用区别。
- ALB 与 API Gateway 的不同入口职责。

不要求一节课内独立搭建整套 AWS；不深入 React 生命周期、后端框架源码、SQL 优化、Kubernetes、复杂 Terraform、多区域高可用或 AWS 考证知识。RAG、Agent 算法仍由原课程承担。

## 6. 贯穿案例与完整成果要求

### 6.1 业务主线

沿用 CareKind：打开对象与任务 → 填写护理记录 → 提交保存 → 查看完整详情 → 刷新后重新打开。审核与确认作为既有 W4 业务权限的衔接展示，不在补课中另造业务功能。

开场先从正式产品组件打开一条完整护理记录，再演示保存与读取，最后拆解请求路径。不得只展示架构图、封面、成功提示或空仪表盘。

### 6.2 备课时需要准备的内容

- 同一产品内可操作的完整记录、列表与详情入口，以及与记录一致的输入材料。
- 一份实际项目 API Contract：请求、成功响应、参数失败与权限失败；路径和字段从代码核实，不能把教学设计中的名称当成现有接口。
- 本地架构图、AWS 架构图、正常请求证据和可恢复故障版本。
- 记录正文应包含上下文、活动、具体观察、处理与后续事项；不得用于真实护理决策。

使用隔离教学数据，数据来源、人工编写方式、非真实患者／学员成果属性写入内部材料。用户页面不放“示例／虚构／模拟”等标签或开发验收提示；场景通过课程和练习任务表达，不能冒充真实业务记录。不得接触真实护理资料、真实账号业务数据或产生真实发送、报名、支付等副作用。

### 6.3 Demo 当前状态

本课运行成果入口为 http://127.0.0.1:8047/ ，默认展示完整晨间记录；可创建并重读记录。数据源为 lab/server.py 的 SEED 与当前会话 SQLite 数据。课程练习已完成本地运行验收；未验证真实学员项目或任何 AWS 部署。证据见 QA.md 与 out/qa/。

## 8. API 模块详细教学范围（45 分钟）

| 子段 | 分钟 | 内容 |
|---|---|---|
| API 与合约 | 7 | 页面操作与接口并非一一对应；应用内部 API 与第三方 API；合约约定输入、输出、权限和失败 |
| 读取请求 | 10 | URL、GET/POST/PATCH/DELETE 的基本意图；path/query/body 的区别；headers、Content-Type、JSON；以项目实际方法为准 |
| 读取响应 | 8 | 状态码与响应正文一起判断；2xx、400、401、403、404、429、5xx；业务错误可能随项目约定表达，不能只看颜色或“200” |
| 对接与安全边界 | 8 | 名称、类型、必填、ID、日期时区、空值、分页；用户 token 与服务端 key 的区别；浏览器校验不能代替后端校验 |
| 实际验证 | 12 | Network 与接口工具发起同一操作；对照请求和返回；接口工具成功不能证明浏览器 CORS 或 cookie 行为正常 |

补充阅读：异步调用、timeout、SSE 流式响应、rate limit、retry、幂等。课堂只建立判断框架：不要无限重试；非幂等写入需要防重复；流式结果中断不代表后端未执行。

## 9. AWS 模块详细教学范围（40 分钟）

### 9.1 单一主线拓扑

以下为教学设计，不能宣称是现有 CareKind 已部署架构：浏览器 → Route 53 域名解析 → HTTPS 请求到 ALB（ACM 证书）→ ECS/Fargate 后端 → RDS。S3 表示独立文件存储；后端按需访问外部 AI 服务。IAM、Secrets Manager、CloudWatch 是支撑关系，不画成每次业务请求都依次经过的节点。

这是后端链路教学图；前端构建产物的托管方式在备课时依实际项目补齐。静态前端可用 S3 与 CloudFront 说明，SSR 应用需运行计算环境，不能把所有前端都讲成上传静态文件。若既有项目采用其他方式，应替换主线图并保持同一套可验证拓扑，不要求迁移项目。

### 9.2 服务与掌握深度

| 子段 | 分钟 | 必讲内容 | 延伸速查 |
|---|---|---|---|
| 找到运行位置 | 4 | Account、Region、AZ；核对账号与区域，避免“资源不见了” | 资源标签 |
| 计算与请求入口 | 8 | 主线 ECS/Fargate 与 ALB；理解容器运行与请求转发 | EC2 虚拟机、Lambda 函数、API Gateway；不要求共同使用 |
| 网络与域名 | 8 | VPC、Subnet、Security Group、公网／私网、端口、Route 53、ACM；DNS 解析不是代理转发 | CloudFront 与 CDN；私网外部访问需要明确出口设计 |
| 数据与文件 | 5 | RDS 与 S3；数据库访问边界；容器临时文件不能替代持久化 | DynamoDB；备份与恢复的作用 |
| 权限与配置 | 7 | IAM Role/Policy、临时凭据、最小权限、Secrets Manager；业务用户角色与 AWS IAM 角色不同 | 参数配置与秘密配置的区别 |
| 日志与费用 | 8 | CloudWatch 日志／指标；关联请求、服务与环境；预算告警及资源清理；计算、存储、流量、ALB/NAT 等可能持续产生费用 | Cost Explorer；不承诺免费或报固定费用 |

### 9.3 演示方式与资源边界

准备经过脱敏的资源图和日志片段；如使用控制台，只在已授权的教学环境执行只读查看。先展示正常请求，再展示网络不可达、IAM 拒绝和应用报错三类证据的差异，不将 CORS、网络防火墙和身份权限混为一谈。

本次文档任务不创建 AWS 资源，不开通服务，不读写凭据，不部署，不调用付费模型。未来如需真实云端实践，另行确认账号、区域、资源、预算、权限、清理责任及执行范围。AWS Budgets 通知可能延迟，不能作为费用硬上限。

## 10. 跨岗位练习与故障库

### 10.1 个人操作重点

- 前端背景：独立验证 API，跟踪后端处理与数据重读。
- 后端背景：从浏览器发起操作，解释 Network、loading 与错误反馈。
- DevOps 背景：追踪业务输入、校验、数据读写和页面结果。
- 各背景都必须说明完整链路，不能长期只负责熟悉的一层。

### 10.2 故障库与诊断范围

| 故障 | 主要观察证据 | 预期定位 |
|---|---|---|
| 页面未发出请求 | Network 无相应请求，检查页面操作与前端错误 | 前端触发路径 |
| 输入字段不符合合约 | 请求 body、错误正文及后端校验日志 | API Contract／输入 |
| 身份或权限失败 | 401/403 与项目实际错误信息 | 身份验证或业务授权 |
| API 地址配置错误 | 实际请求目标与预期环境对照 | 配置／地址 |
| 浏览器跨域受阻 | 浏览器控制台、预检及响应 headers | 浏览器跨域策略 |
| 后端无法连接数据库 | 后端连接错误与网络配置片段 | 服务端依赖／网络 |

实现状态：字段错误、缺少会话、只读角色和错误路径均已实现可切换的真实 HTTP 练习条件；前端无请求、CORS 与数据库网络失败采用诊断讲义，不宣称已注入运行环境。

25 分钟练习采用“讲师示范 5 分钟、个人操作 15 分钟、对照验证 5 分钟”。每人只分配一个故障；其他故障留作可恢复的扩展练习，不能要求当堂完成全部。故障注入限隔离练习环境，不修改真实生产权限或网络规则。

### 10.3 提供给 AI Coding 的修复指令结构

提供操作步骤、预期与实际结果、环境、脱敏请求／响应及日志、已验证事实、允许修改的范围和验收步骤。要求先判断所在层和提出最小修复，再验证正常流程与相关失败路径。不得上传 token、API key、真实患者信息或未授权源码；不允许以关闭校验、开放全部网络或授予管理员权限作为常规修复。

## 12. 开课前与交付验收

### 课后记录

## 13. 风险与取舍

- 内容过多：API 与主线 AWS 拓扑优先，备选服务移至速查，不堆服务清单。
- 技术栈差异：概念统一，课堂演示固定一套，各组项目保留原栈。
- AI 大改导致新故障：以证据限制修改范围，保留可恢复练习版本。
- 环境或云账号受阻：课前准备本地完整链路与脱敏云端材料；如未真实操作云端，验收明确仅完成结构与日志判读。
- 本课与 W4 重复：业务案例复用，重心放在理解链路和独立定位；不再用整堂课自由开发替代讲授。
