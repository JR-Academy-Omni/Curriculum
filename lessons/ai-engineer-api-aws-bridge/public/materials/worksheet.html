Task 0 · Classify the stack

Classify HTML, CSS, JavaScript, React, Node.js, Express or NestJS, Nginx and AWS. Map each item to its responsibility and execution location. Distinguish the frontend build tool from the browser runtime. Explain the page-loading request and a later API request. Map Nginx and the Node.js application as separate processes and show how an API request is proxied.

Task 1 · Trace the application

Open the completed record. Identify the browser, API, backend and persistence layer. Explain where each component runs. Save a new record and reopen it after a reload.

Task 2 · Inspect the API

Capture one POST /api/notes request. Record the method, path, body fields, status, response ID and X-Request-ID. Remove cookies and other credentials from shared evidence.

Task 3 · Verify independently

Use the API request panel. Send GET, then a valid POST, then GET the returned note ID. Compare the result with the record page.

Task 4 · Diagnose one failure

Choose Invalid field name, Missing session, Read-only role or Incorrect API path. Submit once. Record the first failing boundary, evidence and expected correction. Restore Normal request and verify a successful save and reread.

Task 5 · Map to AWS

Map the browser, ALB, ECS/Fargate, RDS and S3. Add DNS, certificate, IAM, secret management, logs and the outbound network path. Separate request flow from supporting services.

Task 6 · Transfer to your project

Identify your actual API contract, data location, runtime environment and current blocker. State which claims you verified and which remain unresolved.

AI Coding repair instruction

Context: [environment and user action]
Expected: [observable result]
Actual: [observed failure]
Evidence: [redacted request, response, timestamp, request ID and logs]
Verified facts: [what was checked]
Allowed scope: [files and configuration]
First explain the failing boundary and propose a minimal fix.
Do not disable authorization or broaden network access as a workaround.
Validate success, relevant failure behavior and persistence reread.

Keep a copy of your evidence in your own course notes. Use the browser print action for a paper worksheet.

Task 7 · Design an AI job workflow

Separate saving a care note from generating a long document. Draw Producer, Message Queue, Worker, Job status and Result store. Define the latency boundary, timeout behavior, bounded retry, idempotency strategy, cache access rules and pressure controls.

Task 8 · Infrastructure as Code

Classify application code, Dockerfile, IaC configuration and CI/CD. Describe which cloud resources an IaC configuration manages. State what must be reviewed before Apply and why a source-code rollback is not a database restore.

Task 9 · Design the delivery pipeline

Draw separate paths for a client-side React build, a Node.js container and IaC. Identify CI checks, verified artifacts, environment-specific configuration, release gates, production readback and rollback. Explain how the same artifact is promoted and how database migration compatibility is protected.

Task 10 · Trace a blocked connection

Map the source, destination, protocol, port and traffic direction for a browser-to-API connection and an API-to-database connection. Distinguish Security Group, WAF, IAM and application authorization. Explain why a timeout alone does not prove a firewall fault.
