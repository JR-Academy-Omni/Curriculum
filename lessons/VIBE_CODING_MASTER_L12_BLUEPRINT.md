# Vibe Coding 大师课 · 第十二节蓝图

> 状态：DRAFT 1.0（2026-09-06）
> 课名：**《Claude Hook》**
> 主题：**把「我跟它说过」变成「它绕不过去」**
> 课型：**96 分钟动手课**（学员在第 20 分钟就亲手挂上第一个 hook 并当场验证；第 40 到 58 分钟看着自己挂的东西咬自己三次）
> 课堂硬产物：**一个学员自己写的、当堂验证过的 hook**（脚本 + settings 配置 + 一次成功拦截的截图），外加一张「我这条规矩为什么挂在这个时点」的判断记录。
> 本文只定义课程。Deck、`RUNSHEET.md` 与 `HANDOUT.md` 必须以本文为唯一事实源生成。

## 0. 立项决定

### 0.1 这一节到底新在哪

前十一节课交给学员的所有产物，有一个共同性质，从来没被点破过：

> **它们全都是「说给它听」的。**

```text
L1   PRD              说给它听
L2   CLAUDE.md        说给它听
L5   Skill            说给它听（只是打包了）
L7   Subagent brief   说给它听
L10  落盘搬空隐藏区    说给它听
L11  七段任务书        说给它听
──────────────────────────────────────
以上全部：它可以不读，读了可以不照做，这次照做了下次可以不照做。
```

第十二节第一次交给学员一个**它不能不照做**的东西。

官方文档把这件事说得比我们更干脆，这句是全节的支点（原文，不许改写）：

> Hooks are user-defined shell commands. Claude Code runs them at specific points in its lifecycle, which gives you **deterministic control: certain actions always happen rather than relying on the LLM to choose to run them.**

**这不是「又一个新功能」。这是把前十一节的全部产物重新定了一次性：那些是请求，这个是规矩。**

### 0.2 全节最重要的一句话（收口立论，不许提前说）

> **hook 挡得住的，只有你说得清的那部分。**
>
> 说不清的那部分，它还在。而且现在你以为它被挡住了。

学员挂上第一个 hook 的那一刻会非常爽 —— 这是本节故意设计的（§0.3）。爽完之后必须马上告诉他代价：

> hook 的力量来自**确定性**，确定性来自它**不动脑**。
>
> 你一让它动脑（prompt hook / agent hook），确定性就还回去了。**能被一个不动脑的脚本判出来的规矩，才挂得上 hook。**

这句话是判断线第③道闸的灵魂，也是本节和 L11 的同构点：L11 说「结果契约要写死三个枚举值，别让它自由发挥」，L12 说的是同一条原理的另一面。

### 0.3 最重要的教学决定：先让它成功，再让它咬人

**L10 和 L11 都用了「先撞墙，再给尺子」。L12 不许再用第三遍。**

学员已经上过两节这样的课了。第三次再让他们在前 30 分钟填表被打回，他们会认出套路，戏剧性归零，而且会开始表演「我答不出来」。

L12 反过来，而且反得有道理 —— **hook 是这个系列里第一个能在 90 秒内跑给人看的东西**。L10 是理论，L11 是判断，L12 有可运行的产物。不用它，是浪费。

```text
0–18 分钟    你说过几遍了 + 老师现场演示「CLAUDE.md 里写着，它照样犯」
18–40 分钟   全班一起挂上第一个 hook，当场故意违反，看它被拦
             ⭐ 全节高光。学员第一次看到「它绕不过去」
40–58 分钟   ⚠️ 你刚挂的那个东西开始咬你，三次，形态不同
58 分钟      判断线第一次出现，台词是「你们刚才被咬的三次，是三个问题」
```

**为什么这个顺序更好：**

1. 学员对 hook 的第一印象是「太爽了，我早该这么干」。这个印象**必须先有**，否则后面的告诫他听不进去 —— 没尝过甜头的人不会认真对待代价。
2. 三次翻车必须是**学员自己挂的那个 hook** 造成的，不是老师演的。自己挂的东西咬自己，教学效果是老师演十次也换不来的。
3. 判断线出现在第 58 分钟，比 L10（32 分）L11（36 分）都晚，因为**前面那 58 分钟学员在动手，不是在听**。晚不等于慢。

### 0.4 第二个教学决定：三次翻车的形态必须不同，且第二次最重要

只翻一次车，学员学到的是「我 hook 写得不够仔细」。必须三次，因为**这三种错的处方完全不同**：

| | 翻车① 拦太宽 | 翻车② 挂错时点 | 翻车③ 脚本自己错了 |
|---|---|---|---|
| 现象 | 它干不了活了，一直被拦 | **拦了个寂寞，事情已经做完了** | 每次工具调用都冒红字 |
| 学员感受 | 烦，但看得见 | **舒服，而且看不见** | 吵，马上就想关掉 |
| 根因 | matcher 太宽 / 判断条件太粗 | 用了 `PostToolUse` 去拦一件该 `PreToolUse` 拦的事 | 退出码用错、扩展名写成 `.js`、配置里忘了 `node` 前缀 |
| 处方 | 收窄 matcher，或降级成提醒 | **换时点**，这是本节最实用的一格 | 排错三板斧（§13.7） |
| 真实后果 | 你会自己把 hook 关掉 = 等于没挂 | **你以为守住了，其实没有** | 你会自己把 hook 关掉 = 等于没挂 |

**翻车②是本节的支点。** 官方文档给了硬依据（原文）：

> `PostToolUse` hooks **can't undo actions since the tool has already executed.**

而且这条在「exit code 2 behavior per event」表里被再说了一遍：`PostToolUse` 的 **Can block? = No**，`What happens on exit 2` = **"Shows stderr to Claude; the tool already ran"**。

**翻车①和③有一个共同结局，必须讲出来：学员回去会把 hook 关掉。** 一个被关掉的 hook 和没挂过，是一回事。所以这两次翻车不是花絮，是「为什么你回去三天后就不用了」的预演。

### 0.5 本节在系列里的位置

```text
L5     Skills       把重复套路打包         —— 它得想起来调用
L6     诊断         它没有记忆，只有 context —— 判据要来自它之外
L7     Subagent     给 context 分家
L8     Team         让成员的发现改变别人的下一步
L9     Legacy       三种债，知识债最贵
L10    四象限       信息在谁那里，决定谁该说什么
L11    无人值守     你不在场时，它凭什么做对
──────────────────────────────────────────────────
L12    Hook         以上所有约定，第一次变成它绕不过去的
```

**L12 结清两笔老账，两笔都要在课上明说：**

| 老账 | 原来的说法 | L12 兑现成什么 |
|---|---|---|
| **L6 铁律** | 「它说完成了不算完成，判据要来自它之外」 | `Stop` hook：**测试不过，它没法说完成**。exit 2 = "Prevents Claude from stopping, continues the conversation"。铁律从**原则**变成**机制** |
| **L6 的病** | context 会被压缩，压缩会丢东西 | `SessionStart` + `compact` matcher：压缩之后自动把关键信息灌回去 |

**和 L11 的接口是明确的一条，必须讲：**

> L11 §8.2 教了三条让它不卡住的做法（提前批 / 取消问 / 全放开），每条都有代价 —— **你放开权限的同时，把该拦的也一起放开了。**
>
> hook 是唯一一个能让「我放开权限」和「但这几件事你永远别碰」**同时成立**的机制。

官方依据（原文）：

> `PreToolUse` hooks fire **before any permission-mode check**, in every permission mode, including `dontAsk`. A hook that returns `permissionDecision: "deny"` blocks the tool **even in `bypassPermissions` mode or with `--dangerously-skip-permissions`**.
>
> The reverse is not true: a hook returning `"allow"` doesn't bypass deny rules from settings... **Hooks can tighten restrictions but not loosen them past what permission rules allow.**

### 0.6 一笔欠了六节课的债（讲师必读）

这节课不是新开的话题，是**系列自己写下的欠条**：

- `VIBE_CODING_MASTER_L5_BLUEPRINT.md:64`（非目标）：「不讲 MCP / **Hooks** / Schedule / Subagent（那些是别的能力层，**放后续**）」
- `VIBE_CODING_MASTER_L6_BLUEPRINT.md:82`（非目标）：「不讲 MCP / **Hooks** / Subagent 的配置细节（**留后续**；子 agent 是 L7）」

四条欠条，Subagent 由 L7 兑现、Schedule 由 L11 兑现，**Hooks 和 MCP 欠到现在**。L8 还把 Hooks 写进了 Team 的扩展路径（`L8:378 → Hooks / MCP / Skills`、`L8:312 Hooks 质量门`），同样没有前置课。

**开场可以用这个（推荐，但讲师自己决定）：** 把 L5 那一行非目标投出来，说一句「这条我欠了你们六节课，今天还」。比任何开场白都有力，而且是真的。

**另有一处必须顺手修的错**：`VIBE_CODING_MASTER_L9_BLUEPRINT.md` 有三处写着「学员已经学过 Skills、Agents、MCP」「不需要预习 Skills / Agents / MCP」。**MCP 至今没有任何一节课讲过，这三处是错的。** 与本节无关，但发现了就该修，别留给下一个人。

### 0.7 必须由讲师确认的东西

**本节的课堂动手依赖学员机器上的三件事，蓝图无法替讲师保证：**

1. `node` 装没装（**本节全部脚本用 Node/.mjs**，不用 bash + `jq`）。
2. 能不能写 `~/.claude/settings.json` 和项目里的 `.claude/settings.json`（公司设备可能锁）。
3. 有没有被管理策略设置（managed settings）接管 —— 组织级配置可能覆盖学员的本地设置。

所以：

- **课前 72 小时发一份三步环境自查**（§2.4），做不出来的人课堂上有兜底路径。
- **硬产物与平台解耦**：判断线、时点二维图、脚本解剖三件事，用不了 Claude Code 的人也学得走、也交得出（退让阶梯见 §8.6）。

讲师课前必须定下来的六件事见 §18 附录 A。

## 1. 课程定位

### 1.1 全节立论

**开场立论（不在第一页说，在第 58 分钟判断线出现时说）：**

> **一条规矩该不该挂成 hook，不取决于它有多重要，取决于「违反了没有」这件事，一个不动脑的脚本判不判得出来。**

**收口立论（见 §0.2）：**

> **hook 挡得住的，只有你说得清的那部分。**

中间全部内容在回答三件事：**这条规矩挂不挂**（判断线）、**挂在哪个时点**（二维图）、**挂在哪个文件**（谁受它管）。

### 1.2 核心框架一：挂哪个时点（二维图）⭐ 全节最实用的一页

**学员最常犯的错不是不会写脚本，是挂错时点。** 这张图必须是全 deck 视觉权重最高的两页之一。

```text
                    它还没动手              它已经动手了
                 ┌────────────────────┬────────────────────┐
                 │                    │                    │
   拦得住        │   PreToolUse       │   ✗ 拦不住         │
                 │   ← 唯一能拦的时点  │   工具已经跑完了    │
                 │                    │                    │
                 ├────────────────────┼────────────────────┤
                 │                    │                    │
   拦不住，      │   SessionStart     │   PostToolUse      │
   只能补 /      │   UserPromptSubmit │   Stop             │
   提醒 / 验收   │   ← 提前把话塞进去  │   ← 事后补救 / 打回  │
                 │                    │                    │
                 └────────────────────┴────────────────────┘
```

**这张图要落到一句判断线，不能只是图：**

> **你怕的是「它做了不该做的」→ 事前拦（`PreToolUse`）。**
> **你怕的是「它漏了该做的」→ 事后补（`PostToolUse` / `Stop`）。**
>
> 这两件事挂反了，都会失败，而且**第一种挂反了你还看不出来**。

**官方依据必须投出来**（`PostToolUse` 那一格为什么是叉）：

> `PostToolUse` hooks **can't undo actions since the tool has already executed.**

**第四格（`Stop`）要单独讲，它是 L6 的兑现：**

> `Stop` 的 exit 2 = **"Prevents Claude from stopping, continues the conversation"**。
>
> 翻译：它说「我做完了」的时候，你的脚本可以说「不，回去接着做」，并且告诉它还差什么。
>
> **L6 那条铁律「它说完成了不算完成」，到这里第一次有了执行机构。**

### 1.3 核心框架二：判断线（四道，有顺序）

**不是四个格子，是一条链。前一道过不了，后面不用问。** 与 L11 的判断闸同构，学员会认出这个形状，这是好事。

```text
              你想让它守的那条规矩
                       │
   ①  这条你已经说过几遍了？ ──── 一遍 ───▶ 先再说一遍。
      （三遍以上才值得挂）                    hook 不是用来代替沟通的
                       │
   ②  它违反的时候，是漏做还是做错？
      ├─ 漏做（该做没做）  ──▶ 事后补：PostToolUse / Stop
      └─ 做错（做了不该做的）──▶ 事前拦：PreToolUse
      ⚠️ 这一格决定时点。挂反了，第二种会静默失败
                       │
   ③  「违反了没有」这件事，一个不动脑的脚本判得出来吗？
      ├─ 判得出（路径匹配 / 字符串包含 / 退出码）──▶ command hook
      ├─ 判不出但能描述  ──▶ prompt / agent hook，但确定性还回去了（§8.5）
      └─ 描述不出        ──▶ 这条规矩今天还挂不了 hook
                       │
   ④  它拦错的时候，你还干得了活吗？ ── 干不了 ──▶ 收窄 matcher，
      （拦太宽 = 你会自己关掉 = 等于没挂）           或降级成「提醒」不「拦」
                       │
                       ▼
            可以挂。剩下的才是：挂在哪个文件（谁受它管）
```

**四道闸和课堂硬产物一一对应**，这是本节结构的骨架：

| 闸 | 学员要交的东西 |
|---|---|
| ① | 一条你说过三遍以上的规矩（原话） |
| ② | 漏做 / 做错的判断 → 定下时点 |
| ③ | 一行「怎么判违反了」的判据（能写成 `if` 的那种） |
| ④ | 一个尽量窄的 matcher + 一句「拦错了会怎样」 |

**闸③是全节的深度所在**，也是收口立论的出处。老师要在这一格停一下，别一带而过。

### 1.4 核心框架三：hook 脚本的解剖（三行机制）

**必须在第 36 到 40 分钟讲，也就是学员刚亲手挂完之后、还没忘记手感的时候。**

```text
   它给你   ──▶  一坨 JSON 进 stdin
                 （哪个事件、哪个工具、什么参数、什么路径、cwd、session_id）

   你给它   ──▶  exit 0   我不表态，走正常权限流程
                 exit 2   拦住。stderr 那句话会变成给它看的反馈
                 JSON     更细的控制（deny / allow / ask，或往 context 里塞话）
```

**这三行就是 hook 的全部。** 剩下的 30 多个事件、五种 type、各种字段，都是这三行的变奏。**deck 上不许出现事件全表**（§4 非目标），只讲怎么查。

完整解剖见 §13，课上只讲这三行，细节留讲义。

### 1.5 老师必须抓住的八个要点

1. **第 20 分钟必须让全班挂上同一个 hook 并跑通。** 这是全节的地基，跑不通后面全塌。兜底见 §6.4。
2. **三次翻车必须用学员自己挂的那个 hook。** 老师演的翻车换不来自己被咬的记忆。
3. **翻车②（`PostToolUse` 拦不住）比另外两次重要十倍。** 时间不够先砍翻车①。
4. **判断线不许在第 58 分钟之前出现。** 提前给判据，前两幕全废。
5. **不要教 30 个事件。** 讲三行机制 + 二维图 + 怎么查文档。讲多了就成了 API 课。
6. **「挂在哪个文件 = 谁受它管」那一格必须落到团队。** 项目级 `.claude/settings.json` 能提交进仓库，克隆的人自动受管 —— 这是本节最值钱的一格。
7. **反转页（§8.4 hook 挡得住的只有你说得清的）是全节收口，前面只埋不点。**
8. **收口必须是一个跑通了的 hook，不是一句总结。** Exit ticket 收实物（截图或配置）。

### 1.6 最容易出错的五类地方

| 类型 | 容易错在哪里 | 当场纠正 |
|---|---|---|
| 定位 | 讲成 hooks API 参考课（逐个念事件和字段） | 「30 多个事件你今天一个都不用背，你要会的是三行机制和怎么查」 |
| 节奏 | 判断线提前上屏，后面全在解释它 | §10.1 铁律第 1 条，P09 之前不许出现任何四步图 |
| 深度 | 只演「拦住了」，不演「拦太宽」和「拦不住」 | §0.4，三次翻车缺一不可，②不许砍 |
| 混淆 | 把「漏做」和「做错」混成一件事，全挂 `PostToolUse` | 二维图那一页必须停够 4 分钟，逼学员当场判自己那条属于哪种 |
| 落地 | 收上来一堆配置，没一个跑通过 | 硬产物是**验证过**的 hook，Exit ticket 要拦截成功的证据 |

## 2. 学员起点与课堂门槛

### 2.1 学员应已具备

- 完成 L1 到 L11。尤其 **L2**（CLAUDE.md）、**L6**（判据要来自它之外）、**L11**（权限那三条做法及其代价）。这三节是本节立论的地基。
- 手上有一个自己的真实项目，**能在课堂上打开、能跑起来最好，跑不起来也行**。
- 能编辑 JSON 文件、会用一个文本编辑器。
- **不要求会写 shell。** 课堂第一个 hook 是抄的（§6.2），学员自己那个只要求写出**判据的那一行**，完整脚本是作业（§16）。

### 2.2 课前必须带来的东西（入场券）

> **一条你已经跟它说过三遍以上、它还是会犯的规矩。原话带来。**

三条硬要求：

1. **必须是你真说过的**，不是「我觉得应该有这条规矩」。假想的规矩过不了闸①，也写不出判据。
2. **说得出它违反的时候现场长什么样。** 说不出的直接卡在闸③，那正好是教学素材，每班需要两三个这样的例子。
3. **别挑「代码质量好不好」这类。** 第一条规矩必须是机器判得出来的（路径、命令、文件名、退出码）。想守的主观规矩留到 §8.5 和作业。

**好例子（学员真会说的话）：**

- 「别动 `.env`」
- 「提交前跑测试」
- 「用 bun 不要用 npm」
- 「改完 TypeScript 记得跑一下类型检查」
- 「别直接推 main」
- 「别碰 `package-lock.json`」
- 「写完给我格式化一下」

**坏例子（当场退回，并说清为什么）：**

- 「代码写好看点」← 闸③过不了，机器判不出
- 「多想想边界情况」← 同上
- 「别自作主张」← 没有可判据的形态

## 3. 学习目标

课程结束后，学员能够：

1. 说清本节和前十一节的差别：**前十一节交给你的都是「说给它听」的东西，本节第一次给你一个它绕不过去的**，并说出 CLAUDE.md / Skill / 任务书 各自属于哪一类。
2. 说出 hook 的**三行机制**：stdin 收 JSON、exit 0 不表态、exit 2 拦住且 stderr 变成给它的反馈。
3. 用**时点二维图**判断自己那条规矩该挂 `PreToolUse` 还是 `PostToolUse`，并说出**挂反了会怎样**。
4. 说清 **`PostToolUse` 拦不住**，以及为什么（工具已经执行了），并说出这种失败为什么是静默的。
5. 用**四道判断线**过一遍自己那条规矩，说出自己挂在第几道。
6. 说出闸③的原理：**hook 的确定性来自它不动脑**，因此说不清的规矩挂不上 hook。
7. **亲手挂上并验证一个 hook**：写配置、写判据、故意违反一次、看到它被拦。
8. 说出 hook 的**五个存放位置**各自管谁、能不能共享，并说出「项目级 `.claude/settings.json` 能提交进仓库」在团队里意味着什么。
9. 说出 **`PreToolUse` 在所有权限模式之前触发**，`deny` 连 `--dangerously-skip-permissions` 都压得过；以及反过来 **hook 只能收紧不能放宽**。
10. 说出 hook 咬人的三种形态（拦太宽 / 挂错时点 / 脚本自己错），并说出前两种的处方。
11. 说出 **`Stop` hook 是 L6 铁律的执行机构**：测试不过它没法说完成。
12. 说出 `prompt` / `agent` hook 存在的理由**和它们的代价**：需要动脑的判断可以交给模型，但确定性还回去了。
13. 写出一条**尽量窄的 matcher**，并说出「宽了会怎样」。
14. 说出在用不了 Claude Code 的环境下，同一条规矩该退到哪一档（git hook / CI / 人工 review），以及每退一步失去什么（§8.6）。
15. 说出 **hook 是一段自动执行的 shell**，因此「挂 hook」和「往仓库里放一段会自动跑的代码」是同一件事。

### 3.1 过关证据（全部落在产物形态，不落在标准答案）

学员离场前必须交出（针对自己那条真实的规矩）：

1. **一张过闸记录**：四道闸逐条的答案，以及自己挂在第几道。
2. **一句时点判断**：我这条是「漏做」还是「做错」，所以挂 `___`，因为 `___`。
3. **一个跑通了的 hook**：配置 + 判据那一行 + **一次成功拦截的证据**（截图 / 终端粘贴都行）。
4. **一句 matcher 说明**：我为什么用这个 matcher，宽了会怎样。
5. **一句位置选择**：我挂在哪个文件、因此谁受它管。

**第 3 项是本节的硬产物，且必须是「验证过」的。** 一份没跑过的配置不算数 —— 本节和前面几节最大的不同就是它有可运行的产物，不用这一点就浪费了。

**助教巡场只查三件事**（其余不管）：

1. **有没有真的触发过一次。** 没触发过的，当场让他触发。
2. **时点对不对。** 拿 `PostToolUse` 去拦「别改 .env」的，当场退回换 `PreToolUse`。
3. **matcher 是不是空的或 `.*`。** 是的话退回收窄，并让他说一句「宽了会怎样」。

### 5.3 演示 A：CLAUDE.md 里写着，它照样犯（4 到 14 分钟）

**形态：老师打开自己项目的 CLAUDE.md，指出其中一条规矩，然后让 Agent 做一件会违反它的事。**

学员预期：写在 CLAUDE.md 里的东西它应该会遵守。

实际发生：它违反了。或者它这次遵守了、老师换个说法它就违反了。

**老师这时候只说一句，然后停三秒：**

> 这条规矩在这个文件里躺了三个月。它每次会话都读到。
>
> **读到，不等于照做。**

**必须现场坐实，不许用截图。** 打开文件让大家看见规矩确实写在那儿，再看见它确实没照做。

> **原理（讲师必须讲出来，这是本节的机制层）：** CLAUDE.md 的内容是**进到 context 里的文字**。它和你说的话、和它读到的代码，在它眼里是同一种东西 —— **都是可以被权衡的信息**。它没有一个「必须遵守」的分区。
>
> **讲师注意分寸：** 「它一定会违反」是行为预期，不是保证。所以 §5.4 的降级必须准备好，别在课堂上把它说成「它每次都这样」。

### 5.4 兜底（演示 A 必须有降级路径）

| 级别 | 情况 | 做法 |
|---|---|---|
| 一级 | 它这次老实遵守了 | 承认：「今天它守规矩。」然后放**预录** —— 预录是必备物料，不是备份 |
| 二级 | 断网 / 工具故障 | 直接放预录 |
| 三级 | 投屏挂了 | 口述 + 直接进第二幕。**第二幕不许砍，演示 A 可以砍** |

> **课前准备的关键一句（§17）：** 演示 A 课前要跑通至少一次，**目的是确认它会违反，不是确认它会遵守**。如果课前那次它老实了，换一条规矩，直到找到一条它会违反的。

### 6.2 全班一起挂同一个 hook（16 到 30 分钟）🎯

**全班挂同一个，不许各挂各的。** 各挂各的会有一半人卡在自己的特殊情况上，这十分钟就废了。学员自己那条规矩留到第五幕。

**课堂统一用官方文档的「保护文件」例子**（§12 例 A-1）。理由：它是官方文档里现成的、可验证的、每个人都能触发的。

三步，老师投屏带着做：

```text
第一步  建脚本  .claude/hooks/protect-files.mjs   （Node，不用 chmod）
第二步  挂上去  .claude/settings.json 里加 PreToolUse
第三步  验证    /hooks 看得到它
```

脚本正文（**Node 版，本课写法**；官方文档给的是 bash + `jq` 版，机制完全相同）：

```js
#!/usr/bin/env node
// .claude/hooks/protect-files.mjs

process.stdin.setEncoding('utf8');
let raw = '';
for await (const chunk of process.stdin) raw += chunk;

const { tool_input = {} } = JSON.parse(raw || '{}');
const file = (tool_input.file_path ?? '').replaceAll('\\', '/');

const PROTECTED = ['.env', 'package-lock.json', 'node_modules/', '.git/'];

const hit = PROTECTED.find((p) => file.includes(p));
if (hit) {
  console.error(`Blocked: ${file} 命中保护规则 '${hit}'`);
  console.error('改配置请改 .env.example，依赖请用 npm install。');
  process.exit(2);
}

process.exit(0);
```

配置：

```json
{ "hooks": { "PreToolUse": [{
  "matcher": "Edit|Write",
  "hooks": [{
    "type": "command",
    "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/protect-files.mjs\""
  }]
}]}}
```

> 🔴 **只有两步，不是三步**：建脚本 → 挂配置。**没有 `chmod +x` 这一步** —— 用 `node` 调用不需要执行权限。
> 这一页的标题「三步」因此是名副其实的：建脚本 · 挂上去 · 验证。

> 🔴 **`.mjs` 扩展名是必须的**（或 `package.json` 里有 `"type": "module"`），否则 top-level await 报 `SyntaxError`。
> **这是 Node 版的排错第一名**，取代了 bash 版的 `chmod +x`。

**第四步：验证挂上了没有。** 敲 `/hooks`，在 `PreToolUse` 下面看到它。

> **老师必须说的一句**：`/hooks` 这个菜单是**只读的**。要改 hook，改 JSON 文件，或者让它帮你改。

### 6.5 你刚才做了什么：三行机制（36 到 40 分钟）

**趁手感还在，立刻讲机制。** 这是 §1.4 那三行，第一次上屏。

```text
   它给你   ──▶  一坨 JSON 进 stdin
                 { "hook_event_name": "PreToolUse",
                   "tool_name": "Write",
                   "tool_input": { "file_path": "/你的项目/.env" },
                   "cwd": "...", "session_id": "..." }

   你给它   ──▶  exit 0   我不表态，走正常权限流程
                 exit 2   拦住，stderr 那句话变成给它看的反馈
```

**指着学员刚写的那个脚本，逐行对上去。** 三行机制不是抽象概念，是他五分钟前刚敲进去的东西。

**这里要点破一个学员一定会误解的地方**（官方原文）：

> **Exit 0**: your hook reports no objection through its exit code. For a `PreToolUse` hook **this doesn't approve the tool call: the normal permission flow still applies.**

翻译：**exit 0 不是「放行」，是「我不表态」。** 它后面该弹权限还是会弹。想真的放行要用 JSON（§13.3），而且放行也突破不了 deny 规则。

### 7.1 翻车① · 拦太宽，它干不了活了（40 到 44 分钟）

**指令：**

> 把你脚本里的 `PROTECTED` 改成一个字符：`['.']`
>
> 然后让它改任何一个文件。

结果：它什么都改不了了。每一次都被拦。

**老师说：**

> 现在这个 hook 百分之百有效。它一次都没让你的规矩被违反过。
>
> **而它也让你一件事都做不成。**
>
> 你回去三天之内会把它关掉。**一个被关掉的 hook，和没挂过，是一回事。**

这一条对上闸④。

### 7.2 翻车② · 挂错时点，拦了个寂寞（44 到 48 分钟）⭐⭐ 本幕支点

**指令：**

> 把 `PROTECTED` 改回来。然后把配置里的 `PreToolUse` 改成 `PostToolUse`。
>
> 再让它往 `.env` 里加一行。

结果：**它加进去了。** 脚本跑了，红字也出来了，`.env` 也被改了。

**老师这时候只说一句，然后停三秒：**

> 脚本跑了。你的判据也判对了。它甚至收到了你那句 "Blocked"。
>
> **而那一行已经在文件里了。**

**必须现场打开 `.env` 让大家看见那一行。**

然后投官方那两句，这是本页的骨头：

> `PostToolUse` hooks **can't undo actions since the tool has already executed.**

> | Hook event | Can block? | What happens on exit 2 |
> |---|---|---|
> | `PreToolUse` | **Yes** | Blocks the tool call |
> | `PostToolUse` | **No** | **Shows stderr to Claude; the tool already ran** |

**收口一句，为二维图铺路：**

> 这一次失败是**没有声音的**。红字照出，日志照写，你的监控上一切正常。
>
> **只有文件变了。**

### 7.3 翻车③ · 脚本自己错了（48 到 52 分钟）

**指令（挑一个，或者让学员自己制造）：**

> 把脚本里的 `exit 2` 改成 `exit 1`。再触发一次。

结果：它没被拦，但 transcript 里冒出 `PreToolUse hook error`。

**老师说：**

> 除了 0 和 2，别的退出码都是「你的脚本出问题了」。它不会拦，它会报错，然后照做。
>
> **hook 挂上不等于生效。** 你得看见它拦成功过一次，才算数。

顺手把排错三板斧给了（详见 §13.7）：

```bash
# 1. 单独喂一坨 JSON 给脚本，看它自己跑不跑得通（正反两条都要）
echo '{"tool_input":{"file_path":"/x/.env"}}' \
  | node .claude/hooks/protect-files.mjs ; echo $?     # 要看到 2
echo '{"tool_input":{"file_path":"/x/README.md"}}' \
  | node .claude/hooks/protect-files.mjs ; echo $?     # 要看到 0

# 2. 扩展名写成了 .js（Node 版最常见）
mv .claude/hooks/protect-files.js .claude/hooks/protect-files.mjs

# 3. 看详细日志
claude --debug        # 或者会话里敲 /debug
```

把 §0.4 那张表投出来。**这是第一次给结构，但还不是判断线。**

一句收口：

> 你们刚才被咬了三次。
>
> 第一次和第三次，你会自己把它关掉。**第二次，你不会 —— 因为你不知道。**

### 7.5 判断线第一次出现（54 到 58 分钟）⭐

第一句台词固定：

> **你们刚才被咬的三次，不是三个 bug。它们是三个问题，而且有顺序。**

然后逐条把 §1.3 那张图放出来，讲清**为什么是这个顺序**：

- **闸①在最前**，因为说过一遍的事不该挂 hook。**hook 不是用来代替沟通的**，你还没好好说过就上强制，是在给自己造第 7.1 节那种局面。

- **闸③是最贵的一道**，因为多数规矩挂在这里 —— 判不出来就挂不上。
- **闸④在最后**，因为它是「已经决定要挂了，怎么挂才不会被你自己关掉」。

### 8.2 三十多个事件，你一个都不用背（62 到 66 分钟）

2. **你今天用得上的就 6 个**：`PreToolUse` / `PostToolUse` / `Stop` / `SessionStart` / `UserPromptSubmit` / `Notification`。
3. **剩下的等你需要了再查**，查的方法是 `/hooks` 看有哪些、官方 hooks 页看每个的输入输出。

### 8.3 它压得过 `--dangerously-skip-permissions`（66 到 70 分钟）⭐⭐

**这一页是本节和 L11 的接口，必须讲。**

先回收 L11：

> 上节课讲无人值守，给了三条让它不卡住的做法：提前批、取消问、全放开。每条都有代价，最大的那个代价是 —— **你放开的时候，把该拦的也一起放开了。**

然后官方原文（两句都要投）：

> `PreToolUse` hooks fire **before any permission-mode check**, in every permission mode, including `dontAsk`. A hook that returns `permissionDecision: "deny"` blocks the tool **even in `bypassPermissions` mode or with `--dangerously-skip-permissions`**.

> The reverse is not true: a hook returning `"allow"` doesn't bypass deny rules from settings... **Hooks can tighten restrictions but not loosen them past what permission rules allow.**

**两句话各落一个「所以」：**

- 「压得过 bypass」→ **所以** 你可以放开权限让它跑得快，同时保证有三件事它永远碰不到。这是 L11 那三条做法的解药。
- 「只能收紧不能放宽」→ **所以** hook 不是后门。你没法用 hook 给自己开一条 settings 里禁掉的路。**这是设计，不是限制。**

### 8.4 反转：hook 挡得住的只有你说得清的（70 到 74 分钟）⭐⭐

前面全部内容都在教「怎么让它绕不过去」。这一页反过来。

> 到现在为止我们挂的每一条，都有一个共同点：**判据是一行 `if`。**
>
> 路径包不包含 `.env`、命令里有没有 `rm -rf`、退出码是不是 0。
>
> 这不是巧合。**hook 的力量来自确定性，确定性来自它不动脑。**

然后是本节的收口立论：

> **hook 挡得住的，只有你说得清的那部分。**
>
> 「别动 .env」你说得清，挂得上。
> 「别写得太复杂」你说不清，挂不上。
> **而你挂了三个 hook 之后，很容易以为自己被保护了。**

**讲师必须点破的机制：** 这一页和 L11 §8.5「绿灯不等于成功」是同一个结构 —— 一个让你安心的信号，和它实际保证了什么，中间有个缺口。L11 是「进程退出了 ≠ 事情做成了」，L12 是「hook 挂上了 ≠ 规矩守住了」。

### 8.5 那要动脑的怎么办：prompt / agent hook（74 到 78 分钟）

**必须紧接反转页讲，否则学员带着「挂不上」的挫败感走。**

官方给了两条路，**但要连代价一起讲**：

| 类型 | 怎么工作 | 什么时候用 | 代价（必须讲） |
|---|---|---|---|
| `type: "prompt"` | 把 hook 的输入喂给一个模型（默认 Haiku），让它返回 `{"ok": true/false, "reason": "..."}` | 光看 hook 的输入数据就够判断 | **确定性还回去了。** 判断的是模型，不是脚本 |
| `type: "agent"` | 起一个 subagent，它能读文件、跑命令，再返回同样的 `ok`/`reason` | 要对着真实代码状态验证才判得了 | 同上，**而且官方标了实验性**：Agent hooks are experimental |

官方那个 `Stop` + agent hook 的例子值得投，因为它正是 L6 铁律的机器形态：

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "agent",
            "prompt": "Verify that all unit tests pass. Run the test suite and check the results. $ARGUMENTS",
            "timeout": 120
          }
        ]
      }
    ]
  }
}
```

**一句判断线收口：**

> **hook 的输入数据就够判 → `prompt`。**
> **得看代码真实状态才判得了 → `agent`。**
> **一行 `if` 就够 → `command`，而且优先用它。**
>
> 官方原话：For production workflows, **prefer command hooks**。

### 8.6 挂在哪个文件 = 谁受它管（78 到 82 分钟）⭐ 本节最值钱的一格

| 位置 | 管谁 | 能不能共享 |
|---|---|---|
| `~/.claude/settings.json` | 你所有项目 | 不能，只在你这台机器上 |
| **`.claude/settings.json`** | **这一个项目** | **能，可以提交进仓库** ⭐ |
| `.claude/settings.local.json` | 这一个项目 | 不能，Claude Code 存设置时会 gitignore |
| 管理策略设置（managed） | 整个组织 | 能，管理员控制 |
| Plugin 的 `hooks/hooks.json` | 启用这个 plugin 时 | 能，跟 plugin 一起走 |
| Skill frontmatter | 这个 skill 被调用之后的整个会话 | 能，写在 skill 文件里 |
| Subagent frontmatter | 那个 subagent 运行期间 | 能，写在 subagent 文件里 |

**第二行要单独停下来讲，这是本节最值钱的一格：**

> 你把这条规矩提交进仓库。明天你同事克隆下来，他的 Claude Code **自动就受这条规矩管**。
>
> 他不需要读 CLAUDE.md，不需要知道有这回事，**也不需要同意**。
>
> 这是本节唯一一个跨过「你自己」的能力。前十一节教的全是怎么管好你自己那一个会话。

**紧接着必须讲反面，不许只讲好处：**

> 反过来也成立。**你克隆一个仓库，就同时接受了它 `.claude/settings.json` 里的每一条 hook。**
>
> 而 hook 是**会在你机器上自动执行的 shell 命令**。

三条实用纪律（讲师给，学员记）：

1. **克隆陌生仓库之后，`/hooks` 看一眼。** 这是本节送给学员的一个新习惯。
2. Skill / Subagent frontmatter 里也能挂 hook，**别只看 settings.json**。
3. 想整体关掉：设置里 `"disableAllHooks": true`。但注意官方这句：**"a project's settings file can override yours"** —— 关不关得掉，取决于设置优先级，**这一条讲师课前必须自己核一遍**（§21.3）。

### 8.7 用不了 Claude Code 怎么办（82 到 86 分钟）

**必讲，不许砍。** 只讲能力维度，不排名、不点评任何具体产品的版本能力。

**先说清楚这一节到底依赖什么能力**，这样退让才有依据：

> hook 这个机制依赖一件事：**宿主愿意在自己生命周期的固定时点，执行你给的命令，并且听你的返回值。**
>
> 你换任何一个 agent 壳，先去查它有没有这个能力。**有就是同一件事，只是名字不同；没有就往下退。**

退让阶梯：

```text
Claude Code hook（它每一次动手之前）
        │  用不了
        ▼
git hook：pre-commit / pre-push（提交或推送那一刻）
        │  用不了
        ▼
CI 检查（推上去之后）
        │  用不了
        ▼
CLAUDE.md 写一条 + 你自己 review（回到第一幕那个状态）
```

**明确告诉学员每退一步失去什么**（这是本段的价值所在，不是安慰）：

| 退到哪 | 失去什么 |
|---|---|
| git hook | **拦得晚了。** 它已经改了一堆文件，你在提交那一刻才拦，返工从「一次工具调用」变成「一整轮改动」 |
| CI | 更晚。**它已经推上去了**，而且反馈回路从秒级变成分钟级 |

## 9. 第五幕 · 落地（86 到 96 分钟）

### 9.1 挂你自己那条规矩（86 到 92 分钟）🎯

**只给骨架，不给范文。** 给了范文，交上来的就全是范文的变体。

> **时间必须说清楚，否则这一段必然崩。** 这六分钟里 P18（原理页）要占掉约 2 分钟，**学员实际动笔只有 4 分钟**。四分钟写不完一个完整脚本，所以课堂交付线定在这里：
>
> - **前四格：写实**，尤其判据那一行要能直接变成 `if`。
> - **脚本本体：只写判据那一行**，其余抄课堂那个骨架。
> - **完整脚本 + 跑通** 是作业第 1 项。**但如果你的规矩和课堂那个够像（多半是），当堂就能跑通，尽量当堂跑。**

```text
【我的第一条 hook】

1. 规矩原话     ___________________（第一幕抄的那句，说过 __ 遍）

2. 时点         这是「做了不该做的」→ PreToolUse
                还是「漏了该做的」  → PostToolUse / Stop
                我选：__________  因为：__________

3. matcher      __________
                （宽了会怎样：__________）

4. 判据         怎么判「违反了」？写成一行：
                if [[ ______________ ]]; then 拦

5. 拦住之后说什么   >&2 那句话：__________________
                    （它会看到这句，要写清「为什么」，不是只写 Blocked）

6. 挂在哪        ~/.claude/settings.json（只管我）
                 .claude/settings.json（管所有克隆这个仓库的人）
                 我选：__________  因为：__________

7. 验证          [ ] 我触发了一次  [ ] 我看见它被拦了
```

**助教巡场只查三件事**（同 §3.1）：触发过没有、时点对不对、matcher 是不是空的。

### 9.2 原理页：这段脚本为什么这么写（穿插在 9.1 中间讲，讲完切回动手页）

**这一页是系列的固定要求，不许省。** 学员要的不是这一个脚本，是以后面对新场景自己能组词。

逐条讲**为什么这样写**，不是讲每格填什么：

- **为什么 stderr 那句话要写清「为什么被拦」，不能只写 `Blocked`？** 因为**它会收到这句话**。写清楚了它能换条路走，写不清它会反复撞同一堵墙，把你的 context 耗光（接 L6）。这句话的读者不是你，是它。
- **为什么 matcher 要尽量窄？** 官方对自动批准那个例子的原话：Matching on `.*` or leaving the matcher empty **would auto-approve every tool permission prompt**。宽 matcher 的错法是静默的 —— 你以为只管了一类，其实管了全部。
- **为什么判据要写成「路径匹配」而不是「这个改动合不合理」？** 因为确定性来自不动脑（§8.4）。**你写的每一个「合不合理」，都是把判断权又交回给了模型。**
- **为什么用 `$CLAUDE_PROJECT_DIR` 而不是相对路径？** 因为 hook 跑的时候工作目录不一定是项目根。官方给的就是这个占位符：`${CLAUDE_PROJECT_DIR}` = the project root where the session started。写相对路径的，换个目录就 command not found。
- **为什么 exit 2 和 JSON 输出不要混用？** 官方明说：**Choose one approach per hook.** 混用的行为要去查表，而你不该让自己的规矩依赖一张需要查的表。
- **为什么 exit 0 不叫「放行」？** 因为它只是「我不表态」，正常权限流程还在后面。**把 exit 0 当放行的人，会以为自己批准了，其实什么都没发生。**
- **为什么「漏做」和「做错」要用不同时点？** 因为 `PostToolUse` 撤不回。这不是风格问题，是机制问题 —— 工具已经执行了。
- **为什么第一条规矩要挑机器判得出来的？** 因为你需要先看见它成功拦一次。**一个从没拦成功过的 hook，你不会信它，也不会留着它。**

### 9.3 讲评（92 到 94 分钟）

**规则：只问「你挂在哪个时点、为什么」和「你的 matcher 宽了会怎样」，不判规矩好坏。**

一判好坏，整个框架当场退化成「老师觉得哪些规矩值得挂」，学员回去就不用了。

优先抽两类人：

1. **时点选了 `Stop` 的那几个**：让他说说他想在收工时验什么 —— 这类人多半在做 L6 铁律的兑现，全班该听见。
2. **卡在闸③（判据写不出来）的**：让他说一句「我这条为什么写不成一行 `if`」。**这类人是全班最该被听见的**，因为他撞到的正是本节的收口立论，而且他没糊弄自己。

### 9.4 收口与作业（94 到 96 分钟）

## 12. 用法样例库 ⭐（本节核心资产）

> **这一章是 deck 附录 P23 和 `HANDOUT.md` 第 4 章的唯一事实源。**
>
> **纪律：** 每一条都标了来源。标「官方」的是从 `code.claude.com/docs` 逐字取的，**不许改写**（改写就失去了权威性）。标「组合」的是本课基于官方机制拼的，**必须在讲义里注明「这是本课的写法，不是官方示例」**。
>
> **课堂上只用 A-1。其余全部是讲义 / 附录内容。**

### 12.A 拦：它动手之前（`PreToolUse`）

#### A-1 · 保护文件不被改【本课 · Node】← 课堂统一用这个

**场景**：`.env`、`package-lock.json`、`node_modules/`、`.git/` 谁都别动。

脚本、配置、验证方法见 §6.2（此处不重复）。

> 🔴 **语言决定（讲师要求）：本节全部脚本用 Node（`.mjs`），不用 bash + `jq`。**
> 理由三条，**课上可以说出来，本身就是教学材料**：
> ① 演示与学员仓库都是 Node 项目，**本来就有 `node`，零额外安装**（原来要先装 `jq`）
> ② `node xxx.mjs` 调用**不需要 `chmod +x`** —— bash 版的「排错第一名」在 Node 版里根本不存在
> ③ `JSON.parse` 对 JS 团队是母语，`jq` 语法反而是门槛
>
> **而三行机制一个字没变。** 这正好坐实 §1.4 要讲的那句：**`jq` / bash 从来不是机制的一部分。**

> 🔴 **出处纪律（§21.1）**：**官方文档的示例是 bash + `jq` 版。** 本节用的是它的 **Node 等价实现**，
> deck 和讲义都标注为「本课写法」。**学员翻官方文档会看到 bash 版，不写明他会以为对不上。**

**要讲的点**：`process.exit(2)` 拦住 + `console.error` 走 stderr 变成它的反馈 + `$CLAUDE_PROJECT_DIR` 的作用 + `.mjs` 扩展名是必须的。

#### A-2 · 拦住危险命令 + 同时记日志【官方】

**场景**：`rm -rf` 这类命令不许跑，但**所有** Bash 命令都要留痕。

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "node .claude/hooks/log-bash.mjs" },
          { "type": "command", "command": "node .claude/hooks/block-rm-rf.mjs" }
        ]
      }
    ]
  }
}
```

**这个例子专门用来讲「多个 hook 同时挂」的三条规则（全部官方原文）：**

1. **都会跑完**：every hook's command runs to completion before Claude Code merges the results。
2. **最严的赢**：the most restrictive answer applies, in the order `deny`, `defer`, `ask`, `allow`。
3. ⚠️ **一个 deny 拦不住兄弟 hook 的副作用**：One hook returning `deny` doesn't stop sibling hooks from executing. **Don't rely on one hook's `deny` to suppress side effects in another hook.**

第 3 条是坑：上面这个例子里，命令**即使被拦了，日志照样写**。官方原文说得很清楚：「The log entry is still written because the logging hook already ran.」

#### A-3 · 用 JSON 输出拦，并告诉它换个做法【官方】

**场景**：不是禁止，是引导。「别用 `grep`，用 `rg`」。

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "Use rg instead of grep for better performance"
  }
}
```

**要讲的点**：`permissionDecision` 四个值 —— `allow`（跳过询问，但突破不了 deny 规则）、`deny`（取消并把 reason 给它）、`ask`（照常弹给用户）、`defer`（只在 `-p` 非交互模式下，给 SDK 包装器用）。

**和 exit 2 的区别**：exit 2 只能拦；JSON 能拦、能放、能改成问用户。官方叮嘱：**Choose one approach per hook.**

#### A-4 · 用 `if` 字段代替正则 matcher【官方字段，本课用法】

**场景**：matcher 写正则容易写宽。官方提供了一个更准的过滤字段。

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "if": "Bash(git push *)",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/guard-push.sh"
          }
        ]
      }
    ]
  }
}
```

官方对 `if` 的定义（原文）：**Permission rule syntax to filter when this hook runs, such as `"Bash(git *)"` or `"Edit(*.ts)"`. The hook command only runs if the tool call matches the pattern.**

**要讲的点**：这是闸④（收窄）的一个具体手段。`matcher` 挑事件层面的工具名，`if` 再往下挑具体调用。

### 12.B 补：它动完手（`PostToolUse`）

#### B-1 · 改完自动格式化【官方】

**场景**：「写完记得格式化」这句话不用再说了。

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/format.mjs\"" }
        ]
      }
    ]
  }
}
```

**要讲的点**：这是「漏做」类规矩的标准形态 —— **不拦，补上**。对上二维图右下格。

**验证方法（官方给的，很妙）**：让它往 JS 文件里加一行单引号字符串，然后打开文件 —— Prettier 默认会把它改成双引号。

**官方提醒**：hook 成功的时候对话里什么都不显示。要确认它跑了，去看文件变没变。

#### B-2 · 它用 Bash 改的文件怎么办【官方提醒 + 本课写法】

**这是 B-1 的坑，必须一起讲。** 官方原文：

> Claude can also create or modify files by running shell commands. If your hook must see every file change, such as for compliance scanning or audit logging, add a `Stop` hook that scans the working tree once per turn. For per-call coverage instead, also match `Bash|PowerShell` and have your script list modified and untracked files with `git status --porcelain`.

```js
#!/usr/bin/env node
// 本课写法：一轮结束扫一遍工作区，而不是逐个工具调用去猜
import { execSync } from 'node:child_process';

const files = execSync('git status --porcelain', { encoding: 'utf8' })
  .split('\n').map((l) => l.slice(3).trim())
  .filter((f) => /\.(ts|tsx|js|jsx)$/.test(f));

if (files.length) execSync(`npx prettier --write ${files.join(' ')}`, { stdio: 'inherit' });
process.exit(0);
```

挂在 `Stop` 上。**要讲的点**：`matcher: "Edit|Write"` 只看得见它用编辑工具做的改动。它 `sed` 一下、`echo >>` 一下，你的 hook 什么都不知道。

#### B-3 · 盯住某个文件，谁改都算【官方】

**场景**：不管是谁改的（它、你、构建脚本），只要这个文件变了就做点什么。

用 `FileChanged` 事件，`matcher` 填要盯的文件名。官方原文：**To run a hook when a specific file changes on disk, whatever wrote it, use a `FileChanged` hook.**

### 12.C 灌上下文：提前把话塞进去（`SessionStart` / `UserPromptSubmit`）

#### C-1 · context 被压缩之后，把关键信息灌回去【官方】← L6 的兑现

**场景**：L6 讲过 context 会被压缩，压缩会丢东西。这是解法。

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "compact",
        "hooks": [
          {
            "type": "command",
            "command": "echo 'Reminder: use Bun, not npm. Run bun test before committing. Current sprint: auth refactor.'"
          }
        ]
      }
    ]
  }
}
```

**要讲的点（三条，都重要）：**

1. `matcher` 在 `SessionStart` 上过滤的是**会话怎么开始的**：`startup` / `resume` / `clear` / `compact` / `fork`。这里只挂 `compact`。
2. **stdout 的纯文本会被加进 context**。这是 `exit 0` 的一个特殊行为，只对 `UserPromptSubmit` / `UserPromptExpansion` / `SessionStart` / `PostModelSwitch` 四个事件成立。
3. **`echo` 可以换成任何命令**，官方举的例子是 `git log --oneline -5`。**动态的比静态的有用得多。**

**官方还给了一句边界，必须讲**：每次会话开始都要灌的东西，用 CLAUDE.md，别用 hook。**hook 是给「只在某种情况下才灌」用的。**

#### C-2 · 每次提问自动附上当前状态【官方】

**场景**：「现在是发布冻结期」这种事，你不想每次都说一遍。

```json
{
  "hookSpecificOutput": {
    "hookEventName": "UserPromptSubmit",
    "additionalContext": "Current branch: release-42. Deploy freeze until Friday."
  }
}
```

⚠️ **官方专门警告的坑**：`additionalContext` 必须嵌在 `hookSpecificOutput` 里面。**放在 JSON 顶层的话，Claude Code 会静默忽略它** —— 不报错，就是不生效。

**要讲的点**：这是「静默失败」的又一个形态，和翻车②同类。**本节反复出现的主题：失败不一定有声音。**

### 12.D 验收：它说做完了的时候（`Stop` / `SubagentStop`）

#### D-1 · 测试不过，它没法说完成【官方 agent hook】← L6 铁律的执行机构

见 §8.5 的 JSON（官方原文）。

**要讲的点**：`Stop` exit 2 = "Prevents Claude from stopping, continues the conversation"。**这是全系列最漂亮的一次前后呼应**，L6 那条原则在这里变成了机制。

#### D-2 · 轻量版：不用模型，用退出码【组合】

```js
#!/usr/bin/env node
// 本课写法。测试没过就把它按回去继续做
import { spawnSync } from 'node:child_process';

const r = spawnSync('npm', ['test', '--silent'], { encoding: 'utf8', shell: true });
if (r.status !== 0) {
  console.error('测试没过，不能收工。失败输出：');
  console.error(`${r.stdout}${r.stderr}`.trim().split('\n').slice(-20).join('\n'));
  process.exit(2);
}
process.exit(0);
```

**要讲的点**：D-1 用 agent hook（会动脑、慢、实验性），D-2 用 command hook（不动脑、快、确定）。**能用 D-2 的场景别用 D-1** —— 这是 §8.5 判断线的一个具体应用。

⚠️ **官方警告的坑**：`Stop` hooks fire whenever Claude finishes responding, **not only at task completion**。你随口问一句「这个函数干嘛的」，它答完也会触发这个 hook，于是跑一遍测试。**所以这类 hook 要么加条件，要么你会被自己烦死。**

另有一条官方提到的保护：`Stop` hook 有 block 次数上限（block cap），防止无限循环。

#### D-3 · prompt hook 版：让模型判「做完没有」【官方】

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Check if all tasks are complete. If not, respond with {\"ok\": false, \"reason\": \"what remains to be done\"}."
          }
        ]
      }
    ]
  }
}
```

**要讲的点**：`ok: false` 时 `reason` 会被喂回给它当下一步指令。还有一个 `impossible: true` 字段 —— 标记「这个条件永远满足不了」，避免它被卡在一个死循环里。

### 12.E 提醒：它在等你（`Notification`）

#### E-1 · 它卡住等批准时，弹个桌面通知【官方】

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude Code needs your attention\" with title \"Claude Code\"'"
          }
        ]
      }
    ]
  }
}
```

**要讲的点（接 L11）**：L11 演示 B 是「它挂在那儿等了一夜，而它不会打电话给你」。**这一条就是让它打电话给你。**

`Notification` 的 matcher 能挑通知类型，其中和前面几节直接相关的：

- `permission_prompt` —— 它要你批准（等了约 6 秒之后才触发）
- `idle_prompt` —— 它答完约 60 秒你没动静
- `agent_needs_input` / `agent_completed` —— 后台会话（接 L7 / L8）

### 12.F 审计：谁改了什么（`ConfigChange` / 日志）

#### F-1 · 配置被改了就记一条【官方】

```json
{
  "hooks": {
    "ConfigChange": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/audit.mjs\""
          }
        ]
      }
    ]
  }
}
```

**要讲的点**：`ConfigChange` 的 matcher 挑配置来源 —— `user_settings` / `project_settings` / `local_settings` / `policy_settings` / `skills`。

**它也能拦**：exit 2 或 `{"decision": "block"}` 就阻止这次配置变更生效。官方注明一个例外：**`policy_settings` 拦不住**。

官方安全页也点名了这个用法（原文）：**Audit or block settings changes during sessions with `ConfigChange` hooks.**

### 12.G 团队：让规矩跟着仓库走

#### G-1 · 提交进仓库的项目级 hook【官方位置表】

把 A-1 的配置写进项目的 `.claude/settings.json` 并提交。**克隆的人自动受管。**

见 §8.6 的完整位置表和三条反面纪律。

#### G-2 · 挂在 Skill 里的 hook【官方】

```yaml
---
name: secure-operations
description: Perform operations with security checks
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/security-check.sh"
---
```

**要讲的点（接 L5）**：L5 教了 Skill 是把重复套路打包。现在 Skill **还能带自己的规矩**。

生命周期要讲清（官方原文）：

- **Skill hooks**：被调用时注册，**之后整个会话都还在跑**，包括后面几轮。想让它跑一次就撤，加 `once: true`。
- **Subagent hooks**：只在那个 subagent 运行期间跑，跑完就撤。而且官方有个细节：subagent 里写的 `Stop` hook **会被自动转成 `SubagentStop`**。

⚠️ **信任门槛（官方原文，安全相关，必须讲）**：项目 subagent frontmatter 里的 hook，**要你接受了 workspace trust 对话框才会跑**；`-p` 会话不算接受。**而项目 skill frontmatter 里的 hook 规则不同** —— 官方明说它「including in a `-p` run in a folder you haven't trusted」也会注册。

**这个差异是真的，且反直觉，讲义里必须写明，并列进 §21.3 课前核对。**

### 12.H 更远的：知道它存在就行

| 类型 | 一句话 | 什么时候才需要 |
|---|---|---|
| `type: "http"` | 把事件 POST 到一个 URL，返回体里给决定 | 团队共用一个审计/策略服务时。注意 headers 里的 `$VAR` **只有列进 `allowedEnvVars` 的才会被替换** |
| `type: "mcp_tool"` | 调用一个已连接的 MCP server 上的工具 | 你已经在用 MCP 了（本系列还没讲 MCP，见 §0.6） |
| `PostToolBatch` | 一批并行工具调用全部结束、下一次模型调用之前 | 要看「这一轮总共干了什么」而不是单次调用 |
| `PermissionRequest` | 它要弹权限框的时候 | 自动批准某一类（例 §12.A 的官方 ExitPlanMode 例子） |
| `SubagentStart` / `TeammateIdle` | 接 L7 / L8 | 给子 agent 或 teammate 加统一规矩 |
| `PreCompact` / `PostCompact` | 压缩前后 | 比 `SessionStart:compact` 更早的介入点 |

## 13. 代码结构分析（hook 解剖）⭐（本节核心资产）

> **这一章是 deck 附录 P24 和 `HANDOUT.md` 第 5 章的唯一事实源。**
> **课上只讲 §13.1 和 §13.2 的三行机制（第 36 到 40 分钟），其余全部是讲义内容。**

### 13.1 一个 hook 的最小骨架（六步 · Node）

```js
#!/usr/bin/env node
// ① 收：把 stdin 整个读进来（它是一坨 JSON）
process.stdin.setEncoding('utf8');
let raw = '';
for await (const chunk of process.stdin) raw += chunk;

// ② 挑：从 JSON 里取出你要判断的那个字段
const { tool_input = {} } = JSON.parse(raw || '{}');
const field = tool_input.file_path ?? '';

// ③ 判：一行 if。这一行就是你那条规矩
if (field.includes('.env')) {
  // ④ 说：写给它看的话，走 stderr
  console.error('Blocked: 这个文件不许改，改配置请改 .env.example');
  // ⑤ 拦：exit 2
  process.exit(2);
}

// ⑥ 不表态（注意：不是放行）
process.exit(0);
```

**六步里，学员自己要写的只有第 ③ 和第 ④ 步。** 其余五步每个 hook 都一样，抄就行。

**这就是为什么课堂动手只要求写判据那一行**（§9.1）。

> **换任何语言都是这六步。** 官方文档用 bash + `jq` 写，本节用 Node 写 —— 讲师要把这一点说出来，它坐实了 §1.4 的立论：**`jq` / bash 不是机制的一部分，任何能读 stdin、能设退出码的东西都行。**

### 13.2 输入：stdin 那坨 JSON 长什么样

**共有字段**（每个事件都有）：

| 字段 | 是什么 |
|---|---|
| `session_id` | 这次会话的唯一 ID |
| `cwd` | 事件触发时的工作目录。⚠️ 进了 worktree 之后，这里是 worktree 根 |
| `hook_event_name` | 哪个事件触发的 |

**`PreToolUse` / `PostToolUse` 额外有**：

| 字段 | 是什么 |
|---|---|
| `tool_name` | 它要用哪个工具（`Bash` / `Edit` / `Write` / ...） |
| `tool_input` | 传给工具的参数。**Bash 看 `.command`，Edit/Write 看 `.file_path`** |

官方给的完整样例（原文）：

```json
{
  "session_id": "abc123",
  "cwd": "/Users/sarah/myproject",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": {
    "command": "npm test"
  }
}
```

**别的事件字段不同**（官方原文）：`UserPromptSubmit` 拿到的是 `prompt` 文本；`SessionStart` 拿到的是 `source`，值为 `startup` / `resume` / `clear` / `compact` / `fork`。

> **讲义纪律：** 不逐个列所有事件的 schema。**教方法**：`claude --debug` 跑一次，把实际收到的 JSON 打出来看，比查表快。见 §13.7。

### 13.3 输出：三条路，选一条

```text
路 1  exit 0   ──▶ 「我不表态」
                    ⚠️ 不是放行！PreToolUse 的正常权限流程还在后面
                    特例：UserPromptSubmit / UserPromptExpansion /
                          SessionStart / PostModelSwitch 四个事件，
                          stdout 的纯文本会被加进 context

路 2  exit 2   ──▶ 「拦住」+ stderr 变成反馈
                    ⚠️ 不是所有事件都拦得住，见 §13.4

路 3  JSON     ──▶ exit 0 + stdout 输出一个对象，做更细的控制
                    PreToolUse:      hookSpecificOutput.permissionDecision
                                     = allow / deny / ask / defer
                    UserPromptSubmit: hookSpecificOutput.additionalContext
                    PostToolUse/Stop: 顶层 decision: "block"
                    PermissionRequest: hookSpecificOutput.decision.behavior
```

**官方铁律：Choose one approach per hook.** 别在一个 hook 里既 exit 2 又输出 JSON。

**其他退出码会怎样**（这是学员最容易踩的，官方原文很细）：

- stdout 是个能通过 schema 校验的 JSON 对象 → **退出码被忽略，JSON 说了算，不算错误**
- stdout 是 JSON 但校验不过、或者看起来像 JSON 但格式错 → **非阻塞错误**，提示里带校验/解析信息
- stdout 是纯文本或空 → **动作照常进行**，transcript 显示 `<hook name> hook error`，加上 stderr 第一行，前缀 `Failed with non-blocking status code:`

> **修 JSON 解析失败的官方建议**：用 `jq` 这类 JSON 编码器构造输出，别用字符串拼接 —— 值里的引号和反斜杠拼接时会出事。

### 13.4 哪些事件拦得住（官方表，逐字）

| Hook event | Can block? | What happens on exit 2 |
|---|---|---|
| `PreToolUse` | **Yes** | Blocks the tool call |
| `UserPromptSubmit` | Yes | Blocks prompt processing and erases the prompt |
| `UserPromptExpansion` | Yes | Blocks the expansion |
| `Stop` | Yes | Prevents Claude from stopping, continues the conversation |
| `SubagentStop` | Yes | Prevents the subagent from stopping |
| `TeammateIdle` | Yes | Prevents the teammate from going idle, so it continues working |
| `TaskCreated` | Yes | Rolls back the task creation |
| `TaskCompleted` | Yes | Prevents the task from being marked as completed |
| `ConfigChange` | Yes | Blocks the configuration change from taking effect (except `policy_settings`) |
| `PostToolBatch` | Yes | Stops the agentic loop before the next model call |
| **`PostToolUse`** | **No** | **Shows stderr to Claude; the tool already ran** |
| `PostToolUseFailure` | No | Shows stderr to Claude; the tool already failed |
| `PermissionRequest` | No | exit 2 不生效，权限流程照常。**要拒绝请用 `decision` 对象** |
| `PermissionDenied` | No | 退出码和 stderr 都被忽略 |
| `StopFailure` | No | 输出和退出码都被忽略（`terminalSequence` 除外） |

**这张表是翻车②的官方依据，讲义里必须完整给出。**

### 13.5 五种 type

| type | 干什么 | 默认超时 | 什么时候用 |
|---|---|---|---|
| `command` | 跑一个 shell 命令 | 10 分钟 | **默认选它。** 官方：For production workflows, prefer command hooks |
| `http` | POST 到一个 URL | 10 分钟 | 团队共用策略/审计服务 |
| `mcp_tool` | 调用已连接的 MCP server 上的工具 | 10 分钟 | 已经在用 MCP |
| `prompt` | 单轮模型判断，默认 Haiku，返回 `{ok, reason}` | 30 秒 | 光看输入数据就够判 |
| `agent` | 起 subagent，能读文件跑命令，最多 50 轮工具调用 | 60 秒 | 得看真实状态才判得了。**实验性** |

**几个被下调的超时（官方原文，容易踩）**：`UserPromptSubmit` / `PreModelSwitch` / `PostModelSwitch` 降到 30 秒；`MessageDisplay` 降到 10 秒；**`SessionEnd` 所有 hook 共享 1.5 秒预算**（配了更长的 `timeout` 才会抬高，最多 60 秒）。

> **数据纪律**：这些默认值**会变**。deck 上不写死，讲义写明「以当天官方文档为准」（§21.3）。

### 13.6 配置文件的结构

```json
{
  "hooks": {
    "<事件名>": [
      {
        "matcher": "<按事件类型过滤，见下表>",
        "hooks": [
          {
            "type": "command",
            "command": "<要跑的命令>",
            "if": "Bash(git *)",
            "timeout": 30,
            "once": false,
            "statusMessage": "跑的时候转圈显示这句"
          }
        ]
      }
    ]
  }
}
```

**两层数组的意思**（学员第一次看必懵，讲义要点明）：

- 外层一项 = 一组 matcher 相同的 hook
- 内层 `hooks` 数组 = 这组里挂了几个命令，**它们并行跑**

**matcher 按事件过滤不同的东西**（官方表节选，讲义给全）：

| 事件 | matcher 过滤什么 | 例子 |
|---|---|---|
| `PreToolUse` / `PostToolUse` / `PostToolUseFailure` / `PermissionRequest` / `PermissionDenied` | 工具名 | `Bash`、`Edit\|Write`、`mcp__.*` |
| `SessionStart` | 会话怎么开始的 | `startup` `resume` `clear` `compact` `fork` |
| `SessionEnd` | 会话为什么结束 | `clear` `resume` `logout` `prompt_input_exit` `other` |
| `Notification` | 通知类型 | `permission_prompt` `idle_prompt` `agent_needs_input` `agent_completed` ... |
| `SubagentStart` / `SubagentStop` | agent 类型 | `general-purpose` `Explore` `Plan` 或自定义名 |
| `PreCompact` / `PostCompact` | 什么触发的压缩 | `manual` `auto` |
| `ConfigChange` | 配置来源 | `user_settings` `project_settings` `local_settings` `policy_settings` `skills` |
| `FileChanged` | 要盯的文件名 | 文件名模式 |

⚠️ **两个官方点名的坑**：

1. **matcher 区分大小写**（Matchers are case-sensitive）。
2. **没有 matcher = 这个事件每次都触发。**

**路径占位符**（官方原文）：

- `${CLAUDE_PROJECT_DIR}` —— 会话启动时的项目根
- `${CLAUDE_PLUGIN_ROOT}` —— plugin 安装目录，**每次 plugin 更新都会变**
- `${CLAUDE_PLUGIN_DATA}` —— plugin 的持久数据目录

### 13.7 排错：它不工作的时候（八条）

| 症状 | 查什么 |
|---|---|
| **压根没触发** | `/hooks` 看它在不在正确的事件下面；matcher 大小写对不对；事件选对没有（`PreToolUse` 在前，`PostToolUse` 在后） |
| **`command not found`** | 用绝对路径或 `${CLAUDE_PROJECT_DIR}`。想彻底躲开 shell 引号问题，加 `"args": []` 切成 exec form |
| **`jq: command not found`** | 装 `jq`，或改用 Python / Node 解析（例 A-1b） |
| **脚本根本没跑** | `chmod +x` 忘了。**这是最常见的一条** |
| **`hook error` 红字** | 退出码用错了（只有 0 和 2 有特殊含义）。单独喂 JSON 测：`echo '{"tool_name":"Bash","tool_input":{"command":"ls"}}' \| ./my-hook.sh; echo $?` |
| **JSON 不生效** | 校验信息 = schema 不对；解析信息 = 格式不对。**用 `jq` 构造输出，别字符串拼接** |
| **`/hooks` 里看不见** | 文件监听一般会自动加载，几秒后还没有就重启会话。检查 JSON 有没有尾逗号或注释（都不允许） |
| **想看到底发生了什么** | `claude --debug` 启动，或会话里敲 `/debug` |

**一条本课加的调试技巧（组合）：**

```bash
# 把每次收到的输入原样存下来，看清它到底给了你什么
INPUT=$(cat)
echo "$INPUT" >> /tmp/hook-input.jsonl   # 加这一行，然后去翻这个文件
```

**比查任何 schema 表都快。** 建议讲义把这条放在排错章开头。

## 15. 评分与 Exit ticket

### 15.1 课堂评分（12 分 · 过关线 10）

| 维度 | 分 | 给分标准 |
|---|---|---|
| 规矩来源 | 2 | 是自己说过三遍以上的原话，不是编的 |
| 时点判断 | 2 | 说得出「漏做 / 做错」以及因此选了哪个时点、为什么 |
| 判据可判 | 2 | 判据能写成一行 `if`。写「判断是否合理」这类的不给分 |
| matcher 收窄 | 2 | 不是空的、不是 `.*`，且说得出宽了会怎样 |
| **跑通了** | 2 | **有一次拦截成功的证据。没跑通的这一项零分** |
| 位置选择 | 2 | 选了一个位置 + 说得出因此谁受它管 |

**评分纪律：不对「这条规矩该不该挂」打分。** 学员判断「我这条现在挂不上，因为判据写不出来」并说清理由的，是满分答案，不是失败 —— 那正是收口立论。

### 15.2 Exit ticket（6 题，现场只收第 6 题）

1. 你那条规矩原话是什么？你说过几遍？
2. 它是「做了不该做的」还是「漏了该做的」？所以你挂在哪个时点？
3. 你的判据那一行 `if` 长什么样？
4. 你的 matcher 是什么？宽了会怎样？
5. 你挂在哪个文件？因此谁受它管？
6. **交你那次拦截成功的证据**（截图 / 终端粘贴 / 配置 + 脚本都行）。← **现场只收这一题**

**第 6 题必须收实物。** 收不上来的人，这节课对他没有发生 —— 本节和前面几节最大的不同就是它有可运行的产物。

## 16. 作业

### 必做

1. **把课堂那条 hook 补完整并跑通**（课堂上只写了判据一行的人，补完脚本）。贴出一次拦截成功的记录。
2. **故意让它失效一次**：改错退出码、删掉执行权限、或者把 matcher 写成别的工具名。**看它是怎么"安静地"不工作的**，写一句你是怎么发现的。
3. 回答一句：**你的 hook 在第一天里，有没有拦住过一次你自己不想被拦的操作？** 如果有，你打算怎么收窄。

### 选做扩展

4. 挂一条 `Stop` hook，让它测试不过就没法收工（例 D-2）。**这是 L6 铁律第一次真正被执行。**
5. 挂一条 `SessionStart` + `compact` 的 hook（例 C-1），把你项目里最容易被压缩丢掉的那三句话灌回去。
6. 挑一条你**判过「现在挂不上」**的主观规矩，试着用 `prompt` hook 写一版，然后回答：**你信它的判断吗？为什么？**
7. 等你有三条 hook 且都验证过了，把它们放进项目的 `.claude/settings.json` 提交。**提交之前，先在 PR 描述里写清楚「这个 PR 会让所有克隆这个仓库的人的 Claude Code 自动执行以下脚本」** —— 这句话你写不出来，就说明还不该提交。
8. 克隆一个你常用的开源仓库，敲 `/hooks` 看一眼。**记录你看到了什么。**

## 21. 事实与数据纪律

### 21.1 概念与机制出处

- **「deterministic control: certain actions always happen rather than relying on the LLM to choose to run them」**：官方 hooks-guide 原文，**是本节的立论支点，必须逐字引用并标明出处**。
- **「`PostToolUse` hooks can't undo actions since the tool has already executed」**：官方原文，翻车②的全部依据。
- **「`PreToolUse` hooks fire before any permission-mode check... blocks the tool even in `bypassPermissions` mode」** 与 **「Hooks can tighten restrictions but not loosen them」**：官方原文，§8.3 的全部依据。
- **「它没有记忆，只有 context」**：L6 立论，标明来源，不要当本节发明。
- **「它说完成了不算完成，判据要来自它之外」**：L6 铁律。本节的 `Stop` hook 是它的机器形态，**要说清这是 L6 的兑现，不是本节的新框架**。
- **时点二维图、四道判断线、hook 三行机制、六步骨架**：**这四样都是本课的教学设计，不是官方文档里的分法。** deck 和讲义必须写明这一点，否则学员去翻官方文档会发现对不上。
- **官方文档没有把 hook 事件按「拦得住 / 拦不住」画成二维图**，这是本课为了教学做的重组。**依据是官方那张 Can block? 表，重组本身是本课的。**

### 21.2 课堂数据纪律

- deck 不出现具体模型名、价格、上下文长度数字。
- **不用本课程仓库自己的文件、`.claude/` 目录、Skill、hook 当教学例子。** 老师用自己的项目，学员用自己的项目，通用例子一律取自官方文档。
- **样例库里每一条必须标明「官方」还是「本课写法」**（§12 开头的纪律）。混着给，学员分不清哪些是有权威背书的。
- 讲到别的 agent 工具时，**只讲能力维度**（有没有生命周期钩子这个能力），不排名、不点评具体产品的版本能力。§8.7 的退让阶梯只用 git hook / CI 这类通用机制，**不依赖任何具体产品的功能宣称**。
- **本节没有标准答案。** 每位学员的规矩不同，deck、讲义、评分表里都不许出现「正确答案应该是」。
- 学员的规矩和项目属于他自己的材料，**不许要求投屏或上交项目原文**，只上交 hook 结构和拦截证据。
- 演示投屏前确认不含敏感信息与真实凭证。

### 21.3 需要课前核对（本节比前几节更重要）

**hooks 的字段、默认值和事件列表变动很快，其中一部分仍在演进（`agent` 类型官方已标实验性）。以下每一条都必须在开课当天重新确认，不许凭上次上课的记忆：**

1. `/hooks` 菜单当天是否仍然只读、显示格式有没有变。
2. **`PreToolUse` 当天是否仍然「在所有权限模式检查之前触发」，`deny` 是否仍然压得过 `--dangerously-skip-permissions`。** 这条是 P13 的立论基础，变了整页要改。
3. **`PostToolUse` 当天是否仍然 `Can block? = No`。** 这条是翻车②和二维图的全部依据，变了半节课要改。
4. 各 type 的**默认超时数值**（`command` 10 分钟、`prompt` 30 秒、`agent` 60 秒、`SessionEnd` 1.5 秒预算等）。
5. 事件列表有没有新增或改名（本蓝图 §13.4 / §13.6 的表按当天版本核）。
6. `agent` hook 是否仍标注 experimental。
7. **`disableAllHooks` 的实际行为**（§18 附录 A.6，必须自己试，不许凭文档字面推断）。
8. **Skill frontmatter hook 与 Subagent frontmatter hook 的 workspace trust 差异**（§12.G-2），这条反直觉且涉及安全，必须核准。
9. 官方文档以 <https://code.claude.com/docs/en/hooks-guide> 和 <https://code.claude.com/docs/en/hooks> **当天版本**为准，不凭记忆写进讲义。
