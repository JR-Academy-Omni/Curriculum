# Vibe Coding 大师课 · 第十一节蓝图

> 状态：DRAFT 1.0（2026-08-30）
> 主题：**让 Agent 定时替你干活：你不在场的时候，它凭什么做对**
> 课型：**96 分钟框架课**（前 24 分钟学员在写、在被打回；24 到 38 分钟看老师现场翻两次车。老师不许连续讲）
> 课堂硬产物：**一份学员自己的「无人值守任务书」，六段齐全，可复用、可做成 Skill。**
> 本文只定义课程。Deck、`RUNSHEET.md` 与 `HANDOUT.md` 必须以本文为唯一事实源生成。

---

## 0. 立项决定

### 0.1 这一节到底新在哪

前十节课有一个从来没说出口的共同前提：

> **你在旁边看着。**

L6 教你认打断信号——**你得在看**。L7 说汇总是你的活——**你得在**。L8 的 Lead 验收——**你得在**。L10 的开场四问是你开工前自己过一遍——**你还是得在**。

第十一节第一次把这个前提抽掉。

```text
L1–L10   你在场。所有技巧都建立在「你随时能喊停」上。
────────────────────────────────────────────────
L11      你不在场。任务在凌晨三点跑，你在睡觉。
         它遇到需要你拍板的地方，没人拍。
```

所以本节不是「教一个新工具的用法」。定时任务的设置本身十分钟能讲完。**难的是：一件事在没人看着的时候交出去，你要提前把什么东西补上。**

### 0.2 全节最重要的一句话（收口立论，不许提前说）

> **你消灭的不是那个问题，是那次提问。**

学员来上这节课，多半想要的是一个答案：怎么让它别卡住来问我。这个答案确实存在，而且很简单（见 §8.2 的三条做法）。

但它有个必然的后果：**提问被取消了，那个决定并没有消失——它被交给了 Agent 自己做。**

于是本节的真正落点是：

> 你把提问关掉的那一刻，就欠下了一笔债：**它可能会问你的每一个问题，你都得提前答完。**
>
> 那份提前答完的东西，就叫任务书。

**这句话是硬产物存在的理由，不是一句总结。** 没有这一步，任务书就只是一张漂亮模板，学员回去不会用。

### 0.3 最重要的教学决定：先让学员交一件不合格的任务

理论上这节课可以这么讲：「哪些任务适合定时，哪些不适合，来我给你四条判据。」

**这样讲一定失败。** 学员会点头，会记下四条，然后回去把一件不该自动化的事自动化了——因为他不觉得那四条说的是他。

本节的顺序是反的：

```text
0–7 分钟     学员写下「我想让它每天替我做的那件事」（不给任何判据）
7–22 分钟    老师用四个问题逐个打回来
22–36 分钟   老师翻车两次给他们看，翻法不一样（一次现场跑，一次翻昨夜的账）
36 分钟      判断闸第一次出现，台词是「你们刚才回答的四个问题，不是四个问题」
```

**大多数人会挂在第二问。** 他说得出想让它干什么，说不出它干错了自己多久会知道。这个「答不出来」就是本节全部的教学动力。

### 0.4 第二个教学决定：演示必须翻车两次，而且翻法不同

只演示一次「它卡住了」，学员学到的是一个可以靠设置解决的小麻烦。

必须演示两次，因为**「卡住」有两种，学员只怕得到其中一种**：

| | 学员以为的卡住 | 真正更危险的那种 |
|---|---|---|
| 现象 | 它停在那儿等你批准，任务没动 | 它没停，它绕过去了，然后报告说做完了 |
| 你的感受 | 烦，但看得见 | 舒服，而且看不见 |
| 后果 | 事情没做 | 事情没做，但你以为做了 |

第二种是本节的支点。学员进教室时脑子里只有第一种。

### 0.5 本节在系列里的位置

```text
L6     诊断        它没有记忆，只有 context
L7     Subagent    给 context 分家
L8     Team        让成员的发现改变别人的下一步
L9     Legacy      三种债，知识债最贵
L10    四象限      信息在谁那里，决定谁该说什么
──────────────────────────────────────────────
L11    无人值守    以上全部，在你不在场的条件下重跑一遍
```

**L11 和 L10 的接口是明确的一条，必须讲出来：**

> L10 的隐藏区（你知道、它不知道），就是**它会来问你的地方**。
>
> 定时任务不给它问的机会。所以隐藏区必须在出发前搬空——这是 L10 的落盘动作第一次变成硬性要求，而不是好习惯。

这条承接不是修辞。它让 L10 那节理论课在 L11 变成一个具体动作，也让本节的任务书第 4 段（预答）有出处。

### 0.6 一处必须由讲师确认的东西

**学员到底能不能在课堂上建云端 routine，本蓝图无法替讲师判断。**

`/schedule`（云端 routines）要求 claude.ai 订阅登录。以下任一情况该命令直接不可用：Console API key 登录、Anthropic profile / federation 凭证、Bedrock / Vertex / Foundry 等云厂商登录、`DISABLE_TELEMETRY` 等关闭 feature flag 抓取的环境变量、组织策略关闭了 Routines。

所以本蓝图**不把任何一条通道设成课堂主线**，改为两条设计：

1. **课前 72 小时发一份通道自查**（§2.4），学员自己测出走哪条，课堂按通道分流。
2. **硬产物与通道解耦**。任务书是一份 prompt 骨架，三条通道都用得上，用不了任何一条的人也交得出来。

讲师课前必须定下来的五件事见 §16 附录 A。

## 1. 课程定位

### 1.1 全节立论

**开场立论（不在第一页说，在第 36 分钟判断闸出现时说）：**

> **能不能交给它自动跑，不取决于这件事有多难，取决于它做错的时候，你多久会知道、还救不救得回来。**

**收口立论（见 §0.2）：**

> **你消灭的不是那个问题，是那次提问。**

中间全部内容在回答三件事：**哪件事能交**（判断闸）、**交给哪条通道**（三选一）、**怎么让它卡不住而且卡住了你能知道**（三条做法 + 一条铁律）。

### 1.2 核心框架一：判断闸（四道，有顺序）

**不是四个格子，是一条链。前一道过不了，后面不用问。**

```text
             你想交出去的那件事
                     │
   ①  它做完，世界上多了什么？ ────── 说不出 ──▶ 这是愿望，不是任务。不能交。
      （一个能指名道姓的产物：一个文件 / 一条消息 / 一个 PR）
                     │
   ②  它做错了，你多久会知道？ ────── 不知道 ──▶ 先把回执加上，再谈自动。
      （判据必须在它之外——L6 铁律）
                     │
   ③  做错了，收得回来吗？ ────────── 收不回 ──▶ 降级：只让它提议，不让它生效。
      （开 PR 不许合 / 存草稿不许发）
                     │
   ④  中途有没有只有你能答的问题？ ── 有 ──────▶ 现在答完，写进任务书。
      （L10 的隐藏区）                            答不出 = 这件事今天还不能交。
                     │
                     ▼
        可以交。剩下的才是：走哪条通道、怎么让它不卡住。
```

**四道闸和任务书前四段是一一对应的**（§9.1），这是本节结构的骨架：闸①→目标，闸②→判据，闸③→边界，闸④→预答。剩下三段（出口、回执契约、重跑规则）由第四幕的翻车和断线现场推出来。

### 1.3 核心框架二：它跑不下去的两种情况——卡住，和断掉

学员会把这两件事混成一件（「反正就是没跑成」）。**必须拆开，因为处方完全不同。**

#### A · 卡住：它还活着，但不往前走了

```text
形态一 · 卡在权限上   它想做的事需要人批准      ──▶ 处方：提前批（选通道 + 白名单）
形态二 · 卡在问题上   它想问你一个业务决定      ──▶ 处方：提前答（任务书第 4 段）
形态三 · 卡在等待上   它在等一个不会来的东西    ──▶ 处方：给边界（超时 / 到点就退出）
```

#### B · 断掉：它没活到最后

**这是学员完全没想过的一块，也是真实世界里最常发生的一块。**

| 断法 | 现场长什么样 | 特点 |
|---|---|---|
| **网络断了** | 它要抓的东西抓不到，或者被网络策略挡在外面 | 最常见。**而且它经常不报错，它换个做法继续** |
| **凭证过期了** | 登录失效、令牌到期 | **无人值守的头号杀手**：它在你不知道的情况下，从某一天起就再也没跑成过 |
| **环境没准备好** | 依赖装不上、工具没连上、目录不在 | 每次冷启动都可能碰上 |
| **被限流 / 超时了** | 退避重试耗尽，或跑太久被掐断 | 长任务的默认结局 |
| **额度用完了** | 到了账号运行上限，这一次直接没起来 | **压根没跑**，但回执里看起来和「跑了没交东西」一样 |

**前四种断法有一个共同点，必须讲出来（第五种不一样，见下）：**

> **它们全都会给你一个「跑完了」的外观。**
>
> 进程退出了，记录上有一条，绿的。你要到很久以后才发现这三个月它一次都没成过。

#### C · 两个机制（本节要教的解法）

```text
断掉  ──▶  ① 结果契约   它必须交回一个固定形状的结论，脚本据此判成败
                          （不是让人去读一段自然语言报告）
            ② 重跑规则   断了从哪继续、能不能直接重跑、重跑会不会做两次
```

**顺序不能颠倒：没有结果契约，重试是盲目的**——你都不知道上次是成是败，重试只是把不确定的事又做了一遍。

### 1.4 核心框架三：四类风险

不列流水账，收敛成四类，每类给一个动作：

| 类 | 它长什么样 | 动作 |
|---|---|---|
| **静默** | 它没做成，但你以为做成了 | **结果契约**：要一个机器能判的状态，不要一段读起来很顺的报告 |
| **越权** | 它做了你没打算让它做的事 | 砍掉不需要的连接器 / 只让它提议不让它生效 |
| **漂移** | 它在你没预期的时间或状态下跑 | 把时间和前置状态写进任务书 |
| **注入** | 它读到的内容里有指令 | 任务书里写明：抓回来的东西是资料，不是命令 |

### 1.5 老师必须抓住的八个要点

1. **判断闸不许提前出现。** 第 36 分钟，一秒都不许早。提前给判据，第一幕就废了。
2. **第二问（多久会知道）学员会卡住，卡住就是教学内容**，不许救场。
3. **两次演示都必须真的翻车。** 演成功了这节课就没了。翻车形态见 §6。
4. **第二种翻车（它绕过去了）比第一种重要十倍。** 时间不够先砍第一种。
5. **卡住和断掉必须拆开讲。** 混着讲，学员回去只会加超时，不会加契约。
6. **不要教「怎么设置定时任务」，要教「交出去之前补什么」。** 设置本身十分钟，讲多了就成了工具课。
7. **铁律那一页（宁可交回「我没做」）是全节反转，前面只埋不点。**
8. **收口必须是一份写完的任务书，不是一句总结。** Exit ticket 收它。

### 1.6 最容易出错的五类地方

| 类型 | 容易错在哪里 | 当场纠正 |
|---|---|---|
| 定位 | 讲成 `/schedule` 使用教程 | 「设置十分钟就够，今天的九十分钟花在别处」 |
| 节奏 | 判断闸提前上屏，后面全在解释它 | 见 §10.1 铁律第 1 条，P10 之前不许出现任何四步图 |
| 深度 | 只演示「它卡住了」，不演示「它绕过去了」 | 见 §0.4，两次演示缺一不可 |
| 混淆 | 把「断了」当成「卡了」，只加超时不加契约 | 「超时只让它别耗着，契约才让你知道它到底成没成」 |
| 落地 | 收口是感想不是产物 | 硬产物是七段齐全的任务书，Exit ticket 现场收 |

## 2. 学员起点与课堂门槛

### 2.1 学员应已具备

- 完成 L1 到 L10。尤其 **L6**（它说「完成了」不算完成）和 **L10**（隐藏区）。这两节是本节立论的地基。
- 手上有一个自己的真实项目，**不要求能跑构建**。
- 一个能用的编码 Agent 环境（哪条通道都行，见 §2.4 自查）。
- **不要求会写 shell。** 第 7 段（重跑规则）写的是规则，不是脚本（见 §4 非目标）。

### 2.2 课前必须带来的东西（入场券）

> **一件你现在每周至少做三次、做的时候基本不用动脑的事。**

三条硬要求：

1. **你真的在做，不是「我觉得这个可以自动化」。** 假想任务填不出第二问和第四问。
2. **你说得出它做完之后世界上多了什么**——一个文件、一条消息、一个 PR。说不出的直接卡在闸①，那正好是教学素材，但每个班只需要两三个这样的例子。
3. **做错一次不会出人命。** 第一个自动化任务不许挑高风险的。真正想自动化的高风险任务留到作业。

### 2.3 没有合格任务的学员怎么办

按优先级三条兜底：

1. **回溯法**：拿他上周手工做过三次的一件事，倒回去过四道闸。**教学效果最好**，因为有真实结局可对照。
2. **借 L9 的老项目**：任务定为「每周把这周合并的改动追加进 `ARCHITECTURE.md`」——这条同时在还知识债。
3. **公开仓库兜底**：助教发一个公开仓库，任务定为「每天检查依赖是否有安全更新并开 PR」。这条最弱，因为第四问（只有你能答的问题）几乎是空的，**要提前告诉他这一点**，并在讲评时让他说出「我这一格为什么填不满」。

### 2.4 课前 72 小时：通道自查（本节特有，必须发）

学员在自己电脑上做三步，把结果带来：

```text
第一步  在 Claude Code 里敲  /schedule
        ├─ 能进入创建流程          → 你走【云端】
        └─ 提示 Unknown command    → 往下走
                                     （常见原因：不是 claude.ai 订阅登录、
                                       设了 API key / 云厂商凭证、
                                       关了 feature flag 抓取、组织策略关闭）

第二步  你有 Claude Code 桌面端吗？
        ├─ 有                      → 你走【本地】
        └─ 没有                    → 往下走

第三步  你能在自己机器上跑命令行、能写系统 cron / 计划任务吗？
        ├─ 能                      → 你走【命令行】
        └─ 不能                    → 课堂上只写任务书，课后再补通道
```

**课前通知稿：**

> 下节课请带**一件你现在每周至少做三次、做的时候基本不用动脑的事**（你自己的项目，能在课堂上打开，不含敏感信息）。
>
> 另外请在课前做一次三步自查（见附件），把「我走哪条通道」这个结果带来。**做不出通道的人也能上这节课**，硬产物不依赖通道。
>
> 不需要预习，不需要提前设置任何定时任务。**尤其不要在课前就把它跑起来**——课堂上要用你还没交出去的状态。

## 3. 学习目标

课程结束后，学员能够：

1. 说清本节和前十节的差别：**前十节假设你在场，本节把你拿掉**，并说出这条前提在 L6 / L7 / L8 / L10 各自哪里被用到过。
2. 用**四道判断闸**过一遍自己的真实任务，并说出自己挂在第几道。
3. 说清第二问（做错了多久知道）为什么排在第三问前面：**发现不了就谈不上收回**。
4. 区分**两种卡住**：停下来等你 / 绕过去接着跑，并说出后者为什么更危险。
5. **区分「卡住」和「断掉」**，并说出五种断法各自的现场表现，以及第五种（压根没跑）为什么和前四种性质不同。
6. 说清**凭证过期**为什么是无人值守的头号杀手：它不报错，它只是从某天起再也没成过。
7. 说出**三条通道**（云端 / 本地 / 命令行）在「要不要开机、能不能读本地文件、会不会弹权限、最小间隔」上的差别，并选出适合自己那件事的一条。
8. 说出「让它不卡住」的三条做法**各自的代价**，尤其是取消提问等于把决定交给它。
9. 守住铁律：**宁可交回一句「我没做，因为 X」，也不要交回一个它猜着做完的结果。**
10. 说清**绿灯不等于成功**，并因此说出**结果契约**存在的理由：进程状态是它给的，成功判据必须是你定的。
11. 写出一条**结果契约**：至少含一个机器可判的状态（做完了 / 没做 / 要人拍板），以及一条它之外的证据。
12. 说出**重试的前提是幂等**：重跑一次会不会把事情做两次；不确定就先让它只提议。
13. 认出四类风险各一个自己项目里的实例。
14. 写出一份**七段齐全的无人值守任务书**（五段给它看 + 两段给脚本看），并按 L5 的判断线决定要不要做成 Skill。
15. 说出在没有订阅 / 国内环境下，同一件事该怎么退而求其次，以及退让掉的是哪一项能力（§8.7）。

### 3.1 过关证据（全部落在产物形态，不落在标准答案）

学员离场前必须交出（针对自己那件真实的事）：

1. **一张过闸记录**：四道闸逐条的答案，以及自己挂在第几道。
2. **一条「只有我能答的问题」及其答案**——这是本节和 L10 的接口，必须有。
3. **一份七段齐全的任务书**（目标 / 判据 / 边界 / 预答 / 出口 ‖ 回执契约 / 重跑规则）。**课堂交付线见 §9.1**：A 块五段写实，B 块两段写到关键行；细化留作业。
4. **一条结果契约**：写明它必须交回什么形状的结论，以及其中哪一项是来自它之外的证据。
5. **一句幂等判断**：这件事重跑一次安全吗？不安全的话，第一版降级成什么。
6. **一条通道选择及理由**：走哪条、为什么、这条通道的代价是什么。

**第 3 项是本节的硬产物。** 第 1、2 项是过程痕迹，第 4、5 项是任务书里最新也最容易被跳过的两段，**助教巡场专查这两项**（§9.1）。没有第 3 项，这节课等于只上了一场讲座。

## 4. 非目标

- **不做 `/schedule` 的功能教程。** 不逐个讲创建表单的字段、不讲 GitHub 触发器的筛选语法、不讲 API 触发器怎么发请求。要用到的部分在 §8.1 一张对照表讲完。

- 不讲 CI/CD 工程（workflow 语法、runner、缓存）。只在通道表里出现一行。
- 不搭多任务编排流水线。本节只做「一件事，交对一次」。
- 不重讲 L7 / L8 的多 Agent 结构。

- 不给「哪些任务适合自动化」的标准清单。**每人的任务不同，本节不存在标准答案**——判断闸是工具，不是答案。

## 5. 第一幕 · 你先交（0 到 22 分钟）

**这一幕的原则：老师只问，不讲。** 每个问题投出来之后，老师闭嘴，学员写。

### 5.1 开场（0 到 7 分钟）

P00 封面**不许剧透**。标题是「**你不在的时候**」，不是「定时任务」「Schedule / Cron」这类词。真名首现在 P10。

P01 只说一句完成标准：

> 今天结束的时候，你手上会有一份东西，让你敢把一件事交给它在你睡觉的时候做。

P02 让学员写下来（4 分钟，安静）：

> **写一件你现在每周至少做三次、做的时候基本不用动脑的事。一句话，动词开头。**

### 5.2 四个问题的定稿措辞

**必须逐个投，一次只投一个，前一个收完再投下一个。** 四个问题看不出是一条链——那是 P10 才揭示的。

| # | 措辞（定稿，不许改写） | 时长 | 学员会怎样 |
|---|---|---|---|
| ① | **这件事它做完之后，世界上多了什么？用一个名词回答。** | 7–11 | 少数人答「就是……处理一下」，卡住 |
| ② | **它做错了，你多久会知道？** | 11–16 | **多数人答不出。这是全课支点。** |
| ③ | **它做错了，你收得回来吗？** | 16–19 | 答得快，但会低估「对外发出去」这类 |
| ④ | **中途它会不会需要问你一件只有你知道的事？** | 19–22 | 想不到。要给例子才启动 |

### 5.3 第二问会卡住，不要救场

这是本节的沉默时刻，等价于 L10 的第三问。

学员写不出「多久会知道」，是因为他从来没想过**这件事目前之所以没出问题，是因为他每次都在做的时候顺手看了一眼**。手工做的时候，检查是免费的、隐形的。自动化把这一眼拿掉了。

**追问只能用这三句（顺序不能改）：**

1. 「你上一次做这件事做错，是怎么发现的？」
2. 「如果那天你没做这件事，你会发现吗？」
3. 「那如果它做了，但做错了呢？」

第三句问完，教室会安静。**这就是要的效果。** 不要接着讲，直接投第三问。

> 这一问是后面**结果契约**那一页的全部动力来源。学员在这里越难受，P17 就越省力。

### 5.4 第四问需要给例子才启动

学员想不出「只有我知道的事」，因为对他来说那些事太显然了。给三个跨行业的例子，不给答案：

- 「这个仓库有两个分支看起来都像主干，只有你知道哪个是活的。」
- 「这类报错在你们这里一向不用管，只有你知道。」
- 「这件事做完要通知的人，只有你知道是谁。」

然后一句：「这样的事，你那件任务里有几件？」

## 6. 第二幕 · 换我：两次翻车（22 到 36 分钟）

### 6.1 演示 A · 它没卡住，它绕过去了（22 到 29 分钟）

**这是全节最重要的七分钟。**

形态：老师在命令行里让 Agent 无人值守地做一件**需要写文件**的事，但**只给它读的权限**。

学员预期：它会报错，或者停下来要权限。

实际发生：**它两样都不做。** 它绕过去——把本该写进文件的内容打印在报告里，或者改成「我建议你这样修改」，然后正常结束，退出码是成功的。

**老师这时候只说一句，然后停三秒：**

> 它没失败。它交了一份看起来做完了的东西回来。**而那件事没做。**

**必须现场把这一点坐实**：打开那个文件，让大家看见它没变。**不要用截图，要当场打开。**

> **原理（讲师必须讲出来，这是本节的机制层）：** 无人值守的会话**没有可以弹给你的提示框**，所以被挡住的动作不会执行，而**这个会话不会因此停下来**——它带着「这条路走不通」继续往下做。**它的目标是完成任务，不是保护你的意图。**
>
> **讲师注意分寸：「会话不会停」是有依据的，「它一定会绕道去做别的」是行为预期，不是保证。** 所以 §6.4 一级降级必须准备好。别在课堂上把它说成「它每次都会这样」。

> **让演示 A 更确定的一个做法（推荐）：** 与其靠「反复被挡」触发绕道，不如**直接把写文件那类工具从它的可见范围里摘掉**——工具不在它眼前，它根本不知道有这个选项，于是必然去找别的路。这比依赖阈值行为可靠得多。具体配置以当天官方文档为准（§19.3 第 5 条）。

### 6.2 演示 B · 它卡住了，挂在那儿等你（29 到 34 分钟）

形态：同一件事，改走**本地定时任务**通道，权限模式留在需要人工批准的那一档。

实际发生：任务到点起来了，跑到需要批准的地方停住，会话挂在侧边栏等你。**第二天早上你打开电脑，它还在那儿等。**

**老师这时候说：**

> 这次它老实。它没瞎猜，它在等你。
>
> 问题是——**它等的时候，你在睡觉。而它不会打电话给你。**

### 6.3 两种翻车并排（34 到 36 分钟）

把 §0.4 那张表投出来。**这是第一次给结构，但还不是判断闸。**

一句收口，为第三幕铺路：

> 你们进这个教室的时候，怕的是第二种。真正会伤到你的是第一种。
>
> 而这两种都不是靠「设置得更仔细」能解决的。

### 6.4 兜底（演示必须有降级路径）

**两次演示的形态不同，不要搞混：**

- **演示 A = 课上现场跑。** 课前必须跑通至少一次（目的是确认它会绕道），课上重跑。
- **演示 B = 展示一个前一天就挂住的会话，不是现场跑。** 这一条没得商量：演示 B 要证明的是「它等了一夜也没人理」，**这件事在五分钟的课堂时段里物理上演不出来**。现场建一个再等，只会等到一个刚挂住三十秒的会话，说服力为零。

三级降级：

| 级别 | 情况 | 做法 |
|---|---|---|
| 一级 | 演示 A 没绕过去，它真的报错停了 | 承认：「今天它选了另一条路。」然后放**预录**——预录是必备物料，不是备份 |
| 二级 | 断网 / 工具故障 / 凭证过期 | 直接放预录，并把这次故障本身当素材：**「你们刚看到的就是第 61 分钟要讲的五种断法之一」**——这是本节唯一一次故障可以当场变成教材 |
| 三级 | 投屏挂了 | 口述两种翻车 + 用 P09 那张表，**演示 B 可以砍，演示 A 不许砍** |

## 7. 第三幕 · 判断闸第一次出现（36 到 47 分钟）

### 7.1 揭示（36 到 40 分钟）

第一句台词固定：

> **你们刚才回答的四个问题，不是四个问题。它们有顺序。**

然后逐条把 §1.2 那张图放出来，讲清**为什么是这个顺序**：

- 闸①在最前，因为**说不出产物的事根本不是任务**，后面三问无从问起。
- **闸②排在闸③前面**，这是本节唯一需要解释顺序的地方：收不回来但你马上知道，还能补救；发现不了，收得回来也没用，因为你不知道要收。
- 闸④在最后，因为它最贵——前三道都过了才值得花这个力气。

这里说开场立论（§1.1）。

### 7.2 回收前十节（40 到 44 分钟）

**这一页证明本节不是新话题，是旧内容在新条件下重跑。**

| 前面哪一节 | 当时的说法 | 你不在场时变成什么 |
|---|---|---|
| L6 | 它说「完成了」不算完成，判据要来自它之外 | **判据必须写成契约**——因为没人替它验 |
| L6 | 认出该打断的三个信号 | **打断信号没人看**，只能提前写成边界 |
| L7 | 汇总是你的活 | 汇总变成**回执契约**，它得替你先摘成固定形状 |
| L10 | 隐藏区：你知道它不知道，你不说它就编 | **隐藏区必须在出发前搬空**（闸④） |
| L10 | 开放区会退化成隐藏区 | 定时任务是**退化最快的地方**：它每天读同一份过期文件 |

最后一条要单独强调：**一个跑了三个月的定时任务，是全项目最老的那份 context。**

### 7.3 隐藏区 = 它会来问你的地方（44 到 47 分钟）

把 L10 的接口讲实：

> 上节课说隐藏区是「你知道、它不知道」的那一格。当时的处方是落盘，属于好习惯。
>
> 今天它不是好习惯了。**它会来问你的地方，就是隐藏区。而定时任务不给它问的机会。**
>
> 所以闸④只有一种通过方式：**现在答完，写下来。答不出来，这件事今天就还不能交。**

## 8. 第四幕 · 怎么设，会出什么事（47 到 78 分钟）

### 8.1 三条通道（47 到 52 分钟）

**一张对照表讲完，不展开任何一条的操作步骤。**

| | 云端 | 本地（桌面定时任务） | 命令行（系统调度 + 无人值守会话） |
|---|---|---|---|
| 跑在哪 | 服务商托管的云端 | 你的机器 | 你的机器 / 你的服务器 |
| 要不要开着机器 | 不要 | **要，而且不能睡** | 要 |
| 能不能读你本地文件 | **不能**（每次重新克隆仓库） | 能 | 能 |
| 会不会弹权限 | **不会**（结构上就没有审批） | **会**（按任务配置，配不对就挂着等） | 由你启动时的参数决定 |
| 最小间隔 | 小时级 | 分钟级 | 分钟级 |
| 错过了会怎样 | **官方文档没写补跑规则**（当天核对，别替它承诺） | 机器睡着就跳过，醒来最多补跑一次 | 看你的系统调度器 |

**每一行都要落到一个「所以」**，不要念表：

- 「不能读本地文件」→ 所以那些依赖你机器上某个没提交的文件的任务，云端做不了。
- 「不会弹权限」→ 所以它在云端能做的每一件事，你都没有机会拦。**这是便利，也是本节最大的风险来源。**
- 「机器睡着就跳过」→ 所以你定的九点，可能在晚上十一点才跑。**时间必须写进任务书**，不能靠调度器保证。

> **数据纪律：** 上面的最小间隔、补跑规则、每日额度这类数字**会变**，deck 上不写死具体数值，讲师课前按官方文档当天版本核对（见 §19.3）。

### 8.2 选哪条 + 「不卡住」的三条做法及其代价（52 到 59 分钟）

选择线一句话：

> **要读你机器上的东西 → 本地。要它在你关机时也跑 → 云端。都不满足或都不可用 → 命令行。**

三条做法**必须连代价一起讲**，只讲做法就是在教人踩坑：

| 做法 | 怎么做 | 代价（必须讲） |
|---|---|---|
| **提前批** | 把它需要的工具逐条预先批准 | 你批的是**工具类别**，不是**具体那次**。批了「能改文件」，它改哪个文件你管不着 |
| **取消问** | 用一种「不询问、不等待」的模式跑 | 它连**该问的问题**也不问了。业务决定它自己做 |
| **全放开** | 关掉所有检查 | **只在隔离容器里做。** 这个模式对内容注入没有任何防护 |

讲完三条，停一下，说本节的关键推论：

> 这三条都能让它不卡住。**但没有一条能让它做对。**
>
> 因为你取消的只是那次提问，**那个决定还在，只是换人做了。**

**收口立论在这里第一次说。** 然后立刻推出任务书第 4 段（预答）的必要性。

### 8.3 铁律：正确的失败方式（59 到 61 分钟）⭐ 反转

前面所有内容都在教「怎么让它跑下去」。这一页反过来：

> **无人值守的任务，宁可交回一句「我没做，因为 X」，也不要交回一个它猜着做完的结果。**

配一句可以直接抄进任务书的话（这是任务书第 5 段「出口」的原型）：

> 遇到你不确定的地方，**不要猜，不要绕**。停下来，把「卡在哪、缺什么、需要谁拍板」写进 `<回执文件>`，然后正常结束。**没做完不算失败，猜着做完才算。**

**讲师必须点破这句话的机制：** 默认情况下，Agent 会把「完成任务」排在「保护你的意图」前面。这句话是在**给它一个比完成任务优先级更高的合法退出**——没有这个出口，它只剩绕道一条路。

### 8.4 中途会出的事：五种断法（61 到 66 分钟）

**过渡句（把卡住和断掉切开）：**

> 到这里为止我们讲的都是「它还活着，但不往前走」。接下来是另一类：**它根本没活到最后。**

按 §1.3-B 的表逐条讲，每条只要一个现场画面：

1. **网络断了** —— 它要抓的东西抓不到，或被网络策略挡在外面。**重点：它经常不报错，它换个做法继续**（这就是演示 A 的另一种形态）。
2. **凭证过期了** —— **本段的重点，要单独停一下**。登录失效之后，它不会尖叫，它只是从那天起再也没成过。等你想起来去看，已经过去三个星期。
3. **环境没准备好** —— 依赖装不上、工具没连上、目录不在。冷启动环境每次都可能碰上。
4. **被限流 / 超时了** —— 退避重试耗尽，或跑太久被掐断。长任务的默认结局。
5. **额度用完了** —— 到了账号的运行上限，**这一次根本没起来**。它和前四种不一样：前四种是跑了没成，这一种是压根没跑。**而「没跑」在你的回执里长得和「跑了但什么都没交」一模一样。**

**收口一句（引出后面两页）：**

> 前四种断法有一个共同点：**它们全都会给你一个「跑完了」的外观。**
>
> 第五种更狠：**它连外观都没有。** 你的回执里什么都没有——而「什么都没有」和「它跑了但没交东西」，在你眼里长得一模一样。

### 8.5 绿灯不等于成功 → 结果契约（66 到 71 分钟）⭐

**这两页是连着的一个论证，不许拆开讲。**

**第一步（问题）：**

> 运行记录里那个绿灯，意思是**进程正常退出了**。
>
> 它不意味着你的任务做成了。网络被挡、凭证过期、它绕过去了——**这些全都会给你一个绿灯。**

接回演示 A：

> 第 22 分钟你们看到的那次，如果它是在凌晨三点跑的，你早上看到的就是一个绿灯。

**第二步（解法）：结果契约**

> 绿灯是**它给你的**。你需要一个**你自己定的**成功信号。

契约的最小形状（这就是任务书第 6 段）：

```text
它跑完必须留下一份结论，里面至少有：

  状态    done | skipped | needs-human      ← 机器能判的三选一，不许自由发挥
  证据    一条来自它之外的检查结果          ← L6 铁律，不是它自己说"我验过了"
  原因    不是 done 的时候，一句话说清卡在哪
```

**三个状态为什么是三个，不是两个**（这一条要讲，是本页的深度）：

> 只有「成功 / 失败」两个状态的时候，它会把「我没做」也塞进成功里——因为它确实正常结束了。
>
> **`needs-human` 这一档，就是第 59 分钟那条铁律的机器形态。** 你给了它一个体面的退出，它才不会去猜。

**然后是脚本那一半：**

> 有了这三个状态，外面那个脚本才有事可干：`done` 就安静，`needs-human` 就叫你，什么都没有就报警——**「什么都没有」是最重要的一种，因为那说明它连结论都没交，多半是断在半路。**

> **机制补充（讲师可讲，deck 不写死）：** 命令行通道支持让 Agent 按你给的结构输出，脚本据此解析；进程退出码也可以让脚本分支。**但不要教语法，只讲「契约要写死形状，别让它自由发挥」这条原则。**

### 8.6 重试与幂等（71 到 74 分钟）

**顺序不能颠倒：先契约，后重试。**

> 没有契约的重试是盲目的——你都不知道上一次是成是败，重试只是把不确定的事又做了一遍。

三个层次，讲清楚谁负责什么：

| 谁在重试 | 它管什么 | 你别指望它管什么 |
|---|---|---|
| **Agent 自己** | 一次网络抖动、一个临时错误 | 它不管「这件事整体上失败了」 |
| **调度器** | 下一个周期自然会再跑一次 | 中间那一次的损失没人补 |
| **你的脚本** | **按契约判，该重跑就重跑，该叫人就叫人** | 得你自己写规则 |

**然后是本段的关键提问，必须让学员当场答自己那件事：**

> **这件事重跑一次，安全吗？**
>
> 会不会开出两个一模一样的 PR？会不会把同一条消息发两遍？会不会把同一笔数据算两次？

三条处理原则：

1. **能重跑的（幂等）** —— 放心让脚本重试。判断方法：**跑两次和跑一次结果一样吗？**
2. **不能重跑的** —— 第一版**先降级成只提议不生效**（对上闸③），等你信得过了再放开。
3. **不确定的** —— 当成不能重跑处理。

> 一句收口：**「重试」不是勇气问题，是幂等问题。**

### 8.7 没有订阅 / 国内环境怎么办（74 到 78 分钟）

**必讲，不许砍。** 只讲能力维度，不排名、不点评具体产品版本能力。

同一件事在受限环境下的退让路径：

```text
云端托管定时（要开机？不要）
        │  用不了
        ▼
本机调度器 + 无人值守会话（系统 cron / 计划任务 + 命令行 Agent）
        │  用不了
        ▼
CI 的定时触发（把仓库当运行环境）
        │  用不了
        ▼
只写任务书，人工按它执行 —— 任务书本身仍然有效
```

**明确告诉学员每退一步失去什么**（这是本段的价值所在，不是安慰）：

| 退到哪 | 失去的能力维度 |
|---|---|
| 本机调度器 | 关机就不跑；要自己管凭证和日志 |
| CI 定时 | 读不到本地文件；每次冷启动；调试回路长 |
| 只有任务书 | 失去「自动」，但**判断闸和七段结构完全保留** |

**这一段还要专门说一句**（对上 §8.4 的凭证过期）：

> 换了通道，凭证过期这条不会消失，只会换个样子——**订阅登录会过期，API key 会被轮换，公司代理的证书会换。**
>
> 所以第 6 段的契约里，「什么都没交回来」必须是一种会报警的状态。

最后一句：

> 通道会变，会被墙，会改名，会涨价。**任务书不会。**

## 9. 第五幕 · 落地（78 到 90 分钟）

### 9.1 动手：写你自己的任务书（78 到 86 分钟）

**只给骨架，不给范文。** 给了范文，交上来的就全是范文的变体。

> **时间必须说清楚，否则这一段必然崩。** 这八分钟里 P25（原理页）要占掉约 2 分钟，**学员实际动笔只有 6 分钟**。六分钟写不完七段的完整内容，所以课堂交付线定在这里：
>
> - **A 块五段：每段写实**，能读懂、能照着执行。
> - **B 块两段：各写到关键行就够**——第 6 段写出三个状态 + 一条外部证据；第 7 段写出一句幂等结论（安全 / 不安全 / 不确定，不安全的写降级成什么）。
> - **细化**（证据怎么取、原因怎么措辞、降级方案怎么落）是**作业第 1 项**，不在课堂。
>
> 老师投这一页时要把这条线讲出来。**不讲，学员会想把七段都写完美，然后一段都没写完。**

**投出来的时候必须先讲这个结构，一句话：**

> 这份任务书分两块。**前五段是写给它看的，后两段是写给盯着它的那个脚本看的。**
>
> 无人值守从来不是「一个 Agent 自己跑」，是「**一个 Agent，加一个盯着它的东西**」。少了后面那半，你就是在赌。

```text
【无人值守任务书】

A · 给它看的（写进 prompt）
  1. 目标      跑完之后，世界上多了什么？（一个名词）
  2. 判据      我怎么知道它成了？（一条来自它之外的检查）
  3. 边界      不许碰什么？（路径 / 分支 / 对外发送）
  4. 预答      它可能问我的三个问题，答案先写在这
  5. 出口      不确定的时候：不要猜，写进 ____，然后正常结束

B · 给脚本看的（写进调度）
  6. 回执契约  它必须交回什么形状的结论
               状态：done / skipped / needs-human
               证据：一条来自它之外的检查结果
               原因：不是 done 时，一句话说清卡在哪
               —— 什么都没交回来 = 报警
  7. 重跑规则  这件事重跑一次安全吗？
               安全 → 脚本可以直接重试
               不安全 → 第一版只提议不生效
               不确定 → 当成不安全处理
```

**七段的来历必须让学员看见**（这决定了他回去会不会用）：

| 段 | 来自哪 |
|---|---|
| 1 目标 | 闸① |
| 2 判据 | 闸② + L6 铁律 |
| 3 边界 | 闸③ |
| 4 预答 | 闸④ + L10 隐藏区 |
| 5 出口 | §8.3 铁律 |
| 6 回执契约 | §8.5 绿灯不等于成功 |
| 7 重跑规则 | §8.6 幂等 |

**助教巡场只查三件事**（其余不管）：

1. **第 4 段是不是空的。** 空的就是没过闸④，追问「真的一个都没有？」
2. **第 2 段的判据是不是它自己说了算。** 写「它确认已完成」的，退回重写。
3. **第 6 段有没有 `needs-human` 这一档。** 只写了成功 / 失败两档的，退回——**这是本节最容易被省掉的一格**。

### 9.2 原理页：这七段为什么这么组词（穿插在 9.1 中间讲，讲完切回动手页）

**这一页是系列的固定要求，不许省。** 学员要的不是这一份模板，是以后面对新场景自己能组词。

逐条讲**为什么这样写**，不是讲每段填什么：

- **为什么目标要用名词，不用动词？** 动词是过程，名词是产物。产物才能被检查，过程只能被相信。
- **为什么判据必须来自它之外？** 因为让它自己判断自己做完没有，等于没有判据（L6 铁律）。
- **为什么边界写成否定句？** 「不许碰 X」比「只碰 Y」可靠：Y 你列不全，X 你划得清。**显式收窄范围比穷举授权有效。**
- **为什么预答要写成问答，不写成背景资料？** 资料它会跳读，问答是它需要那个答案时能对上号的形状。
- **为什么出口要给一个具体文件名？** 「不确定就停下」是态度，「写进这个文件」才是动作。**没有落点的指令等于没有指令。**
- **为什么状态要写死成三个词，不让它自己描述？** 因为**自然语言没法被脚本判**。你要的不是一段读起来很顺的报告，是一个能触发动作的信号。**写死枚举值，是把「人来读」变成「机器来判」的唯一办法。**
- **为什么要有 `needs-human` 这一档？** 因为二选一会逼它撒谎——它没做成，但也确实正常结束了，于是它填「成功」。**给它第三个选项，就是给它说实话的余地。**
- **为什么重跑规则写在任务书里，而不是留给脚本？** 因为幂等不是脚本的属性，是**这件事本身的属性**。只有你知道它重跑安不安全。

### 9.3 讲评（86 到 88 分钟）

**规则：只问「你挂在第几道闸」和「你的 needs-human 是什么样子」，不判任务好坏。**

一判好坏，整个框架当场退化成「老师觉得哪些事能自动化」，学员回去就不用了。

优先抽两类人：

1. **第二问答不出来的那几个**（P04 举过手的）：让他说一句「我为什么答不出来」。
2. **第 7 段填「不安全」的**：让他说「所以我第一版打算降级成什么」——**这类人是全班最该被听见的**，因为他做出了本节最正确的一个决定：先别全自动。

### 9.4 收口与作业（88 到 90 分钟）

**收口是一个动作，不是总结。** 接 L5：

> 这份任务书你要是写到第三份，就该发现七段里有四五段每次都一样。
>
> **一样的那几段，就是一个 Skill。**

Exit ticket 现场只收一题（见 §13.2）。

### 10.1 节奏铁律

1. **P10 之前不许出现任何四步图、闸门图或「判断线」三个字。** 违反这条，第一幕全废。

7. **P23（国内环境）不许砍。**
8. **P24 的八分钟里老师不许连续讲超过 90 秒。** 中途只插 P25 一次。

### 10.2 时间超支的三级砍法

## 12. 高频失败模式

| # | 失败长什么样 | 根因 | 防它的做法 |
|---|---|---|---|

## 13. 评分与 Exit ticket

### 13.1 课堂评分（12 分 · 过关线 10）

| 维度 | 分 | 给分标准 |
|---|---|---|
| 过闸记录 | 2 | 四道闸都有答案，且说得出自己挂在第几道 |
| 闸④非空 | 2 | 至少一条「只有我能答的问题」+ 它的答案。**空的不给分**——但走 §2.3 第 3 条公开仓库兜底的学员例外：他说清「我这一格为什么填不满」同样满分（这一格本来就该是空的，不是他没想） |
| 判据在它之外 | 2 | 第 2 段不是「它确认已完成」这类自证 |
| 回执契约 | 2 | 三个状态齐全（含 `needs-human`）+ 一条外部证据 |
| 重跑规则 | 2 | 有明确的幂等判断；判「不安全」并给出降级方案的**同样满分** |
| 通道选择 | 2 | 选了一条 + 说得出这条的代价 |

**评分纪律：不对「这件事该不该自动化」打分。** 学员判断「我这件事现在不能交」并说清理由的，是满分答案，不是失败。

### 13.2 Exit ticket（7 题，现场只收第 7 题）

1. 你那件事挂在第几道闸？没挂就写「四道全过」。
2. 第二问（多久会知道）你的答案是什么？
3. 你的闸④里，「只有你能答的问题」是哪一条？
4. 你选了哪条通道？它的代价是什么？
5. 你的 `needs-human` 会在什么情况下出现？举一个具体场景。
6. 你那件事重跑一次安全吗？不安全的话，第一版降级成什么？
7. **交你的任务书（七段）。** ← **现场只收这一题**，其余课后提交。

**第 7 题必须收实物**（照片、文件、粘贴都行）。收不上来的人，这节课对他没有发生。

## 14. 作业

### 必做

1. **把课堂那份任务书真的挂上去跑一次**（任一通道，跑不了通道的人手工按任务书执行一次），把第一次的回执贴出来。
2. **故意让它断一次**：切网、改错一个路径、或者把凭证临时失效，看你的契约有没有把这件事报出来。**没报出来就是契约没写对**，改了再交。
3. 回答一句：**第一次跑完之后，你改了任务书的哪一段？** 几乎所有人都会改第 6 段。

### 选做扩展

4. 把第 4 段（预答）里那几个答案，落进项目里一个长期文件——这是 L10 的落盘动作在本节的延续。
5. 连着跑一周，然后回答：**这七天里它有没有哪一天其实没成，但你以为它成了？**
6. 写到第三份任务书时，把重复的那几段做成 Skill（接 L5）。
7. 拿一件你**判过「现在不能交」**的高风险任务，写出「它要满足什么条件我才敢交」。

## 15. 老师课前准备

### 15.1 演示准备（最重的一块）

- **演示 A 必须课前跑通至少一次，目的是确认它会绕道，不是确认它会成功。** 如果课前那次它老实报错了，换一个任务，直到找到一个它会绕道的。
- **两段预录都要录**（演示 A / 演示 B 各一段，各不超过 90 秒），存本地，不依赖网络。
- 演示用的项目**必须是老师自己的真实项目**，不许用本课程仓库自己的文件、Skill、目录当例子（见 §19.2）。
- 投屏前确认：不含敏感信息、不含真实凭证、终端字号够大。
- 演示 B 的任务要**提前一天**建好并让它跑过一次挂住，课上直接展示那个挂了一夜的会话——比现场等更有说服力。

### 15.2 材料准备

- 课前 72 小时发出通道自查（§2.4）+ 入场券要求（§2.2）。
- **回收自查结果**，统计三条通道各多少人，课堂按此分流（§16 A.5）。
- 打印或发放任务书七段骨架（空白），人手一份。
- 准备三个「只有你知道的事」的跨行业例子（§5.4），至少一个非技术行业。

### 15.3 学员准备（课前 72 小时发出）

见 §2.4 通知稿。**额外强调一句：不要提前把任务跑起来。**

## 16. 附录 A：讲师必须在课前填的空

本蓝图无法代填，deck 和 RUNSHEET 里要给这五处留位置。

### A.1 演示 A 的具体任务

哪个项目、让它做什么、只给什么权限、预期它会怎么绕道。
**要求：老师自己的项目；那件事必须是「必须写文件才算做完」的。**

### A.2 演示 B 的通道和档位

走哪条通道、权限停在哪一档、提前一天建好的那个任务叫什么。

### A.3 老师自己的一次真实翻车

**开场第二幕的可信度全靠这一句。** 从下面挑一件真发生过的：

- 一个定时任务凭证过期了，你 ___ 天后才发现。
- 一个任务连着跑绿灯，直到你去看产物才发现它三周没做成过。
- 一次它绕过去了，你按它的报告以为做完了。

**必须说出具体多久之后发现的。** 说不出天数的，这个素材不能用。

### A.4 老师自己那份任务书

用于讲评时露一段，**不投给学员当范文**（§12 第 9 条）。

### A.5 学员通道分布

课前自查回收结果：云端 ___ 人 / 本地 ___ 人 / 命令行 ___ 人 / 都用不了 ___ 人。
**「都用不了」超过三分之一时，P13 的讲法要调整**：先讲第三条通道，再讲云端。

## 17. HANDOUT 必须包含的材料

`HANDOUT.md` 是学员带走的版本，要能脱离课堂读懂：

## 18. RUNSHEET 必须包含的材料

`RUNSHEET.md` 是讲师逐分钟讲稿：

## 19. 事实与数据纪律

### 19.1 概念与机制出处

- **「它没有记忆，只有 context」**：L6 立论，标明来源，不要当本节发明。
- **「它说完成了不算完成，判据要来自它之外」**：L6 铁律。本节的结果契约是它的机器形态。
- **隐藏区 / 四象限**：L10 框架，本节只借用作闸④的锚点，**不重讲**。
- **三条通道的能力差异、权限行为、调度限制**：均来自工具官方文档，**属于会变的产品行为，不是原理**。deck 上以能力描述呈现（「不会弹权限」），**不写死具体参数名、版本号、数值**；讲师口播时可以给具体参数，RUNSHEET 里标注「当天核对」。
- **结果契约的三状态**：本课的教学设计，不是任何工具的内置机制。**deck 和讲义必须写明这是约定，不是功能。**
- **「三条通道」这个分法是本课的教学分类，不是官方文档的分法。** 官方把定时分成 云端 / 桌面本地 / **会话内循环** 三种；本节用「命令行（系统调度 + 无人值守会话）」换掉了会话内循环，理由是**后者随会话消亡、且有自动过期，结构上不适合无人值守**。**讲义要写明这个替换和理由**，否则学员去翻官方文档会发现对不上。

### 19.2 课堂数据纪律

- deck 不出现具体模型名、价格、上下文长度数字。
- **不用本课程仓库自己的文件、Skill、目录当教学例子。** 老师用自己的项目，学员用自己的项目。
- 国内工具只讲**能力维度**，不排名、不写具体产品的版本能力。合规部分只讲「要确认哪两条条款」，不替学员做合规判断。
- **本节没有标准答案。** 每位学员的任务不同，deck、讲义、评分表里都不许出现「正确答案应该是」。
- 学员的任务内容属于他自己的材料，**不许要求投屏或上交任务原文**，只上交任务书结构和过闸结论。
- 演示投屏前确认不含敏感信息与真实凭证。

### 19.3 需要课前核对（本节比前几节更重要）

**定时与自动化相关的产品行为变化很快，其中一部分仍在预览阶段。以下每一条都必须在开课当天重新确认，不许凭上次上课的记忆：**

1. `/schedule` 当天是否可用，创建流程的字段有没有变。
2. 云端定时任务当天是否仍然「运行中不弹审批」。**这条是 P13 和 P15 的立论基础，变了整节课要改。**
3. 本地定时任务在「需人工批准」档位下，是否仍然挂起等待（演示 B 的全部依据）。
4. 最小间隔、错过补跑规则、每日运行额度的**当天数值**。
5. 演示 A 那条命令当天的实际行为：它到底会绕道，还是会报错停下。
6. 结构化输出与退出码的当天行为（讲义第 7 项伪代码的依据）。
7. **云端定时任务错过 / 失败之后有没有补跑或重试**（§8.1 表里这一格当前写的是「文档没写」，如果当天文档补上了，表要改）。
8. **账号运行额度的当天口径**（§8.4 第 5 种断法的依据）。
9. 官方文档以 <https://code.claude.com/docs> **当天版本**为准，不凭记忆写进讲义。
