## P01 ｜ 4–14 分钟 ｜ 这条规矩在这个文件里躺了三个月 🎬 现场跑

**口播（开场，念完再动手）：**

> 换我。这是我自己的项目。

打开你的 CLAUDE.md，指着 K.1 那条规矩。

> 这条规矩写在这儿。它在这个文件里躺了 **___**（填 K.1 的时长）。
>
> 它每一次会话都读到这一条。
>
> 现在我让它做一件会违反这条的事。你们盯两件事：一，它读没读到；二，它照没照做。

**现场动作：**

1. 起跑。**跑的过程中不要解说**，让学员自己看。
2. 它违反了之后，**先把 CLAUDE.md 那条规矩再指一遍**，再指它刚做的事。
3. 停三秒。

**收口口播（这三句是这一页的全部）：**

> 这条规矩在那个文件里躺了三个月。它每次会话都读到。
>
> **读到，不等于照做。** ← 🔥 埋点 1

**接着必须回答「为什么」—— 这一段是全课的机制底座，别用比喻糊过去。**

> 🚨 **讲师注意**：学员这时候一定会想「可它明明读到了啊」。你要是只答「因为它把 CLAUDE.md 当成一段可以权衡的文字」，那是**比喻不是机制**，追问一句你就没词了。
> **完整的四层诊断在 §N**，课上只讲**下面这三句**（约 1 分钟），把深的留到答疑和讲义。

**课上口播（三句，一句一停）：**

> 第一，**它可能根本没读到。** CLAUDE.md 不是「一直都在」的 —— 它是**按需加载**的：进到某个子目录才加载那一层，碰到匹配的文件路径才加载对应规则。而且**上下文一压缩，早先加载的东西可能就被摘掉了**。
>
> 第二，**就算读到了，它也在做权衡。** 你三个月前写的那行，和你刚才说的那句话，都在它眼前。上节课我们说过一句：**它的目标是完成任务，不是保护你的意图。**
>
> 第三，也是最要命的一条 —— **它是在「选」，不是在「执行」。**

**然后投官方那句原文，这是全节的支点：**

```
Hooks ... give you deterministic control: certain actions always happen
rather than relying on the LLM to CHOOSE to run them.
```

> 官方自己的用词是 **choose**。
>
> **你写进 CLAUDE.md 的每一条，都是在等它「选」照做。** 今天要给你的，是不用它选的那个东西。

**硬停 14 min。**

> 🚨 **五种走向见 §D。** 最可能的两种：它违反了（理想），或它这次老实了（承认，放预录）。
> 🚨 **分寸**：说「读到不等于照做」，**不要说「它一定不照做」**。后者是错的，而且课前那次可能就打你的脸。
> 🔥 **埋点 1 必须说出口**，P05 要回收。

### 第一步 · 建脚本（Node）

> 在你项目里建这个文件：`.claude/hooks/protect-files.mjs`

```js
#!/usr/bin/env node
// .claude/hooks/protect-files.mjs

process.stdin.setEncoding('utf8');
let raw = '';
for await (const chunk of process.stdin) raw += chunk;

const { tool_input = {} } = JSON.parse(raw || '{}');
const file = (tool_input.file_path ?? '').replaceAll('\\', '/');

const PROTECTED = ['.env', 'package-lock.json', 'node_modules/', '.git/'];

const hit = PROTECTED.find((p) => file.includes(p));
if (hit) {
  console.error(`Blocked: ${file} 命中保护规则 '${hit}'`);
  console.error('改配置请改 .env.example，依赖请用 npm install。');
  process.exit(2);
}

process.exit(0);
```

> 🚨 **出处要说清楚（蓝图 §21.1 纪律）**：
> **官方文档给的是 bash + `jq` 版。** 上面是它的 **Node 等价实现**，属于「本课写法」。
> 学员回去翻文档会看到 bash 版，**你不说，他会以为对不上。**

**边敲边说这三句（每句都有后面的回收点）：**

> `.mjs` —— **扩展名必须是这个**（或者 `package.json` 里有 `"type": "module"`），不然 top-level await 会报语法错。**这是 Node 版的排错第一名。**
>
> `process.exit(2)` —— **拦住**。上面那两行 `console.error` 走的是 stderr，**它会收到那两句话**。
>
> `PROTECTED` 这个数组里的四项 —— 都是 Node 项目真会被误改的东西。**`node_modules/` 那条尤其值钱。**

> 💡 **可以顺口说一句，很有说服力**：
> 「我们不装 `jq`，因为**它从来不是这个机制的一部分**。你们等一下会看到，机制只有三行 —— 用 Node 写、用 bash 写、用 Python 写，**那三行一模一样**。」

---

### 第二步 · 挂上去

> 打开项目里的 `.claude/settings.json`（没有就新建）：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/protect-files.mjs\""
          }
        ]
      }
    ]
  }
}
```

**边敲边说三句（每句都是后面要回收的）：**

> `PreToolUse` —— **它动手之前**。这个词等一下第四幕我们要专门讲。
>
> `matcher: "Edit|Write"` —— 只管这两个工具。它跑 Bash、读文件，这个 hook 不响。
>
> `node "$CLAUDE_PROJECT_DIR/..."` —— 两件事：**用 `node` 起，所以不需要 `chmod +x`**（bash 版的排错第一名在 Node 版里根本不存在）；**别写相对路径**，hook 跑的时候工作目录不一定是这儿。

> 🚨 如果学员的 `settings.json` 里已经有 `hooks` 这个 key，**要把 `PreToolUse` 加成兄弟键，不是替换整个对象**。这条一定要说，不说会有人把别的配置覆盖掉。

> **不该拦的放过了** —— 证明它**没误伤**。

> **一会儿我就让你们亲手做出那种脚本。** ← 🔥 为 P06 翻车①埋线

## P05 ｜ 36–40 分钟 ｜ 你刚才做了什么 ⭐ 三行机制

**口播（开场）：**

> 趁你手感还在，我讲一下你刚才到底做了什么。**只有三行。**

**投这张图：**

```
   它给你   ──▶  一坨 JSON 进 stdin

                 {
                   "hook_event_name": "PreToolUse",
                   "tool_name": "Write",
                   "tool_input": { "file_path": "/你的项目/.env" },
                   "cwd": "/你的项目",
                   "session_id": "abc123"
                 }

   你给它   ──▶  exit 0   我不表态，走正常权限流程
                 exit 2   拦住，stderr 那句话变成给它看的反馈
```

**现场动作：**

- ⭐ **把学员刚写的那个脚本调出来，逐行对上去。** 这是本页的全部价值 —— 三行机制不是抽象概念，是他五分钟前刚敲进去的东西。

```js
let raw = '';
for await (const c of process.stdin) raw += c;   // ← 这是「收」

const { tool_input } = JSON.parse(raw);
const file = tool_input.file_path;               // ← 这是「挑」

if (file.includes('.env')) {                     // ← 这一行就是你的规矩
  console.error('Blocked: ...');                 // ← 这是「说给它听」（stderr）
  process.exit(2);                               // ← 这是「拦」
}

process.exit(0);                                 // ← 这是「不表态」
```

> 💡 **这里补一句，回收第一步那个伏笔**：
> 「官方文档那段是 bash 写的，我们这段是 Node 写的。**你对一下 —— 收、挑、判、说、拦，一模一样。**
> **语言不是机制。** 你用 Python、用 Go、用任何能读 stdin 和设退出码的东西写，都是这三行。」

**然后点破一个必踩的坑：**

> 最后这个 `exit 0`，**不叫「放行」，叫「我不表态」。**
>
> 官方原话：

```
Exit 0: your hook reports no objection through its exit code.
For a PreToolUse hook this doesn't approve the tool call:
the normal permission flow still applies.
```

> 翻译：exit 0 之后，该弹权限还是会弹。**把 exit 0 当放行的人，会以为自己批准了，其实什么都没发生。**

**硬停 40 min。**

### 排错三板斧（这一页顺手给，学员回去天天用）

**第一板 · 单独喂一坨 JSON 给脚本，看它自己跑不跑得通**

```
              你想让它守的那条规矩

```

**逐条讲为什么是这个顺序（这是本页的深度，别念图）：**

> **闸①在最前** —— 因为说过一遍的事不该挂 hook。**hook 不是用来代替沟通的。** 你还没好好说过就上强制，就是在给自己造刚才第一次翻车那种局面。

> 它不照做有四层原因 —— **没在 context 里 / 被淹没 / 和别的冲突 / 它就是没选**。

> **所以闸①问的不是「你烦不烦」，是「你到第四层了没有」。** 说过一遍就挂 hook，你很可能在**用 hook 解决一个 context 问题** —— 挂完还是犯，然后你会以为 hook 没用。

> **闸②排第二** —— 因为它决定时点。**而时点挂反了，后面全白搭**，刚才第二次翻车你们都看到了。
>
> **闸③是最贵的一道** —— 多数规矩挂在这里。判不出来就挂不上。**等一下我们专门讲这一格。**
>
> **闸④在最后** —— 它是「已经决定要挂了，怎么挂才不会被你自己关掉」。← 🔥 回收埋点 3

**这里说开场立论：**

> **一条规矩该不该挂成 hook，不取决于它有多重要，取决于「违反了没有」这件事，一个不动脑的脚本判不判得出来。**

## P13 ｜ 66–70 分钟 ｜ 它压得过 --dangerously-skip-permissions ⭐⭐

**口播（先回收 L11）：**

> 上节课讲无人值守，我给了三条让它不卡住的做法：提前批、取消问、全放开。
>
> 每条都有代价。**最大的那个代价是：你放开的时候，把该拦的也一起放开了。**
>
> 今天这一页是那三条的解药。

**投官方原文（两句都要投，不许只投一句）：**

```
PreToolUse hooks fire before any permission-mode check, in every
permission mode, including dontAsk. A hook that returns
permissionDecision: "deny" blocks the tool even in bypassPermissions
mode or with --dangerously-skip-permissions.
```

```
The reverse is not true: a hook returning "allow" doesn't bypass deny
rules from settings... Hooks can tighten restrictions but not loosen
them past what permission rules allow.
```

**每句落一个「所以」（这是本页的全部，别只念原文）：**

> 第一句：**它压得过 bypass。**
>
> **所以** 你可以放开权限让它跑得飞快，同时保证有三件事它**永远**碰不到。这就是上节课那三条做法的解药。
>
> 第二句：**只能收紧，不能放宽。**
>
> **所以** hook 不是后门。你没法用 hook 给自己开一条设置里禁掉的路。
>
> **这是设计，不是限制。** 一个能放宽的 hook，等于把安全边界交给了每个能改配置文件的人。

## P15 ｜ 74–78 分钟 ｜ 那要动脑的怎么办

**口播（先接住上一页的失落）：**

> 那说不清的怎么办？官方给了两条路。**但我要连代价一起讲。**

**投这张表（「代价」列视觉更重）：**

| 类型 | 怎么工作 | 什么时候用 | **代价** |
|---|---|---|---|
| `command` | 跑一个 shell，退出码说话 | 一行 `if` 就够 | 无。**优先用它** |
| `prompt` | 把 hook 的输入喂给一个模型（默认 Haiku），返回 `{"ok": ..., "reason": ...}` | 光看输入数据就够判 | **确定性还回去了。** 判断的是模型，不是脚本 |
| `agent` | 起一个 subagent，能读文件跑命令，最多 50 轮 | 得看代码真实状态才判得了 | 同上，**而且官方标了实验性** |

**投官方那个 `Stop` + agent hook 的例子：**

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "agent",
            "prompt": "Verify that all unit tests pass. Run the test suite and check the results. $ARGUMENTS",
            "timeout": 120
          }
        ]
      }
    ]
  }
}
```

**然后给轻量版对照（本课写法，讲义里有）：**

> 但同一件事，如果你的测试命令是固定的，**根本不用模型**：

```js
#!/usr/bin/env node
// 挂在 Stop 上：测试没过就把它按回去继续做
import { spawnSync } from 'node:child_process';

const r = spawnSync('npm', ['test', '--silent'],
                    { encoding: 'utf8', shell: true });

if (r.status !== 0) {
  console.error('测试没过，不能收工。失败输出：');
  console.error(`${r.stdout}${r.stderr}`.trim().split('\n').slice(-20).join('\n'));
  process.exit(2);
}
process.exit(0);
```

**收口判断线：**

> **hook 的输入数据就够判 → `prompt`。**
> **得看代码真实状态才判得了 → `agent`。**
> **一行 `if` 就够 → `command`，而且优先用它。**
>
> 官方原话：**For production workflows, prefer command hooks.**

**硬停 78 min。**

> 🚨 顺口提一句 `Stop` hook 的坑（讲义里有详版）：**`Stop` 是「它答完话」就触发，不是「任务完成」才触发。** 你随口问一句"这函数干嘛的"，它答完也会跑一遍测试。**这类 hook 要么加条件，要么你会被自己烦死。**

## P19 ｜（穿插在 P18 中间，约 2 分钟）｜ 这段脚本为什么这么写

> 🚨 **系列固定要求，不许省。** 学员要的不是这一个脚本，是以后自己能组词。
> 挑其中 4 到 5 条讲，讲完立刻切回 P18 让他们继续写。

**口播（逐条，每条一句，别展开）：**

> **为什么 stderr 那句话要写清「为什么被拦」，不能只写 Blocked？**
> 因为**它会收到这句话**。写清楚了它能换条路走；写不清，它会反复撞同一堵墙，把你的 context 耗光。**这句话的读者不是你，是它。**
>
> **为什么 matcher 要尽量窄？**
> 宽 matcher 的错法是**静默的** —— 你以为只管了一类，其实管了全部。官方对自动批准那个例子的原话是：matcher 写 `.*` 或者留空，**would auto-approve every tool permission prompt**。
>
> **为什么判据要写成「路径匹配」，不能写「这个改动合不合理」？**
> 因为确定性来自不动脑。**你写的每一个「合不合理」，都是把判断权又交回给了模型。**
>
> **为什么用 `$CLAUDE_PROJECT_DIR` 不用相对路径？**
> 因为 hook 跑的时候，工作目录不一定是项目根。写相对路径的，换个目录就 `command not found`。
>
> **为什么 exit 2 和 JSON 输出不要混用？**
> 官方明说：**Choose one approach per hook.** 混用的行为要去查一张表 —— 而你不该让自己的规矩，依赖一张需要查的表。
>
> **为什么第一条规矩要挑机器判得出来的？**
> 因为你需要先看见它成功拦一次。**一个从没拦成功过的 hook，你不会信它，也不会留着它。**

## G. 止争句（学员抬杠的时候）

**争议 1：「我这条规矩到底算不算机器判得出来？」**

> 别争定义。**你就试着把它写成一行 `if`。**
>
> 写得出来，就是判得出来。写不出来，就是判不出来。**这一格没有中间状态。**

**争议 2：「那我用 prompt hook 不就行了，什么都能判。」**

> 能。**代价是你把确定性还回去了。**
>
> 你现在有两个模型：一个干活的，一个判它干得对不对。**判的那个也会错。**
>
> 我不是说不能用 —— 我是说你要知道自己换掉了什么。

**争议 3：「我用的不是 Claude Code，某某工具能不能这么干？」**

> 我不评价具体产品。**给你一个判断方法：去查它有没有『在生命周期时点执行你的命令、并且听你返回值』这个能力。**
>
> 有，就是同一件事。没有，就退到 git hook 或者 CI —— 第 82 分钟那一页讲了每退一步失去什么。

**争议 4：「挂这么多 hook，不会很慢吗？」**

> 会。**所以闸①在最前面** —— 说过一遍的事不该挂。
>
> hook 是给你说过三遍还不管用的那几条用的，不是给所有规矩用的。

**争议 5：「那我全用 `bypassPermissions` 加一堆 hook 不就完美了？」**

> 这个想法方向对，**但记住第 66 分钟那句：hook 只能收紧，不能放宽。**
>
> 它挡得住你列出来的那几件事。**你没列的，它一件都挡不住。**

**争议 0：「可它明明读到了啊，为什么不照做？」** ⭐⭐ **全课最高频，答案见 §N，别用比喻糊过去**

> 四层：**没在 context 里 / 被淹没 / 和别的冲突 / 它就是没选**。
>
> 官方自己的用词是 **choose** —— 「rather than relying on the LLM to **choose** to run them」。**你写进 CLAUDE.md 的每一条，都是在等它选。**
>
> 怎么判断自己在第几层：**同一个请求跑三次** —— 三次都犯是冲突（第③层），有时犯有时不犯就是概率（第④层，上 hook）。完整版见 **§N**。

**争议 7：「我怎么知道它真的在保护？」** ⭐ **答案见 §O 四级阶梯**

> 一句话：**该拦的拦住了，只证明它有效；不该拦的放过了，才证明它可用。**
>
> **只测正面等于没测** —— 一个永远 `exit 2` 的脚本，正面测试满分。

**争议 6：「PR 收到 review，能不能让它自动改？」** ⭐ 高频，**答案见 §M，别临场编**

> 第一句先说：**这件事不是 hook 干的** —— hook 只在 Claude Code 自己的生命周期时点触发，**它监听不到 GitHub**。
>
> 触发靠 GitHub Actions；**hook 的位置是跑起来之后**（拦住它不该碰的 + 收工时验收）。
>
> 完整答案、可跑的 workflow、三个坑，见 **§M 番外**。

## M. 番外：「PR 收到 review 能不能让它自动改？」

> **这一节是给讲师准备的答案，不占课堂时间，deck 上没有这一页。**
>
> **什么时候会被问到**：讲完 P16（prompt / agent hook）或 P17（挂在哪个文件 = 谁受它管）之后，班上一定有人举手问这个。它是学员学完 hook 的自然下一想法。

---

### M.1 第一句必须先说这个 ⭐

> **这件事不是 hook 干的。**

**理由要讲清楚，这是本节的核心机制：**

> hook 只在 **Claude Code 自己的生命周期时点**触发 —— `SessionStart`、`PreToolUse`、`Stop`、`SessionEnd`。
>
> 你翻遍那 33 个事件，**没有一个叫「GitHub 上有人提交了 review」**。
>
> **hook 监听不到外部世界。** 它是挂在它自己身上的，不是挂在 GitHub 上的。

**顺手回收 P12 的时点二维图：**

> 还记得那张二维图吗？横轴是「它动手没有」，纵轴是「拦得住拦不住」。
>
> **那张图的整个坐标系，是「它的一次会话」。** GitHub 上发生的事，压根不在这张图里。

---

### M.2 那这件事谁干？—— GitHub Actions

**触发靠 GitHub Actions，不是 hook。** 官方有现成的 action：`anthropics/claude-code-action@v1`。

装法一句话：在仓库里跑 `/install-github-app`，它会装 GitHub App、配好 secret、直接给你开一个带 workflow 的 PR。

#### 方案 A · 半自动（**推荐，先讲这个**）

reviewer 在 review 里 `@claude` 一下，它才动。

```yaml
name: Claude on PR review
on:
  pull_request_review:
    types: [submitted]           # 整份 review 提交（approve / request changes / comment）
  pull_request_review_comment:
    types: [created]             # 代码行上的单条评论
jobs:
  claude:
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      id-token: write            # action 默认的 GitHub App 认证要用
      actions: read              # 让它能读 CI 结果
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
```

**这就是「交互模式」** —— 官方定义：**没有 `prompt` 输入时，它等触发词**（默认 `@claude`），可以出现在 issue / PR 评论里、**在一份 pull request review 里**、或新开 issue 的标题正文里。

于是 reviewer 的用法是：

```text
这里的错误处理漏了 null 的情况。@claude 按上面说的改一下
```

#### 方案 B · 全自动（**要讲代价**）

给一个 `prompt` 输入，它就不等触发词了，**任何 review 提交都会跑**。

```yaml
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: |
            读这个 PR 上最新一条 review 的全部意见。
            逐条处理：能改的直接改并 push 到这个 PR 的分支；
            不该改或你不确定的，在 PR 上回一条评论说明为什么不改。
            不要碰 .github/ 下的任何文件。不要合并这个 PR。
          claude_args: |
            --max-turns 15
```

**讲师必须连代价一起说，这正是本节闸④：**

> 方案 B 的代价是：**你失去了「这条 review 要不要照做」的那一次判断。**
>
> 有人在 review 里写一句「这块要不要考虑改成异步？」—— 那是个**问句**，不是要求。方案 B 会当成要求去改。
>
> 这跟第 40 分钟那次「拦太宽」是同一个毛病：**它百分之百有效，而它做的不全是你想要的。**

---

### M.3 那 hook 在这件事里的位置在哪？⭐ 这才是本节的落点

**hook 管不了「什么时候跑」，但管得了「跑起来之后能干什么」。**

那个 CI 里跑起来的，**是一个完整的 Claude Code 会话** —— 所以你在课上学的每一条 hook，在那个会话里照样生效。

把仓库里那份 `.claude/settings.json` 显式传给它：

```yaml
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          settings: ".claude/settings.json"     # ← 你的 hook 在这儿
```

**两个位置，正好对上二维图的左上和右下：**

```
   事前拦（PreToolUse）      别碰 .github/ · 别推 main · 别改 .env
                             ← 它在无人看管的 CI 里跑，这道闸比本地更要紧

   收工验（Stop）            改完了？测试跑过没有？每条 review 都回应了吗
                             ← 没过就把它按回去继续做
```

**一句收口，把 P14 那条铁律接上：**

> 这个 CI 会话是**无人值守**的 —— 没人在旁边盯着，也没有权限框弹给谁看。
>
> 而你学过：**`PreToolUse` 的 `deny` 在所有权限模式之前触发，连 `--dangerously-skip-permissions` 都压得过。**
>
> **所以恰恰是在这种没人看着的地方，hook 是你唯一还生效的那道闸。**

---

### M.4 三个坑，讲师要知道（学员一定会踩）

| 坑 | 官方行为 | 怎么办 |
|---|---|---|
| **死循环** | Claude 改完 push → 触发新 review → 又跑一次 | 官方**内置了防护**：action 会**拒绝 bot 发起的触发**，除非你把它列进 `allowed_bots`。所以另一个 bot（比如自动 review 机器人）发的 review **不会**触发它 |
| **CI 不在它的 commit 上跑** | GitHub **不会**为用默认 `GITHUB_TOKEN` 提交的 commit 触发 workflow | **别传 `github_token: ${{ secrets.GITHUB_TOKEN }}`** —— 去掉它，让 action 以 Claude GitHub App 身份认证 |
| **谁能触发** | 触发者必须有仓库 **write 权限**；**bot 一律拒绝** | 外部贡献者的 review 默认不会触发。要放行特定人，设 `allowed_non_write_users` 并传你自己的 `github_token` |

**再加两条钱和安全上的：**

- **两份账单**：GitHub Actions 分钟数 + Claude 用量。`--max-turns` 一定要设，`timeout-minutes` 也设一个。
- **公开仓库的 fork PR 拿不到 secret** —— 这类 PR 上它根本跑不起来，别以为是配错了。

---

### M.5 顺带说清另一个学员会混的东西

有人会问「那 Routines（`/schedule`）能不能干这个？」**不能，要说清楚为什么：**

> Routine 的 GitHub 触发**只支持两类事件：Pull request 和 Release**。
>
> **「有人提交了一份 review」不在里面。** 过滤条件也只到 PR 本身的字段（作者、标题、分支、标签、是不是草稿、是不是已合并）。
>
> 所以：**定时的事找 Routine，PR 上的事找 GitHub Actions。**

---

### M.6 这段番外要回收到本节的三个点

讲完这个问题，用一句话把它收回课堂：

> 所以这个问题的答案，其实是今天三页内容的组合：
>
> **一，`hook 监听不到 GitHub`** —— 那张时点二维图的坐标系是「它的一次会话」（P12）。
>
> **二，触发归触发，约束归约束** —— GitHub Actions 决定什么时候跑，hook 决定跑起来之后能干什么。
>
> **三，`.claude/settings.json` 提交进仓库，CI 里也生效**（P17）—— 你今天挂的那条规矩，连它在云上替你改 PR 的时候都管得住。

> 📎 **数据纪律**：本节的 workflow 字段、支持的事件、`allowed_bots` 等行为**都会变**。上课前按 §0 检查清单第 9 条，去 `code.claude.com/docs/en/github-actions` 和 `/routines` 核当天版本。**别凭这份讲稿的记忆讲。**

## N. 机制底座：为什么它读到了还是不照做 ⭐ 全课最该讲清的一件事

> **这一节是 P01 那句「读到，不等于照做」的完整版。**
>
> **为什么单独成章**：整节课立在这句话上。学员追问一句「可它明明读到了」，你要是只能答「它把那当成可以权衡的文字」，**那是比喻不是机制** —— 追问第二句你就没词了，这节课的地基就塌了。
>
> **课上只讲 P01 那三句（约 1 分钟）。这一整节是给答疑和讲义用的。**

---

### N.1 四层，从「它没看见」到「它看见了但选了别的」

```text
①  它根本没在 context 里          ← 最常见，而且大多数人从没怀疑过
        │  排除了
②  在 context 里，但被淹没了
        │  排除了
③  看见了，但和别的东西冲突
        │  排除了
④  看见了，没冲突，还是没做        ← 只有这一层，hook 是唯一解
```

**顺序不能倒。** 大多数人一上来就跳到④（「这模型不听话」），于是去挂 hook 解决一个其实是①的问题 —— 挂完发现还是犯，因为根因没动过。

---

### N.2 第一层 · 它根本没在 context 里

**这一层最容易被跳过，但它有硬依据。**

官方的 `InstructionsLoaded` 事件，matcher 过滤的是**「加载原因」**，一共五个值：

```text
session_start      会话开始时加载
nested_traversal   进到某个子目录，才加载那一层的 CLAUDE.md
path_glob_match    碰到匹配的文件路径，才加载对应的规则
include            被别的文件引入
compact            压缩之后重新加载
```

**这五个值本身就是答案：规矩是「按需加载」的，不是「一直都在」。**

- 你在 `src/api/CLAUDE.md` 里写的规矩，它在改 `src/ui/` 的时候**根本不在它眼前**（`nested_traversal`）。
- 你写成 `.claude/rules/*.md` 只对某类文件生效的规矩，它没碰到那类文件就**不会加载**（`path_glob_match`）。

**再加上压缩**，官方原话：

```
When Claude's context window fills up, compaction summarizes the
conversation to free space. This can lose important details.
```

> **所以一个长会话跑到后半程，你早上说的规矩、开场加载的 CLAUDE.md，可能已经被摘掉了。**
>
> 你以为它「读过」，它确实读过 —— **但那是两小时前的事，现在不在了。**

**处方（都不是 hook 的活，或者说不是「拦」那类 hook）：**

| 做法 | 说明 |
|---|---|
| `SessionStart` + `compact` matcher | 压缩之后自动把关键几句灌回去（§P22 附录例 C-1）。**这是最直接的一条** |
| CLAUDE.md 放对目录层级 | 想让它全程生效，就别只放在子目录里 |
| 挂 `InstructionsLoaded` 记日志 | **先搞清楚它到底加载了什么**，见 §N.6 |

---

### N.3 第二层 · 在 context 里，但被淹没了

一个 500 行的 CLAUDE.md，第 300 行那条规矩，要和**你刚说完的那句话**竞争注意力。**位置和篇幅是有代价的。**

官方在 GitHub Actions 那页的最佳实践里直说了一句（在讲省钱，但道理一样）：

> **Keep your CLAUDE.md concise, since Claude reads it on every run.**

**处方**：砍 CLAUDE.md。把「必须守」的和「知道一下」的分开 —— 后者搬去 wiki 或注释，别都堆在同一个文件里。

> 🚨 **这一层有个反直觉的结论要讲给学员**：**你往 CLAUDE.md 里加的每一条，都在稀释已有的每一条。** 加规矩不是免费的。

---

### N.4 第三层 · 看见了，但和别的冲突

两种冲突，形态不同：

**（a）你自己前后矛盾 —— 而且新的赢面大**

> CLAUDE.md 里躺着「别动 `.env`」，你刚才说「把配置改成生产环境」。
>
> **两条都在 context 里。你当下说的那句，天然比三个月前文件里那行更「近」。**

**（b）完成任务 vs 遵守禁令 —— 这条 L11 已经建立过，直接回收**

上节课的原话（L11 演示 A 的机制层）：

> **它的目标是完成任务，不是保护你的意图。**

L11 演示过：只给读权限，让它做一件必须写文件的事 —— **它不报错也不停，它绕过去**，把内容打印在报告里，然后说做完了。

> **它没有违反「不许写文件」。它违反的是你要它干的那件事的本意。**

**处方**：
- （a）→ 消除矛盾，或者把「绝对不许」的那几条从 CLAUDE.md 提出来**挂成 hook**（hook 不参与权衡）
- （b）→ 给它一个**比完成任务优先级更高的合法退出**（这正是 L11 那条铁律：宁可交回「我没做，因为 X」）

---

### N.5 第四层 · 看见了，没冲突，还是没做 ⭐ 只有这一层 hook 是唯一解

前三层都排除了，它还是犯。**到这里就没有「为什么」了，这就是机制本身。**

官方那句话的用词是关键：

```
deterministic control: certain actions always happen
rather than relying on the LLM to CHOOSE to run them
```

> **choose。**
>
> 你写进 CLAUDE.md 的每一条，都是在**等它选**照做。它大概率会选，但那是概率，不是保证。
>
> **同样的 context、同样的请求，跑两次可以不一样。**

**所以：**

> 「它这次照做了」**不构成**「它下次也会」的证据。
>
> 而你的规矩之所以叫规矩，是因为你要的是**每次**。

---

### N.6 怎么判断自己在第几层 ⭐ 讲师被追问时给这个

**三个动作，从便宜到贵：**

**① 直接问它**（十秒）

> 「你的 CLAUDE.md 里，关于 X 有什么规定？」

- 答不出来 → **第①层或第②层**（没加载，或被淹没）
- 答得出来还照犯 → **第③层或第④层**

**② 同一个请求跑三次**（几分钟，**最有用的一个**）

- 三次都犯 → **第③层**。有一个稳定的冲突在，去找它
- 有时犯有时不犯 → **第④层**。这就是概率，别再找原因了，**上 hook**

**③ 挂一个 `InstructionsLoaded` hook 记日志**（一次性成本，之后一劳永逸）

```js
#!/usr/bin/env node
// 本课写法：看它到底加载了哪些规则文件、为什么加载
import { appendFileSync } from 'node:fs';
import { homedir } from 'node:os';

let raw = ''; for await (const c of process.stdin) raw += c;
const d = JSON.parse(raw);
appendFileSync(`${homedir()}/.claude/instructions-loaded.log`,
  JSON.stringify({ t: new Date().toISOString(), reason: d.matcher, file: d.file_path }) + '\n');
process.exit(0);
```

> 触发几次，去翻那个日志。**你会发现有些规矩根本没被加载过** —— 那就是第①层，实锤。

---

### N.7 这一节真正的教学价值：它让闸①从经验变成机制 ⭐

判断线闸①是「**这条你已经说过几遍了？三遍以上才值得挂**」。

**学员会觉得「三遍」是个拍脑袋的数字。它不是。** 四层诊断给了它理由：

| | 再说一遍有用吗 | 为什么 |
|---|---|---|
| **第①②③层** | **有用** | 补上下文、砍 CLAUDE.md、消除冲突，都能真的提高命中率 |
| **第④层** | **说一百遍也没用** | 问题不在于它不知道 |

> **所以闸①问的不是「你烦不烦」，是「你到第四层了没有」。**
>
> 说过一遍就挂 hook —— 你很可能在**用 hook 解决一个 context 问题**，挂完还是犯，然后你会以为 hook 没用。
>
> **说过十遍还犯，那就是第四层。到这一层，hook 是唯一治得了的东西。**

---

### N.8 一句话版本（讲师背下来这句就够应付大部分追问）

> **它不照做，四种可能：没在 context 里、被淹没了、和别的冲突了、或者它就是没选。**
>
> **前三种，再说一遍是有用的。第四种，说一百遍也没用 —— 因为它压根不是「知不知道」的问题。**
>
> **hook 一层都不受影响，因为 hook 根本不经过它。**

---

> 📎 **出处纪律**（蓝图 §21.1）：
> · `InstructionsLoaded` 的五个加载原因、压缩会丢细节、`choose` 那句 —— **都是官方文档原文**，可以直接引。
> · 「四层诊断」这个分法、§N.6 三个判断动作 —— **是本课的教学设计，不是官方分法**，讲义里要写明。
> · 「它的目标是完成任务，不是保护你的意图」—— **L11 的立论**，标明是上节课的，不要当本节发明。

## O. 怎么验证一个 hook 真的在保护 ⭐ 四级阶梯

> **为什么单独成章**：讲稿原来所有验证都是**单向的** —— 只验「该拦的拦住了」。
>
> **后果很实在：一个永远 `exit 2` 的脚本，能通过原来全部的检查。** 而那正是翻车①「拦太宽」的形态 —— 它百分之百有效，也让你一件事都干不成。
>
> **双向验证才算数。** 下面四级，每一级都写清「证明了什么 / 没证明什么」。

---

### O.1 四级阶梯

| 级 | 做什么 | **证明了** | **没证明** |
|---|---|---|---|
| **1** | `/hooks` 里看得到它 | 你的 JSON 被解析了 | 脚本能不能跑 · 判据对不对 · 会不会拦 |
| **2** | 单独喂 JSON 给脚本，看退出码（**正 + 反**） | 脚本自己的逻辑对 | Claude Code 会不会真的调它 |
| **3** | 真让它去违反一次 | **端到端通了** | 有没有误伤别的操作 |
| **4** | **让它做一件不该被拦的事** | **没误伤**（matcher 够窄） | — |

**第 1 级最容易被当成「挂好了」。它什么都没证明**，只说明 JSON 没写错。

---

### O.2 第 2 级 · 离线测脚本（不用进会话，十秒）

```bash
# 正面：该拦的 —— 要看到 2
echo '{"tool_input":{"file_path":"/x/.env"}}' \
  | node .claude/hooks/protect-files.mjs ; echo $?

# 反面：不该拦的 —— 要看到 0
echo '{"tool_input":{"file_path":"/x/README.md"}}' \
  | node .claude/hooks/protect-files.mjs ; echo $?
```

**两条都跑。** 只跑正面的话，下面这个脚本也能"通过"：

```js
#!/usr/bin/env node
console.error('Blocked');
process.exit(2);   // ← 什么都不判，一律拦。正面测试满分，实际不可用
```

---

### O.3 第 3、4 级 · 端到端双向（在真会话里）

| | 让它做什么 | 期望 |
|---|---|---|
| **正向** | 改 `.env` | 被拦，且**你看得见你自己写的那句 stderr** |
| **反向** | 改 `README.md` | **顺利改掉，一点动静都没有** |

> **反向那一次是闸④的实做**：它证明你的 matcher 够窄、判据没写宽。
>
> **课堂上这一步在 P04 做**（Blocked 之后的 30 秒），不许砍。

---

### O.4 第 5 级（可选，但最有说服力）· 证明它压得过权限模式

讲完 P13（它压得过 `--dangerously-skip-permissions`）之后，如果时间允许，**当场证一次**：

```bash
claude --dangerously-skip-permissions
```

然后让它改 `.env`。**它照样被拦。**

> 这一下比讲十遍官方原文都管用 —— 学员会亲眼看到 **hook 在权限体系之外**。
>
> ⚠️ **只在演示仓库里做，别在有价值的项目上开这个 flag。**

---

### O.5 一条判据，用来判断「这个 hook 我敢不敢留着」

> **该拦的拦住了 → 它有效。**
> **不该拦的放过了 → 它可用。**
>
> **只有第一条 = 你三天内会把它关掉。**
> **只有第二条 = 它等于没挂。**
>
> **两条都有，这个 hook 才算立住了。**

---

### O.6 讲师容易被问到的两个追问

**「那我怎么知道它是没触发，还是触发了但放行了？」**

> 这两件事**外观完全一样**（都是什么都没发生）。
>
> 分辨方法：在脚本第二行加一句日志（§P08 排错第四条），触发一次去翻那个文件。
> **有记录 = 触发了但放行；没记录 = 压根没触发**，回到 §P08 排错第一条查 matcher。

**「我要不要给每条 hook 都写测试？」**

> 不用。但**每条 hook 至少要有一次双向的手动验证记录** —— 这就是 Exit ticket 第 6 题收的东西。
>
> 真要自动化，第 2 级那两行 `echo | script ; echo $?` 本身就是一个能塞进 CI 的最小测试。

> 第 2 级的离线测法和 `claude --debug` 出自官方排错章节。
