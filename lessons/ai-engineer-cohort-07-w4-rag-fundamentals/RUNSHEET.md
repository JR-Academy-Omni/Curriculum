## 答案速查

- 第 3 页：ABBC（1 Fine-tuning→A LLM、2 RAG→B Agent、3 Memory→B Agent、4 Knowledge base→C 外部数据）。
- 第 4 页：DCEAB（1 Context Window、2 RAG、3 Memory、4 Tool Results、5 Cache）。
- 第 6 页：没有标准答案。常见的办法归成四类：全塞进 prompt（第 7 页 Long context）、让它自己去查（Agentic search）、先建索引（Indexed RAG）、拿去训练（指回第 3 页：改的是 LLM 本身，不是填知识这一格）。
- 第 11 页的提问：rollback 到上一版索引，修好 parser 再重建。
- 第 16 页：「去年」要先换成 2025；「第三季度 / Q3」和中英文可能不够像；数字和代号需要精确匹配。修法是 query rewrite 和 hybrid search。
- 第 27 页：答案 1 是 R，讲预约的块没进 top-k；答案 2 是 G，证据在，回答没跟着证据。追问：答案 2 只看 recall@k 发现不了，要看 faithfulness。

## 口头补充（不在页面上）

- 第 6 页：静态 vs 动态上下文。RAG 是请求时才决定放什么的那部分。
- 第 7 页：Anthropic 在 Contextual Retrieval 一文中说，知识库小于 20 万 token 时可以整个放进 prompt，并配合 prompt caching。
- 第 18 页：超出 token 预算被截断，属于 Assembly 层失败（讲义里的 failure taxonomy）。
- 第 19 页：Anthropic 的 Citations API 由 API 解析引用，`cited_text` 直接从文档里取。
