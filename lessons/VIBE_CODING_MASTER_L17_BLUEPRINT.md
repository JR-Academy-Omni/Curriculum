## 0. 立项决定

### 0.1 这一节为什么存在：这套东西一直假装只有一个使用者

L13 到 L16 做完之后，学员手上有：一个规则仓、一个接了权限的 agent、一套运行痕迹、
一个定时任务、一套加改删的流程。

**全部是按"一个人在用"设计的。**

**而身份这件事，文档里只做了两层：**

| 层 | 谁做的 | 原话 |
|---|---|---|
| **角色** | L13 §1.3 L3 组织层 | 花名册 + 角色文件。「**角色文件回答这顶帽子答应什么，换个人戴内容不变**」 |
| **人** | L13 `people/ASSIGNMENTS.md` | 「**名字属于 `people/`**」,, 明确不进 `rules/` |
| **执行者** | ❌ **没有人做过** | ,, |

**第三层缺席的后果，文档里到处都是，只是没人把它们连起来：**

| 哪一节留下的 | 原话 / 现状 | 它其实是同一个洞 |
|---|---|---|
| **L14 §6.3** | 漂移检查「**只数数、不点名**」，因为账号映射不进规则仓 | **它看得见账号，看不见那个账号背后是人还是 agent** |
| **L14 §3.1** | 个人覆盖放 `settings.local.json` 并 **gitignore** | **那份规矩没有任何人见过** |
| **L14 §3.2** | 写权限表「谁批准的：**一个具体的角色**」 | **批准给了角色，执行的是一个具体的执行者，中间那一跳没人管** |
| **L15 痕迹三级** | 2 级 = 「能被**重新打开来读**」 | **它只要求能核，没要求知道是谁** |
| **L15 定时任务** | 冷启动、以服务凭据跑 | **它跑出来的东西，署名是谁？** |
| **L16 变更四动作** | 留一条"为什么改"的记录 | **署名的是提案人，不是执行者** |

**一句话立项：**

> **一个人用的时候，"算谁的"和"谁做的"是同一个答案。**
> **五个人用的时候，它们是两个答案 ,, 而这套东西只记了前一个。**

### 0.2 开场第一句（不许改）

> 一个问题，聊天框回答，三十秒：
>
> **你那个仓库，现在有几个使用者？**
>

> **你们那个服务账号**、以及 ,,
> **某个人在某个时候配的、现在还在跑的定时任务，而他自己已经忘了。**

### 0.3 全节最重要的三句话

**立论**（第二幕点出）：

> **署名回答的是"算谁的"。它回答不了"谁做的"。**
> **一个人用的时候这是同一件事，五个人用的时候是两件。**

**反转**（第三幕末，学员刚把冲突规则定好、觉得有秩序了的时候翻）：

> **真正危险的那种冲突，git 一次都不会报。**

**收口**（全程不许提前说）：

> **你追不到人，多半不是因为没记名字。**
> **是因为那一下，确实没有人做 ,, 它是一个很久以前的决定，在一个没有人记得的时间，自己发生的。**
>
> **所以"这套东西有几个使用者"这个问题，答案从来不是你们团队的人数。**
> **是【人数 + 还在跑的、没人记得的决定数】。**

> ⭐ **收口的结构：它回头重新回答开场那个问题。**
> 开场问"有几个使用者"，学员报了个人数；**收口告诉他那个数该怎么算。**
> **这是全系列唯一一次首尾在同一个问题上收**（L16 收的是 L13 的问题，L17 收的是自己的）。

**三句的链条，讲师必须能说出来：**

```
署名只记了【算谁的】
      ↓
所以同一个名字底下，有三种完全不同的执行者（人 / 他的 agent / 一个定时任务）
      ↓
三种执行者读同一条规则，理解可以不一样，而且各自都做得"对"
      ↓
这种冲突 git 不报，检查也绿 ,, 因为两边都合法
      ↓
更糟的是，连规则本身都不是同一份：个人覆盖在本机、gitignore 掉了、没人见过
      ↓
而这一切在一个人走的那天全部引爆：
   他的 agent 配置、他的个人覆盖、他的定时任务、他留下的痕迹
      ↓
其中定时任务还在跑，还在用他的名字
      ↓
所以：这套东西里有一部分，【没有现任主人】
```

### 0.5 收口收掉四样东西

| 课上哪一格 | 怎么被收口收掉 |
|---|---|
| 痕迹只写了"做了什么" | 你知道发生了，不知道算谁的 |
| 个人覆盖不进仓、被 gitignore | 他那台机器上的规矩，**没有任何人见过** |
| 语义冲突 git 不报、检查也绿 | **两个人都做对了，合起来是错的** |
| 他走了，定时任务还在跑 | **而且还在用他的名字** |

**四件事是同一个形状：这套东西里有一部分，【没有现任主人】。**

> ⭐ **和前三节收口的关系要讲出来，这是本节在系列里的位置：**
>
> | 节 | 收口讲什么 |
> |---|---|
> | L14 | **一次运行**骗了你 |
> | L15 | **整套系统**骗了你 |
> | L16 | 它**只会长大，不换血** |
> | **L17** | **它有一部分，没有主人** |

### 0.6 最重要的教学决定：这一节最大的风险是讲成"团队协作课"

L13 靠终端拉回来，L14 靠终端表，L15 靠终点宣告，L16 靠"删"当引力中心。

**L17 的危险在于：身份、署名、冲突、交接,, 这四个词全是 HR 和项目管理的词。**
**一旦滑过去，这节课会变成一场关于"团队怎么配合"的座谈，而这不是这门课。**

**定版：把每一格都钉在一个【可以当场跑出来的数】上。**

| 幕 | 那个数是什么 | 终端 |
|---|---|---|
| 一 | **使用者到底有几个**（四类分别几个） | ✅ |
| 二 | 一条痕迹里出现了几个身份字段 | ✅ |
| 三 | **两边都绿的那次合并，检查报了几条红**（答案：0） | ✅ |
| 四 | **本机覆盖和共享规则不一致的条目有几条** | ✅ |
| 五 | **某人走了之后，清单上有几项追不到主人** | ✅ |

> **铁律：每一幕的产出都是一个数字，不是一段话。**
> **讲师每一幕结束前必须在聊天框收一次那个数。**
> **收不到数 = 这一幕讲飞了。**

### 0.7 第二个教学决定：三次翻车，第二次最重（回到 L13/L14/L15 的排法）

> **L16 故意把最重的放在第五幕**（因为那节真正要讲的是"删"）。
> **本节回到第二次最重**，因为第三幕那一下是全课唯一一个"学员看完会后背发凉"的时刻，
> 而第五幕的离职演练是**收束**，不是**冲击** ,, 它要的是沉，不是惊。

| | 翻车① | **翻车②** ⭐⭐ | 翻车③ |
|---|---|---|---|
| 在哪 | 一幕 | **三幕** | 四幕 |
| 做什么 | 盘点四类使用者 | **造一次语义冲突，两边都合法** | 比对本机覆盖和共享规则 |
| 几乎必然的结果 | **比自己报的数字多** | **git 不报冲突，检查也全绿** | **有几条不一样，而且仓里看不见** |
| 形态 | **比你以为的多** | **都对，合起来错** | **看不见的那一份** |
| 感受 | 意外 | **后背发凉** | 不安 |
| 指向 | 开场那个数字是错的 | **反转：git 不报的那种冲突** | 连规则都不是同一份 |
| 讲轻的后果 | 后面四幕没有基数 | **反转和收口同时落空** | 第五幕离职清单少一整类 |

### 0.8 第三个教学决定：全程不出现真人姓名，用"张三"

本节通篇在讲"谁干的"，**讲师极容易顺口说出自己同事的名字**。

> ⚠️ **定版：全程只用"张三"。** 需要第二个人用"李四"。
> **这不只是脱敏，它还有教学收益**：张三这个名字本身在提醒学员
> **"这是一个位置，不是一个人"** ,, 正好是 L13 "角色 vs 人名" 那一刀的回声。

**产品名纪律沿用 L15 §0.11 / L16 §0.7 的切法**：学员公司的系统不说，Claude 自己的照说。

### 0.9 单位沿用 L13 §1.0：不一定是公司

| 本节哪一格 | 三人小组怎么读 |
|---|---|
| **使用者盘点**（一幕） | **三人小组最容易低估** ,, 他们会报"3"。实际上是 3 个人 + 3 个 agent + 可能两个定时任务 |
| **三层署名**（二幕） | 照做。**小组的"角色"那一层可能只有一顶帽子，但执行者那层照样有三种** |
| **权限分化**（四幕） | 行数少，**但个人覆盖那一格对小组更疼**：三个人三台机器，三份不一样的本机设置 |
| **离职**（五幕） | **小组反而最危险** ,, 三个人走一个是走三分之一，而且没有任何交接流程 |

**而且有一格对小组反而更强：**

> 第五幕"谁来接管那个定时任务"。
> 大公司会说"交给某个组"。**三个人的组只能指一个具体的人，而且当场就能指。**
> **所以这一格请小组先答，他们给得出真答案。**

## 1. 核心框架

### 1.1 框架一：身份五问 ⭐⭐ 全节脊椎（第四次沿用五问体例）

| 幕 | 问 | 学员产出 | 那个数 | 分钟 |
|---|---|---|---|---|
| 一 | **这套东西现在有几个使用者？** | **使用者盘点表**（四类） | 四类各几个 | 0-24 |
| 二 | **一条痕迹要写几个身份？** | **三层署名的痕迹** ⭐ | 痕迹里几个身份字段 | 24-50 |
| 三 | **两个人同时改怎么办？** | 冲突两分法 + 反转 | **两边都绿时红了几条**（0） | 50-78 |
| 四 | **每个人的权限一样吗？** | 共享表 + 每人差异行；裁决表加个人层 | 本机和共享不一致几条 | 78-104 |
| 五 | **一个人走了怎么办？** | **离职清单** ⭐⭐ | **追不到主人的有几项** | 104-135 |

**五问有顺序，不能打乱：**
先知道有谁（基数），才谈怎么署名（记下来），才谈撞上了怎么办（冲突），
才谈各自能干什么（分化），**最后才谈走了怎么办** ,, 因为离职会把前四问同时引爆。

> **四次五问并排，封面之后第一页要放：**
> **L14 交底（长什么样）→ L15 追责（干过什么）→ L16 变更（怎么改）→ L17 身份（谁干的）。**

### 1.2 框架二：使用者有四类，多数人只数了第一类 ⭐ 第一幕

```
一  人              你们团队的人                        ← 多数人只数了这个
二  人的 agent      每台机器上那个，带着【本机覆盖】      ← §1.5 的伏笔
三  服务账号        定时任务用的那个（L15 §0.12 形状 3）  ← 它没有脸
四  还在跑的决定 ⭐  某人在某时配的、现在还在跑的东西      ← 【收口的地基】
```

**四类的性质完全不同，必须拆开讲：**

| | 会离职吗 | 有没有人记得它 | 出事能找到谁 |
|---|---|---|---|
| 人 | 会 | 有 | 他自己 |
| 人的 agent | 跟着人走 | **半记得**（他知道有，不记得配了什么） | 他，但他要去翻 |
| 服务账号 | 不会 | **通常只有一个人记得** | **那个人走了就没人了** |
| **还在跑的决定** | **不会** | **没有人** | **没有人** ⭐ |

> **第四类是本节唯一一个"学员盘点之前根本不知道它存在"的东西。**
> **它就是收口那句话里的"很久以前的决定"。**

**第一幕的动作：把四类各数一个数出来。**
**第四类数不出来，就是这一幕的产物** ,, 「数不出来」本身是一个答案。

### 1.3 框架三：三层署名 ⭐⭐ 核心产物，而且它是改 L15 的

**L15 的痕迹 2 级要求"能被重新打开来读"。本节补上它漏掉的那一半：**

| 层 | 回答什么 | 谁做的这一层 | 例 |
|---|---|---|---|
| **角色** | 这一下**算哪顶帽子**的 | **L13 做了** | 值班人 |
| **人** | 这一下**算谁**的 | **L13 做了**（在 `people/`） | 张三 |
| **执行者** ⭐ | 这一下**是谁做的** | **本节补** | 张三本人手动 / 张三的 agent / 定时任务 `每日汇总` |

**立论就在这张表上：**

> **前两层回答"算谁的"。第三层回答"谁做的"。**
> **一个人用的时候，这三层是同一个答案。五个人用的时候，是三个答案。**

**第三层的取值必须是**封闭的四选一**，不许自由填：**

```
human        一个人手动做的
agent        某个人当时在场，由他的 agent 做的
scheduled    定时任务做的，没有人在场          ← 这一类必须带上【是哪个任务】
service      服务账号做的，不属于任何具体的人    ← 这一类必须带上【谁是它的现任主人】
```

> ⚠️ **后两类必须带一个额外字段，这条是硬要求。**
> **因为它们是唯二"没有人在场"的，而没有人在场的东西，必须有一个【现任主人】。**
> **这两个字段就是第五幕离职清单的全部输入。**

**一句话给学员带走：**

> **署名不是为了追责，是为了【下次出事的时候，知道该去问谁】。**
> **追责要的是过去时，问人要的是现在时 ,, 所以记的不是"当时是谁"，是"现在归谁"。**

### 1.4 框架四：冲突有两种，git 只报一种 ⭐⭐ 第三幕，反转的全部论证

| | **文本冲突** | **语义冲突** ⭐ |
|---|---|---|
| 长什么样 | 两个人改了同一行 | 两个人改了**不同的地方**，各自合法 |
| git 报吗 | **报** | **不报** |
| 检查抓吗 | 用不着 | **抓不到 ,, 因为两边都合规** |
| 例 | 都改了那条额度的数字 | 一个人在规则里**加了一个新角色**，另一个人在 SOP 里**假设角色只有三种** |
| 多久发现 | 当场 | **下一次有人按那条 SOP 做事的时候** |
| 谁来发现 | git | **一个倒霉的人** |

**为什么多人 + 多 agent 会放大语义冲突（三条，第三条最硬）：**

```
1  每个 agent 读的是【同一条规则】，但它们各自做的推断不一样
2  每个 agent 都会【很合理地】把规则往自己这次任务的方向理解一下
3  ⭐ 而且它们都【没有对方的上下文】
   两个人至少会在群里碰一句；两个 agent 之间，一句话都不会说
```

**第三条要讲慢，它是本节和 L8（Agent Team）的分界：**

> **L8 讲的是你主动让几个 agent 一起干一件事 ,, 那是你编排的。**
> **今天讲的是五个人各自用各自的 agent 干各自的事 ,, 没有人编排。**
> **前者有协调，后者只有碰撞。**

**兜底是什么（不要给幻觉，要给真能做的）：**

| 做得到的 | 做不到的 |
|---|---|
| **加一条"引用计数"检查**：规则里的角色数 vs SOP 里假设的角色数，对不上就红 | **指望检查抓住所有语义冲突** ,, 它抓不住，这是 L13 反转那句话的又一个实例 |
| **把"我改了什么、可能影响谁"写进变更记录**（L16 四动作第 4 条的扩展） | 指望大家自己想起来 |
| **承认剩下的停在第 0 级**（L13 兜底三级） | 假装覆盖了 |

> ⚠️ **这一格必须老实。** L13 §1.5 兜底三级的第三级原话是：
> 「写成规则，承认停在第 0 级，**但必须写下来它是第 0 级，不许假装**。」
> **语义冲突的绝大部分，就停在第 0 级。**

### 1.5 框架五：规则不是同一份 ⭐ 第四幕，而且它改两张表

**L14 §3.1 说个人覆盖放 `settings.local.json` 并 gitignore。那条是对的，但它留了个洞：**

> **一份被 gitignore 的规矩，没有任何人见过 ,, 包括它自己的主人，三个月之后。**

**改法不是"禁止个人覆盖"（那会逼人去改共享的，更糟），是两条：**

| # | 改什么 | 改哪张表 |
|---|---|---|
| 1 | **L13 裁决表加一行"个人层"**：本机覆盖和共享规则冲突时谁赢，以及**哪几类绝不许被本机覆盖** | **L13 `AUTHORITY.md`** |
| 2 | **L14 写权限表从一张变成"一张共享 + 每人一行差异"**，**差异那部分必须在仓里可见**（可以只写"张三比共享多一条：能写工单"，不写他本机怎么配的） | **L14 写权限表** |

**个人层的裁决，给判据不给结论**（沿用 L14 §6.4 体例）：

```
可以被本机覆盖的     纯个人便利：确认弹窗少一点、输出详细一点、用哪个编辑器
                     判据：【覆盖掉之后，别人看不出任何区别】

绝不许被本机覆盖的   任何会改变【对外可见结果】的：写权限、禁令、审批人、不可逆清单
                     判据：【覆盖掉之后，世界上会多出一样东西】
```

> ⭐ **这条判据和 L14 入场券那条"必须产生对外可见的结果"是同一把尺子。**
> **讲师要点出来，这是它第三次出现**（L14 入场券 / L15 不可逆清单 / 这里）。

**第四幕的终端动作：跑一条"本机 vs 共享"的比对，数出不一致几条。**

> ⚠️ **比对的是【条目】，不是【内容】**（沿用 L14 §6.3 "只数数、不点名"的精神）：
> 「本机多了 3 条共享里没有的」就够了，不需要把那三条是什么交出去。
> **这让这条检查在学员真实环境里跑得起来 ,, 否则没人敢跑。**

### 1.6 框架六：离职清单 ⭐⭐ 第五幕，核心产物

**一个人今天走了。清单上五类，每一类问同一个问题：现任主人是谁。**

| # | 他留下了什么 | 怎么查 | 最常见的答案 |
|---|---|---|---|
| 1 | 他的账号和权限 | **L14 §6.3 漂移检查** | 能查到 ✅ |
| 2 | 他的 agent 配置 / 本机覆盖 | **§1.5 那条比对** | **查不到 ,, 在他机器上** |
| 3 | 他署名的规则和 SOP | 搜 `people/` 和各份文件 | 能查到 ✅ |
| 4 | **他配的定时任务** | **§1.3 第三层署名的 `scheduled` 那一类** | **这是今天补的那一层的唯一回报** ⭐ |
| 5 | **他是谁的审批人 / 升级路径终点** | L14 写权限表 + L16 SOP 第 9 节 | 能查到，**但多数人从没反查过** |

**第 4 行是全节的收束：**

> **如果今天没有补第三层署名，第 4 行是查不到的。**
> **那个定时任务会继续跑，继续用他的名字，而没有任何人知道它存在。**

**追不到主人的，走 L16 的删除三步：**

> **标记过时 → 一个复审期 → 真删。**
> **一个没有现任主人的自动化，默认应该停掉，而不是默认继续跑。**
> **把举证责任翻过来** ,, 和 L16 §1.6 是同一招，**换了个对象。**

> ⭐ **讲师要点出这个复用：**
> 「L16 教删规矩的时候，我说过'默认到期删，反对的人要具名说话'。
> 　**今天这条，对一个没主的定时任务同样成立，而且更该成立。**」

### 1.7 老师必须抓住的九个要点

1. **开场必须先收那个错的数字**（§0.2）。没收，第一幕的翻车①没有对照。
2. **每一幕结束收一个数**（§0.6）。收不到数 = 讲飞了。
3. **四类使用者的第四类（还在跑的决定）要在第一幕就点出来** ,, 它是收口的地基。
4. **三层署名的后两类（`scheduled` / `service`）必须带现任主人字段**，这条是硬要求（§1.3）。
5. **语义冲突那一格要老实**：承认大部分停在第 0 级（§1.4）。
6. **L8 和本节的分界要说清**：L8 是你编排的，今天是没人编排的（§1.4）。
7. **个人覆盖不许讲成"禁止个人覆盖"**（§1.5）。那会逼人去改共享的，更糟。
8. **第四幕比对只数条目不看内容**，否则学员不敢跑（§1.5）。
9. **第五幕第 4 行要明说"这是今天补那一层的唯一回报"** ,, 否则前面四幕的投入在学员眼里没有兑现。

### 1.8 最容易出错的七类地方

| # | 出错长什么样 | 后果 |
|---|---|---|
| 1 | **讲成团队协作 / HR 课** | 本节最大风险（§0.6）。靠"每幕一个数"防 |
| 2 | 翻车②造不出"两边都绿" | **反转和收口同时落空**。见 §9.3 R1 |
| 3 | 第三层署名讲成"加个字段" | 它是改 L15 的产物，**必须说"我在改前面那节"**（§0.4） |
| 4 | 个人覆盖讲成禁止 | 学员回去改共享规则，比覆盖更糟 |
| 5 | 语义冲突给了过度承诺的兜底 | 学员以为加条检查就解决了。**必须说第 0 级** |
| 6 | 第五幕离职清单只念不跑 | **第四类（定时任务）查不到，全课投入没兑现** |
| 7 | 讲师顺口说了真同事的名字 | §0.8。全程张三 / 李四 |

## 5. 五幕设计意图

> **逐页口播在 RUNSHEET（待写，§9.2 M6）。本节只写"这一幕为什么存在"。**

### 5.1 第一幕 · 这套东西现在有几个使用者（0 到 24）

| 段 | 分钟 | 做什么 |
|---|---|---|
| 1 | 0-4 | 开场（§0.2）。**聊天框收那个数字，讲师记下来** |
| 2 | 4-10 | 四类使用者（§1.2）。**第四类单独停一下** |
| 3 | 10-20 | **翻车①**：四类各数一个数。**多数人的总数比第 1 段报的大** |
| 4 | 20-24 | 四类的性质对照（§1.2 那张表）。**最后一列"出事能找到谁"最重** |

**第 1 段必须真的把数字收上来并记住**，否则第 3 段没有对照，翻车①就不成立。

**第 2 段第四类要这么说：**

> 「还有第四类，**它没有脸，也没有人记得它**：
> 　**某个人在某个时候配的、现在还在跑的东西。**
> 　上节课（L15）你们开了定时任务。**那现在你那个仓库旁边，一共挂着几个？**
> 　……说不出来，是正常的。**说不出来本身就是今天的第一个发现。**」

### 5.2 第二幕 · 一条痕迹要写几个身份（24 到 50）⭐ 立论在这

| 段 | 分钟 | 做什么 |
|---|---|---|
| 1 | 24-30 | **我在改上节课的东西**（§0.4-1）：L15 痕迹 2 级少了一半 |
| 2 | 30-36 | 三层署名（§1.3）+ **立论** |
| 3 | 36-46 | **在自己的痕迹里加上三层** ⭐ 跑一次 |
| 4 | 46-50 | 后两类的现任主人字段（硬要求）+ "记的不是当时是谁，是现在归谁" |

**第 1 段的说法（沿用 L15 改 L14 的体例）：**

> 「上节课那条痕迹的标准是'**能被重新打开来读**'。那个标准是对的。
> 　**但它只管了'能不能核'，没管'去核谁'。**
> 　一个人用的时候这不是问题 ,, **因为只有一个候选人。**」

**第 3 段是第一个核心动手，10 分钟。**

**第 4 段那句要讲慢，它是全幕最值钱的一句：**

> 「署名不是为了追责，是为了**下次出事的时候知道该去问谁**。
> 　**追责要的是过去时，问人要的是现在时。**
> 　**所以记的不是'当时是谁'，是'现在归谁' ,, 这两个在三个月后不是一个人。**」

### 5.3 第三幕 · 两个人同时改怎么办（50 到 78）⭐⭐ 全节高光

| 段 | 分钟 | 做什么 |
|---|---|---|
| 1 | 50-56 | 冲突两分法（§1.4 那张表） |
| 2 | 56-68 | **翻车②** ⭐⭐：造一次语义冲突，**合并，跑检查，全绿** |
| 3 | 68-73 | 为什么多 agent 放大它（§1.4 三条，**第三条最硬**）+ L8 分界 |
| 4 | 73-76 | 兜底：做得到的 / 做不到的，**承认第 0 级** |
| 5 | 76-78 | **反转** |

**第 2 段是全课最重要的十二分钟。**

**具体做法（M3 要给可跑脚本）：** 两份改动，各自合法：
一边在规则里加一个新角色，一边在 SOP 里写"角色只有三种"。
**合并，git 不报冲突。跑 L13 的检查，全绿。**

> 三句，一句都不能省（沿用 L14 / L15 翻车的三连问手法）：
>
> ```
> 1. git 报冲突了吗？        →「没有」
> 2. 检查红了吗？            →「没有，全绿」
> 3. 那这个仓库现在对不对？  →「……不对」
> ```
>
> **第 3 句之后停两秒。这是全课唯一一次"后背发凉"。**

> 🔥 **埋点：这一格是收口的地基。** 讲师这里说「**这一格今天最后会回来**」，然后走。

**第 3 段第三条要讲慢：**

> 「两个人至少会在群里碰一句。
> 　**两个 agent 之间，一句话都不会说。**
> 　**它们甚至不知道对方存在。**」

**第 5 段 · 反转（三句，一口气到底）：**

```
1  你刚才定的那套冲突规则，管的是【文本冲突】。
2  而真正会咬你的那种，git 一次都不会报。
3  因为两边都合法 —— 它们只是对同一条规矩，理解得不一样。
```

> ⚠️ **反转是对"靠工具发现冲突"的，不是对"冲突管理"的。**
> **别让学员理解成"管不了就别管了"。** 结论是：**管得了的机械化，管不了的写明它停在第 0 级。**

### 5.4 第四幕 · 每个人的权限一样吗（78 到 104）

| 段 | 分钟 | 做什么 |
|---|---|---|
| 1 | 78-84 | **我在改前面两节的两张表**（§0.4-2 / §0.4-3） |
| 2 | 84-90 | 个人层的判据（§1.5）：**覆盖掉之后别人看不出区别 vs 世界上会多出一样东西** |
| 3 | 90-100 | **翻车③**：跑本机 vs 共享比对，**报条数** |
| 4 | 100-104 | 给裁决表加那一行 + 写权限表加差异行 |

**第 1 段要先承认 L14 §3.1 那条是对的，再说它留了什么：**

> 「上节课说个人覆盖放本地、gitignore 掉。**那是对的，不改。**
> 　**但是：一份被 gitignore 的规矩，没有任何人见过 ,, 包括它自己的主人，三个月之后。**」

> 「**'会不会在世界上多出一样东西' ,, 这句话今天是第三次出现了。**
> 　**它是这套东西里最通用的一把尺子。**」

**第 3 段只数条目不看内容**（§1.5 注），**讲师要说出来**，否则学员不敢跑。

### 5.5 第五幕 · 一个人走了怎么办（104 到 135）⭐ 收束

| 段 | 分钟 | 做什么 |

| 4 | 128-131 | 追不到主人的走 L16 删除三步 + **默认该停不该跑** |
| 5 | 131-135 | **收口 + 作业** |

**第 2 段是第三个核心动手，14 分钟。**

**第 3 段必须明说，否则前面四幕的投入在学员眼里没兑现**（§1.7 要点 9）：

> 「看第 4 行。**如果今天上午没有补第三层署名，这一行是查不到的。**
> 　**那个定时任务会继续跑，继续用他的名字，而没有任何人知道它存在。**
> 　**这是今天这节课唯一的、也是全部的回报。**」

**第 4 段回收 L16：**

> 　**今天这条，对一个没主的定时任务同样成立，而且更该成立 ,,**
> 　**因为规矩放在那儿不会自己动，一个定时任务会。**」

### 5.6 收口（131 到 135，四分钟，一秒不能少）

**必须回到开场那个数字。这是本节结构上最关键的一手。**

```
开场的时候我问你们，这套东西有几个使用者。
你们报了一个数。那是你们团队的人数。

现在回头看四样东西：
   痕迹只写了做了什么          , 你知道发生了，不知道算谁的
   个人覆盖被 gitignore        , 他那台机器上的规矩，没有任何人见过
   语义冲突 git 不报、检查也绿  , 两个人都做对了，合起来是错的
   他走了，定时任务还在跑      , 而且还在用他的名字

四件事是同一个形状：
【这套东西里有一部分，没有现任主人。】
```

**停一秒，收口：**

> **你追不到人，多半不是因为没记名字。**
> **是因为那一下，确实没有人做 ,, 它是一个很久以前的决定，**
> **在一个没有人记得的时间，自己发生的。**

**停一秒，回到开场那个数：**

> **所以"这套东西有几个使用者"这个问题，**
> **答案从来不是你们团队的人数。**
> **是【人数 + 还在跑的、没人记得的决定数】。**

**作业（一句话）：**

> 这周就一件事：**回去把那些还在跑的东西列出来，每一个写一个现在还在的人的名字。**
> **写不出名字的那个，这周停掉。**
> **停掉之后没有人来问你，那它本来就不该在跑。**

> ⚠️ **最后那句"停掉之后没有人来问你"要留给学员自己消化，不要解释。**
> 它同时是 L16 删除三步的回声，**解释了就没味道了。**

> ⚠️ **如果本节是系列最后一节**（§9.1-1），收口后加一段，**不超过三十秒**，
> 并把 L16 §5.6 那段"十六节课"改成"十七节课"：
> 「我们从'一条没人执行的规矩'开始，造了仓库、接了手、留了痕迹、学会了拿掉，
> 　**今天把最后一件事补上：这一切，到底是谁的。**」
> **不许加感谢、不许加总结页、不许加"未来展望"。** 收口之后就下课。

**R1 · 语义冲突素材的设计风险（本节唯一的硬风险，对偶于 L15 R1 / L16 R1）：**

翻车② 成立的唯一条件是 **"两份改动各自合法，合并后 git 不报、检查全绿、但仓库确实不对了"**。

```
1  两份改动必须【碰不到同一行】       → 碰到了 git 就报了，这一幕就废了
2  两份都必须能【单独通过全部检查】   → 任何一份单独红，学员会以为是那份写错了
3  合并后的【不对】必须一眼看得出     → 不能是"要仔细想才发现"，三连问第 3 句要秒答
4  零依赖                            → 纯文本 + L13 那套检查，不要网络不要配置
```

**候选做法（待实测）：** 一边在花名册里加第四个角色，
一边在某份 SOP 的第 3 节写死"角色只有三种"。
**两边都合法，合并后 SOP 对不上花名册，而没有任何一条现有检查在比对这两者。**

> **第 3 条是设计重点：学员要在第 3 句问出口的瞬间就答得出"不对"。**
> **要想三秒的，这一幕的冲击就没了。M3 实测的时候以"三秒内能不能答出"为验收线。**
