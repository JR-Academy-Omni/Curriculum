## 逐页规格（在实现前发 parent 供 PRD 整合）

1. F01_SeedToFestival：种子学生 → 网站报名/领票 → 到场获得真实价值 → 分享/邀同学 → 新学生 → 网站报名；授权内容库存作为累积支线。主体一图，核心解释为本轮输出成为下一轮输入。
2. F02_TeamReferral：已报名学生 → 可识别邀请码/邀请入口 → 同学独立报名 → 同学签到 → 按规则奖励 → 新获值学生愿意再次邀请。区分组队与个人邀请条件；不保证所有人会分享。
3. F03_ContentCompounds：真实体验 → 自愿授权内容/攻略 → 下一批学生发现 → 报名到场 → 真实体验；内容库存是累积资产。现有社交任务与拟议官网库存/归因分开标识。
4. F04_Automation：用户事件 → 判断条件 → 触发动作 → 回读结果，四条泳道。前两条现有代码能力，后两条新增教学设计。网站/App作为承接/记录/规则执行工具。

- 种子学生主动招募策略、完整的增长循环视图，是对真实业务结构的课堂解释。
- 官网授权内容库存、分享链接精确归因到新报名/签到、分群到场提醒，为新增教学设计。没有完成 provider、触达、到达/送达验证，不能宣称上线。
- 记录建议：活动ID、匿名/已授权用户ID、来源/邀请人、报名ID、事件时间、签到、内容ID、奖励历史、动作执行状态。只记录业务必要数据，实际Schema字段以源代码为准。
- 真实增量证据暂无：每种来源的新报名、真实签到、首次/重复人群、分享率、邀请成功率、每名获值学生带来的新获值学生数、内容成本、奖励成本、发送送达率，均未从线上取数。
- 截图审核能证明符合任务规则，不能证明内容产生增量获客；点赞、曝光、奖券总数不是新获值用户。

## 建议顺序与讲师备注

最终58页版本：F01–F04对应主课第9–12页，放在Growth Hacker、种子扩散、追踪、实验与飞轮原理后，拼多多/Notion前。新生节负责解释城市落地价值、真实到场、组队规则、UGC权益与事件追踪；拼多多负责交易/供给循环，Notion负责用户创作模板。每组承担不同教学任务，避免重复讲同一个普通推荐流程。

F01 notes：第一批人需要人工找。问学生刚到一个城市最需要什么：朋友、熟悉城市、可靠信息。活动先把这个价值交付出来。网站把线索变成报名记录，但“领票”还不等于获值。真正到场后，有人带朋友，有人留下可复用体验内容。下一批学生通过这些信任资产来到网站，输出成为下一轮输入。箭头展示机制，不是已证明转化率。

F02 notes：这里有两套路径，不要混为一谈。组队有成员、邀请码、满员与全员签到条件；个人邀请有推荐关系和被邀请人签到。奖励作用是增加动力，交朋友和一起到场才是实用价值。OPC可以让首批客户推荐真正完成一个任务的人，再给与服务有关的权益。要去重、记成本，看有价值的人数而非邀请链接点击数。

F03 notes：一场活动结束，素材如果只能发一次，积累有限。经过同意的真实体验可以变成可重复发现的城市攻略和活动答案。越多真实体验可用，下一批学生判断越容易。但需要内容质量、授权与维护。现有截图任务不自动证明增量。官网库存与来源关联是建议设计；公开社交平台到网站可能丢失来源，要承认归因不完整，不编造精确转化。

F04 notes：让自动化先从有确定事件的动作开始。签到成功再依据规则发券，审核通过再奖；执行后读取结果，失败要进待处理队列，不能看到请求成功就认为发奖/送达成功。拟议报名提醒必须基于同意和状态，拟议内容归因要关联网站记录。已有代码只是能力证据，实际某场活动有没有启用、是否执行成功、是否带来增量都要分别验证。
