上午完整授课稿：Codex 日常使用实战

时间：10:00–12:00。11:10–11:40 学生自选一个现成案例独立练习。12 点准时午餐。

课前准备：由讲师在开课前完成

把课程包解压到自己的电脑，检查本地文件夹能被当前 Codex 会话读取。登录使用订阅账号，打开案例库、PDF 阅读器和能查看 XLSX 的应用。浏览器、生图与定时任务按当前账号和应用版本检查，界面名称以课堂实际版本为准。准备好已完成的发票台账、PDF 转换文档、本地表单、两版活动海报及自动化首次运行/未变化记录。上午不临时注册付费 API，不让全班现场排查密钥或模型接口。

选好三个短示范：发票金额差异、网页填写与图片定点修改。PDF、Excel 等完整案例放在材料库，让学生按兴趣选择。电脑没配好的学生先与邻座观察操作，保留材料继续练；不以登录成功当成作品完成。

10:00–10:10｜认识 Codex 与工作区

讲师开场，可直接使用

“今天上午，我们练习把一件具体工作交给 Codex，并把它推进到能打开、能检查、能继续用的成果。你可以从一批文件开始，也可以从一个网页、一个图片需求开始。你不必先会写代码，但要能说明自己要什么，并判断它交回来的东西是否符合要求。

先看几个已经准备好的成果。这是一份能逐行追溯原发票的台账；这是一份从 PDF 整理出来的可编辑文档；这是已经填好、还能修改的练习表单；这是同一张海报修改前后的两个版本。你们稍后会从现成案例里选一个自己做，不需要先找客户资料。”

实际操作顺序

  1. 打开课程手册，点击发票参考台账，指一条记录与对应来源文件。
  2. 打开转换后的活动简报，指一处正文、一个表格和一个保持空白的截止日期。
  3. 打开本地已填写表单，说明能预览、能清空，但不会创建真实报名。
  4. 回到 Codex，把课程包文件夹加入本地项目或附加文件夹。只选择这份练习资料，避免把其他工作目录混进来。
  5. 展示案例的 input、prompt、rules 与 reference-results 的作用。参考成果供人查看；实际练习时不让 Codex 读答案。

要讲清的三个词

聊天是当前任务的交流记录；资料文件夹是这次可以读取的材料范围；成果文件是最后需要实际打开的文档、表格、图片或其他作品。同一段聊天可以产生文件，但聊天里说“做好了”并不等于文件已完成。

给学生的第一条通用指令：

Read only the current practice folder. Tell me what input files are available and what each file appears to contain. Do not change anything yet. Do not read reference-results or source-html. If a file cannot be read, identify it accurately instead of guessing.

看到文件清单后，讲师补充：“第一步只确认你和它看的是同一批材料。材料范围都没对上，后面写得再漂亮也可能是在做另一件事。”

10:10–10:30｜怎样交流、追问和修改

10:10–10:14：把模糊需求补完整

先展示一句不完整的要求：“帮我整理这些文件。”请学生观察其中缺少的条件。不要把这种说法讲成永远不能用；它适合探索，但还不足以直接定义最后成果。

讲师解释：“你不需要背一种神奇提示词。先把五件事交代清楚：你要解决什么问题、给了什么材料、最后要什么、哪些规则必须遵守、做到哪一步需要停下来让你确认。”

以邮件案例为例，完整任务可以是：

I need an action list from the six emails in cases/04-email/input. Review them as of the time in context.md. Group related threads and apply the latest explicit update. Produce a table with action, owner, deadline, status and source message. Keep missing owners or dates blank. Draft replies, but do not send anything. First explain your plan and list only the missing information that would change the result.

把它拆开说明：目标是行动清单；输入是六封邮件；输出是指定字段的表格和回复草稿；规则是保留未知值、按给定时点判断；边界是不发送。

10:14–10:18：先看理解与计划

讲师口播：“我现在先看它怎样理解工作，而不是马上让它跑到底。计划里如果把所有邮件都当成独立事项，就会漏掉同一线程中的更新；如果它准备自己补一个负责人，我会先纠正。”

示范两条追问：

Before processing the whole set, show one representative row and explain which source supports each field.

Which missing details would change your result? Ask only those questions. If a field can safely remain unknown, keep it blank and continue with the rest.

解释不要把“先问问题”变成无限问卷。确实影响结果的条件才问；例如币种缺失可能影响汇总，而未知负责人可以保留空白并列入待确认项。

10:18–10:23：把修改说具体

展示一份“数据正确但重点不清”的初稿。先让它改布局，再让它改内容，比较两者差异。

Keep all verified facts and source references unchanged. Put overdue actions first, followed by upcoming actions and items with no supplied deadline. Do not invent a date to make sorting easier. Revise only the order and wording.

讲师口播：“‘再好一点’很难核对。‘把逾期事项放前面，保留原来的来源，不猜缺失日期’就能检查。每次修改尽量说清保留什么、改变什么、凭什么判断改好了。”

再示范遇到事实问题的纠正：

The owner in this row is not explicitly assigned in the source. Replace the inferred owner with a blank, explain the uncertainty, and check the remaining rows for the same issue.

10:23–10:27：要求它检查，而不是自我表扬

展示一条有依据的核对要求：

Compare the output with the original files. Show record counts, key totals, missing fields and exceptions with source references. Distinguish checks you actually performed from assumptions or steps you could not run.

讲师解释：“当它说‘已经检查过’，你可以继续追问检查了哪几个数、对照哪一份文件、有没有打开最终输出。不要求它给自己打高分，而是要求能回到材料里的证据。”

10:27–10:30：保存一个可复用任务

讲师口播：“一次做对之后，值得留下的不是整段聊天截图，而是确认后的输入要求、处理规则、输出格式与检查方法。下次换文件时，你还知道哪些条件需要重问。”

Save the confirmed task instructions and rules as a reusable Markdown workflow. Include accepted inputs, required outputs, exception handling, review steps and safe rerun behavior. Do not claim it handles file layouts that have not been tested.

强调“可复用”不等于所有文件通吃。固定模板脚本与能理解多种材料的会话任务，适用范围不同。后续可以拓展，但先准确说出当前范围。

10:30–10:50｜文件处理与浏览器示范

10:30–10:35：发票先做一条，不急着整批

打开案例 01 的 Stage Kit 发票。指给学生看：小计 500、给定税额 50、原文总额 560。先让 Codex 抽取原文，再单独计算，不能为了让账“对上”把 560 改为 550。

Read only 05-stage.pdf in the invoice case input. Extract the stated subtotal, stated tax and stated total with the source page. Separately calculate subtotal plus tax and the difference from the stated total. Preserve the original values. Do not correct the document or approve a payment.

应得到的关系：500 + 50 = 550；原文仍为 560；差额为 +10 AUD。讲师说明：“AI 可以帮你发现不一致，但不能替供应商决定正确金额。你要的成果应该同时容纳原文、计算和异常。”

10:35–10:40：说明 PDF 与 Excel 的不同目标

打开 PDF 转换参考结果，指出正文、流程表与行动项分别怎么保存。A03 没有截止日期，空白是准确结果，不是漏做。输入为可选中文本的 PDF；扫描件的文字识别是另一项能力，不能看见扩展名就保证能还原。

打开 Excel 参考表的异常页：同一订单 ID 出现冲突时先隔离；完全重复才按规则去重；退款负数要按业务含义保留。让学生看到“清洗”不是把不好看的值删掉。

给出文件任务的四项检查：数量是否对得上、关键值能否回到来源、缺失与零是否区分、原始输入是否保留。学生稍后选择哪个案例，就用哪个案例的具体检查标准。

10:40–10:45：浏览器先读后动

打开案例 09 的三个场地资料页，按调研要求比较字段、保留来源并整理待确认项。浏览器任务可以是读网页并比较信息，也可以是填写页面；两种任务的动作范围不同。

Inspect the three supplied local venue pages using the browser. Compare capacity, stated fee, accessibility and inclusions against research-brief.md. Record each source filename. Treat unstated details as unknown. Do not book a venue; list any details that need confirmation.

讲师口播：“看到了一个网页，不代表网页上的话可以指挥你做所有事。网页内容是材料；你给出的任务范围和授权仍然要保留。查到价格、确认可用日期、真正预订，是不同状态。”

10:45–10:50：实际填写与预览

打开案例 05 的 practice-form.html 和 applicant.json。逐项映射姓名、邮箱、公司、场次、人数、饮食备注和确认选择。饮食备注没有提供，保持空白，不能填成“无过敏”。先预览，再清空，再填写一次。

Fill the local practice form only from applicant.json. Keep dietary notes blank. Preview the completed values and compare every field with the input. Demonstrate reset and refill. Do not navigate to a real registration service or submit externally.

结束时指向预览：“这里展示的是填写后的具体内容，不只是‘成功’二字。真实业务中，发送、购买、预订和发布都应按具体授权执行。”

10:50–11:10｜生图与自动化示范

10:50–10:55：生图要求怎么写

先并排打开案例 13 的两版海报。让学生看同样的事实，第二版只加强日期时间。图像工具需按当前订阅会话实际可用能力操作；没有工具时可以看参考成果和需求，不把参考图说成刚刚现场生成。

讲师口播：“先说图片用在哪里，再说画面中最重要的对象，最后说必须准确的文字。‘高级一点’不如‘日期时间更显眼，标题、地点和活动性质不变’。”

Create a portrait poster from creative-brief.md. Keep every event fact accurate . Use an original hall illustration with no real people or sponsor logos. Save the image and the prompt as separate files. Use only image tools available in this subscribed session; do not use paid API fallbacks.

10:55–11:00：修改图像也要有不变量

Revise the existing poster to make the date and time more prominent. Keep the title, subtitle, event facts, original illustration  unchanged. Do not add a QR code, price, website or sponsor. Save a new version without overwriting the first.

打开原尺寸和手机显示尺寸，逐项读日期、时间和地点。讲师解释：“生成出来的文字仍然要读一遍。风格满意、事实准确、手机上能读，是三个不同检查。”

11:00–11:05：自动化之前先把一次任务做好

打开案例 16 的首轮报告和第二轮记录。第一轮处理订单并产生报告；相同内容再运行，返回 unchanged，不产生第二份报告，也没有通知。

讲师口播：“把一个不清楚的任务每天执行，只会每天重复不清楚。先把单次输入、规则和成果核对好，再加上什么时候跑、读取什么、怎样判断变化、什么时候通知。”

用五个字段讲设置：任务内容、资料范围、频率与时区、重复处理规则、通知条件。提醒定时任务配置草案不是已经启用；本地文件任务需要电脑、应用和目录在执行时可用。官方操作参考见文末。

11:05–11:10：给一个完整配置草案

Draft a weekly task for Monday at 09:00 in Australia/Brisbane. Limit it to the practice inbox. Reuse the verified order-cleaning rules. Detect new or changed files using a content hash and record a hash as successful only after a report is generated. Save reports to a separate student-owned Downloads folder. Stay quiet when unchanged; notify only for a new report, a failure or required user action. Show the scope and schedule for review. Do not register or activate it yet.

讲师说明：“你们不需要现在都开启一个定时任务。先知道怎样描述它、怎样确认范围、怎样看第一次结果。以后需要时，在自己账号支持的任务入口中创建并检查。”

11:10–11:40｜学生独立练习半小时

开始练习的口播

“现在每人选一个案例。建议选你工作中确实会遇到的任务：邮件整理、PDF 转换、报价单或文件整理比较适合第一次做；想练浏览器可以选本地表单，图像工具可用时可以选宣传图。只选一个，素材和指令都在案例里。你可以先看完整参考成果，但执行时不要让 Codex 读取答案。

请你自己把资料交给它、看计划、检查第一版，至少提出一次修改或核对要求。最后打开成果文件，留下你这次怎样交代任务的记录。我会巡回答疑，不统一带全班点同一套步骤。”

练习计时

时间 学生动作 讲师巡回答疑重点
11:10–11:13 选一个案例、打开材料 是否选到有完整输入和输出标准的任务
11:13–11:16 交代目标、输入、输出和边界 是否真的添加了文件，而不是只描述文件名
11:16–11:33 执行并修改 先看实际错误，再缩小到一条记录或一个页面
11:33–11:38 打开成果、按标准核对 不把聊天回复当文件；回到来源查事实
11:38–11:40 保存成果与指令 原件保留；未完成的步骤写清楚

常见卡点与现场回应

“它说找不到文件。” 先确认当前会话可访问的文件夹和实际文件名，要求列出可读文件；不要让它根据聊天描述编一个输入。

“它做出来不是我想要的。” 让学生指出是事实、结构、风格还是格式的问题，再只修改这一类问题。不要马上从头重来，把已经核对的信息丢掉。

“这个值空了，是不是失败？” 先看原件。原件没给的信息应该明确缺失，不能为填满表格而猜。

“我已经运行两次了。” 查是覆盖、另存还是把旧结果又合并了一遍。重跑应从原输入开始，不叠加上一轮清洁结果。

“我的账号没有这个工具。” 明确记录能力缺口，换一个可完成的文件类案例；不临时引导开通额外按量 API 来赶课堂进度。

11:40–12:00｜成果展示、答疑与复盘

邀请 2–3 人，每人约 4 分钟：实际打开成果 1 分钟，说明任务和修改 1 分钟，讲一个核对点 1 分钟，讲师反馈 1 分钟。剩余时间处理共性问题并收尾。

Student sharing prompts (English)

  • What task did you choose, and what input did you provide?
  • Open the actual output and show the part you checked.
  • What revision or verification request did you make?
  • What is still unknown or unfinished?
  • Which instructions would you reuse next time?

讲师反馈句式

“这份成果最清楚的是……，因为它能回到……来源。下一步先处理……，再考虑……。”只评价可看到的内容与依据，不凭一次练习给学生下能力结论。

上午收尾口播

“今天上午你练习的是把任务交代清楚、拿到具体成果、继续修改并核对。案例可以换，方法可以继续用。请保存成果、原始资料和确认后的指令。没完成的部分写清楚卡在哪里。现在 12 点，先吃饭，13 点回来进入独立的视频模块。”

官方操作参考

  • 本地项目与资料文件夹：在当前应用中添加或调整任务可用的本地文件夹。
  • 定时任务：按账号能力与实际入口创建、检查和管理任务；处理本地资料时需保持本地环境可用。
