# 上午完整授课稿：Codex 日常使用实战

时间：10:00–12:00。11:10–11:40 学生自选一个现成案例独立练习。12 点准时午餐。

## 课前准备：由讲师在开课前完成

把课程包解压到自己的电脑，检查本地文件夹能被当前 Codex 会话读取。登录使用订阅账号，打开案例库、PDF 阅读器和能查看 XLSX 的应用。浏览器、生图与定时任务按当前账号和应用版本检查，界面名称以课堂实际版本为准。准备好已完成的发票台账、PDF 转换文档、本地表单、两版活动海报及自动化首次运行/未变化记录。上午不临时注册付费 API，不让全班现场排查密钥或模型接口。

选好三个短示范：发票金额差异、网页填写与图片定点修改。PDF、Excel 等完整案例放在材料库，让学生按兴趣选择。电脑没配好的学生先与邻座观察操作，保留材料继续练；不以登录成功当成作品完成。

## 10:00–10:10｜认识 Codex 与工作区

### 讲师开场，可直接使用

“今天上午，我们练习把一件具体工作交给 Codex，并把它推进到能打开、能检查、能继续用的成果。你可以从一批文件开始，也可以从一个网页、一个图片需求开始。你不必先会写代码，但要能说明自己要什么，并判断它交回来的东西是否符合要求。

先看几个已经准备好的成果。这是一份能逐行追溯原发票的台账；这是一份从 PDF 整理出来的可编辑文档；这是已经填好、还能修改的练习表单；这是同一张海报修改前后的两个版本。你们稍后会从现成案例里选一个自己做，不需要先找客户资料。”

### 实际操作顺序

1. 打开课程手册，点击发票参考台账，指一条记录与对应来源文件。
2. 打开转换后的活动简报，指一处正文、一个表格和一个保持空白的截止日期。
3. 打开本地已填写表单，说明能预览、能清空，但不会创建真实报名。
4. 回到 Codex，把课程包文件夹加入本地项目或附加文件夹。只选择这份练习资料，避免把其他工作目录混进来。
5. 展示案例的 input、prompt、rules 与 reference-results 的作用。参考成果供人查看；实际练习时不让 Codex 读答案。

### 要讲清的三个词

**聊天**是当前任务的交流记录；**资料文件夹**是这次可以读取的材料范围；**成果文件**是最后需要实际打开的文档、表格、图片或其他作品。同一段聊天可以产生文件，但聊天里说“做好了”并不等于文件已完成。

给学生的第一条通用指令：

```text
Read only the current practice folder. Tell me what input files are available and what each file appears to contain. Do not change anything yet. Do not read reference-results or source-html. If a file cannot be read, identify it accurately instead of guessing.
```

看到文件清单后，讲师补充：“第一步只确认你和它看的是同一批材料。材料范围都没对上，后面写得再漂亮也可能是在做另一件事。”

## 10:10–10:30｜怎样交流、追问和修改

### 10:10–10:14：把模糊需求补完整

先展示一句不完整的要求：“帮我整理这些文件。”请学生观察其中缺少的条件。不要把这种说法讲成永远不能用；它适合探索，但还不足以直接定义最后成果。

讲师解释：“你不需要背一种神奇提示词。先把五件事交代清楚：你要解决什么问题、给了什么材料、最后要什么、哪些规则必须遵守、做到哪一步需要停下来让你确认。”

以邮件案例为例，完整任务可以是：

```text
I need an action list from the six fictional emails in cases/04-email/input. Review them as of the time in context.md. Group related threads and apply the latest explicit update. Produce a table with action, owner, deadline, status and source message. Keep missing owners or dates blank. Draft replies, but do not send anything. First explain your plan and list only the missing information that would change the result.
```

把它拆开说明：目标是行动清单；输入是六封邮件；输出是指定字段的表格和回复草稿；规则是保留未知值、按给定时点判断；边界是不发送。

### 10:14–10:18：先看理解与计划

讲师口播：“我现在先看它怎样理解工作，而不是马上让它跑到底。计划里如果把所有邮件都当成独立事项，就会漏掉同一线程中的更新；如果它准备自己补一个负责人，我会先纠正。”

示范两条追问：

```text
Before processing the whole set, show one representative row and explain which source supports each field.
```

```text
Which missing details would change your result? Ask only those questions. If a field can safely remain unknown, keep it blank and continue with the rest.
```

解释不要把“先问问题”变成无限问卷。确实影响结果的条件才问；例如币种缺失可能影响汇总，而未知负责人可以保留空白并列入待确认项。

### 10:18–10:23：把修改说具体

展示一份“数据正确但重点不清”的初稿。先让它改布局，再让它改内容，比较两者差异。

```text
Keep all verified facts and source references unchanged. Put overdue actions first, followed by upcoming actions and items with no supplied deadline. Do not invent a date to make sorting easier. Revise only the order and wording.
```

讲师口播：“‘再好一点’很难核对。‘把逾期事项放前面，保留原来的来源，不猜缺失日期’就能检查。每次修改尽量说清保留什么、改变什么、凭什么判断改好了。”

再示范遇到事实问题的纠正：

```text
The owner in this row is not explicitly assigned in the source. Replace the inferred owner with a blank, explain the uncertainty, and check the remaining rows for the same issue.
```

### 10:23–10:27：要求它检查，而不是自我表扬

展示一条有依据的核对要求：

```text
Compare the output with the original files. Show record counts, key totals, missing fields and exceptions with source references. Distinguish checks you actually performed from assumptions or steps you could not run.
```

讲师解释：“当它说‘已经检查过’，你可以继续追问检查了哪几个数、对照哪一份文件、有没有打开最终输出。不要求它给自己打高分，而是要求能回到材料里的证据。”

### 10:27–10:30：保存一个可复用任务

讲师口播：“一次做对之后，值得留下的不是整段聊天截图，而是确认后的输入要求、处理规则、输出格式与检查方法。下次换文件时，你还知道哪些条件需要重问。”

```text
Save the confirmed task instructions and rules as a reusable Markdown workflow. Include accepted inputs, required outputs, exception handling, review steps and safe rerun behavior. Do not claim it handles file layouts that have not been tested.
```

强调“可复用”不等于所有文件通吃。固定模板脚本与能理解多种材料的会话任务，适用范围不同。后续可以拓展，但先准确说出当前范围。

## 10:30–10:50｜文件处理与浏览器示范

### 10:30–10:35：发票先做一条，不急着整批

打开案例 01 的 Stage Kit 发票。指给学生看：小计 500、给定税额 50、原文总额 560。先让 Codex 抽取原文，再单独计算，不能为了让账“对上”把 560 改为 550。

```text
Read only 05-stage.pdf in the invoice case input. Extract the stated subtotal, stated tax and stated total with the source page. Separately calculate subtotal plus tax and the difference from the stated total. Preserve the original values. Do not correct the document or approve a payment.
```

应得到的关系：500 + 50 = 550；原文仍为 560；差额为 +10 AUD。讲师说明：“AI 可以帮你发现不一致，但不能替供应商决定正确金额。你要的成果应该同时容纳原文、计算和异常。”

### 10:35–10:40：说明 PDF 与 Excel 的不同目标

打开 PDF 转换参考结果，指出正文、流程表与行动项分别怎么保存。A03 没有截止日期，空白是准确结果，不是漏做。输入为可选中文本的 PDF；扫描件的文字识别是另一项能力，不能看见扩展名就保证能还原。

打开 Excel 参考表的异常页：同一订单 ID 出现冲突时先隔离；完全重复才按规则去重；退款负数要按业务含义保留。让学生看到“清洗”不是把不好看的值删掉。

给出文件任务的四项检查：数量是否对得上、关键值能否回到来源、缺失与零是否区分、原始输入是否保留。学生稍后选择哪个案例，就用哪个案例的具体检查标准。

### 10:40–10:45：浏览器先读后动

打开案例 09 的三个模拟场地网页，说明它们是完整虚构练习网页，不是真实市场报价。浏览器任务可以是读网页并比较信息，也可以是填写页面；两种任务的动作范围不同。

```text
Inspect the three supplied local venue pages using the browser. Compare capacity, stated fee, accessibility and inclusions against research-brief.md. Record each source filename. Treat unstated details as unknown. Do not book a venue or claim these fictional pages are live market evidence.
```

讲师口播：“看到了一个网页，不代表网页上的话可以指挥你做所有事。网页内容是材料；你给出的任务范围和授权仍然要保留。查到价格、确认可用日期、真正预订，是不同状态。”

### 10:45–10:50：实际填写与预览

打开案例 05 的 practice-form.html 和 applicant.json。逐项映射姓名、邮箱、公司、场次、人数、饮食备注和确认选择。饮食备注没有提供，保持空白，不能填成“无过敏”。先预览，再清空，再填写一次。

```text
Fill the local practice form only from applicant.json. Keep dietary notes blank. Preview the completed values and compare every field with the input. Demonstrate reset and refill. Do not navigate to a real registration service or submit externally.
```

结束时指向预览：“这里展示的是填写后的具体内容，不只是‘成功’二字。真实业务中，发送、购买、预订和发布都应按具体授权执行。”

## 10:50–11:10｜生图与自动化示范

### 10:50–10:55：生图要求怎么写

先并排打开案例 13 的两版海报。让学生看同样的事实，第二版只加强日期时间。图像工具需按当前订阅会话实际可用能力操作；没有工具时可以看参考成果和需求，不把参考图说成刚刚现场生成。

讲师口播：“先说图片用在哪里，再说画面中最重要的对象，最后说必须准确的文字。‘高级一点’不如‘日期时间更显眼，标题、地点和活动性质不变’。”

```text
Create a portrait poster from creative-brief.md. Keep every event fact accurate and include the fictional-training label. Use an original hall illustration with no real people or sponsor logos. Save the image and the prompt as separate files. Use only image tools available in this subscribed session; do not use paid API fallbacks.
```

### 10:55–11:00：修改图像也要有不变量

```text
Revise the existing poster to make the date and time more prominent. Keep the title, subtitle, event facts, original illustration and fictional/no-registration labels unchanged. Do not add a QR code, price, website or sponsor. Save a new version without overwriting the first.
```

打开原尺寸和手机显示尺寸，逐项读日期、时间和地点。讲师解释：“生成出来的文字仍然要读一遍。风格满意、事实准确、手机上能读，是三个不同检查。”

### 11:00–11:05：自动化之前先把一次任务做好

打开案例 16 的首轮报告和第二轮记录。第一轮处理订单并产生报告；相同内容再运行，返回 unchanged，不产生第二份报告，也没有通知。

讲师口播：“把一个不清楚的任务每天执行，只会每天重复不清楚。先把单次输入、规则和成果核对好，再加上什么时候跑、读取什么、怎样判断变化、什么时候通知。”

用五个字段讲设置：任务内容、资料范围、频率与时区、重复处理规则、通知条件。提醒定时任务配置草案不是已经启用；本地文件任务需要电脑、应用和目录在执行时可用。官方操作参考见文末。

### 11:05–11:10：给一个完整配置草案

```text
Draft a weekly task for Monday at 09:00 in Australia/Brisbane. Limit it to the practice inbox. Reuse the verified order-cleaning rules. Detect new or changed files using a content hash and record a hash as successful only after a report is generated. Save reports to a separate student-owned Downloads folder. Stay quiet when unchanged; notify only for a new report, a failure or required user action. Show the scope and schedule for review. Do not register or activate it yet.
```

讲师说明：“你们不需要现在都开启一个定时任务。先知道怎样描述它、怎样确认范围、怎样看第一次结果。以后需要时，在自己账号支持的任务入口中创建并检查。”

## 11:10–11:40｜学生独立练习半小时

### 开始练习的口播

“现在每人选一个案例。建议选你工作中确实会遇到的任务：邮件整理、PDF 转换、报价单或文件整理比较适合第一次做；想练浏览器可以选本地表单，图像工具可用时可以选宣传图。只选一个，素材和指令都在案例里。你可以先看完整参考成果，但执行时不要让 Codex 读取答案。

请你自己把资料交给它、看计划、检查第一版，至少提出一次修改或核对要求。最后打开成果文件，留下你这次怎样交代任务的记录。我会巡回答疑，不统一带全班点同一套步骤。”

### 练习计时

| 时间 | 学生动作 | 讲师巡回答疑重点 |
|---|---|---|
| 11:10–11:13 | 选一个案例、打开材料 | 是否选到有完整输入和输出标准的任务 |
| 11:13–11:16 | 交代目标、输入、输出和边界 | 是否真的添加了文件，而不是只描述文件名 |
| 11:16–11:33 | 执行并修改 | 先看实际错误，再缩小到一条记录或一个页面 |
| 11:33–11:38 | 打开成果、按标准核对 | 不把聊天回复当文件；回到来源查事实 |
| 11:38–11:40 | 保存成果与指令 | 原件保留；未完成的步骤写清楚 |

### 常见卡点与现场回应

**“它说找不到文件。”** 先确认当前会话可访问的文件夹和实际文件名，要求列出可读文件；不要让它根据聊天描述编一个输入。

**“它做出来不是我想要的。”** 让学生指出是事实、结构、风格还是格式的问题，再只修改这一类问题。不要马上从头重来，把已经核对的信息丢掉。

**“这个值空了，是不是失败？”** 先看原件。原件没给的信息应该明确缺失，不能为填满表格而猜。

**“我已经运行两次了。”** 查是覆盖、另存还是把旧结果又合并了一遍。重跑应从原输入开始，不叠加上一轮清洁结果。

**“我的账号没有这个工具。”** 明确记录能力缺口，换一个可完成的文件类案例；不临时引导开通额外按量 API 来赶课堂进度。

### Student sharing prompts (English)

- What task did you choose, and what input did you provide?

- What revision or verification request did you make?

“这份成果最清楚的是……，因为它能回到……来源。下一步先处理……，再考虑……。”只评价可看到的内容与依据，不凭一次练习给学生下能力结论。

“今天上午你练习的是把任务交代清楚、拿到具体成果、继续修改并核对。案例可以换，方法可以继续用。请保存成果、原始资料和确认后的指令。没完成的部分写清楚卡在哪里。现在 12 点，先吃饭，13 点回来进入独立的视频模块。”

# 视频制作流程与 Skills 实操：从剧本到 MP4

本章是下午的操作主线。上午仍是 10:00–12:00 的 Codex 日常使用课，12:00–13:00 午餐。下午 13:00–17:00，包含工具安装说明、HyperFrames 主线、Remotion 对照和学生练习。学生不必先学会写代码，但要会给任务、看预览、提修改和打开导出结果。

## 一、先把完整制作流程讲出来

**需求 → 事实与素材 → 剧本 → 分镜 → 镜头动作 → 工程 → 预览 → 修改 → 导出 → 播放验收。**

| 步骤 | 要回答的问题 | 交回什么 | 进入下一步之前看什么 |
|---|---|---|---|
| 需求 | 给谁看，在哪里看，看完记住什么 | 一份短 brief | 一个主要目标，比例与大致时长 |
| 事实与素材 | 哪些话有依据，哪些文件真的存在 | 事实表、素材台账与授权说明 | 未知信息不补猜，计划素材与实际文件分开 |
| 剧本 | 从什么问题进入，怎样展开，怎样收束 | 完整口播与屏幕文字 | 逻辑、事实、重复与自然表达 |
| 分镜 | 每一句配什么画面，先后怎么排 | 时间、旁白、画面、素材、字幕的表格 | 每段内容有对应画面 |
| 镜头动作 | 谁在动，为什么动，动完看到什么 | 主体、初态、触发、变化、结果、转场 | 不是只写“科技感”“高级转场” |
| 工程 | 用哪条制作路线承载这些画面 | HyperFrames 或 Remotion 可编辑项目 | 素材路径、字体、比例与时间线 |
| 预览 | 实际播放时看起来怎样 | 浏览器预览与关键帧 | 开头、最密一镜、转场、结尾 |
| 修改 | 哪一处影响理解或观看 | 新版本与修改记录 | 保留什么、只改什么、怎样核对 |
| 导出 | 生成什么格式，保存在哪里 | 实际 MP4 文件 | 输出路径明确，不覆盖旧文件 |
| 验收 | 最终文件能不能正常用 | 播放记录与问题清单 | 声音、文字、画幅、时长、完整性 |

讲师口播：“不要一开始就让 AI ‘做一个酷炫视频’。先把内容和画面关系写清楚，再让制作工具执行。Skill 帮助 Codex 按一套规则工作，HyperFrames 或 Remotion 把工程变成预览和视频文件，它们各自承担不同角色。”

## 二、剧本、分镜与镜头，分别写到什么程度

### 剧本：把话说完整

剧本包含完整旁白、屏幕上要出现的文字和基本结构。只有“开头吸引人—中间解释—结尾总结”不是可制作剧本。先写受众、问题、一句话结论，再写能自然读出的正文。时长先作为目标，配音或真人朗读后再测量。

```text
Write a complete Chinese narration script about why fitting a landscape image into a portrait canvas can leave empty space, while filling the canvas can crop the sides. Audience: first-time video editors. Use one visual example, preserve aspect ratio, and finish with a practical choice. Separate narration from screen text. Do not invent platform rules or fixed timing. Give three opening alternatives, select one with a reason, then deliver the full script. Do not create the video yet.
```

讲师先打开上一版课程包《视频示范脚本与分镜》的完整旁白，让学生知道目标输出是什么。改脚本时先改事实与逻辑，定稿后才大规模做画面，减少后面因旁白大改导致返工。

### 分镜：把一句话和一个画面对应起来

分镜不是把剧本复制进几行表格。每一行至少有：镜头 ID、暂定时间、对应旁白、画面主体、屏幕文字、实际素材或原创图解、声音、与下一镜的关系。单一镜头可以承担多句话，但要让内容与画面变化对应。

```text
Turn the approved narration into a storyboard. For each shot include: shot ID, provisional start/end, exact narration segment, visible subject, on-screen text, real asset ID or original diagram requirement, audio, and transition to the next shot. Keep missing assets explicit. Do not invent filenames or claim planned footage already exists. Do not change the approved facts.
```

### 镜头：把“怎么动”写成动作链

| 抽象描述 | 可执行描述 |
|---|---|
| 做个科技感画面 | 横版画框进入竖版边框，按比例缩小，剩余区域显现，停稳给观众看 |
| 这里加酷炫动画 | 同一个对象拆成三部分，按步骤落位，组合成完整结果，再接下一个场景 |
| 文字动起来 | 关键词在对应旁白时出现；解释完成后保持可读，其他装饰退场 |
| 转场高级一点 | 上一镜的作品对象保持位置，下一镜的展示台从其下方进入，形成相同对象的接力 |

```text
For every storyboard shot, specify the initial state, trigger, main-object change, visible result, readable hold, and transition anchor. Use the same object when demonstrating before/after conditions. Avoid replacing explanation with whole-page zooms, unrelated stock images or decorative motion.
```

镜头表确认后，把三份文档分别保存为 brief.md、script.md、storyboard.md；镜头动作写进 shots.md。名字是本课程建议结构，不是软件强制约定。

## 三、Skills 到底是什么，怎样安装与确认

### 先分清三层

| 层次 | 作用 | 不能替代什么 |
|---|---|---|
| Codex 会话 | 理解材料、写脚本、编写与修改工程、调用可用工具 | 不自动等于已经有所有软件和素材 |
| Skill | 给 agent 的流程、格式、检查规则与参考资料 | 不是渲染器，也不自动授予账号或付费权限 |
| 运行工具与依赖 | Node、HyperFrames/Remotion、浏览器、媒体工具等 | 安装了工具也不会自动有好剧本和分镜 |

讲师口播：“Skill 可以理解为一份会被 Codex 读取的专业操作手册。你装了它，还需要工程和运行环境。反过来，机器装了渲染器，也不代表 Codex 已经读过制作规则。安装后要确认两件事：这份 Skill 是否真的可读，工具是否真的能运行。”

### 课前环境检查

本课程为两条路线统一准备兼容的 Node 环境；HyperFrames 当前官方要求 Node.js 22+ 与 FFmpeg。其他依赖按课堂实际安装版本检查。以下是只读检查示例：

```bash
node --version
npm --version
git --version
ffmpeg -version
```

没有安装时，让 Codex 说明操作系统、所缺工具与安装方案；不要覆盖学生已有工程，也不要自行更改其他项目版本。依赖下载需要网络；先完成课前检查，课堂保留几分钟讲安装方法与验证，不让全班从零排障。

### 先判断是插件安装，还是独立 Skill

如果 HyperFrames 是通过 agent 的插件管理器安装，技能和 CLI 版本由插件管理。使用该插件的更新与调用方式；不要再用独立安装命令覆盖插件目录。插件模式由 agent 读取自身的 Skill 与启动器规则，不要求学生复制讲师电脑的内部路径。

下面的命令用于**独立 Skill 路线**。课堂只选这一条演示即可；插件安装方式留作对照说明。

### HyperFrames 独立技能安装

在准备使用的视频项目目录里，让 Codex 先检查是否已有同名技能和未提交修改；已经可用时不重复覆盖。官方核心技能安装/刷新入口为：

```bash
npx hyperframes skills update
```

交互安装的另一种入口是：

```bash
npx skills add heygen-com/hyperframes
```

只采用一种安装方式。交互选择时选择实际使用的 agent 与范围，核心组包含 hyperframes、hyperframes-cli、hyperframes-registry、media-use；不必为了数量把全部可选技能装上。独立技能状态可按实际版本执行：

```bash
npx hyperframes skills check --json
```

检查输出与安装器显示的目标目录，再在新的聊天或后续一轮让 Codex 确认能读取实际 SKILL.md。插件模式不执行这些独立技能刷新命令。

### Remotion 技能安装

官方技能仓库入口为：

```bash
npx skills add remotion-dev/skills
```

在已有 Remotion 工程中也可按当前官方 CLI 文档使用：

```bash
npx remotion skills add
```

二选一，按安装器选择 agent 与项目范围；已有技能先检查再处理。基础入口为 remotion-best-practices；创建、预览和导出分别由 remotion-create、remotion-studio、remotion-render 等技能提供对应规则。不要把讲师本机的绝对路径写成全体学生的安装路径。

### 安装后，怎样让 Codex 真正使用

不要求学生记住所有斜杠命令。可以直接在任务中写技能名称，并要求先读取：

```text
Use the installed hyperframes skill. Read its SKILL.md and the relevant creation/preview guidance before editing. Tell me which skill files you could actually read and which project directory you will use. If the skill is unavailable, report that instead of pretending it was loaded. Do not call paid media APIs or change an existing plugin installation.
```

```text
Use the installed remotion-best-practices and remotion-create skills for this project. Inspect the existing files first. Open Remotion Studio as soon as the project can run. Follow the approved script and storyboard. Do not render or publish until I explicitly ask for the export.
```

Skill 的名字、版本、安装目标与运行依赖分别记录。安装成功提示、文件存在、预览能打开和导出成功是四个不同检查。

## 四、HyperFrames：从分镜到可预览工程

### 它负责哪一段

HyperFrames 以 HTML/CSS、媒体和可定位时间的动画构成视频工程，再渲染视频文件。适合本课的图解动画、文字与图像编排。这里用它做宽高比科普片。脚本、分镜和素材仍然由前面的步骤明确，不把渲染器当内容策划者。

### H1：在新目录初始化

以下命令在专门的练习父目录执行，不能在课程资料根目录或已有项目中直接覆盖。目录已经存在时换一个新名字，或先确认它是否是需要继续使用的工程。

```bash
npx hyperframes init aspect-ratio-hf
cd aspect-ratio-hf
```

保留脚手架生成的依赖版本与文件。init 可补齐缺失的核心技能，但不等于刷新已有技能。采用插件模式时，由 agent 根据插件 Skill 使用其版本化启动器，不能直接把此独立命令套在插件目录。

### H2：把内容材料交给工程

讲师指给学生看三类东西：index.html 为入口；compositions/ 放场景；assets/ 放实际图像、字体与媒体。脚手架与项目版本可能影响具体文件，先读实际目录再修改。

```text
Use the HyperFrames skill to build the approved aspect-ratio explainer in this new project. Read brief.md, script.md, storyboard.md and shots.md first. Make one editable scene per storyboard shot, with stable IDs. Keep the canvas 1080 by 1920 at a planned 30 fps, preserve the same diagram objects across comparisons, and keep important text readable. Use local assets and seekable animation. Create the project and preview first; do not generate voiceover, music, paid media or an MP4 yet. Report missing assets accurately.
```

学生不必手写 HTML，但要检查 Codex 是否保留事实、能否找到场景与素材、是否在执行自己确认的分镜。第一轮可先完成 8–12 秒关键镜头，确认风格和动作，再扩展整片；短片段不是整片完成的证明。

### H3：检查、截图与预览

在工程目录中执行：

```bash
npx hyperframes check --json
npx hyperframes snapshot --review
npx hyperframes preview --background
```

读取 check 的实际输出，修复错误，解释剩余警告。snapshot 生成的画面要真的打开看，不能只看命令退出码。浏览器使用 preview 实际打印的项目 URL；不能把源 index.html 直接当作完整编辑预览。预览服务需在检查时保持运行，不把一个猜测端口写给学生。

先检查开头、最密一镜、转场两侧和结尾，再正常速度播放全段。看同一个图解对象是否随旁白变化，是否出现静止卡片轮播、遮挡、比例变形或字体缺失。

### H4：提出一条可核对修改

```text
Keep the approved narration, dimensions and shot order unchanged. In the cropping comparison, show the same landscape frame scaling proportionally until it fills the portrait canvas. Make the hidden side regions understandable, then hold the result before the next shot. Fix only this explanation and preserve the previous version. Rerun the relevant checks and open the changed preview.
```

说明一条有效修改必须包含：保留什么、改变什么、怎样看出改好了。修改后重新查看受影响镜头；改了声音或时长还要看相邻转场。

### H5：明确请求导出

```text
The reviewed preview is approved for a local export. Render the video using the project's documented HyperFrames command. Save the MP4 in a new clearly named location in my system Downloads directory; add a numbered suffix if needed. Do not publish or upload it. Check the exported duration, dimensions and file size, then open and play the actual file. Report any missing audio or unfinished item honestly.
```

CLI 模板如下，方括号中的输出说明必须由 agent 换成真实绝对路径；不要原样粘贴一个不存在的位置：

```bash
npx hyperframes render --quality delivery --output "[absolute path in the system Downloads folder]/Aspect Ratio Explainer - v1.mp4"
```

不同版本以当前项目帮助与技能为准；不添加云端渲染、付费素材或发布步骤。若这是一份无旁白图解预览，就准确交付该版本，不用未授权配音补位。

## 五、Remotion：同样的内容，另一种工程方式

### 它负责哪一段

Remotion 用 React 组件描述画面，通过帧数组织时间线，在 Studio 中预览并渲染。课堂用同一套已确认脚本对照，理解“相同内容，不同工程表达”。不要求学生同时精通两种框架，也不把使用 React 等同于自动获得更好审美。

### R1：新建空工程

在独立的练习父目录执行；若已有工程，就先检查并继续使用，不重复 scaffold。

```bash
npx create-video@latest --yes --blank --no-tailwind aspect-ratio-remotion
cd aspect-ratio-remotion
npm install
```

技能可在脚手架安装流程中添加，也可使用上一节的独立技能安装入口。课前准备好工程，课堂重点是讲清步骤、展示结果，不把大部分时间花在下载上。

### R2：先打开 Studio

```bash
npx remotion studio --no-open
```

打开终端实际打印的本地 URL，确认 Studio 和画面都能加载。已有项目先打开预览，再让 Codex 继续修改。运行中的预览会占用一个终端会话，需要保留它而不是把它误认为卡死。

### R3：让 Codex 把分镜写成组件

```text
Use the installed Remotion skills and the approved script/storyboard. Create a composition named AspectRatioExplainer at 1080 by 1920, 30 fps. Start with the approved 12-second diagram segment as 360 frames; treat this as a preview segment, not the full narration. Give each editable shot its own component and derive animation from frame time. Reuse the same diagram objects for contain, cover and distortion comparisons. Do not use wall-clock timers or introduce paid API calls. Keep Studio open and show the preview before any export.
```

讲清两个概念：composition 是一份可选的视频配置；frame 是时间刻度。30 fps 下，12 秒是 360 帧，这只是本例参数。完整视频时长按实际脚本和声音确定，不能把 45 秒旁白塞进这个 12 秒预览。

画面在某个时间点的样子应由帧确定。学生只需知道为什么这样能预览、跳到某帧并重复导出同一内容，不必在基础课背 React API。

### R4：预览与修改

在 Studio 选择实际注册的 composition，播放、暂停、拖动时间线。先看边界与留白，再看动作与节奏。只看到启动页面或 composition 名称，不算视频预览可用。

```text
In AspectRatioExplainer, keep the composition settings and verified facts unchanged. Fix only the final comparison hold: stop unnecessary motion and leave enough time to inspect the diagram. Verify that jumping backward and forward produces the same visual state. Show the updated Studio preview and record the change.
```

### R5：导出指定 composition

在确认过预览、确实要 MP4 时执行。先检查项目实际 entry point 和 composition ID，不能复制模板后猜它们存在。

```text
Export the approved AspectRatioExplainer composition locally. Confirm its real entry point and registered ID first. Save to a new path in my system Downloads directory without overwriting. Do not publish, use cloud rendering or call media APIs. Open the exported file and check its dimensions, duration, visible text and playback.
```

命令模板：

```bash
npx remotion render [actual entry point] AspectRatioExplainer "[absolute path in the system Downloads folder]/Aspect Ratio Explainer - Remotion - v1.mp4"
```

标准脚手架可能使用 src/index.ts，但必须读取实际工程确认后再替换占位。示例导出完整片而非 12 秒预览前，先更新 composition 的真实时长和对应内容。

## 六、活动素材怎样进入这两条路线

“把素材丢进去”需要拆成可检查的步骤：实际导入 → 读取可用元数据与内容 → 建素材台账 → 选片 → 人工确认结构 → 裁切与排列 → 声音与字幕 → 预览 → 修改 → 导出。某个工具无法理解视频内容时，使用人工选片记录，不让它从文件名猜镜头。

| 台账字段 | 示例性质 | 作用 |
|---|---|---|
| asset_id / real_path | 必须对应实际文件 | 避免计划镜头冒充存在的素材 |
| duration / orientation | 从真实文件或工具读取 | 决定可用时间与构图 |
| in / out | 人工或工具确认的范围 | 实际选取哪个片段 |
| observed_content | 已观察到的动作与对象 | 让结构有证据 |
| original_audio | 可用、需修整、无有效原声等 | 保留讲话意思与声画关系 |
| permission | 已确认范围或待确认 | 未确认部分不进入公开交付 |
| purpose | 该镜头支持什么内容 | 决定保留还是删去 |

HyperFrames 中，素材要进入符合项目规则的媒体元素与时间属性；Remotion 中，素材进入可独立编辑的片段组件和时间线。具体媒体 API 按已安装技能和当前项目文档使用，学生不必手写所有代码。两者都不能只凭台账就声称已经看过全部原片。

```text
Build a proposed event edit from the verified clip log and real authorized files only. Keep each selected clip independently editable, preserve the agreed in/out points and original speech meaning, and produce a preview first. If a file or capability is missing, stop that step and identify the gap. Do not fabricate event footage, transcribe from filenames, or infer audience sentiment. Let me review the rough cut before export.
```

## 七、两条路线怎样选

| 情况 | 本课处理 |
|---|---|
| 第一次学习，用自然语言做图解/文字/图片编排 | 以 HyperFrames 主线跟做 |
| 已有 React/Remotion 工程，或想理解组件与帧时间 | 保持 Remotion，使用其技能 |
| 已有可编辑工程 | 先读原工程，不为演示另一工具而迁移 |
| 活动素材很多 | 两条都先做素材与选片台账，再确认粗剪 |
| 想做酷炫营销视频 | 先确定卖点与逐镜动作，再选工程路线；框架不替代创意与迭代 |
| 想接扣子、火山引擎或其他服务 | 基础流程跑通后再设计接入；存在端点/凭证不等于已验证制作闭环 |

学生练习只选一条引擎路线。先完成 8–12 秒可修改片段也可作为阶段成果，但必须标清范围；最后要声称视频完成，仍要导出并实际播放对应完整作品。

## 九、常见错误与处理

| 看到什么 | 先查什么 | 不应怎样解释 |
|---|---|---|
| Skill 已安装，但不会执行 | 是否实际读取 Skill、CLI 与依赖是否可运行 | 不把 Skill 当万能软件包 |
| 预览空白 | 真实入口、场景注册、素材路径、浏览器报错 | 不把“服务 200”当画面正常 |
| 出现静止画面 | 时间线是否可定位、场景是否正确挂载 | 不靠随机计时器假装能渲染 |
| 中文缺字 | 字体文件、字形覆盖与渲染环境 | 不把系统本机能看当所有机器都能看 |
| 字幕/声音错位 | 实际声音时长、镜头边界、字幕分段 | 不以设计表时间码当真实对齐 |
| 导出位置找不到 | 命令真实输出路径与文件存在性 | 不只报告“已成功” |
| 修改后另一个镜头坏了 | 相邻边界、共享组件和全段播放 | 不只看修改处截图 |

### Final engine-workflow checklist (English)

- The script and storyboard were approved before full implementation.
- The selected Skill was actually readable and the runtime was available.
- The project opens in the correct preview surface with visible content.
- At least one targeted revision was made and rechecked.
- The export uses a real entry/composition and a collision-safe Downloads path.
- The exported file was opened and played; unsupported or unfinished steps are recorded.
- No paid media/API operation, external publication or cloud job was introduced without authorization.

# 视频示范脚本与分镜包

本包是可直接用于备课与制作的完整文本方案。时间码为暂定设计，需按实际声音与画面播放修订；不代表已经生成音频或视频。虚构活动、概念画面与实际活动录像必须区分。

## 示例 A：科普视频

### 内容卡

标题：横版视频放进竖屏，为什么会留边或被裁掉？

受众：第一次处理横竖版转换的人。一个问题：同一段素材怎样放进不同宽高比的画布。一句话结论：完整显示与铺满画布各有取舍，要按用途分别构图，不能靠拉伸保持形状。示范使用 16:9 横框和 9:16 竖框；它们是宽高比，不是所有平台的固定要求。

### 三个开头与选择

| 候选 | 内容 | 判断 |
|---|---|---|
| A | 视频的宽高比是什么？ | 可以使用，但不够直接呈现观看问题 |
| B | 横版视频放进竖屏，为什么不是留边，就是切掉两边？ | 选用：问题能立刻变成可见画面 |
| C | 一键适配所有屏幕，还完全不裁切。 | 舍弃：没有限定条件，承诺不成立 |

### 完整旁白草稿

“横版视频放进竖屏，为什么不是留边，就是切掉两边？看同一张横向画面。如果要把它完整放进去，宽度对齐后，上下就会留下空出来的区域。如果要铺满整个竖屏，就得保持比例继续放大，两边超出的内容会被裁掉。直接把画面拉长，虽然也能填满，但人物和物体的形状会改变。所以先确定视频给谁看、放在哪里，再选择完整显示、重新构图，或者分别制作横版和竖版。关键不是找一个万能尺寸，而是让重要内容始终看得见。”

这段旁白不承诺固定秒数；先真人朗读测时，再调整停顿和分镜。不得为了贴合表格时间而加速到难以理解。

### 逐镜设计

| 暂定时间 | 旁白内容 | 主体与画面模式 | 触发与变化 | 可见结果与下镜承接 |
|---|---|---|---|---|
| 00–06 | 提出留边/裁切问题 | 同一横向画面与竖向画布 | 横框进入竖框；两种结果短暂对比 | 问题落在同一对象上，进入完整显示演示 |
| 06–15 | 完整放入，宽度对齐 | 横框内含圆形和两侧小物件 | 横框按比例缩到竖框宽度，剩余区域显现 | 所有物件保留，上下有空区；保留圆形作为不变量 |
| 15–25 | 铺满后两边超出 | 同一横框、同一物件 | 按比例放大到填满竖框，超出部分被遮罩 | 左右物件部分不可见，圆形仍是圆；以边界线说明裁切 |
| 25–33 | 拉伸会改变形状 | 同一画面短暂比较 | 仅演示一次不等比拉伸，并对照原形 | 圆变椭圆；立即回到保持比例的正确比较 |
| 33–45 | 按用途选择 | 两种构图并排 | 标出完整显示、重构图、分别制作三个选择 | 保持主要对象和结论可读，稳定结束 |

### 画面与声音要求

同一组对象贯穿，避免每句话换一张无关图片。尺寸变化由画布与素材关系承担，不以整页文字缩放替代。字幕不能盖住左右裁切区域。解释拉伸时明确是对比示范，不作为推荐。音效只提示边界或状态变化，不能压过旁白。无旁白版本不能伪造逐字字幕。

### 第一版与修改版对照

| 第一版问题 | 精准修改 | 应观察到的变化 |
|---|---|---|
| 只有两个标题，没有显示哪里被裁 | 保持同一画面，增加边界与超出区域对比 | 能指出哪部分可见、哪部分超出 |
| 画面一直运动，结果看不清 | 变化完成后稳定停留 | 能检查重要对象是否还在 |
| 字幕放在裁切示例上 | 移到不承担说明的区域，按句子断开 | 字幕与示例都能读 |

### 制作任务（English）

```text
Create an explainer from the supplied narration and shot plan. Use a consistent diagram, preserve aspect ratio except in the explicitly labelled distortion comparison, and align changes with the narration. Keep the final takeaway readable. Save the editable source, timing notes and export. Do not claim a completed video until the actual exported file has been played and checked.
```

## 示例 B：活动精华片

### 内容卡

虚构场景：Cedar Community Showcase。主要信息：演示、交流、作品展示。目标观众：未到场但想理解活动内容的人。建议练习范围：约 45 秒。不以人数、报名率或满意度证明效果。

下面的 A01–A10 是**计划镜头 ID**，不是已存在的媒体文件名，也不是已经拍摄过的证据。讲师使用实际获授权素材后，将真实文件名、可用范围和许可记录填入素材台账；缺少相应镜头时调整结构，不伪造素材。

### 完整备拍/选片设计

| 计划 ID | 需要看见什么 | 作用 | 可用替代 | 不能据此声称什么 |
|---|---|---|---|---|
| A01 | 场地环境与活动信息 | 建立位置与主题 | 已授权活动主视觉与场地空镜 | 不能据单个镜头推断总人数 |
| A02 | 来宾到场或签到动作 | 进入活动 | 工作人员准备场地的真实片段 | 不能显示无授权姓名或签到表 |
| A03 | 演示者完成一个可见动作 | 展示内容 | 已授权的手部与作品细节 | 不能把摆拍说成课堂原声 |
| A04 | 演示结果或作品整体 | 让观众看清产物 | 原创作品图解，明确来源性质 | 不能把概念图当真实学生作品 |
| A05 | 一段听得清、意思完整的问答 | 显示交流内容 | 无人声的现场动作与客观字幕 | 不能拼接出未说过的话 |
| A06 | 小组讨论或观察作品 | 展示参与方式 | 已获许可的无人物细节 | 不能写“全员认可” |
| A07 | 作品细节 | 解释作品差异 | 同一作品另一个有效角度 | 不能添加没有依据的功能 |
| A08 | 作品与使用场景同框 | 建立上下文 | 全景与细节成对使用 | 不能暗示未验证成果 |
| A09 | 收尾整理或交流结束 | 形成结束感 | 场地空镜与主视觉收束 | 不能伪造离场评价 |
| A10 | 活动事实信息 | 信息收束 | 文字卡，事实逐项核对 | 不加入未确认报名/链接 |

### 素材台账字段

真实文件名、素材 ID、方向、时长、可用起止、直接观察到的内容、原声情况、已知授权范围、不能展示的内容、被选理由。起止时间从实际文件读取，不能从计划表推算。

### 完整 45 秒剪辑结构

| 时间 | 内容 | 画面选择 | 屏幕文字 | 声音处理 |
|---|---|---|---|---|
| 00–05 | 立即建立活动主题 | A01，必要时接 A02 | Cedar Community Showcase；虚构案例标识 | 环境声起，音乐按授权情况使用 |
| 05–15 | 看见具体演示 | A03 → A04 | 演示：从动作到结果 | 有效原声保留完整意思 |
| 15–25 | 交流如何发生 | A05/A06 | 交流：围绕作品提出问题 | 听清问答时降低音乐；无问答则不编台词 |
| 25–36 | 看清作品 | A07 → A08 | 展示：细节与整体 | 留出观察作品的时间 |
| 36–41 | 收束活动内容 | A09 | 演示 · 交流 · 作品 | 声音平稳收束 |
| 41–45 | 结束信息 | A10 | 教学示例，不开放报名 | 不突然截断原声或音乐 |

如果没有 A05 的许可或清楚原声，使用 A06 的获授权画面与客观字幕，不生成一个人讲话来补位。若只有少量可用素材，缩短成片，不重复镜头硬凑时长。

### 可选旁白草稿

“这份活动精华片，把内容分成三个部分：先看演示动作和结果，再看围绕作品发生的交流，最后回到作品的细节与整体。剪辑时，每个镜头都要支持这条结构。没有授权或没有依据的内容不补猜，重复镜头也不必全部保留。让没到场的人看懂发生了什么，比把所有素材放进去更重要。”

这是**教学解析版**旁白，不是现场人物原声，也不是实际活动宣传口径。对外活动片可选无旁白剪辑，保留真实环境声和准确字幕。

### 验收清单（English）

- Every selected clip exists and has a recorded permission status.
- The opening establishes the subject without a long unrelated lead-in.
- Demonstrations, interaction and works are supported by visible evidence.
- Captions do not invent attendance, sentiment or outcomes.
- Speech retains its original meaning and remains intelligible.
- The export plays fully and the source project is preserved.

## 示例 C：营销概念片段

### 内容卡

对象：虚构 Cedar Community Showcase。主张：把想法变成可以观看、讨论的作品。交付范围：15 秒概念片段，表现“想法 → 作品 → 展示”。它是设计练习，不冒充真实活动纪录或真实学生成果。

### 开头比较

| 候选 | 设计 | 选择理由 |
|---|---|---|
| A | 泛光背景里出现很大的活动名 | 能显示标题，但价值还没出现 |
| B | 一张创意卡片形成一个具体作品对象 | 选用：先看见结果怎样形成 |
| C | 宣称参与后人人获得商业成功 | 舍弃：无事实依据，也超出案例范围 |

### 完整屏幕文字与口播草稿

屏幕文字顺序：把想法，变成看得见的作品 → 演示 · 交流 · 展示 → Cedar Community Showcase → 14 NOV 2026 / 14:00–17:00 / Cedar Hall（fictional）→ 虚构教学概念，不开放报名。

可选口播：“把一个想法，变成看得见、聊得清的作品。演示、交流、展示，放在同一个下午。这是一份社区展示会的虚构概念练习。”

如果实测口播不能自然放入 15 秒，就缩短口播或延长片段，不压缩事实标签的可读时间。也可以制作无旁白版本，保留准确文字。

### 逐镜动作规格

| 暂定时间 | 主体 | 触发与变化 | 必须看见的结果 | 转场理由 |
|---|---|---|---|---|
| 00–04 | 一张创意卡片与一个原创作品对象 | 卡片展开，作品组成部分依次进入位置 | 一个完整可辨认的作品对象形成 | 相同对象被带到下一个空间 |
| 04–08 | 作品与小型展示台 | 展示台进入，作品落位，另两个作品出现 | 观众看见“作品展示”的场景 | 展示台边缘引导视线到活动信息 |
| 08–11 | 演示、交流、展示三个内容对象 | 按顺序连接，展示各自关系 | 三个活动内容可读且有对象支持 | 连接线收束到活动名称 |
| 11–15 | 活动名、日期时间、虚构地点 | 信息落定，停止多余运动 | 日期、地点与虚构标识稳定可读 | 直接稳定结束，不插入虚假报名按钮 |

### 不变量与修改要求

不变量：活动事实、虚构性质、主对象和叙事顺序。可修改项：对象进入顺序、停留时间、画面密度、信息层级与声音提示。第一轮只改结尾可读性；第二轮只改对象形成过程；每次保留前一版便于比较。

### 制作与核对任务（English）

```text
Build the fictional concept segment from the supplied shot specification. Keep the visible result of each shot clear before transitioning. Use one consistent visual language and retain all fictional-event labels. Preserve versions. Check the opening, the densest shot, both sides of each transition and the final hold. Do not claim generated imagery is real event footage or add real attendance, endorsements or registration links.
```

## 三类视频共用的交付结构

1. 需求：受众、用途、一个主要目标、已确认事实与授权范围。
2. 内容：确认后的脚本、分镜或选片清单。
3. 制作：可编辑工程、用到的素材及其来源说明。
4. 检查：实际播放发现的问题、修改记录、未完成项。
5. 成果：能打开播放的导出文件；未导出则准确记录状态。

实际导出存到系统 Downloads 或用户选择的位置，命名包含主题与版本，不覆盖已有文件。文本方案完成、工程完成、成片完成和发布完成分别记录。
