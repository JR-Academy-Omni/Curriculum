## 1. 这一节的三句话（讲师必须能默写）

**立论** —— 第一幕末尾说，全课只说一次：

> **装不到第二台机器上的，不是系统，是习惯。**

**反转** —— 第四幕，学员刚把自己的包装成功、最有成就感的时候翻：

> **你交出去的不是文件，是默认值。**
> **别人不会读你的 README，他们会直接用你设的默认。**

**收口** —— 全程不许提前说：

> **一套系统的真正考验，不是它跑得多好，**
> **是它的作者离开之后它还在不在。**

**三句话怎么连起来（讲飞的时候回到这条链）：**

```
东西散在一台机器上
  → 散的东西没法交
  → 交的形状是一个【包】
  → 而包里装的是【默认值】，不是文件
  → 默认值 = 你替别人做了、但没说出口的决定
  → 所以交接的本体是【把那些决定说出口】
  → 而最后一个没人说出口的决定是：你走了之后，谁来收
```

**收口那句同时收掉四样东西：**

| 课上哪一格 | 怎么被它收掉 |
|---|---|
| 三层 scope（P04） | user 级 + 没进 git = 只有你有，你走了它就没了 |
| 凭据不属于包（P11） | 包能交出去，钥匙交不出去，钥匙跟着人走 |
| 四件要说出口（P21） | 没说出口的决定，作者走了就没人知道当初为什么这么定 |
| 定时任务还在跑（P26） | 他走了，他配的东西没走，还在以他的名义跑 |

**四件事是同一个形状：系统活着，但那个唯一懂它的人不在了。**

## P04 ｜ 18–24 ｜ 三层，不是一个文件

你刚才看到的三段，对应三层。

第一层，是装给你自己的。它不属于任何一个项目，你在哪儿干活它都跟着你。你换一个项目，它还在。

第二层，是装给这个项目的。它跟着项目走，而且它进 git。

第三层，只在这台机器的这个项目里有效。它不进 git。

这三层的区别有很多条，今天我们只看一条，就是这里的第三列：进不进 git。

进 git 的东西，别人把仓库 clone 下来就有了。不进 git 的东西，只有你这台机器上有。别人拿不到，你换一台机器也拿不到。

〔不要展开，不要解释为什么这一列最重要。这是埋点，收口回收。〕

〔硬停二十四分钟。〕

## P05 ｜ 24–27 ｜ 立论

〔整屏一句话。说之前停一秒。全课只说这一次。〕

装不到第二台机器上的，不是系统，是习惯。

〔停两秒。不要立刻解释。〕

我先挡掉一个最容易产生的误会：我说的不是「跑在一台机器上就不算系统」。一台服务器上跑着的服务，当然是系统 —— 因为别人可以照着把它重建出来。

所以分界线不在它跑在几台机器上。在于一件事：除了你，还有没有第二个人能把它立起来。

第一节课我们讲 Source of Truth，讲一件事只应该有一处权威出处。十四节课下来，你确实做到了，你的每件事都有出处，都落在了具体的文件上。

但是那个出处，只存在于你这一台笔记本上。

而一个只有你能用的权威出处，对别人来说，跟不存在是一样的。

〔硬停二十七分钟。〕

## P07 ｜ 32–36 ｜ 别人做的东西，是怎么到你机器上的

既然散着的东西交不出去，那我们看看别人是怎么交的。

你一定装过别人做的插件。那个插件是怎么跑到你机器上来的？

答案比大多数人想的简单：一个插件市场，就是一个 git 仓库，加一份清单。没有别的。

那个仓库里放着若干个目录，每个目录是一个插件。仓库根目录有一份清单文件，写着这个市场叫什么、里面有哪些插件、每个插件在哪个目录。就这些。没有服务器，没有审核流程，没有商店。它就是一个仓库。

所以你当然也能做一个。不过今天我们不讲怎么做市场，今天讲怎么做那个被装的东西本身。

〔硬停三十六分钟。〕

## P08 ｜ 36–44 ｜ 装一个现成的

我们先装一个别人做好的，把完整的过程走一遍。

```bash
claude plugin marketplace add anthropics/claude-plugins-official
claude plugin install feature-dev@claude-plugins-official --scope user
```

第一条，把那个市场加进来。参数就是一个 GitHub 仓库地址。它做的事情，就是把那个仓库克隆到你本地。

第二条，装其中一个插件。注意这里的写法：插件名，一个 at 符号，然后是市场名。为什么要带市场名？因为不同的市场里可能有同名的插件，你得说清楚要哪一个。

最后那个参数是装到哪一层。我们今天选第一层，装给你自己，所以写的是 user。

〔等。跑通了发 1，卡住了发 2 加一个词。〕

〔如果市场拉不到，立刻切本地兜底，不要让全班等网络。附录第二页有完整说法。〕

〔硬停四十四分钟。〕

## P09 ｜ 44–49 ｜ 刚才那一下，东西去哪了

装完了。我们看看东西去哪了。

第一处，那个市场的仓库被克隆到了你本地，整个躺在那儿，你现在就能打开看。

第二处，插件本身被放进一个缓存目录，按市场、插件、版本分三层放好。

第三处，有一份记录文件，记下了你装了什么、装在哪一层、是哪个版本、什么时候装的、对应哪一次提交。

这三处都是纯文本。你现在打开任何一个，都能看懂。

这里没有黑盒。装一个插件这件事，从头到尾就是三个动作：把一个仓库拉下来，把一个目录放到约定好的位置，在一份清单上记一笔。

你之所以觉得它像个黑盒，只是因为以前没打开看过。

〔硬停四十九分钟。〕

## P10 ｜ 49–57 ｜ 一个包，能带什么

〔这一页是整节课的枢纽。讲慢。要点名问，不要自己一口气念完。学员在这一页认不出自己造的东西，这节课就白讲了。〕

现在是今天最重要的一页。

一个包能带六类东西。我每念一类，你想一下：这一类，对应你前面哪一节课造的那个东西。

第一类，技能。

〔停，点一两个人回答。〕

对，第五节课。你把一个反复用的套路固化成了一个技能文件，当时它放在你自己的目录里。它可以进包。

第二类，助手，也就是 subagent。第七节课，你给上下文分家，做了一个专门干某件事的助手。它可以进包。

第三类，斜杠命令。你自己定义的那些快捷入口。它可以进包。

第四类，钩子。第十二节课你写的那个，把「我跟它说过」变成「它绕不过去」的那个。它可以进包。

第五类，脚本。第十一节那个定时任务背后跑的东西，第十三节那个会拦人的检查。它们都可以进包。

第六类，外部连接。这一类跟前五类不太一样，我下一页单独讲。

〔整页回望。这是全课的转折点，说得重一些。〕

所以你看这张表。这不是一个新工具的功能列表。这是你前面十四节课造出来的东西的清单。

你一直以为你在上一节一节分开的课。它们其实一直在往同一个盒子里放东西，只是那个盒子今天才拿出来。

〔硬停五十七分钟。〕

## P11 ｜ 57–60 ｜ 第六类不一样

第六类，外部连接，跟前面五类不一样。

第十四节课我们讲过连接器，讲过怎么让它够得着外面的东西。那一节还讲过，那种点一下同意的授权，撑不过一个定时任务。

包可以带「它怎么连」这件事：连到哪里去、用什么方式、连不上的时候怎么办。但是包带不走那把钥匙。

别人装上你的包，他拿到的是「这里要接一个外部系统」这个结构。他必须用他自己的凭据去接。

这是对的，不是缺陷。一个能把钥匙一起交出去的包，是一个你根本不该交出去的包。

〔轻轻放下，不展开。这是埋点，第二十六页回收。〕

〔硬停六十分钟。〕

## P12 ｜ 60–65 ｜ 怎么知道插件真的装进来了

装完了，你怎么知道那个插件真的生效了？

你刚才屏幕上是不是出现了一行字，说安装成功？

〔等一下。〕

那行字证明的是「安装这个动作执行了」，不是「这个东西在工作」。这两件事不一样。

第十四节课最后那句话，还记得吗。它最危险的时候，不是它做错了事，是它什么都没做，而你以为它做了。一行「安装成功」，是这句话最便宜的一个例子。

所以我们不看提示，我们去看行为。

```bash
claude plugin details feature-dev
```

它会打出一份清单，叫 component inventory。技能有几个、助手有几个、钩子挂在什么时机触发、有没有外部连接，一行一行列出来。

这一行一行，是它实际带进来的东西。安装提示证明动作执行了，这份清单才证明东西在。

〔等。看到清单而且里面确实有东西，才算数。看到了发 1。〕

〔硬停六十五分钟。〕

## P13 ｜ 65–70 ｜ 那现在，做你自己的包

别人的装完了，现在做你自己的。

我们先看一眼，做一个能被安装的东西，最少需要什么。答案可能比你想的少得多：一个目录，和一份四行的说明文件。

```json
{
  "name": "my-handover",
  "version": "0.1.0",
  "description": "我的技能和钩子。",
  "author": { "name": "换成你的名字" }
}
```

名字，版本，一句话描述，作者。就这些。

〔重复一遍，因为没人会信。〕

一个能被安装的包，它的全部身份信息，就是这四行。

剩下的事情不需要配置，只需要把东西放对地方。技能放在叫 skills 的目录里，助手放在 agents，命令放在 commands，钩子放在 hooks。这些目录名是约定好的，你不能自己起名字，但你也不用写任何配置去声明它们。放对位置，它们就会被认出来。

课前包里那个 `p13-my-package` 目录，就是这样一个已经搭好的空骨架。它现在里面放的是占位的东西，接下来两步，我们把它换成你自己的。

〔硬停七十分钟。〕

## P15 ｜ 77–85 ｜ 再放一个钩子进去

再放一个钩子进去，第十二节课那个。

钩子跟技能不一样。技能是一个目录丢进去就行，钩子需要一份配置，说清楚它在什么时机触发、触发之后跑什么。

```json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "node \"${CLAUDE_PLUGIN_ROOT}/scripts/leave-a-trace.mjs\"",
            "timeout": 5
          }
        ]
      }
    ]
  }
}
```

〔现在是本页的重点。放慢。〕

请你看这一行里的路径，特别是前面那个大括号包起来的东西。

你的钩子要跑一个脚本。那个脚本的路径，绝对不能写死。

因为你写死的路径，是你这台机器上的路径。别人装上你的包，那个路径在他机器上根本不存在。然后会发生什么？钩子静默失败。不报错，不提示，什么都不发生。而他完全不会知道。

〔一句话点一下，不要重复讲第十四节。〕

又是那句话：什么都没发生，而你以为发生了。

所以这里要用这个占位符。装上去的时候，它会被自动换成这个包在那台机器上的真实位置。你不用管它在哪，系统知道。

〔跑通了发 1。〕

〔硬停八十五分钟。〕

## P16 ｜ 85–90 ｜ 有些东西不该进包

包里能放什么讲完了。现在讲不该放进去的。

你第十三节课造了一个规则仓库，里面有角色、有花名册、有裁决表、有那些会拦人的检查。

那个不进包。

这里有一条很清楚的分界线：跟着人走的东西，进包；跟着项目走的东西，留在项目里。

你的技能、你的助手、你的钩子、你的工作习惯，这些是你的。你换一个项目，它们理应跟着你走。所以它们进包。

而这个项目的规则、这个团队的角色、谁说了算、什么不许做，这些是项目的。换一个人来做这个项目，这些东西不该变。所以它们留在仓库里，进 git。

如果你把项目的规则塞进了你的个人包，会发生一件很糟糕的事：团队的规矩变成了你的个人习惯。然后你走了，规矩跟着你一起走了。

〔这句话是收口的半截，说完就往下，不要说破。〕

〔硬停九十分钟。〕

## P17 ｜ 90–100 ｜ 把你的包装到一台不是你这台的环境上

〔全课最硬的一处，十分钟。先说安全，而且要说得让人放心。〕

现在是今天最重要的一个动作。

在做之前，我先把安全这件事说清楚。接下来我们用的是一个隔离环境，它不会动你平时的配置。所有的读和写都被引到一个临时目录里去了，脚本里还有一道硬拦截：万一那个临时路径指向了你的真实配置目录，它会直接拒绝执行。做完之后有一条清理命令，清掉之后你的机器跟现在一模一样。

四步。

```bash
bash p17-clean-profile/clean-profile.sh new
bash p17-clean-profile/clean-profile.sh add ./p13-my-package
bash p17-clean-profile/clean-profile.sh install my-handover@my-package
bash p17-clean-profile/clean-profile.sh verify my-handover
```

第一步，建一个干净的环境。建完它会告诉你里面装了什么，答案是什么都没有。那就是干净的样子。

第二步，在那个干净环境里，把你自己的包当成一个市场加进来。注意这里的参数是一个本地路径，不是网址。市场不一定要在 GitHub 上，一个本地目录一样可以当市场用。

第三步，装。写法跟你刚才装别人东西的时候一模一样：插件名，at 符号，市场名。

第四步，验证。用我们刚才那个办法，不看提示，看清单。

〔等。这一步会慢。〕

〔这是全课唯一必须等到八成以上才能往下的环节。跑通了发 1，卡住了发 2 加一个词。〕

〔到点仍有人没通：让他们先看着往下走，告诉他们附录第二页有完整的排查步骤，课后可以自己跑完。后面两幕是收口，不能丢。〕

〔全班通了之后，说这一句，然后停两秒。〕

你刚才做的事情是：你把你的工作方式，装到了一台不是你的机器上，而且它工作了。

这就是这门课十五节的终点。

〔硬停一百分钟。〕

## P18 ｜ 100–105 ｜ 装不上，通常是这三种

〔正面讲，不做演示，不要让学员故意去把包装坏。〕

装不上的情况，绝大多数是这三种里的一种。我正面讲一遍，你们不用自己去试。

第一种，路径写死了。症状是：在你机器上好好的，到别人那儿什么都不发生，而且不报错。解法就是刚才那个占位符。

第二种，东西放错了目录。症状是：装上了，但那个技能或者钩子像不存在一样。解法是记住那几个目录名是约定好的，不能自己起。

第三种，包里依赖了一个只有你有的东西。症状是：别人一装就报错，错误信息指向一个他没有的文件、命令、或者凭据。

第三种的解法要多说一句：一个包，只能依赖两样东西，一是它自己带着的，二是那台机器上一定有的。除此之外的所有东西，都必须在交接说明里写出来。

而交接说明长什么样，就是下一幕的内容。

〔另外，做完包先验证再交。这一条写在课前包的说明里了，课上提一句就行。〕

```bash
claude plugin validate p13-my-package
```

〔硬停一百零五分钟。〕

## P20 ｜ 108–111 ｜ 反转

〔整屏一句话。说之前停一秒。时机写死：必须在上一页收完数之后。〕

你交出去的不是文件，是默认值。

别人不会读你的说明文档，他们会直接用你设的默认。

## P21 ｜ 111–116 ｜ 所以有四件事，必须说出口

〔四格。一格一格问，不要一口气念完。〕

那么哪些决定必须说出口？

有四件。而且这四件不是我编出来的，它们正好就是第十四节课那四幕。

第一，它会碰什么。第十四节第二幕那张写权限表。别人装上你的包之前，得知道这个东西能动哪些地方。

第二，它什么时候会自己跑。第十四节我们讲过人触发和自动跑的区别。一个会在别人不在场的时候自己动起来的东西，必须在装之前就说清楚。

第三，它依赖什么外部凭据。刚才说过，包带不走钥匙。那就得告诉别人：你要用这个，得自己准备哪几把钥匙。

第四，它坏了之后谁修。

〔这一格停久一点。〕

这一格最容易空着。而它空着的时候，答案默认是你。永远是你。

〔不要说破，收口会收。〕

〔硬停一百一十六分钟。〕

## P22 ｜ 116–118 ｜ 一份交接要写清楚什么

这四件事写下来，就是一份交接。

一份像样的交接，在成熟的做法里是有固定的节的。今天我们只取其中四节，因为这四节一旦空着，交接就不成立。

第一节，负责人：谁对这个包负责。第二节，触发：这个包在什么时候会动。第三节，证据：这个包干了什么，留在哪，能不能被重新打开来读。第四节，复审日期：下一次什么时候再看一眼。

〔停在后两节。〕

后面这两节最常空。而它们恰恰是唯二能回答一个问题的：这东西现在还算不算数。

〔不展开，往下。〕

〔硬停一百一十八分钟。〕

## P24 ｜ 122–125 ｜ 你的包会变旧

〔最后一幕。节奏放慢，这一幕是收口的坡道。〕

最后一幕。

你的包做好了，也交出去了。然后呢？

然后你的包会变旧。它依赖的东西会升级，它接的外部系统会改接口，你写下的那个默认，半年之后可能已经不对了。

第十四节课我们讲过漂移，讲过权限会漂、配置会漂。包也一样，而且更安静。

一个没有复审日期的包，等于一个没有维护者的包。

它不会报错，它只会慢慢变得不对。而因为它不报错，所以没有人会去看它。

## P25 ｜ 125–128 ｜ 有一格，填不出来

〔脱敏纪律：只说「一套真实在运转的系统」。不点名，不说是谁的，不给任何文件数量。〕

我见过一套真实在运转的系统。它的流程文件写得相当完整，每一份都有负责人，每一份都写清楚了什么时候触发、谁来做、做完算什么。

只有一份例外。那一份的负责人那一格，是空的。

而那一份，恰好是讲「一个人离开之后，怎么把他的权限收回来」的。

〔停，让它沉一下。〕

我一开始以为那是没写完。

后来我看到了那一格旁边的注释。它写的是：负责回收权限的那顶帽子，本来就没有人戴。而这份文件存在的理由，就是把这件事摆到台面上。

〔停两秒。这一页的论点，说慢。〕

所以我想说的是：一份流程文件最大的价值，可能恰恰是它的某一格填不出来。

你写到某一节写不下去了，那不是你没写完。那是你刚刚找到了这个组织里真正的那个洞。

〔硬停一百二十八分钟。〕

## P26 ｜ 128–131 ｜ 你今天走，留下什么

那我们就来问这个问题。

你今天走。你留下什么？

第一类，人。这个简单，谁都知道要办，流程也是现成的。

第二类，你的助手。你配过的那些东西，还在你的账号下面跑着。

第三类，服务凭据。刚才我们说过，包交得出去，钥匙交不出去。所以钥匙还在你手上。或者更糟，还在某个已经没人记得的地方，继续生效着。

第四类，还在跑的定时任务。

〔这一格要重。〕

第十一节课，你让一个 agent 定时替你干活。那个东西现在还在跑。

你走了，它不会停。它会继续按你几个月前定的规矩，以你的名义，在没有人看着的时候，继续做事。

而现在，没有任何一张表上有它。

〔硬停一百三十一分钟。〕

## A2 ｜ 附录 ｜ 装不上怎么办 · 讲师兜底

〔课上不讲，但讲师必须熟。第十七页卡住的人课后看这一页。〕

**线上市场拉不到的时候**，课前包里有一个本地市场可以直接顶替，流程完全一样：

```bash
bash p17-clean-profile/clean-profile.sh add ./p17-offline-fallback
bash p17-clean-profile/clean-profile.sh install handover-demo@jr-l15-local
bash p17-clean-profile/clean-profile.sh verify handover-demo
```

**隔离环境没清干净**的时候：

```bash
bash p17-clean-profile/clean-profile.sh clean
```

它删的是一个独立的沙箱目录，不碰你平时的配置。

|---|---|
