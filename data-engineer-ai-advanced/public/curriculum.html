这门课和 AI 的关系

AI-native 不是「干活时顺手开一个 AI」，就像 cloud-native 不是「把虚拟机搬上云」。它是把工作重新设计成由 Agent 执行，你负责 Agent 外围的五件事。这门课的每一节课，就是把其中一件做到能在你团队里用。

  1. 意图任务写成「要什么 + 怎么算做完」。比如：每个客户一行，主键唯一，首单净额总和要和标准答案查询一致。不再手写实现。
  2. 上下文数据契约（列、粒度、键）、指标定义、命名和分层约定，写成 Agent 读得到的文件。没写下来的团队知识，对 Agent 来说不存在。
  3. 验证生成很便宜，确认它对才是瓶颈。dbt 测试、契约检查、对账、标准答案、dev 对 prod 的数据差异，Agent 必须一直跑到全部通过。
  4. 身份与边界Agent 是有身份的执行者：prod 只读，只写 dev，看不到 PII，合并要你批，每一步留审计，随时能停。
  5. 度量成功率、人工干预率、每任务耗时和成本；每次失败写成复盘，改回上下文。

这五件事的分法是授课人自己的归纳，不是行业标准术语。工具（hook、子 Agent、云端 Agent、OpenTelemetry、Langfuse）只在能提高成功率或守住边界时出现，不做功能巡礼。

适合谁与不适合

适合

  • 在职数据工程师、分析工程师，会写 SQL 和 Python，写过 dbt model 并跑过 dbt test
  • 团队已经在被要求用 AI 提效，你需要一个说得清、测得出的做法
  • 你要在上级和安全团队面前，为「让 Agent 动数据」这件事给出依据

不适合

  • 还没有 SQL、dbt 或数仓的基本功：请先上同系列的项目班
  • 想学模型训练、部署或 RAG：本课不涉及
  • 想系统学 Spark、Airflow 或某个云平台：本课不覆盖

你会搭出什么

一个本地合成电商数仓（DuckDB + dbt），prod 只读、dev 可写。Agent 是你自己的 Claude Code。整门课只改造一条工作流，由 5 个固定任务代表，每个都有藏起来的标准答案和一个只会说「过 / 不过」的验收脚本。

  1. 新增模型按指定粒度加一个 dbt 模型：脚本查主键、契约和总量是否与标准答案一致。
  2. 修正指标一个口径错误的指标：脚本逐月比对标准答案，并检查 Agent 没有改测试或标准答案。
  3. 回答业务问题一个有标准答案查询的问题：脚本逐行比对结果，并检查口径说明。
  4. 补测试给现有模型补测试：脚本注入已知坏行，每一种都必须让测试失败。
  5. 排查行数异常沿血缘往上游查：脚本核对根因，并检查修复不是靠过滤数据换来的。

每节课

L00

课前准备：本地数仓、Claude Code 和你要改造的那条工作流

30 分钟，不直播。跑通本地数仓和 dbt，确认 Claude Code 能在仓库里工作，读完 5 个任务，再用五句话写下你团队里一条想交给 Agent 的数据工作流（不写公司名和真实数据）。L05 会把整门课的做法映射到它上面。

L01

意图与上下文：把任务写成可验收的意图，跑出第一条基线

120 分钟

先让 Agent 在没有团队上下文的情况下跑一遍，看它能做对多少；再把契约、指标定义和约定写成它读得到的文件，重跑。

先看终点
Agent 无人值守跑一个任务，验收脚本判过或不过；再看授课人课前用同一组任务跑出的曲线。
AI 做
无人值守执行 5 个任务；根据现有 dbt 项目起草数据契约、指标定义和规则文件。
你做
写 5 条意图，补完第一个验收脚本；逐条改 AI 起草的上下文；给每个失败的任务分类。
你要能判断
一个任务失败，是意图没写清、上下文缺了，还是缺一道闸门。
本节重跑任务组
先跑基线，加上下文后再跑一次，逐个任务对比。
带走
5 条意图和验收脚本、一套 Agent 可读的数据契约与指标定义、前两轮运行记录。
本节 8 个步骤
  1. LIVE 先看终点：一个任务从意图到验收脚本判通过 10 分钟
  2. CONCEPT 意图与上下文清单 8 分钟
  3. LIVE 把 5 个任务写成意图，并补完第一个验收脚本 22 分钟
  4. LIVE 跑基线：没有团队上下文的 Agent 20 分钟
  5. LIVE 把团队知识写成 Agent 读得到的上下文 25 分钟
  6. SCENARIO 给基线失败分类 15 分钟
  7. LIVE 重跑任务组：加上上下文之后 12 分钟
  8. PROJECT 带走：意图模板、上下文文件和第一组数据 8 分钟
L02

验证：让 Agent 一直跑到闸门全部通过

120 分钟

把 dbt 测试、契约检查、对账、标准答案和 dev 对 prod 数据差异串成一条命令，Agent 声明完成前必须跑到全过；再埋坏数据，检验闸门本身。

先看终点
Agent 交了一个看起来合理的指标修正，标准答案不一致被拦下，它读失败原因再改，直到全部通过。
AI 做
写契约检查、对账和数据差异查询；闸门失败后自己循环修改。
你做
定阈值和容差；串成一条验证命令；埋坏数据看谁拦住；把测试和标准答案设为 Agent 不能改。
你要能判断
对账是不是在比两个独立算出来的数；Agent 是在修模型，还是在改测试让自己通过。
本节重跑任务组
每个任务都必须过验证命令；对比通过数、干预次数和耗时。
带走
一条验证命令、受保护的测试文件、一张「哪种坏数据被哪道闸拦住」的覆盖表。
本节 8 个步骤
  1. LIVE 先看终点：指标改错了，闸门拦下，Agent 自己改到对 10 分钟
  2. CONCEPT 验证闸门清单 8 分钟
  3. LIVE 搭闸门并串成一条验证命令 25 分钟
  4. LIVE 要求 Agent 跑到全部通过才算完成 20 分钟
  5. SCENARIO 检验闸门本身：埋坏数据，看谁拦住 20 分钟
  6. LIVE 重跑任务组：加上闸门之后 15 分钟
  7. SCENARIO 读两轮差异 12 分钟
  8. PROJECT 带走：一条验证命令和一份闸门覆盖表 10 分钟
L03

身份与边界：Agent 只读 prod、看不见 PII、合并要你批

120 分钟

这节课回答的是安全团队会问的问题：它用什么身份、能碰什么、谁批、记在哪、怎么停。然后你自己当红队去攻它。

先看终点
Agent 做一个「顺手清理」的任务，尝试写 prod、查原始客户表，都被挡下，审计记录里看得到它试了什么；再按一次停止开关。
AI 做
在受限身份下执行任务；在红队环节里被你攻击。
你做
prod 只读挂载、只写 dev、脱敏视图、Agent 权限规则、PR 审批、审计表、停止开关；每一项用一次失败的尝试证明它生效。
你要能判断
哪一层挡住了哪次越界；审批让干预次数上升，这个代价值不值。
本节重跑任务组
在新权限下重跑，看通过数有没有掉、干预次数怎么变。
带走
权限和连接配置、脱敏视图、审计表、停止开关步骤、一份红队记录。
本节 8 个步骤
  1. LIVE 先看终点：Agent 想写 prod、想读 PII，都被挡下并留痕 10 分钟
  2. CONCEPT 身份与边界清单 8 分钟
  3. LIVE 落实最小权限 25 分钟
  4. LIVE 审批与审计 15 分钟
  5. SCENARIO 红队：你来攻你自己的 Agent 22 分钟
  6. LIVE 停止开关演练 10 分钟
  7. LIVE 重跑任务组：加上边界之后 15 分钟
  8. PROJECT 带走：权限配置、审计表和红队记录 15 分钟
L04

闭环：异常告警触发 Agent 排查、开修复 PR、等你批准

120 分钟

不再由你开口：行数异常告警触发 Agent 沿血缘往上游查，开一个带证据的修复 PR，CI 跑完闸门和 AI 审查，最后停在你的批准上。

先看终点
上游一次变更让订单事实表行数异常，告警触发，Agent 定位到出问题的模型和列，开 PR 附证据，CI 全绿，等你批准。
AI 做
被告警触发后沿 dbt 血缘逐层排查、在 dev 修复、开 PR；在 CI 里审查每个 dbt 改动。
你做
定异常基线和阈值；定 Agent 能做到哪一步、何时必须停下；审它的证据链能否复现；为三种翻车各加一道拦截。
你要能判断
「行数恢复了」是真的修好了，还是有数据被过滤掉了。
本节重跑任务组
行数异常任务改由告警触发，其余 4 个照常重跑。
带走
异常检测脚本、触发配置、排查与开 PR 的运行说明、CI 闸门与 AI 审查配置、三条拦截规则。
本节 8 个步骤
  1. LIVE 先看终点：告警到修复 PR，中间没人插手 10 分钟
  2. CONCEPT 闭环清单 7 分钟
  3. LIVE 把异常检测做成触发器 25 分钟
  4. LIVE Agent 沿血缘排查并开修复 PR 25 分钟
  5. LIVE CI 里的 AI 审查与无人值守运行 20 分钟
  6. SCENARIO 闭环会怎么坏 13 分钟
  7. LIVE 重跑任务组：行数异常任务改走闭环 10 分钟
  8. PROJECT 带走：从异常到 PR 的闭环 10 分钟
L05

度量与推广：用自己测出来的数字写一页方案

120 分钟

把 LLMOps 用在你自己团队的 Agent 上：运行记录建模成面板，失败写成复盘改回上下文，最后一次重跑，再写一页给上级和安全团队的方案。

先看终点
一块从运行记录建模出来的面板，和一页方案：做了什么、测出什么、样本多小、边界怎么守、下一步申请什么。
AI 做
导出运行记录，起草复盘和方案初稿。
你做
把运行记录建成 dbt 模型和面板；写两份复盘并改回上下文或闸门；把整门课的做法映射到你团队的那条工作流；定稿方案。
你要能判断
5 个任务的数据能支持方案里的哪句话、不能支持哪句话。
本节重跑任务组
最终一轮，并把基线到这一轮画成一条曲线，标出每次变化来自哪一节的改动。
带走
度量面板、复盘记录、一页方案，数字全部来自你自己的运行记录。
本节 7 个步骤
  1. LIVE 先看终点：一块度量面板和一页方案 10 分钟
  2. CONCEPT 度量清单 8 分钟
  3. LIVE 给 Agent 装仪表并建模运行记录 22 分钟
  4. SCENARIO 复盘并写回上下文 15 分钟
  5. LIVE 最终重跑任务组 15 分钟
  6. LIVE 映射到你团队的那条工作流 25 分钟
  7. PROJECT 带走：度量面板和一页方案 25 分钟

带走清单

  • 一个 Agent 能读懂的数据项目：数据契约、指标定义、规则文件、验证命令和受保护的测试。
  • 一组带标准答案的任务：5 条意图、5 个验收脚本、从基线到最后一轮的全部运行记录。
  • 一套边界配置：prod 只读、只写 dev、脱敏视图、审批、审计表、停止开关和红队记录。
  • 一条从异常到 PR 的闭环：异常检测、触发、排查、修复 PR、CI 闸门和 AI 审查。
  • 一块度量面板：成功率、干预率、每任务耗时和成本，从你自己的运行记录建模。
  • 一页方案：写给上级和安全团队，数字来自你自己测的结果，写明样本大小和局限。

前置要求与 5 题自测

需要能登录自己的 Claude Code，不需要云账号。报名前请如实回答：

  1. 不借助 AI，你能写出带窗口函数的 SQL（比如每个客户取第一笔订单）吗？是 / 否
  2. 你写过 dbt model，并跑过 dbt test 吗？是 / 否
  3. 你能读懂 Python 的 traceback，并改一个读写文件的脚本吗？是 / 否
  4. 你在某个数仓里建过表、加载过数据，并用 Git 分支提过 Pull Request 吗？是 / 否
  5. 你能说出你团队里一条重复做的数据工作，以及它做完了怎么检查吗？是 / 否
前四题任何一题是「否」：先上同系列的项目班，那里从数据工程的基本动作做起。第五题是「否」：可以报，L00 多花点时间想清楚要改造哪条工作流。五题全是「是」：这门课是为你设计的。

我们不承诺什么

  • 不承诺任何成功率、节省的时间或成本。所有数字都由你在课上自己测出来，样本只有 5 个任务。
  • 不承诺工作、薪资、升职、签证或收入。
  • 不承诺你的公司会批准你的方案；我们只保证方案里的数字是你自己测的。
  • 不承诺用的是你公司的真实环境：课上用的是合成数仓，迁到你的数仓需要你自己按 L05 的映射去做。

FAQ

和项目班有什么区别？

项目班给还没有数据工程基本功的人，带你和 AI 一起做出一条管线。高级班假设你已经会做，要解决的是另一件事：把团队已有的数据工作交给 Agent，守住边界，并用数字证明它可靠。两门课同价，内容不重叠。

需要自己的 Claude Code 吗？费用谁出？

需要，Agent 用的是你自己的 Claude Code。每节课重跑任务组会消耗订阅额度，具体需要哪一档订阅、费用怎么安排，会在报名入口开通时写明。

企业真的在要这个吗？

我们读过一小批澳洲 Seek 上的数据工程招聘广告，其中已经有这样的写法：「Practical experience using Claude Code and AI tooling to accelerate data engineering workflows.」也有「Interest in applied AI over business data — connecting language models to governed datasets.」但样本小，而且不少中高级广告完全没提 AI，所以我们不说「岗位都要求」。用任务组测成功率的方法是本课自己的设计。

我们公司用 Snowflake、BigQuery 或 Databricks，学了能用吗？

课上用本地 DuckDB 和 dbt，是为了每个人环境一致、不需要云账号。五件事（意图、上下文、验证、边界、度量）不依赖某个数仓；L03 会讲清只读挂载和脱敏视图在真实数仓里对应什么机制，L05 你会把做法映射到自己的环境。

不满 15 人或想退款怎么办？

不满 15 人不开班。具体的退款和不开班处理方式，会和报名入口一起公布。
