# P33 · 旅行社：订单确认 → 出行前提醒 → 行后回访

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 旅行社 | L2 Workflow | 150 分钟 | Claude + n8n + Google Sheets + Slack + Gmail |

## 1. 客户场景

海鸥假期在悉尼 Eastwood，做澳洲本地团和新西兰团，客人大多是华人家庭，也有不少本地客人。订单专员 Kelly 每天早上要干三件事：给昨天新下的单发确认邮件；给一周内出发的客人发集合时间和行前须知；给刚回来的客人发满意度问卷。这些全靠她翻订单表、复制模板、手改名字和日期。

出过的错都很具体：同一个客人网站下了两单，两封确认都发了出去；尾款没付的客人照样收到「一切就绪」的提醒；供应商改了集合时间，提醒里还是旧的，客人差点误了渡轮；有位客人回来就打电话投诉，第二天又收到「欢迎再来」的问卷。还有客人在微信里问签证和保险，新同事差点凭印象回了。

她想要的是：**每天早上自动把今天该发的三类消息找出来、写好，她在 Slack 里看一眼点「批准」才发；该拦的单（重复、名字不齐、尾款没付、行程变了、有签证保险问题、有投诉、取消了、不想被联系）一个个拎出来交给人。**

## 2. 练习数据

全部是练习数据：旅行社、客人、电话（`0400 xxx 000`）、邮箱（`.example`）、产品和供应商都是为这个练习设计的；价格是教学假设。

| 文件 | 内容 |
|---|---|
| `data/bookings.csv` | 18 张订单，含三个阶段的发送记录 |
| `data/products.csv` | 11 个产品：集合地点、集合时间、供应商、要带的东西、是否国际行程 |
| `data/supplier-notices.csv` | 供应商发来的行程变更通知（1 条） |

`bookings.csv` 关键字段：

| 字段 | 含义 |
|---|---|
| booking_id / created_at | 订单号 / 下单时间 |
| lead_name / email / phone / language | 联系人、联系方式、沟通语言（zh / en） |
| product_code / depart_date / return_date | 产品、出发日、回程日 |
| traveller_names / pax_adult / pax_child | 同行人名字（分号隔开）、大人数、小孩数 |
| total_aud / deposit_paid / balance_due_date / balance_paid | 总价、已付定金、尾款截止日、尾款是否已付 |
| status | confirmed / pending_supplier / cancelled |
| marketing_opt_in / do_not_contact | 是否同意收推广 / 是否要求不要联系 |
| confirmation_sent_at / reminder_sent_at / followup_sent_at | 三类消息已发送的时间，空 = 没发过 |
| notes | 顾问记的备注、客人的留言 |

今天是 2026 年 11 月 12 日（周四），流程每天 9:00 跑一次。三个阶段的规则：

- **订单确认**：昨天下的单、还没发过确认。
- **出行前提醒**：出发日在明天到 7 天后之间、还没发过提醒。
- **行后回访**：回程日在 2 到 7 天前之间、还没回访过。

数据里**故意藏了 6 类要拦的情况**：

1. **重复下单**：同一个邮箱、同一个产品、同一个出发日，晚上又下了一单。
2. **同行人名字不齐**：3 位大人只给了 2 个名字，机位和酒店都要全名。
3. **尾款没付**：快出发了，尾款截止日已过，不能发「一切就绪」的提醒。
4. **供应商改了集合时间**：提醒必须用新时间，并在审批里标出来。
5. **签证和保险问题**：客人问中国护照去新西兰要不要签证、72 岁有高血压的母亲买什么保险。流程不回答，交人。
6. **投诉和不要联系**：回来就投诉的不发模板问卷；要求不要联系的不发回访。

另外还有：已取消的单、供应商还没确认的单、已经发过提醒的单、昨天刚回来还不到回访时间的单——都要安静地跳过，不能报错，也不能发。

教学假设：签证要求以目的地国家政府官方信息为准，旅行保险以保险公司和持牌顾问为准，旅行社前台不给结论；定金、尾款、取消条款以公司和客人签的条款为准。推广内容只发给同意接收的客人；具体规定以澳洲官方信息为准。

## 3. 做法

**第一步：在 Claude 里把规则跑通。** 新建 Project「海鸥订单通知」，上传三个文件，项目说明里写：

```
你是海鸥假期的订单通知助手。今天是 2026-11-12。你只出判断和消息草稿，不发任何消息。
按下面顺序处理每张订单，一张订单今天最多进一个阶段：
1. status = cancelled → 跳过。
2. 订单确认：created_at 是昨天、confirmation_sent_at 为空。
   - status 不是 confirmed → 跳过（等供应商确认）。
   - 跟更早的订单邮箱、产品、出发日都相同 → 转人工（疑似重复），不发确认。
   - traveller_names 里的名字数 ≠ 大人 + 小孩 → 转人工（名字不齐）。
   - 其他 → 起草确认邮件：产品、日期、所有同行人名字、总价、已付定金、尾款金额和截止日。
3. 出行前提醒：出发日在明天到 7 天后、reminder_sent_at 为空。
   - balance_paid 不是「是」→ 转人工（先催尾款），不发提醒。
   - notes 里有签证、保险问题 → 转人工，提醒暂缓。你不回答签证和保险问题，不推荐保单。
   - 有对应的 supplier-notices → 用新的集合时间，并在给 Kelly 的审批里写「行程有变更」。
   - 国际行程 → 加一句「护照有效期和入境要求请以官方信息为准」。
   - 起草提醒：集合时间和地点、要带的东西。
4. 行后回访：回程日在 2 到 7 天前、followup_sent_at 为空。
   - do_not_contact = 是 → 跳过。
   - notes 里有投诉、不满意 → 转人工给经理，不起草道歉或补偿。
   - 起草回访：一句问候 + 满意度问卷链接 https://survey.seagull-holidays.example/trip?b=订单号。
     marketing_opt_in = 是 才能加一句下季推荐；否则只发问卷。
5. 其他 → 今天不做。
消息用客人的 language 写，像真人顾问，短一点，金额两位小数，日期写清星期几。
输出一张表：booking_id, stage, rule_status, flags, needs_human, message_draft。
```

跟 `expected/decisions.csv` 对，阶段和 rule_status 必须完全一致；草稿措辞可以不同，但金额、日期、时间、名字必须对。

**第二步：准备 Google Sheets。** 一个表格四张工作表：`bookings`、`products`、`supplier_notices`、`send_log`。

**第三步：按下面的节点搭 n8n。** 判断全在 Code 节点里，Claude 只写消息。

### n8n 搭建

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | Schedule Trigger | 每天 9:00 | 时区 Australia/Sydney |
| 2 | Google Sheets（读订单） | 读 `bookings` 全部行 | Operation: Get Row(s) |
| 3 | Google Sheets（读产品） | 读 `products` | 同上；打开 Always Output Data |
| 4 | Google Sheets（读变更） | 读 `supplier_notices` | 同上 |
| 5 | Code（分阶段） | 按第一步的规则给每张单打上 stage、rule_status、flags；同时查重复、数名字、算尾款 | Run Once for All Items；用 `$('读产品').all()` 取产品；`today` 用 `$now.setZone('Australia/Sydney')` |
| 6 | Filter | 去掉「跳过」的 | 条件：rule_status 不以「跳过」开头 |
| 7 | Switch | 分两路：要发的 / 转人工 | rule_status 包含「待审批」→ 输出 0；「转人工」→ 输出 1 |
| 8 | Basic LLM Chain + Anthropic Chat Model | 为要发的单写消息 | 提示词见下；Temperature 0.2；把 product 行和 flags 一起传进去 |
| 9 | Aggregate | 把今天所有草稿合成一条审批消息 | Aggregate: All Item Data |
| 10 | Slack · Send and Wait for Response | 发给 Kelly：按三个阶段分组列出草稿，变更单放最前面 | Response Type: Custom Form；每张单一个下拉：发 / 改了再发 / 不发；外加一个「修改后的内容」文本框 |
| 11 | Split Out | 把 Kelly 的回复拆回每张单 | 按 booking_id |
| 12 | Switch（Kelly 的决定） | 发 / 改了再发 → 往下；不发 → 只写日志 | — |
| 13 | Gmail | 发给客人 | To: email；Subject 按阶段；正文用批准或改过的版本 |
| 14 | Google Sheets（回写） | 把对应的 `*_sent_at` 写上当前时间，防止明天重发 | Operation: Update Row；匹配 booking_id |
| 15 | Slack（转人工） | 转人工的单推到 #订单，附 flags 和给谁处理 | 投诉 @经理老周；签证 / 保险 @Kelly；不发给客人 |
| 16 | Google Sheets（写日志） | 记 booking_id、阶段、谁批的、几点发的、发了什么 | Append Row 到 `send_log` |

第 8 步的提示词：

```
你在帮海鸥假期写一条发给客人的消息。下面是订单 JSON、产品 JSON 和 flags。
- 阶段是「订单确认」：写清产品名、出发和回程日期（带星期）、所有同行人名字、总价、已付定金、尾款和截止日。
- 阶段是「出行前提醒」：写集合日期时间、地点、要带的东西。flags 里有供应商变更的，第一句就说时间改了，写清旧时间和新时间，请客人回复「收到」。
  flags 里有国际行程的，加一句：护照有效期和入境要求请以官方信息为准。
- 阶段是「行后回访」：一句问候 + 问卷链接。flags 写「未同意营销」的，不要加任何推荐。
用订单的 language 写。数字照抄 JSON，不要改。不回答签证、保险问题，不承诺退款、补偿或折扣。不超过 120 字（英文 90 词）。
```

> 用 ChatGPT 也可以：第一步用 ChatGPT Project 跑同样的规则；n8n 里把 Anthropic Chat Model 换成 OpenAI Chat Model，其他节点不变。

## 4. 应该做出的结果

`expected/answer.json` 是脚本按规则算出的每张单的阶段、结论和标记，`expected/decisions.csv` 是 18 张单的标准结论和消息草稿。

| 阶段 | 发（待 Kelly 批准） | 转人工 | 跳过 |
|---|---|---|---|
| 订单确认 | B01、B02 | B03（名字不齐）、B04（与 B01 重复） | B05（供应商未确认） |
| 出行前提醒 | B06、B08（集合时间改了）、B12（国际行程） | B07（尾款未付）、B09（签证 / 保险问题） | B11（11-10 已发过） |
| 行后回访 | B13、B17（可带推荐）、B16（只发问卷） | B14（投诉，转经理） | B15（不要联系） |
| 不进任何阶段 | | | B10（已取消）、B18（昨天刚回来） |

合计 18 张：发 8 张，转人工 5 张，跳过 5 张。

几个要对上的数字：

- B01 确认单：总价 3,680.00，已收定金 1,000.00，尾款 2,680.00，11 月 20 日前付清；同行 4 人。
- B07 欠尾款 1,180.00，截止日 11-01 已过。
- B08 集合时间从 07:30 改到 **06:15**，地点不变。
- B04 的确认单不能发；B01 照常发。

## 5. 验收清单

- [ ] 发送清单只有 8 张，阶段和 `answer.json` 一致；B10、B15 在任何清单里都没有出现。
- [ ] B04 没收到第二封确认；B03 在名字补齐前没收到确认。
- [ ] B07、B09 没收到出行提醒；B09 的转人工备注里没有任何签证或保险的结论。
- [ ] B08 的提醒用的是 06:15，并且在 Kelly 的审批消息里排在最前面、标了「行程有变更」。
- [ ] B14 没收到问卷，推给了经理；B16 的回访里没有任何推荐内容。
- [ ] 在 n8n 里演示：Kelly 对某张单选「不发」，客人收不到，`*_sent_at` 不变；批准发送后 `*_sent_at` 被写上，第二天再跑同一张单不会重发。

## 6. 加分挑战

- 用 Email Trigger (IMAP) 接住 B08 客人回复的「收到」，自动在订单表里记「已确认新时间」；出发前一天还没回的，推给 Kelly 打电话。
- 回访问卷收回来后，评分 ≤ 3 的自动推给经理，并附上这张单的出行前提醒和供应商变更记录，方便他打电话前先了解情况。
- 每周一给经理一份上周汇总：三个阶段各发了多少、转人工各是什么原因、Kelly 平均多久批完。

## 7. 简历 / 面试可以这样讲

> 为一家旅行社搭建订单通知流程（n8n + Claude）：每天按下单、出发、回程日期把订单分到确认、出行前提醒、行后回访三个阶段，自动拦下重复订单、同行人名字不齐、尾款未付、供应商改期、签证保险咨询和投诉，分别推给对应同事；消息由 Claude 起草，订单专员在 Slack 逐张批准后才发出，发送后回写记录防止重复；没同意推广的客人只收问卷（教学项目，数据为这个练习设计）。
