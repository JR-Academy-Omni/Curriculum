# P29 · 建筑装修：现场日报与照片说明整理成周进度报告

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 建筑装修 | L1 自动化 | 50 分钟 | Claude（Projects）+ Excel / Google Sheets |

## 1. 客户场景

筑宁建设是墨尔本 Doncaster 的一家住宅翻新公司，手上同时有三四个工地。这一单（J-2611）是一套独立屋的厨房、主浴室和后院平台翻新，业主每周六要一份进度报告。现场主管阿杰每天收工在共享表里写日报，拍了照片就在另一张表里写一句说明。项目经理张工周六早上要把这一周的东西翻一遍，对着进度计划算每项工程走到哪了、哪项慢了，再挑照片写给业主。常出的错：别的工地的日报混进来、同一条交了两次、照片里拍到了邻居家的孩子也一起发给了业主，业主随口提的「岛台加长」被写成了本周进度，结果业主以为已经在做了。

他想要的是：**周六早上把这周的日报和照片说明丢进去，十几分钟拿到一份对得上计划的周报草稿；安全问题放最前面，业主提的变更单独列出来等他拍板，有问题的记录列给阿杰核对。**

## 2. 练习数据

三份文件，都是为这个练习设计的（公司、工地、人名都不是真实的）。没有照片文件，照片只用文字说明代替。

`data/site-diary-week-2026-11-02.csv`：11 月 2 日到 7 日（周一到周六）的现场日报，共 17 行。

| 字段 | 含义 |
|---|---|
| date / job_id / author | 日期、工地编号、谁写的 |
| trade / task_id / area | 工种、对应计划里的任务、区域 |
| work_done | 当天做了什么 |
| pct_after | 当天收工时这项任务的完成百分比 |
| workers / hours | 几个人、每人几小时 |
| issue | 问题、等待、业主说的话 |
| photo_ids | 当天照片编号，多个用分号隔开 |

`data/schedule.csv`：7 项任务的进度计划：task_id, task, trade, planned_start, planned_finish, pct_start_of_week（本周一开始时的完成度）, planned_pct_end_of_week（计划本周末应到的完成度）。

`data/photo-captions.csv`：20 条照片说明：photo_id, date, taken_by, area, caption。

数据里**故意藏了 6 处问题**：

1. 一条别的工地（J-2608）的日报混进来了；
2. 同一条日报交了两次；
3. 后院平台的进度从 60% 倒退成了 55%；
4. 日报里写了一张照片 P21，照片说明表里没有；
5. 有一张照片 P20 是上周五拍的，本周日报没提到它；
6. 一张照片说明里写着拍到了隔壁的孩子，不能放进给业主的报告。

另外，日报的 issue 里有一条安全问题（浴室墙里有裸露旧电线）、一条业主提的变更（岛台加长 + 加插座），都要单独列。

公司的规则（这家公司自己定的，不是行业标准）：进度偏差 = 本周末实际 − 计划；+10 以上算超前，0 到 +9 按计划，−1 到 −10 略慢，低于 −10 落后。业主提的变更要老板和业主书面确认价格和工期，周报里不写成进度。真实的变更和工期调整以双方签的装修合同为准。

## 3. 做法

**第一步：在 Claude 里建一个 Project。** 名字叫「J-2611 周报」，把 `schedule.csv` 放进项目文件，说明里写：

```
你是筑宁建设 J-2611 工地的周报助手。我每周六会上传本周的现场日报和照片说明。项目文件里有进度计划 schedule。
先挡问题，再算数：
1. job_id 不是 J-2611 → 不用，列进「需要核对」。
2. 完全一样的日报出现两次 → 只算一次，列进「需要核对」。
3. 按日期顺序看每项任务的 pct_after：比之前的值低就不接受，沿用之前的最高值，列进「需要核对」。
4. 日报里提到的照片编号，在照片说明表里找不到 → 列进「需要核对」；照片说明表里有、但本周日报没提到的照片 → 不放进报告，列进「需要核对」。
5. 照片说明里出现邻居、小孩、车牌、门牌、业主家人、人脸 → 不放进给业主的报告，单独列进「仅内部」。
然后输出：
① 安全问题（放最前面）：日期、任务、问题原文。
② 进度表：任务、工种、本周初 %、本周末 %、计划 %、偏差、状态（超前 / 按计划 / 略慢 / 落后；计划为 0 且没开始的写「未开始（按计划）」）。
③ 业主提的变更：原话照抄，写「待老板和业主书面确认，不计入进度」。
④ 其他等待事项：日报 issue 里的其他内容。
⑤ 每项任务配的照片说明（只用可以给业主看的）。
⑥ 本周工时：按工种合计 workers × hours。
⑦ 需要阿杰核对：日期、问题、说明。
⑧ 给业主的一段话（不超过 150 字）：本周做完了什么、哪项慢了为什么、下周做什么。只写数据里有的，不承诺完工日期。
```

**第二步：上传两份文件，发一句：**「出 11 月 2 日这一周的 J-2611 周报。」

**第三步：核对。** 用第 5 节的清单逐条对。至少手工检查一项：后院平台在日报里的 pct_after 依次是 50、60、55、70、75，确认周报用的是 75，并且 55 那一条进了核对表。

**第四步：变成每周的流程。** 张工每周六上传当周的两份文件，看一遍周报草稿，改好给业主的那段话，再连同照片发出去。安全问题和变更这两块他自己处理，不发给业主。

> 用 ChatGPT 也可以：建一个 ChatGPT Project（或自定义 GPT），把计划表放进文件，同样的规则写进说明，上传日报和照片说明即可。

## 4. 应该做出的结果

`expected/answer.json` 是标准答案（脚本按同样规则算出来的）。日报 17 行，用了 15 行（去掉别的工地 1 行、重复 1 行）。

| 任务 | 工种 | 本周初 | 本周末 | 计划 | 偏差 | 状态 |
|---|---|---|---|---|---|---|
| 厨房水电预埋 | 水电 | 30% | 95% | 100% | −5 | 略慢 |
| 主浴室防水 | 防水 | 0% | 90% | 100% | −10 | 略慢 |
| 主浴室贴砖 | 贴砖 | 0% | 0% | 20% | −20 | 落后 |
| 厨房石膏板 | 石膏板 | 0% | 35% | 50% | −15 | 落后 |
| 后院木平台 | 木工 | 40% | 75% | 80% | −5 | 略慢 |
| 前窗更换 | 门窗 | 50% | 100% | 100% | 0 | 按计划 |
| 卧室刷漆 | 油漆 | 0% | 0% | 0% | 0 | 未开始（按计划） |

- 状态：按计划 1 项、略慢 3 项、落后 2 项、未开始 1 项。贴砖落后是因为防水的闭水测试周日才出结果，日报里写了「结果出来之前不能贴砖」；石膏板落后跟 11-05 上午下雨有关。
- 本周工时（人 × 小时）：木工 66、水电 48、门窗 27、石膏板 24、防水 13，合计 **178**。
- 安全问题 1 条：11-04 主浴室地漏旁墙里有裸露旧电线，已断电贴警示。
- 业主变更 1 条：11-03 岛台想加长 30cm、多加一个插座。
- 照片：18 张可以放进给业主的报告；P14（说明里拍到隔壁小孩）仅内部；P21 没有说明、P20 不是本周的，都进核对表。
- 需要阿杰核对 5 条：别的工地、重复记录、平台进度倒退（11-05 报 55%）、P21 说明缺失、P20 不在本周日报。

## 5. 验收清单

- [ ] 周报只用了 15 行日报；Box Hill 那单的洗衣房贴砖没出现在任何地方。
- [ ] 后院平台本周末是 75%，11-05 的 55% 进了核对表，没有把进度往回算。
- [ ] 安全问题在报告最前面；岛台加长单独列为待确认的变更，没有写进厨房的进度。
- [ ] P14 没有出现在给业主的照片里；P20、P21 都在核对表里。
- [ ] 7 项任务的偏差和状态跟标准答案一致；工时合计 178。
- [ ] 给业主的那段话没有承诺完工日期，也没有提到岛台已经在做。

## 6. 加分挑战

- 加一列「按这周的速度，还要几个工作日完成」，并说明这只是按本周速度的粗算。
- 拿下一周的日报再做一份，把两周的进度画成一张简单的表，看哪项一直在落后。
- 让 Claude 单独写一条给张工的内部备忘：安全问题谁去处理、变更要准备什么报价资料，和给业主的周报分开。

## 7. 简历 / 面试可以这样讲

> 为一家住宅翻新公司设计每周进度报告流程：用 Claude Project 固化进度计划和统计规则，把现场日报和照片文字说明整理成对照计划的进度表，自动排除别的工地和重复的日报、拦下进度倒退和缺失的照片说明，把安全问题置顶、业主提出的变更单独列出等老板确认，并按规则过滤掉拍到邻居和家人的照片后再给业主（教学项目，公司和数据都是为练习设计的）。
