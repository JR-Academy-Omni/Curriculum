# P09 · 建筑装修：报价请求 → 报价单 → 老板审批 → 发送

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 建筑装修 | L2 Workflow | 180 分钟 | Claude（Projects）+ n8n + Gmail + Google Sheets |

## 1. 客户场景

恒建装修在布里斯班 Sunnybank，老板老周带四个师傅，做刷漆、贴砖、浴室翻新、铺地板这些住宅小活。报价请求从网站表单、邮件、微信、前台电话四个地方进来，现在全靠老周晚上自己对着单价表一条条算，再用 Word 改上一份报价发出去。常见的坑：忘了加防水、小活忘了收出工费、客户说「是你朋友」就随口打折、同一个客户催两次被报了两份价，还有客户顺嘴一句「把那面墙打掉」被员工照单价随手估了个数。

老周想要的是：**报价请求进来，系统按单价表把草稿算好，把需要他拍板的地方标出来，他在手机上点「批准」才发给客户。**

## 2. 练习数据

| 文件 | 内容 |
|---|---|
| `data/quote-requests.txt` | 7 条报价请求（2026-11-09 至 11-11），每条有编号、渠道、客户、邮箱、区域、原话 |
| `data/rate-card.csv` | 13 个计价项目：item_code, description, unit, unit_price_ex_gst |
| `data/company-rules.md` | 老周定的 8 条报价规则（防水、出工费、定金、折扣、审批） |

全部是练习数据，公司、客户、邮箱（`example.com`）都是为这个练习设计的，单价是这家公司的价格，不代表市场价。

数据里**故意藏了 5 处问题**：

1. **浴室贴砖没提防水**（Q-2611-02）：按规则必须自动加湿区防水，面积 = 地砖面积 + 4 平方米。
2. **数量缺失**（Q-2611-03）：只说换台面，没有长度，不能猜，要回信问尺寸。
3. **单价表里没有的活**（Q-2611-04）：「把墙打掉」可能是承重墙，不能估价，交老周。
4. **重复提交**（Q-2611-05）：林先生把同一个需求又发了一次，只能合并。
5. **客户要折扣**（Q-2611-06）：草稿照标准价，折扣只有老周能定；而且这单小计不足 800，要加最低出工费。

另外 Q-2611-07 总价超过 20,000，用来练定金比例切换。

教学假设：GST 按 10% 计（以 ATO 为准）；定金上限按 QLD 住宅工程规则简化为「合同总价低于 20,000 收 10%，20,000 及以上收 5%」，合同金额超过 3,300 的住宅工程另有书面合同要求，都以 QBCC 官方为准。这个项目只练报价流程，不构成法律或合规意见。

## 3. 做法

**先在 Claude 里把规则跑通，再搬到 n8n。**

**第一步：建 Claude Project「恒建报价」**，上传 `rate-card.csv` 和 `company-rules.md`，项目说明写：

```
你是恒建装修的报价助理，只负责起草，不负责定价和发送。
每收到一条报价请求，按下面步骤处理：
1. 提取：客户、邮箱、区域、客户原话里的每一项工作和数量。只使用 rate-card.csv 里的 item_code。
2. 判断走哪条路：
   - 和之前某条请求是同一邮箱、同一需求 → merge_duplicate，不出报价；
   - 有任何必需数量缺失 → ask_client，写一封简短回信问清楚，不出报价；
   - 有单价表里没有的工作 → 能算的照算，没法算的写「需现场评估，另行报价」，不写任何金额，标给老周；
   - 其余 → draft_quote。
3. 套公司规则：浴室贴砖必须加防水（地砖面积 + 4 平方米）；工程小计不足 800 加最低出工费；GST 10%；定金按总价是否 ≥ 20,000 选 10% 或 5%。
4. 输出报价表：项目、单位、数量、单价、小计；再写小计（不含 GST）、GST、总价、定金、有效期 30 天、不含客户自购材料。
5. 单独列「请老周确认」：自动加的项目、未计价项目、折扣要求、工期要求、金额 ≥ 20,000。
红线：不打折、不改单价、不承诺工期、不说「已确认」；所有报价都写「待老周审批」。
```

逐条贴入 7 条请求，把结果和 `expected/` 对一遍。数字对上了，规则才算写清楚。

**第二步：在 n8n 里搭流程。** 计算交给 Code 节点，不交给模型——模型只负责「读懂客户在说什么」和「把邮件写得像人话」。

### n8n 搭建

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | Email Trigger (IMAP) | 监听 quotes@ 邮箱的新邮件（网站表单也转发到这里） | Mailbox: INBOX；Action: Mark as read |
| 2 | Information Extractor（接 Anthropic Chat Model） | 把客户原话抽成结构化字段 | 字段：client, email, suburb, items[{item_code, qty}], unpriced_work[], missing_info[], discount_request, deadline_request；System prompt 附上单价表的 item_code 清单 |
| 3 | Google Sheets | 读「报价记录」表里同一邮箱 7 天内的记录 | Operation: Get Row(s)；Filter: email = `{{$json.email}}` |
| 4 | If | 判断是不是重复提交 | 有 7 天内同邮箱、状态非「已发送」的记录 → true |
| 5 | Google Sheets（重复分支） | 在原记录备注里写「客户催问过一次」 | Operation: Update Row，按 quote_id 匹配 |
| 6 | Switch | 分三路：ask_client / draft_quote / draft_quote_with_exclusion | 规则：missing_info 非空 → ask_client；unpriced_work 非空 → with_exclusion；否则 draft_quote |
| 7 | Basic LLM Chain + Gmail（ask_client 分支） | 写一封问尺寸的回信，存成草稿给前台确认 | Gmail Resource: Draft, Operation: Create；不直接发送 |
| 8 | Google Sheets | 读单价表 | Operation: Get Row(s)，sheet: rate-card |
| 9 | Code | 套规则算钱：加防水、加出工费、逐行小计、GST、总价、定金 | 金额四舍五入到分；输出 lines[], subtotal, gst, total, deposit_rate, deposit, notes[], flags[] |
| 10 | Basic LLM Chain（接 Anthropic Chat Model） | 把 Code 算好的数字写成给客户的报价邮件正文 | Prompt 写明「数字原样照抄，不许改、不许四舍五入、不许提折扣」 |
| 11 | Google Sheets | 追加到「报价记录」，状态 = 待审批 | Operation: Append Row |
| 12 | Gmail · Send and Wait for Response | 把报价草稿 + 「请老周确认」清单发给老周，等他回 | Response Type: Custom Form；字段：决定（批准 / 驳回 / 改价后再发）、备注；Limit Wait Time: 2 天 |
| 13 | Switch | 按老周的决定分流 | 批准 / 驳回 / 改价 |
| 14 | Gmail（批准分支） | 把报价发给客户 | To: `{{email}}`；Subject 带 quote_id；正文用第 10 步的内容 |
| 15 | Google Sheets | 更新状态（已发送 / 驳回 / 待改价）和老周备注 | Operation: Update Row |
| 16 | Slack（驳回 / 改价分支） | 通知前台按老周备注改，改完重新走第 9 步 | Channel: #报价 |

人工审批点：第 12 步。没有老周的「批准」，第 14 步永远不会执行。第 7 步的问询回信也只存草稿，不自动发。

> 用 ChatGPT 也可以：Project 规则原样贴进 ChatGPT Project；n8n 里把 Anthropic Chat Model 换成 OpenAI Chat Model，其他节点不变。

## 5. 验收清单

- [ ] 7 条请求出 5 份报价草稿；Q-2611-03 只出问询回信，Q-2611-05 被合并。
- [ ] Q-2611-02 自动加了 10 平方米防水（650.00），并在备注里解释了原因。
- [ ] Q-2611-04 的拆墙一项没有任何金额，被标给老周。
- [ ] Q-2611-06 按标准价出草稿、加了 180 出工费，给客户的文字里没提八折。
- [ ] 所有金额跟标准答案差距在 0.01 以内；Q-2611-07 定金是 5% 不是 10%。
- [ ] n8n 里能演示：老周点「驳回」后，客户收不到任何邮件。

## 6. 加分挑战

- 老周点「改价后再发」时，让他在表单里直接填新的折扣率，Code 节点重算后再走一次审批。
- 加一个 Schedule Trigger，每天早上把「待审批超过 24 小时」的报价在 Slack 里提醒老周。
- 把报价邮件同时生成一份 HTML 报价单（带公司抬头和条款），存到 Google Drive。

## 7. 简历 / 面试可以这样讲

> 为一家住宅装修公司设计报价审批流程：用 Information Extractor 把客户的口语化需求抽成计价项目，计价、GST 和定金比例全部放在 Code 节点按单价表计算，模型只负责理解需求和写邮件；流程自动处理防水必加、最低出工费、重复提交和数量缺失，把单价表外的工作和折扣要求交给老板，老板在邮件里一键审批后才发出（教学项目，公司和数据都是为练习设计的）。
