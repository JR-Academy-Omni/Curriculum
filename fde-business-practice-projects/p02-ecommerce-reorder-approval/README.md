# P02 · 零售电商：低库存预警 → 补货单 → 采购确认

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 零售电商（Shopify 小店） | L2 Workflow | 150 分钟 | Claude + n8n + Google Sheets + Slack + Gmail |

## 1. 客户场景

竹间茶事是墨尔本 Box Hill 的一家 Shopify 网店，卖茶叶、茶具和礼盒，三个供应商：本地茶叶批发、做茶具的海外供应商、本地包装耗材商。店员 Amy 每周一早上把 Shopify 库存导出来，凭感觉挑「快没了」的东西，再一个个给供应商写邮件下单。问题是：茶具从下单到货要三周，她常常等卖断了才想起来补；停售的圣诞礼盒也被补过一次；老板林先生不知道每周花了多少钱进货，金额大的单子也没人把关。

他们想要的是：**每天早上自动算出哪些货该补、补多少，按供应商出好补货单，Amy 点一下确认，超过 3,000 澳元的单子再让林先生批一次，批完才发给供应商。**

## 2. 练习数据

`data/inventory-2026-11-11.csv`：Shopify 库存导出加上店里自己维护的几列，共 22 个 SKU（练习数据，店名、供应商、SKU 都是为这个练习设计的）。

| 字段 | 含义 |
|---|---|
| sku / product | 商品编码 / 名称 |
| status | active 在售 / discontinued 已停售 |
| supplier_id | 供应商编号，对应 `suppliers.csv` |
| on_hand | 仓库现有数量 |
| committed | 已下单未发货（被占用）的数量 |
| incoming | 已经下过采购单、还在路上的数量 |
| avg_daily_28d / avg_daily_7d | 近 28 天 / 近 7 天日均销量 |
| safety_days | 安全库存天数（店主定的，茶叶 7 天、茶具 14 天、包装 5 天） |
| moq / case_pack | 最小起订量 / 整箱数量（下单必须是整箱的倍数） |
| unit_cost | 进货单价（澳元，不含 GST） |

`data/suppliers.csv`：3 个供应商，含交期 `lead_time_days`、起订金额 `min_order_value`、联系邮箱（都是 `.example` 假邮箱）。

数据里**故意藏了 5 处问题**，真实店铺也常见：

1. 有个 SKU 库存是负数（Shopify 同步或盘点出错），算出来的补货量不可信；
2. 一个已停售的圣诞礼盒低于补货点，不该再补；
3. 一个 SKU 的供应商编号在供应商表里找不到；
4. 一个 SKU 需要补货，但进货单价是空的，没法出采购单；
5. 一个 SKU 近 7 天日均销量突然是 28 天日均的 5 倍（大概率是一笔团购），按规则照常进单，但要在审批消息里单独标出来，让人决定要不要多订。

教学假设：单价不含 GST，采购单金额也按不含 GST 算；真实发票上的 GST 以供应商开票为准。审批线 3,000 澳元是这家店自己定的规则，不是行业标准。

## 3. 做法

**补货规则**（先在 Claude 里跑通，再搬进 n8n 的 Code 节点）：

- 可用量 = on_hand − committed + incoming
- 补货点 = 向上取整( 28 天日均 × (供应商交期 + 安全天数) )
- 可用量 ≤ 补货点 → 需要补货
- 目标库存 = 向上取整( 28 天日均 × (交期 + 安全天数 + 30 天) )
- 补货量 = max(目标库存 − 可用量, 最小起订量)，再向上取整到整箱倍数
- 按供应商合并成一张采购单；单张总额 > 3,000 → 要老板批；总额 < 供应商起订金额 → 标出来让 Amy 决定凑单还是推迟

**第一步：在 Claude 里把规则跑通。** 新建 Project「竹间茶事补货」，把两份 CSV 传进去，说明里写：

```
你是竹间茶事的补货助手。我会给你库存表 inventory 和供应商表 suppliers。
按下面顺序处理每个 SKU，先挡异常，再算数：
1. status 不是 active → 不补货，写进「异常 / 跳过」，原因写清。
2. on_hand < 0 → 不算补货量，写进「异常」，建议先盘点。
3. supplier_id 在 suppliers 里找不到 → 不算，写进「异常」。
4. 其余按规则算：可用量、补货点、是否补货、目标库存、补货量（max(目标−可用, moq)，向上取整到 case_pack 倍数）。
5. 需要补货但 unit_cost 为空 → 不进采购单，写进「异常」。
6. avg_daily_7d ≥ 3 × avg_daily_28d → 照常按 28 天日均进单，但在这一行标「放量，请人确认」。
7. 按供应商合并：每张单列出 SKU、数量、单价、小计、总额；总额 > 3000 标「需老板批准」；总额 < min_order_value 标「未达起订金额」。
输出三块：① 采购单（每个供应商一张表）；② 异常清单（SKU + 类型 + 原因 + 建议动作）；③ 一段给 Amy 的三行摘要。
所有数字保留两位小数，不确定就写出来，不要猜。你只出草稿，不发任何邮件。
```

发一句「按今天的库存出补货单」，拿结果跟第 4 节的数字对。对不上先改规则，规则对了再进 n8n。

**第二步：把库存表和供应商表放进 Google Sheets。** 一个表格两张工作表：`inventory`、`suppliers`，再加一张空的 `po_log` 记录每张采购单的状态。

**第三步：按下面的节点搭 n8n。** 算数全放在 Code 节点里（确定、可复查），Claude 只负责写给供应商的邮件和给 Amy 的摘要。

### n8n 搭建

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | Schedule Trigger | 每天早上触发 | 每天 08:00，时区 Australia/Melbourne |
| 2 | Google Sheets（读库存） | 读 `inventory` 全部行 | Operation: Get Row(s)，选整张表 |
| 3 | Google Sheets（读供应商） | 读 `suppliers` 全部行 | 同上；节点设置里打开 Always Output Data |
| 4 | Merge | 把两路数据放到一起交给 Code | Mode: Append（或用 Code 里 `$('读供应商').all()` 直接取） |
| 5 | Code（算补货） | 按第 3 节规则逐个 SKU 算，输出两类 item：`type=po_line` 和 `type=exception` | Run Once for All Items；规则跟 Claude Project 里一字不差 |
| 6 | Switch | 按 `type` 分两路 | 规则：`po_line` → 输出 0；`exception` → 输出 1 |
| 7 | Aggregate（异常） | 把所有异常合成一条消息 | Aggregate: All Item Data |
| 8 | Slack（异常提醒） | 发到 #库存 频道给 Amy 和仓库 | Send Message；列出 SKU、类型、建议动作 |
| 9 | Code（按供应商合单） | 把 po_line 按 supplier_id 合并，算总额、是否需老板批、是否未达起订 | 每张单输出一个 item，生成 `po_number = PO-日期-供应商` |
| 10 | Basic LLM Chain + Anthropic Chat Model | 为每张单写一封给供应商的下单邮件草稿（中英双语可选） | 提示词见下；Temperature 0.2；只写草稿 |
| 11 | Slack（Send and Wait for Response，Amy 确认） | 把采购单表格 + 邮件草稿 + 放量标记发给 Amy，等她点 Approve / Decline | Response Type: Approval；超时 1 天自动按 Decline 处理 |
| 12 | If（Amy 是否批准） | 拒绝的单写进 `po_log` 状态 declined，结束 | 条件：`approved` 为 true |
| 13 | If（是否需老板批） | 总额 > 3,000 走老板审批，否则直接发 | 条件：`needs_owner_approval` 为 true |
| 14 | Gmail（Send and Wait for Response，林先生批准） | 发给林先生，等他点批准 | Response Type: Approval；邮件里写清金额、行数、放量标记 |
| 15 | Gmail（发给供应商） | 两级都批准后才发 | To: 供应商邮箱；正文用第 10 步草稿 |
| 16 | Google Sheets（写 po_log） | 记采购单号、供应商、金额、谁批的、几点发的 | Operation: Append Row |

第 10 步的提示词：

```
你在帮竹间茶事写一封给供应商的补货邮件。下面是这张采购单的 JSON。
要求：称呼对方联系人；列出 SKU、品名、数量、单价、小计和总额，数字照抄 JSON，不要改；
写明期望到货时间 = 今天 + 供应商交期；请对方回邮件确认价格和交期。
语气客气、简短，不超过 150 字（表格除外）。不要承诺付款时间，不要写 JSON 里没有的价格或折扣。
```

> 用 ChatGPT 也可以：第一步用 ChatGPT Project 跑同样的规则；n8n 里把 Anthropic Chat Model 换成 OpenAI Chat Model，其他节点不变。

## 6. 加分挑战

- 在 Slack 审批里加「修改数量」：Amy 回复新数量，Code 节点重算总额后再走一遍审批。
- 供应商回邮件确认后，把这批数量写回 `inventory.incoming`，第二天就不会重复下单（用 Email Trigger (IMAP) 监听回信）。
- 每周一给林先生发一份上周进货汇总：每个供应商花了多少、拦下了几个异常。

## 7. 简历 / 面试可以这样讲

> 为一家 Shopify 茶叶网店搭建补货审批流程：用 n8n 每天读取库存和供应商表，按交期、安全天数和整箱规则算出补货量并按供应商合单；负库存、停售、缺供应商、缺单价的 SKU 自动拦下提醒，异常放量单独标注；采购单经店员确认、超额再经老板批准后才发给供应商，全程写入采购日志（教学项目，数据为为练习设计）。
