# P05 · 记账事务所：银行流水按科目初步分类

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 记账事务所 | L1 自动化 | 60 分钟 | Claude（Projects）+ Excel / Google Sheets |

## 1. 客户场景

信达记账是墨尔本的一家小记账事务所，两个会计带一个助理，手上四十多家小客户。每个月初，助理小周要把客户的银行流水导出来，一行行判断这笔钱算哪个科目、有没有 GST，再交给会计复核、录进 Xero。金叶面包坊（Glen Waverley）是其中一家：一个月四十多笔流水，大部分是 Square 刷卡到账、面粉供应商、房租和工资，小周闭着眼都能分；真正花时间的是那几笔看不懂的——老板用公司卡买的私人东西、转给自己的钱、现金存款、看不出卖什么的商户。

他们想要的是：**把流水丢进去，几分钟拿到一份初分类表，常规的都分好，拿不准的全部单独列出来等会计看，不要替会计下结论。**

## 2. 练习数据

`data/bank-2026-10.csv`：金叶面包坊 2026 年 10 月公司账户流水，共 44 行（练习数据，商户名、人名、账号都是为这个练习设计的）。期初余额 18,450.32。

| 字段 | 含义 |
|---|---|
| date | 交易日期 |
| description | 银行显示的交易描述 |
| debit | 支出（澳元） |
| credit | 收入（澳元） |
| balance | 交易后余额 |

`data/chart-of-accounts.csv`：这家客户用的简化科目表，17 个科目，每个科目带一个「GST 默认初判」和备注。`999 待复核` 是专门放拿不准的流水的。

数据里**故意藏了 5 类、7 笔问题**，真实流水里每个月都有：

1. 个人支出走了公司账户：Netflix、Sephora 化妆品；
2. 转账到老板个人账户：可能是提款，也可能是还老板垫付的钱；
3. 看不出卖什么的商户：`SQ *KL TRADING`；
4. 海外网购：PayPal 付给深圳卖家的烘焙模具，GST 能不能抵要看发票；
5. 来源不明的钱：一笔没有备注的现金存款，还有一笔贷款还款（本金和利息要拆开才能入账）。

这 7 笔都应该进 `999 待复核`，不能被随手分进某个费用或收入科目。

**GST 部分全部是教学假设，以 ATO 规定和会计复核为准。** 本项目里的口径：澳洲标准 GST 税率 10%，含 GST 的金额里 GST = 金额 ÷ 11；普通面包、面粉等基本食品多数免 GST，咖啡、热食等要收；银行手续费、工资、养老金、缴给 ATO 的税不涉及 GST；水费多数免 GST。银行流水只是钱进出的记录，**能不能抵进项税最终看税务发票**，所以这一步只叫「初判」。

## 3. 做法

**第一步：在 Claude 里建一个 Project。** 名字叫「信达记账 · 流水初分类」。把 `chart-of-accounts.csv` 传进项目文件，在说明（Instructions）里写：

```
你是信达记账的流水初分类助手。我会上传一个客户某个月的银行流水 CSV。科目表在项目文件 chart-of-accounts.csv 里。
请逐行处理，输出一张表，列为：row, date, description, debit, credit, account_code, account_name, gst_first_pass, confidence(高/中/低), needs_review(是/否), reason。
规则：
1. 只能用科目表里的科目。认得出、和这家店经营明显相关的，分到对应科目，GST 初判先用科目的默认值，必要时在 reason 里写清要看发票。
2. 以下情况一律分到 999 待复核、needs_review = 是，不要猜：
   - 看起来是个人消费（娱乐订阅、化妆品、服装等和经营无关的）；
   - 转到个人账户或其他账户的钱；
   - 商户名看不出买的是什么；
   - 海外购买、GST 是否已收不清楚的；
   - 来源不明的入账（现金存款、无备注转入）；
   - 贷款还款（本金和利息需要拆分）。
3. reason 用一句话写清你的依据，像跟会计交代一样，不要写「可能」以外的结论性判断。
4. 表后面再给：① 收入合计、支出合计，核对 期初余额 − 支出 + 收入 是否等于最后一行余额；② 每个科目的笔数和金额；③ 待复核清单（行号、金额、原因、需要客户补什么材料）。
5. 你只做初分类，不给税务结论，不说「可以抵扣」「不用报税」这类话。所有 GST 都写「初判」。
```

**第二步：上传 `bank-2026-10.csv`，发一句话：**「帮我初分类金叶面包坊 10 月的流水，期初余额 18450.32。」

**第三步：核对。** 先看余额核对通不通过（通不过说明漏行或读错了数）。再对着验收清单查 7 笔待复核是不是一笔不少。最后抽查 5 笔常规流水的科目，比如房租是不是进了 400、ATO 付款是不是进了 800 而不是费用。

**第四步：交给会计。** 把待复核清单单独复制出来，变成给客户的问题清单（「10 月 15 日转给 Li Wei 的 3,000 是提款还是还垫付款？」），客户回复后会计再决定入 850 老板提款、880 贷款还是别的科目。常规流水的分类可以导出 CSV，对照 Xero 的银行规则批量入账。

> 用 ChatGPT 也可以：建一个 Project（或自定义 GPT），把科目表和同样的说明放进去，上传流水即可。

## 5. 验收清单

- [ ] 余额核对通过：18,450.32 − 34,735.78 + 34,033.56 = 17,748.10。
- [ ] 7 笔待复核全部在 999：Netflix、Sephora、转给 Li Wei 的 3,000、SQ *KL TRADING、PayPal 深圳模具、现金存款 2,600、Westpac 贷款还款。
- [ ] 每笔待复核都写了原因，并能变成一句问客户的话。
- [ ] ATO 付款进 800、工资进 477，没有被当成普通费用；Square 到账的 GST 初判写的是「按 POS 报表拆分」，不是简单的 ÷ 11。
- [ ] 输出里没有「可以抵扣」「不用交税」之类的结论，GST 都标为初判。

## 6. 加分挑战

- 把常规流水的商户和科目对应关系整理成一张「银行规则表」，下个月先按规则表自动分，Claude 只处理表里没有的新商户。
- 让 Claude 根据待复核清单写一封给面包坊老板的邮件草稿，列出要补的小票和说明，由会计确认后再发。
- 用 11 月的流水再跑一次，看新出现的商户有没有被正确放进待复核。

## 7. 简历 / 面试可以这样讲

> 为一家记账事务所设计银行流水初分类流程：用 Claude Project 固化科目表和分类规则，常规流水自动分到科目并给出 GST 初判，个人支出、转账、来源不明、海外采购和贷款还款统一进待复核，并自动做余额核对；会计只需处理待复核清单，不再逐行判断（教学项目，数据为为练习设计，GST 口径为教学假设）。
