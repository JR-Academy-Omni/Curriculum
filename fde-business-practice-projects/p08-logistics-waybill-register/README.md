# P08 · 物流 / 仓储：运单邮件提取成发货台账

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 物流 / 仓储 | L1 自动化 | 45 分钟 | Claude（Projects）+ Excel / Google Sheets |

## 1. 客户场景

南星仓储在墨尔本 Truganina，帮三家华人网店（悦禾茶饮供应、木可家居、蓝鲸母婴）代发货，每天用三家快递：FastLane Freight、袋鼠快运、Coastline Couriers。每下一单，快递就往 ops 邮箱发一封确认邮件，三家格式完全不一样：一家是「字段: 值」，一家是中文模板，一家干脆写成一段话，重量还用克。仓库主管 Jenny 每天下班前把这些邮件一封封抄进 Excel 发货台账，第二天客户来问「我那单发了没」才能查得到。抄漏、抄错邮编、把取消的单也记上，是常事。

她想要的是：**下班前把当天邮件整包导出丢进去，五分钟拿到一份干净的台账，有问题的单单独列出来。**

## 2. 练习数据

`data/inbox-2026-11-10.txt`：ops 邮箱一天的邮件纯文本导出，共 19 封（练习数据，公司、承运商、收件人、单号都是为这个练习设计的；邮箱都是 `.example` 域名）。每封以 `========== EMAIL nn ==========` 分隔，带 From / Date / Subject 和正文。

台账要提取的字段：

| 字段 | 含义 | 注意 |
|---|---|---|
| waybill_no | 运单号 / Consignment No / Tracking number | 三家叫法不同 |
| carrier | 承运商 | 看发件人和模板 |
| client_ref | 客户单号（YH- / MK- / LX- 开头） | |
| consignee | 收件人 | |
| suburb / state / postcode | 收件地区 | |
| pieces | 件数 | |
| weight_kg | 重量（公斤） | Coastline 用克，要换算 |
| service | Standard / Express | 袋鼠快运写「标准 / 加急」 |
| pickup_date | 揽收日期，统一写成 2026-11-10 | 三家日期格式不同 |
| status | active / cancelled / needs_check | |
| note | 问题说明 | |

数据里**故意藏了 5 处问题**：

1. 同一封运单邮件被同事转发了一次（主题带 `Fwd:`），只能记一行。
2. 有一单下午被承运商取消了，要标 cancelled，不计入当天发货量。
3. 有一单邮编和州对不上（邮编 2 开头却写了 VIC）。
4. 有一封邮件里没有重量。
5. 有一封是快递公司的账单提醒，根本不是运单，不能进台账。

邮编和州的对应按教学简化规则：第一位 2=NSW、3=VIC、4=QLD、5=SA、6=WA、7=TAS、0=NT（这份数据没有 ACT 邮编；真实规则以 Australia Post 为准）。

## 3. 做法

**第一步：在 Claude 里建一个 Project，叫「南星发货台账」。** 在项目说明里写规则：

```
你是南星仓储的发货台账助手。我每天会上传一份 ops 邮箱的邮件导出（纯文本）。请按下面规则整理：
1. 只处理承运商的「下单 / 建标签」邮件，每个运单号一行。账单、通知、营销邮件不进台账，在「已跳过」里写一句为什么。
2. 字段：waybill_no, carrier, client_ref, consignee, suburb, state, postcode, pieces, weight_kg, service, pickup_date, status, note。
3. 重量统一换成公斤，保留 1 位小数（克 ÷ 1000）。service 统一写 Standard / Express（标准=Standard，加急=Express）。日期统一 YYYY-MM-DD。
4. 同一个运单号出现多次（比如被转发），只记一行，note 里不用写，但在「需要核对」清单里说明。
5. 同一天有取消邮件的运单：status=cancelled，note 写原因，不计入当天合计。
6. 邮编第一位和州对不上（2=NSW, 3=VIC, 4=QLD, 5=SA, 6=WA, 7=TAS, 0=NT）：保留原文，status=needs_check，note 写清楚。
7. 缺字段就留空，status=needs_check，note 写缺什么。不要猜，不要补。
8. 输出：① 台账 CSV（代码块，可直接粘进 Excel）；② 按承运商汇总：单数、件数、总重量（不含取消单，缺重量的单单独计数）；③「需要核对」清单：运单号 + 原因；④「已跳过」的邮件。
```

**第二步：上传 `inbox-2026-11-10.txt`，发一句：**「整理 11 月 10 日的发货台账。」

**第三步：核对。** 按验收清单一条条对。至少挑一封 Coastline 的邮件，手算克换公斤，再看 Fwd 那封有没有被记成两行。

**第四步：变成每天的流程。** 规则存在 Project 里，Jenny 每天只要导出当天邮件上传，把 CSV 粘到台账表末尾。台账表加一列「录入日期」，方便客户来问时按日期筛。

> 用 ChatGPT 也可以：建一个 Project 或自定义 GPT，把同样的规则写进说明，上传 txt 文件即可。

## 4. 应该做出的结果

`expected/answer.json` 和 `expected/register.csv` 是标准答案（脚本按同样规则算出）。

- 19 封邮件 → 台账 16 行（1 封转发重复、1 封取消通知、1 封账单不单独成行）。
- 16 行里：1 行 cancelled（ROO113683），2 行 needs_check（CC820261 邮编州不符、CC475549 缺重量），13 行 active。

| 承运商 | 单数（不含取消） | 件数 | 总重量 kg | 缺重量 |
|---|---|---|---|---|
| FastLane Freight | 6 | 14 | 177.6 | 0 |
| 袋鼠快运 Roo Express | 4 | 8 | 109.8 | 0 |
| Coastline Couriers | 5 | 13 | 86.5 | 1 |
| **合计** | **15** | **35** | **373.9** | **1** |

需要核对清单应有 5 条：ROO113683 已取消、CC820261 邮编 2122 是 NSW 却写 VIC、CC475549 缺重量、FLF100620 被转发重复、INV-77812 是账单不是运单。

## 5. 验收清单

- [ ] 台账是 16 行，不是 19 行；FLF100620 只出现一次。
- [ ] ROO113683 标为 cancelled，没算进合计（合计 15 单、35 件）。
- [ ] CC820261 保留了原文 VIC，没有被 Claude 自己改成 NSW，而是标 needs_check。
- [ ] CC475549 重量为空，没有被编一个数字。
- [ ] Coastline 的克都换成了公斤（例如 27000 g → 27.0），合计总重 373.9 kg，差距在 0.1 以内。
- [ ] 账单提醒邮件出现在「已跳过」里，没进台账。

## 6. 加分挑战

- 加一列「客户」（YH=悦禾、MK=木可、LX=蓝鲸），再按客户出一张汇总，月底跟客户对账用。
- 让 Claude 为 needs_check 的单各写一封给客户的核对邮件草稿（只是草稿，Jenny 看过再发）。
- 把台账放进 Google Sheets，用 n8n 的 Email Trigger (IMAP) + Information Extractor 每封邮件进来就自动追加一行，为后面 L2 项目打底。
