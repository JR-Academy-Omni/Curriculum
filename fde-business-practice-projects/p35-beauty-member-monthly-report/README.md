# P35 · 美业 / 美容院：会员消费记录生成会员月报

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 美业 / 美容院 | L1 自动化 | 50 分钟 | Claude（Projects）+ Excel / Google Sheets |

## 1. 客户场景

芊颜美容在悉尼 Burwood，做面部护理、睫毛、美甲和身体按摩，四个美容师，十几位常来的储值会员。老板娘 Coco 每个月初要做一份会员月报：这个月每位会员来了几次、花了多少、卡里扣了多少、还剩多少；门店一共做了多少服务、实际收进来多少钱。她现在是把 POS 系统导出的流水贴进 Excel，一行行手工对。最头疼的是数字老对不上：退了款的单、录错又作废的单、导出时重复的一行、跨到 11 月 1 日的单都混在里面；还有会员说「我卡里明明还有钱」，一查才发现储值被扣成了负数。

她想要的是：**每月 1 号把 POS 导出和会员表丢进去，十几分钟拿到一份对得上的会员月报：每人一行对账单，加一页门店汇总；有问题的流水单独列出来，不混进数字里。**

## 2. 练习数据

全部是练习数据：店名、会员姓名、美容师、价格都是为这个练习设计的。

| 文件 | 内容 |
|---|---|
| `data/pos-transactions-2026-10.csv` | POS 导出的 10 月流水，73 行 |
| `data/members.csv` | 15 位会员：会员号、姓名、卡级、入会日期、10 月 1 日的储值余额、常做项目 |

`pos-transactions-2026-10.csv` 字段：

| 字段 | 含义 |
|---|---|
| txn_id / datetime | 流水号 / 时间 |
| member_id | 会员号；空 = 散客 |
| type | service 服务 / topup 充值 |
| item / category | 项目名 / 类别（面部、睫毛、美甲、身体、充值） |
| amount | 服务是标价；充值是客人实际付的钱 |
| credit | 只有充值有：到账金额（含赠送） |
| payment | card 刷卡 / cash 现金 / prepaid 储值扣款 |
| staff / status | 美容师 / completed、refunded、voided |

数据里**故意藏了 5 处问题**：

1. 一笔**退款**的单；
2. 一笔**作废**的单（录错项目后作废）；
3. 同一笔流水被**导出了两次**；
4. 一笔流水的会员号 **M099 在会员表里找不到**；
5. 一笔 **11 月 1 日**的单混在 10 月的导出里。

另外有一位会员的储值被**扣成了负数**——这不是导出问题，是要告诉 Coco 去核对的事。

教学假设：充值优惠是「充 500 送 50、充 1000 送 150」。会员充值收进来的钱在报表里算「实收」，但不算「服务消费额」——储值是先收的钱，服务做了才算消费。真实的会计和 GST 处理以会计师意见为准，月报只做经营参考。

## 3. 做法

**第一步：在 Claude 里建一个 Project。** 名字叫「芊颜会员月报」，项目说明写：

```
你是芊颜美容的月报助手。每月初我会上传 POS 流水导出和会员表。请按下面规则出上个月的会员月报：
1. 只统计 status = completed、日期在本月、txn_id 不重复的流水。
   refunded、voided、重复导出、不在本月的，列进「需要核对」，写清原因，不计入任何数字。
2. member_id 不在会员表里的，列进「需要核对」，不进会员对账单，也不进门店合计。member_id 为空的是散客，进门店合计。
3. 会员对账单每人一行（会员表里的 15 人都要有，本月没来的也要有）：
   来店次数（按日期去重）、服务消费额（服务标价合计，不管怎么付）、储值扣款（payment = prepaid 的服务合计）、
   充值实付、充值到账、期初余额、期末余额 = 期初 + 充值到账 − 储值扣款、最常做的项目（次数最多，一样多取单价高的）。
   期末余额为负的，备注写出来提醒核对；本月没来、本月新入会的，也在备注里写。
4. 门店汇总：服务消费额合计（会员 + 散客）、按类别拆分、刷卡和现金实收（服务刷卡现金 + 充值实付）、
   储值扣款合计、充值实付和到账合计、所有会员期末余额合计、本月来过的会员数、做得最多的 3 个项目。
5. 金额保留两位小数。对账单里只写会员号、姓名、卡级，不写电话邮箱。不确定的地方写出来，不要猜。
6. 最后写三句给老板的话：一句讲整体，一句讲哪些会员要跟进，一句讲要核对的流水。分清哪些是数据、哪些是建议。
```

**第二步：上传两个文件，发一句：**「出 10 月的会员月报。」

**第三步：核对。** 至少手工对两处：

- 在 Excel 里筛选 M1008，把 payment = prepaid 的金额加起来，应该是 204.00；80.00 − 204.00 = −124.00。
- 所有会员的期初余额合计 5,055.00，加上充值到账 2,250.00，减去储值扣款 3,324.00，应该等于期末余额合计 3,981.00。这一条对上了，说明对账单没有漏人、没有重复。

**第四步：每月用。** 规则存在 Project 里，Coco 每月 1 号上传新导出就行。可以让 Claude 另外输出一份 CSV 版的对账单，粘进她的年度会员表。

> 用 ChatGPT 也可以：建一个 ChatGPT Project 或自定义 GPT，把同样的规则写进说明，上传两个文件即可。

## 5. 验收清单

- [ ] 计入 68 行，不是 73 行；5 行问题流水都出现在「需要核对」里，并写了原因。
- [ ] 对账单 15 行，没来的两位也在；M1008 期末是 −124.00，备注提醒核对。
- [ ] 期初合计 + 充值到账 − 储值扣款 = 期末合计（5,055.00 + 2,250.00 − 3,324.00 = 3,981.00）。
- [ ] 服务消费额 6,485.00、实收 5,161.00，跟标准答案差距在 0.01 以内；充值没有被算进服务消费额。
- [ ] M099 那笔没有进门店合计，也没有被猜成某位会员。
- [ ] 对账单里没有电话、邮箱。

## 6. 加分挑战

- 加一列「储值够用几次」：期末余额 ÷ 常做项目单价，向下取整，给 Coco 一个「谁该提醒充值」的名单（只出名单，不自动发消息）。
- 按美容师拆一张表：每人做了多少单、服务消费额多少，并说说为什么提成不能直接按这张表算（退款、作废、储值赠送部分怎么处理）。
- 做 9 月和 10 月两个月，对比哪些会员来得少了，列出来交给店长决定要不要回访。

## 7. 简历 / 面试可以这样讲

> 为一家美容院设计会员月报流程：用 Claude Project 固化统计规则，把 POS 流水和会员表整理成每位会员的对账单和门店月度汇总；自动排除退款、作废、重复导出、跨月和会员号错误的流水并列出原因，区分服务消费额和实收现金，用「期初 + 充值 − 扣款 = 期末」做整体对账，并标出储值透支的会员（教学项目，数据为这个练习设计）。
