# P24 · 诊所 / 牙医：新病人登记 → 保险信息核对 → 前台确认

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 诊所 / 牙医 | L2 Workflow | 150 分钟 | Claude + n8n（n8n Form）+ Google Sheets + Slack + Gmail |

## 1. 客户场景

华康牙科在墨尔本 Doncaster，三位医生，前台 Vivian。新病人在网站上填登记表：姓名、生日、联系方式、私人保险、Medicare、病史。表单提交后变成一封邮件，Vivian 再手抄进诊所系统、打电话约第一次看诊。问题一个接一个：同一个人填错邮箱又填了一次，系统里出现两份档案；老病人搬家了来重新登记，也被当成新病人；15 岁的孩子自己填了表，没有家长信息；保险公司名字写得五花八门，会员号少一位，到诊当天刷 HICAPS 才发现报不了；有病人把信用卡号写进备注「下次直接扣」，这封邮件在前台的收件箱里躺了一个月。

诊所想要的是：**表单一提交，流程自动查重、认出老病人、挡住缺监护人和没同意隐私条款的、核对保险公司和会员号格式，把所有号码打码；前台在 Slack 里看一张干净的摘要、点批准，才建档和给病人发邮件。病史只给医生，不进 Slack、不进 AI。**

## 2. 练习数据

都是练习数据，诊所、病人、电话（`04xx xxx 000`）、邮箱（`.example`）、地址都是为这个练习设计的；4 家保险公司是编出来的名字，会员号格式和能不能现场报销都是**教学假设**，真实规则以各保险公司官方说明和诊所与保险公司的协议为准。表单里的 Medicare 号、会员号、卡号都是随手写的数字。

| 文件 | 内容 |
|---|---|
| `data/registrations-2026-11-11.json` | 一天的 10 份网站登记：编号、提交时间、姓名、生日、手机、邮箱、地址、紧急联系人、监护人姓名和手机、隐私同意、有没有私人保险、保险公司、会员号、Medicare 号、病史、备注 |
| `data/health-funds.csv` | 诊所认的 4 家保险公司：别名、会员号格式（规则 + 正则）、能不能现场 HICAPS 报销 |
| `data/existing-patients.csv` | 3 位老病人：档案号、姓名、生日、手机、邮箱 |
| `data/front-desk-rules.md` | 前台规则：监护人、隐私同意、查重、老病人、保险、打码、病史 |

数据里**故意藏了这几类问题**：

1. **重复提交**：Sophie Martin 三分钟内填了两次，第一次邮箱拼错（`mial`）；
2. **老病人重新登记**：王海的姓、生日、手机和档案 HK0412 一致，是来改地址的；
3. **未成年没有监护人**：15 岁的 Oscar 自己填了表；另一位 12 岁的李欣怡监护人信息齐全，可以正常建档；
4. **保险信息有问题**：一个保险公司不在列表里（Koala Care）；一个会员号少了两位；一个写成小写的 `wattle mutual`（应该能认出来）；一个是 Bluegum Health，不能现场报销，要提前说；
5. **不该出现的号码和信息**：张伟明在备注里写了完整的信用卡号；几乎每个人都填了 Medicare 号或会员号；有两位在病史里写了过敏和高血压；
6. **没同意隐私条款**：Lucy Green 的 privacy_consent 是 N。

## 3. 做法

**规则**（先在 Claude 里跑通，再搬进 n8n 的 Code 节点）：

- 同一手机号 + 同一生日几分钟内提交两次，以最后一次为准，前面那次作废；
- 姓 + 生日 + 手机和老病人对上 → 不新建档案，前台更新老档案；
- privacy_consent 不是 Y → 暂停，前台先打电话；未满 18 岁且监护人姓名或手机缺一 → 暂停；
- 保险公司按别名匹配（大小写、空格不限）；不在列表里，或会员号不符合格式 → 请病人到诊时带卡；Bluegum Health 格式对也要提前告诉病人不能现场报销；
- Medicare 号、会员号在任何摘要和邮件里只显示后 4 位；备注里 13–19 位的卡号一律换成 `[已打码]`；
- 病史栏不进 Slack、不进 Claude、不进邮件。

**第一步：在 Claude 里把规则跑通。** 新建 Project「华康新病人登记」，传入 `health-funds.csv`、`existing-patients.csv`、`front-desk-rules.md` 和登记 JSON。**练习时先把 JSON 里的 `medical_history` 字段删掉再上传**——真实流程里病史根本不会到 Claude 手上，练习也照这个习惯来。项目说明写：

```
你是华康牙科的新病人登记助手。我会给你一批网站登记（JSON）、保险公司表、老病人表和前台规则。
逐份登记处理，按这个顺序：
1. 查重：同一手机号 + 同一生日的多次提交，以最后一次为准，前面的标「重复提交，作废」。
2. 老病人：姓 + 生日 + 手机和 existing-patients 对上，标「老病人 档案号，不新建档案」，写清要更新什么。
3. 暂停：privacy_consent 不是 Y；或未满 18 岁（按 2026-11-11 算）且监护人姓名或手机缺一。写清原因。
4. 保险：按 aliases 匹配保险公司（不分大小写）；不在表里、或会员号不符合 member_number_regex → 「请病人到诊时带卡」；hicaps_on_the_spot = N → 写明要提前告诉病人不能现场报销。
5. 打码：Medicare 号、会员号只显示后 4 位，例如 ****1273；备注里像银行卡号的数字换成 [已打码]，并标「诊所不通过表单收卡号」。
6. 其余标「可以建档」。
输出一张表：编号、姓名、状态、保险核对结果、会员号（打码）、Medicare（打码）、提醒。
然后只给「需要病人做事」的人写邮件草稿（会员号要核对、保险公司不在列表、缺监护人、没同意隐私条款、备注里有卡号）：称呼病人（未成年发给监护人时称呼监护人），说清要他做什么，不超过 120 字。病人用中文名就用中文，否则用英文。
不要在任何输出里写完整号码；不要评论任何病情；不要承诺保险一定能报。你只出草稿，不发任何邮件。
```

拿结果跟 `expected/decisions.csv` 和 `expected/patient-emails.md` 对。对不上先改规则，规则对了再进 n8n。

**第二步：准备 Google Sheets。** 一个表格放 `health_funds`、`existing_patients`、`registrations`（每份登记一行，只存打码后的号码）、`intake_log`；另开一个**只有医生和前台经理能看**的表格 `clinical_intake`，专门接病史。练习时用它代替诊所系统的病历入口。

**第三步：按下面的节点搭 n8n。** 查重、匹配、打码全在 Code 节点里做（确定、可复查），Claude 只写需要病人做事的那几封邮件。

### n8n 搭建

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | n8n Form（Form Trigger） | 新病人登记表 | 字段跟 JSON 一致；privacy_consent 用勾选框；生日用日期字段 |
| 2 | Code（拆出病史） | 把 `medical_history` 单独拿出来，后面的 item 里删掉这个字段 | 输出两路：病史一路、其余字段一路 |
| 3 | Google Sheets（写病史） | 病史连同提交编号写进 `clinical_intake` | 只这一个节点碰病史；不接 Slack、不接 AI |
| 4 | Google Sheets（读保险公司） | 读 `health_funds` | Operation: Get Row(s) |
| 5 | Google Sheets（读老病人） | 读 `existing_patients` | 同上 |
| 6 | Google Sheets（读今天的登记） | 读 `registrations` 里今天提交的行，用来查重 | 同上；打开 Always Output Data |
| 7 | Code（核对 + 打码） | 按第 3 节规则算：查重、老病人、暂停、保险结果、打码后的号码、需不需要病人做事 | 完整号码只在这个节点里出现一次，输出里只留后 4 位；重复时输出被替换的旧编号 |
| 8 | Google Sheets（记登记） | 写进 `registrations`：编号、状态、保险结果、打码号码 | Operation: Append Row；旧的重复那行用 Update Row 标「作废」 |
| 9 | If（是否需要病人做事） | 是 → 第 10 步；否 → 第 11 步 | 条件：`needs_patient_action` 为 true |
| 10 | Basic LLM Chain + Anthropic Chat Model | 为需要病人做事的登记写邮件草稿 | 输入只有姓名、状态、保险结果、提醒；Temperature 0.2 |
| 11 | Edit Fields (Set) | 正常建档的用固定模板生成确认邮件 | 模板见 `expected/patient-emails.md`；老病人、重复提交不生成邮件 |
| 12 | Merge | 两路草稿合回一处 | Mode: Append |
| 13 | Slack · Send and Wait for Response（Vivian 确认） | 发到 #新病人：打码后的摘要 + 邮件草稿 | Response Type: Custom Form；字段：决定（批准 / 改了再发 / 不发）、修改后的邮件 |
| 14 | Switch | 按决定分流，并按状态区分「新建档案 / 更新老档案 / 只记录」 | 批准且可以建档 → 第 15 步；老病人 → 第 16 步；不发 → 只更新 `intake_log` |
| 15 | Google Sheets（新病人档案） | 追加一行新病人（练习时代替诊所系统建档），号码只存后 4 位 | 完整号码由前台到诊时从卡上录入，不经过这个流程 |
| 16 | Slack（更新老档案） | 提醒 Vivian 在 HK0412 里更新地址 | 只发编号和要更新的字段 |
| 17 | Gmail | 批准后才给病人（未成年发监护人邮箱）发邮件 | To: 表单邮箱 |
| 18 | Google Sheets（intake_log） | 记谁批的、几点发的、发了哪种邮件 | Operation: Append Row |

人工审批点：第 13 步。没有 Vivian 的「批准」，不会建档，也不会给病人发任何邮件。

> 用 ChatGPT 也可以：第一步用 ChatGPT Project 跑同样的规则（同样先删掉病史字段）；n8n 里把 Anthropic Chat Model 换成 OpenAI Chat Model，其他节点不变。

## 6. 加分挑战

- 查重放宽一点：同一个人隔天又填了一次（不是几分钟内），而第一份已经建档了。流程该怎么处理？先写规则，再改 Code 节点。
- 会员号格式对不上时，不只是「请带卡」：让 Code 节点再判断一下是不是多打了空格或把字母 O 打成了数字 0，能自动纠正的标「已纠正，请到诊时确认」，不能的再请带卡。
- 每周五给诊所经理一份汇总：多少新病人、多少暂停、保险公司分布、多少人需要带卡核对。只放数字，不放任何病人的号码和病史。
