# P32 · 招聘 / 人力外包：筛选 → 约面 → 面试反馈汇总

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 招聘 / 人力外包 | L2 Workflow | 150 分钟 | Claude + n8n + n8n Form + Google Sheets + Slack + Gmail |

## 1. 客户场景

安康护理人力（Ankang Care Staffing）在 Adelaide 东北区，帮几家居家养老机构招 casual 的社区陪护员，上门照顾长者。招聘顾问 Mandy 每周要过二三十份网上报名表：有没有 Cert III、急救证书过没过期、有没有车、工作日能上几天。合适的，她再跟客户方的护理协调员 Ruth 对时间，一个个发邮件约视频面试；面完了，两个人各填一张评分表，她再自己算分、写汇总、决定发录用还是拒信。

最让她头疼的有三件事：同一个人改了时间又报一次，结果约了两回；有个新同事看到报名表里写「58 岁」，就在备注里写了「年纪偏大」；还有一次，拒信是系统按条件自动发出去的，后来才发现那位候选人第二周就能续上急救证书。

她想要的是：**报名一进来就按岗位必备条件过一遍，能约的直接排好面试时间、起草好邀约；不通过的只给「建议」，她逐个点确认后才发拒信；面试后把两张评分表自动算好、汇总好，有分歧、有不该出现的评语，单独拎出来给她看。**

## 2. 练习数据

全部是练习数据：机构、候选人、电话（`0400 xxx 000`）、邮箱（`.example`）都是为这个练习设计的。

| 文件 | 内容 |
|---|---|
| `data/job-JOB-HC-11.json` | 岗位：社区陪护员，12 月 1 日开工，5 条必备条件（M1–M5）、加分项、面试安排 |
| `data/applications.csv` | 14 份报名表（n8n Form 收上来的样子） |
| `data/interviewer-slots.csv` | 11 月 16–20 日 Mandy 和 Ruth **都空**的 30 分钟时间格（free / busy） |
| `data/interview-scorecards.csv` | 上周 6 位候选人（C01–C06）的面试评分表，每人应有 2 张 |

`applications.csv` 字段：

| 字段 | 含义 |
|---|---|
| submission_id / submitted_at | 报名编号 / 提交时间 |
| full_name / email / phone / suburb | 基本联系信息 |
| cert3_status | Cert III：已完成 / 在读 / 没有 |
| first_aid_expiry | 急救证书到期日 |
| driver_licence / has_car | 有没有驾照 / 有没有车 |
| available_days | 能上班的日子，如「周一;周三;周五」 |
| work_rights | 在澳洲工作的权利：是 / 否 / 不确定（候选人自填） |
| interview_windows | 能面试的半天，如「11-16 上午;11-18 下午」 |
| notes | 候选人自己写的补充说明（自由文字） |

评分表 4 个维度各 1–5 分：沟通 30%、照护经验 30%、安全意识 25%、排班匹配 15%，外加「推荐 / 不推荐」和一句评语。

数据里**故意藏了 5 类问题**：

1. **重复报名**：同一个邮箱报了两次，第二次改了面试时间，应该用新的。
2. **备注里有跟岗位无关的个人信息**：年龄、助听器。年龄不能参与判断；助听器是候选人在提面试安排要求（想要视频面试），要照办，但健康信息不能写进筛选理由。
3. **规则判不了、要人看的**：Cert III 在读；工作权利填「不确定」；急救证书过期了但备注说开工前会复训——规则会说「不满足」，但这条不能直接建议拒。
4. **时间撞车和没有共同时间**：两组候选人想要同一个半天，先报名的先排；有一位只能周六面试，面试官周六没空。
5. **评分表有问题**：一位只收到一张；一位两个面试官意见相反；一位的评语里提到了口音和年纪。

教学假设：澳洲的反歧视规定不允许用年龄、残障、种族、口音等做招聘决定，并要求为残障人士提供合理的面试安排；具体适用范围以官方信息和法律意见为准。Cert III、急救证书是这个岗位的教学设定，真实要求以客户机构和行业主管部门为准。流程不判断签证，工作权利有疑问一律交顾问。

## 3. 做法

**规则**（先在 Claude 里跑通，再搬进 n8n 的 Code 节点）：

- 同一邮箱多次报名，只处理最新一份，旧的标「被取代」。
- 逐条判断 M1–M5：满足 / 不满足 / 不确定。Cert III「在读」、工作权利「不确定」= 不确定。急救证书到期日早于 12 月 1 日 = 不满足。工作日（周一至周五）少于 3 天 = 不满足。
- 有「不确定」→ 转人工。有「不满足」→ **建议不通过（待顾问确认）**，但备注里写了开工前能补齐的，改成转人工。全部满足 → 找面试时间。
- 面试时间：按提交时间先后，在候选人写的半天里找第一个两位面试官都空的 30 分钟（上午 9:00–11:30 开始，下午 13:00–16:30 开始），排出去就从空档里拿掉。找不到 → 转人工。
- 面试评分：每张表加权分 = 沟通×30% + 照护经验×30% + 安全意识×25% + 排班匹配×15%，两张取平均。
- 汇总：少于 2 张 → 等待；评语里有年龄、口音、怀孕、孩子、宗教、国籍这类信息 → 转人工，并把那句从汇总里去掉；推荐不一致或任一维度差 ≥ 2 分 → 转人工；都推荐且平均 ≥ 3.50 → 建议录用；都不推荐且平均 < 3.00 → 建议不录用；其余 → 转人工。

**第一步：在 Claude 里把规则跑通。** 新建 Project「安康招聘流程」，上传四个文件，项目说明里写：

```
你是安康护理人力的招聘助手，帮顾问 Mandy 处理社区陪护员岗位（JOB-HC-11）。你只出判断和草稿，不发任何邮件。

筛选：
1. 同一邮箱多次报名，只看最新一份。
2. 按岗位文件里的 M1–M5 逐条写「满足 / 不满足 / 不确定」，规则见下。
   M1 Cert III 已完成=满足，在读=不确定；M2 急救证书到期日 ≥ 2026-12-01=满足；
   M3 有驾照且有车=满足；M4 周一到周五能上的天数 ≥ 3=满足；M5 是=满足，否=不满足，不确定=不确定。
3. 读 notes：如果候选人说开工前能补齐某条，不要建议不通过，改成转人工并写清楚。
   notes 里出现年龄、健康、残障、家庭、国籍等信息，一律不作为理由，也不写进 reason。
   候选人提出的面试安排要求（比如要视频面试），写进给面试官的备注，只写要求，不写原因。
4. 全部满足的，按提交时间先后，在 interviewer-slots 里找他能面试的半天里第一个 free 的 30 分钟，用掉就不能再给别人。
5. 「不满足」只能写「建议不通过（待 Mandy 确认）」，拒信里只写跟岗位有关的原因，客气、不提任何个人特征。
6. 签证、工作权利的问题不判断，不在邮件里讨论政策，交给 Mandy。

面试汇总：
7. 每张评分表算加权分：沟通 30%、照护经验 30%、安全意识 25%、排班匹配 15%；每人两张取平均，保留两位小数。
8. 按这个顺序判断：不到 2 张=等待；评语里有年龄、口音、怀孕、孩子、宗教、国籍=转人工（这句话从汇总里删掉）；
   推荐不一致或任一维度差 ≥2=转人工；都推荐且 ≥3.50=建议录用；都不推荐且 <3.00=建议不录用；其他=转人工。
9. 录用通知草稿不写薪资、时薪、合同条款，只说会另发正式文件。

输出两张表：① 每份报名一行：submission_id, rule_status, slot, needs_human, reason, draft；
② 每位面试者一行：candidate_id, weighted_avg, cards_received, status, 一两句理由。
```

把结果跟 `expected/decisions.csv` 和 `answer.json` 对，对不上先改规则。

**第二步：准备 Google Sheets。** 一个表格四张工作表：`applications`（Form 写进来）、`slots`、`scorecards`、`log`（记每一步谁批的、几点发的）。

**第三步：按下面的节点搭 n8n。** 两条工作流。判断全在 Code 节点里，Claude 只负责读 notes 和写草稿。

### n8n 搭建

**工作流 A：报名 → 筛选 → 约面**

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | n8n Form (Form Trigger) | 候选人填报名表 | 字段跟 `applications.csv` 一致；日期、是 / 否用下拉，减少乱填 |
| 2 | Google Sheets（写报名） | 先把原始报名存下来 | Operation: Append Row，表 `applications` |
| 3 | Google Sheets（读同邮箱） | 查这个邮箱以前报过没有 | Operation: Get Row(s)；Filter: email 等于当前邮箱 |
| 4 | Code（标重复） | 有旧报名就把旧的标「被取代」，只让最新一份往下走 | 输出 `superseded_ids` 交给下一步回写 |
| 5 | Code（必备条件） | 按 M1–M5 规则逐条判断，输出 must_have 和 rule_status | 规则跟 Claude Project 里一字不差 |
| 6 | Basic LLM Chain + Anthropic Chat Model | 只读 notes：有没有「开工前能补齐」、有没有面试安排要求、有没有不该参与判断的个人信息 | 输出 JSON：`will_fix_before_start`、`interview_adjustment`、`ignored_personal_info`（只填类别，不填原文）；Temperature 0 |
| 7 | Structured Output Parser | 固定第 6 步的输出格式 | 三个字段都 required |
| 8 | Switch | 分三路：全部满足 / 建议不通过 / 转人工 | 「不满足」且 `will_fix_before_start` 为 true 的，走转人工 |
| 9 | Google Sheets（读空档） | 全部满足的，读 `slots` 里 status = free 的行 | Get Row(s)；节点设置里打开 Always Output Data |
| 10 | Code（排时间） | 在候选人的半天里找第一个空档；找不到就改走转人工 | 输出 `slot`；同时生成要回写成 busy 的行 |
| 11 | Basic LLM Chain + Anthropic Chat Model | 写邀约 / 拒信草稿 | 提示词见下；Temperature 0.2 |
| 12 | Slack · Send and Wait for Response | 每份发给 Mandy：结论、M1–M5、时间、草稿 | Response Type: Custom Form；选项：确认发送 / 改了再发 / 不发；**建议不通过的每个人单独一条，不做批量确认** |
| 13 | Switch（Mandy 的决定） | 确认 / 改了再发 → 往下；不发 → 只写 log | — |
| 14 | Google Sheets（锁时间） | 确认后才把 slot 改成 busy；改之前再读一次，被别人占了就退回 Mandy | Get Row(s) + If，再 Update Row |
| 15 | Google Calendar | 邀约确认后建面试日程，邀请 Mandy、Ruth、候选人 | Operation: Create；视频会议链接；面试安排要求写进日程备注 |
| 16 | Gmail | 发邀约或拒信 | 正文用 Mandy 批准（或改过）的版本 |
| 17 | Slack | 转人工的推到 #招聘，附原因 | 不给候选人发任何东西 |
| 18 | Google Sheets（写 log） | 记 submission_id、结论、谁批的、几点发的 | Append Row |

**工作流 B：面试评分 → 汇总**

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | Schedule Trigger | 每个工作日 16:30 | 时区 Australia/Adelaide |
| 2 | Google Sheets | 读 `scorecards` | Get Row(s) |
| 3 | Code | 按 candidate_id 分组，算加权平均、份数、各维度差、推荐是否一致，并做一遍关键词初筛（年纪、岁、口音、accent、怀孕、孩子、宗教、国籍） | 输出 rule_status；关键词只是初筛，不要用英文 `age`，它会误中 `aged care` |
| 4 | Basic LLM Chain + Anthropic Chat Model | 写给 Mandy 的汇总；再检查一遍评语里有没有关键词没抓到的无关个人特征，有就删掉那句并标转人工 | Temperature 0.2 |
| 5 | Switch | 建议录用 / 建议不录用 / 等待 / 转人工 | — |
| 6 | Gmail | 等待的：提醒还没交表的面试官 | 只发给面试官 |
| 7 | Slack · Send and Wait for Response | 录用通知、拒信草稿逐个交 Mandy 确认 | Response Type: Approval；不批就不发 |
| 8 | Gmail | Mandy 确认后才发给候选人 | — |
| 9 | Google Sheets（写 log） | 记结论、审批人、时间 | Append Row |

工作流 A 第 11 步的提示词：

```
你在帮安康护理人力的顾问 Mandy 起草一封给候选人的邮件。下面是这份报名的 JSON（含结论、面试时间、notes 判断结果）。
- 约面试：写明日期、星期、时间、30 分钟视频面试、面试官是 Mandy 和客户方的护理协调员 Ruth，请对方回复确认。
  候选人提过面试安排要求的，在邮件里说按他的要求安排，并问还有没有别的需要。
- 建议不通过：只写跟岗位必备条件有关的原因，一句话说清，客气地留一个以后联系的口子。
  不写年龄、健康、家庭、国籍、签证等任何个人情况。
候选人用中文报名就写中文，用英文就写英文。不超过 100 字（英文 80 词）。不承诺录用，不写薪资。
```

> 用 ChatGPT 也可以：第一步用 ChatGPT Project 跑同样的规则；n8n 里把 Anthropic Chat Model 换成 OpenAI Chat Model，其他节点不变。

## 6. 加分挑战

- 候选人回邮件说「这个时间不行」：用 Email Trigger (IMAP) 接住回信，释放原来的时间格，按剩余空档重新排，再走一次 Mandy 审批。
- 给 Mandy 做一个周五汇总：本周报名多少、约了几场、转人工各是什么原因、拒信平均等了多久才确认。
- 把加权分的权重改成可配置（放进 Google Sheets 一张 `settings` 表），并说说如果客户要「照护经验 50%」，C04 和 C06 的结论会不会变。

## 7. 简历 / 面试可以这样讲

> 为一家护理人力外包公司搭建招聘流程（n8n + Claude）：报名表进来后按岗位必备条件自动初筛、去重，并按提交顺序在面试官共同空档里排时间；候选人自由填写的备注交给 Claude 判断「开工前能否补齐」和面试安排要求；面试后自动汇总两位面试官的加权评分，分歧和含无关个人特征的评语转人工。所有邀约、拒信和录用通知都要顾问在 Slack 里逐个确认后才发出，流程里明确排除年龄、残障、口音等因素（教学项目，数据为这个练习设计）。
