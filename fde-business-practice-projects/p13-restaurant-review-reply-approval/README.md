# P13 · 餐饮：差评监测 → 起草回复 → 店长审批后发布

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 餐饮 / 外卖 | L2 Workflow | 150 分钟 | Claude（Projects）+ n8n + Google Sheets + Slack |

## 1. 客户场景

还是 P01 里 Chatswood 的明月小馆。日报做顺了以后，老板陈姐发现另一件事更让她睡不着：Google、Uber Eats、DoorDash、Menulog 四个地方都有人留评价，差评有时挂了一个礼拜都没人回。店长阿杰想起来就去各个后台翻一遍，回的时候带着火气，有一次还跟顾客在评论区吵起来。更要命的是，上个月有人说吃完拉肚子，店员顺手回了一句「我们的食材都很新鲜，可能是您自己肠胃不好」，被截图转了好几个群。

他们想要的是：**每周三早上，把四个平台上周的 1–3 星评价收齐、去重，分好类，起草好回复；食品安全、辱骂、看着不像真顾客的单独拎出来；阿杰在 Slack 里一条条点批准，批准了才发。**

## 2. 练习数据

都是练习数据：店名沿用 P01，评价、顾客名、订单号都是为这个练习设计的。

| 文件 | 内容 |
|---|---|
| `data/reviews-2026-11-04_10.csv` | 四个平台导出合并在一起的评价，27 行 |
| `data/reply-guide.md` | 店里定的回复规范：营业时间（周一店休）、菜单、哪些评价要处理、怎么写、哪些必须交给人、怎么发布 |

`reviews-2026-11-04_10.csv` 的字段：

| 字段 | 含义 |
|---|---|
| review_id | 平台上的评价编号，同一条评价编号不变 |
| platform | Google / Uber Eats / DoorDash / Menulog |
| posted_at | 发布时间 |
| reviewer / reviewer_review_count | 评价人昵称 / 这个账号一共留过几条评价 |
| rating | 1–5 星 |
| order_id / order_items | 外卖平台带订单号和点了什么；Google 没有 |
| text | 评价原文 |
| owner_replied | 店里是不是已经回过 |

数据里**故意藏了 5 类要单独处理的情况**：

1. **食品安全**：有人说吃完半夜拉肚子、呕吐。不能在评论区辩解或给身体方面的建议，要当天报给阿杰和陈姐，公开回复只发一句。
2. **辱骂**：一条纯骂人的 Google 评价，没有任何用餐信息。不回、不对骂，截图留存，阿杰决定要不要举报。
3. **重复**：同一条 Google 评价被导出了两次（review_id 相同）。
4. **英文评价**：要用英文回。
5. **看起来不像真实顾客**：说「周一晚上」来吃（店里周一休息）、点了菜单上没有的北京烤鸭、账号只有这一条评价、凌晨 3 点发的。不指控对方造假，只说明查不到记录，举不举报阿杰定。

另外还有两条上周以前、已经回过的评价，不在这次的范围里；一条「豆腐像放了很久」只说口感、没说身体不适，按普通差评处理，不要误判成食品安全。

**教学假设：** 各平台能不能通过接口回复评价、要什么权限，以平台官方文档和商家后台为准；举报规则以平台的社区规范为准。本项目不判断谁对谁错，也不给任何关于身体状况的说法。

## 3. 做法

规则分两层：**收哪些、去不去重、打哪些风险标记**是确定的，放在 Code 节点里；**分类和写回复**交给 Claude，按规范写，人来批。

**第一步：在 Claude 里把判断和回复跑通。** 建 Project「明月小馆评价回复」，上传 `reply-guide.md`，项目说明写：

```
你是明月小馆的评价回复助手。我每周给你一批 1–3 星、还没回复过的评价，已经去过重。
每条评价请按回复规范处理，输出一行 JSON：
{"review_id", "category", "route", "priority", "reason", "reply_draft"}

category 从这些里选：配送 / 出餐慢、漏餐、口味、分量、包装、服务、等位、食品安全、辱骂、疑似非真实评价（可以组合，如「口味 + 服务」）。
route 只能是：
- 起草回复 → 店长审批
- 紧急转人工（食品安全）
- 不回复，截图留存，店长决定是否举报（辱骂）
- 起草中性回复 + 建议店长决定是否举报（疑似非真实）

硬规则：
1. 提到吃完身体不适、拉肚子、呕吐、异物、变质 → 食品安全，priority = 紧急。回复只写「已经私信您，想当面了解一下情况」这一类的话，不解释原因，不说食材新鲜，不给任何身体方面的建议。
2. 只说口感不好、没说身体不适的，不算食品安全，按普通差评回。
3. 辱骂、人身攻击 → reply_draft 留空。
4. 说的日子我们店休、提到菜单上没有的菜、账号只有 1 条评价，有两条以上就按疑似非真实处理：不说对方造假，只说明查不到这次用餐记录，请对方私信。
5. 公开回复不承诺退款、补偿、代金券或折扣；需要补救的请对方私信订单号，外卖退款提醒走平台流程。
6. 不写还没做的事（不写「已经处理好了」），只写「我们会……」。
7. 对方用英文就用英文回。中文不超过 80 字，英文不超过 60 词，落款按规范。
```

把 11 条差评逐条贴进去，跟 `expected/decisions.csv` 对。route 和标准答案不一样的，先改提示词再进 n8n。

**第二步：把评价放进 Google Sheets。** 一张 `reviews` 表放导出数据，一张 `reply_log` 记每条评价的处理状态（待审批 / 已批准 / 已发布 / 不回复）。练习时直接把 CSV 导进去；真实店里由店员每周二晚上从四个后台导出贴进来，能用接口的平台再换成 HTTP Request。

**第三步：按下面的节点搭 n8n。**

### n8n 搭建

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | Schedule Trigger | 每周三早上触发 | 每周三 09:00，时区 Australia/Sydney |
| 2 | Google Sheets（读评价） | 读 `reviews` 全部行 | Operation: Get Row(s) |
| 3 | Remove Duplicates | 同一个 review_id 只留一条 | Compare: Selected Fields → review_id |
| 4 | Filter | 只留窗口内、1–3 星、还没回复的 | posted_at 在 11-04 到 11-10 之间；rating ≤ 3；owner_replied = no |
| 5 | Code（风险标记） | 打确定性标记，交给模型前先做一遍 | 食品安全关键词、辱骂关键词、提到「周一」、提到菜单外的菜、账号只有 1 条评价、凌晨发布、纯英文；结果写进 `rule_flags` |
| 6 | Basic LLM Chain + Anthropic Chat Model | 按第一步的提示词出分类、路线和回复草稿 | Temperature 0.2；`rule_flags` 一起传进去 |
| 6a | Structured Output Parser | 强制输出 JSON 结构 | 字段全部 required |
| 7 | Code（安全复核） | 模型输出之后再查一遍：有食品安全标记但 route 不是紧急的，强制改成紧急；草稿里出现「给您退」「补偿」「代金券」「折扣」「免单」「肠胃」「新鲜」就退回重写（提醒对方走平台退款流程是允许的，所以不拦「退款」两个字） | 规则写死，不靠模型 |
| 8 | Switch | 按 route 分四路 | 普通 / 紧急 / 辱骂 / 疑似非真实 |
| 9 | Slack（紧急提醒） | 食品安全的当天 @阿杰 和 @陈姐 | Channel: #店务-紧急；附订单号、点了什么、原文 |
| 10 | Slack · Send and Wait for Response（店长审批） | 每条草稿发给阿杰：原文、标记、分类、草稿 | Response Type: Custom Form；字段：决定（批准 / 改了再发 / 不回）、修改后的回复；超时 2 天按「不回」处理并提醒 |
| 11 | Switch | 按阿杰的决定分流 | 批准 / 改了再发 / 不回 |
| 12 | Edit Fields (Set) | 定下最终要发的文字 | 「改了再发」用阿杰改过的版本 |
| 13 | HTTP Request（能接口回复的平台） | 调平台的评价回复接口 | 只在批准后执行；有没有权限以平台文档为准，练习时改成写入表格 |
| 14 | Slack（待手动发布） | 不能接口回复的平台，把批准后的文字发到 #待发布，店员复制到后台 | 附平台和 review_id，发完点 ✅ |
| 15 | Google Sheets（写 reply_log） | 记 review_id、路线、谁批的、几点批的、最终文字、状态 | Operation: Append or Update Row，按 review_id 匹配 |

辱骂那一路不进审批草稿，直接写进 `reply_log`（状态：不回复，待店长决定是否举报），并在第 10 步的汇总里列出来让阿杰知道。

> 用 ChatGPT 也可以：第一步用 ChatGPT Project 跑同样的规则；n8n 里把 Anthropic Chat Model 换成 OpenAI Chat Model，其他节点不变。

## 6. 加分挑战

- 把 4–5 星也接进来：让 Claude 写一句短的感谢回复，每周批量审一次，跟差评分开走。
- 每月第一个周三多发一份小结：各平台平均星级的变化、哪类差评最多（比如包装问题连续三周出现），给阿杰一个具体要改的点。
- 同一个顾客在两个平台都留了差评时，合在一起提醒阿杰，回复内容保持一致。

## 7. 简历 / 面试可以这样讲

> 为一家多平台经营的中餐馆搭建差评回复流程：n8n 每周汇总四个平台的评价，去重、筛出 1–3 星，用确定性规则先标出食品安全、辱骂、疑似非真实和英文评价，再由 Claude 按店里的回复规范分类、起草回复；模型之后加一层关键词复核，禁止承诺补偿和解释食品安全原因；所有回复经店长在 Slack 审批后才发布，食品安全当天提醒店长和老板（教学项目，数据为为练习设计）。
