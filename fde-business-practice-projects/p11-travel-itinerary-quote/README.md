# P11 · 旅行社：客人行程需求整理成报价草案

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 旅行社 | L1 自动化 | 60 分钟 | Claude（Projects）+ Excel / Google Sheets |

## 1. 客户场景

金桥旅行在墨尔本 Box Hill，三个顾问专做华人家庭和长辈团的澳新短线游。客人的需求都是邮件、微信里的一段话：「我们一家三口 12 月想去黄金海岸」「父母过来探亲想去塔斯马尼亚」。顾问 Amy 每天要把这些话拆成酒店几间几晚、门票几大几小、接送几程，再去翻价目表一项项乘。旺季要不要加价、2 岁宝宝算不算人头、哪个一日游的价格已经过了有效期，经常算错。更麻烦的是客人顺手问的签证和保险，新人有时会凭印象直接回，这是最不该出错的地方。

她想要的是：**把当天收到的需求邮件丢进去，每封拿到一份按价目表算好的报价草案；算不了、不该答的，明明白白标出来交给人。**

## 2. 练习数据

全部是练习数据，公司、客人、邮箱都是编的；价格是教学假设，不代表任何真实酒店或供应商。

| 文件 | 内容 |
|---|---|
| `data/enquiries/E1101.txt` … `E1106.txt` | 6 封客人需求邮件（发件人、时间、主题、正文） |
| `data/price-list-2026-27-summer.csv` | 价目表，21 项：酒店、一日游 / 门票、机场接送 |
| `data/quote-rules.md` | 公司报价规则（旺季加价、儿童价、房间人数、定金等） |

价目表字段：

| 字段 | 含义 |
|---|---|
| code | 价目编码，如 H-GC-02（酒店）、T-CNS-01（一日游）、X-GC-S（接送轿车） |
| category | hotel / tour / transfer |
| unit | 每间每晚 / 每人 / 每车每程 |
| price_adult / price_child | 大人价 / 小孩价（澳元，含 GST，教学假设） |
| max_occupancy | 酒店每间最多住几人；接送车最多坐几人 |
| valid_from / valid_to | 这个价格的有效期 |

数据里**故意藏了 5 类问题**，真实工作里天天碰到：

1. **签证问题**：E1103 问中国护照去新西兰要不要签证。
2. **保险问题**：E1104 问 70 多岁的父母、有高血压，旅游保险怎么买、既往病能不能保。
3. **人数超过房型上限**：E1105 六个人（含 2 岁宝宝）想挤一间最多住 4 人的公寓。
4. **价格过期**：E1102 要的库兰达小火车，价目表价格只到 2026-12-15，客人 12 月 26 日才去。
5. **信息不全**：E1106 只说「明年春天、几个人没定」，没法报价。

签证、保险属于需要资质和官方信息的问题（教学假设：报价助手一律不答，签证以官方移民部门信息为准，保险以保险公司条款为准）。

## 3. 做法

**第一步：建一个 Claude Project。** 名字叫「金桥报价草案」。把 `price-list-2026-27-summer.csv` 和 `quote-rules.md` 上传到项目知识库（Project knowledge），在项目说明里写：

```
你是金桥旅行的报价助手，只做报价草案，不直接回复客人。
我每次会贴一封或几封客人需求邮件。请对每封邮件：
1. 先抽取：目的地、入住和离开日期、晚数、每位同行人的年龄（没写年龄的按大人）、要的酒店、一日游、接送。
2. 只用项目里价目表的价格，严格按 quote-rules.md 计算。不许估价，不许用价目表以外的价格。
3. 输出一张报价表：编码、项目、数量、单价、金额；最后写合计、定金（合计 × 30%）。
4. 下面几种情况必须单独列在「需要人工处理」里，写清原因：
   - 客人问签证、旅游保险、入境健康要求：不回答内容，只写「转人工」；
   - 人数超过房型 max_occupancy：按最少需要的房间数计算，并写「请客人确认房间数」；
   - 出行日期不在某项价格有效期内：这一项不计入合计，写「价格过期，需向供应商确认」；
   - 缺日期或人数：不出报价，列出要问客人的问题。
5. 最后给每封邮件一个状态：「可发给客人」/「草案，有标出项待人工处理」/「信息不全，不出报价」。
6. 金额保留两位小数。不确定的地方写出来，不要猜。
```

**第二步：一次贴一封邮件**，说：「出 E1101 的报价草案。」先做 E1101（最干净的一封），对上标准答案后再做其他几封。

**第三步：核对。** 每封至少手算一项：比如 E1103 的酒店，1 月 8、9、10 日三晚在旺季（每晚 320 × 1.2 = 384），1 月 11 日一晚按平价 320，合计 1,472。对不上就回去看是不是旺季日期或「入住夜晚」算错了（离开那天不算一晚）。

**第四步：做成每天的流程。** 规则和价目表都在 Project 里，Amy 每天把新邮件贴进去，拿到草案后自己看一眼「需要人工处理」那一栏再回客人。价目表换季时只换知识库里那一个 CSV。

> 用 ChatGPT 也可以：建一个自定义 GPT，把价目表和规则作为知识文件上传，说明里放同样的提示词；算账部分让它用代码解释器（数据分析）算，比心算稳。

几个容易错的点：

- E1102 三晚全在旺季（12 月 26–28 日），酒店每间每晚 258，2 间 × 3 晚 = 1,548。
- E1105 的 2 岁宝宝：门票免费，但要算进房间人数；6 人坐商务车（每程 130）。
- E1101 的 8 岁女儿按小孩价 109。

## 5. 验收清单

- [ ] 6 封邮件都有结果；E1106 没有出数字，而是列了要问客人的问题。
- [ ] 5 个合计和定金跟标准答案的差距在 0.01 以内。
- [ ] E1103 和 E1104 的草案里没有任何签证或保险的具体说法（没有「不需要签证」「可以保」这类话），只写了转人工。
- [ ] E1102 的库兰达小火车没有计入合计，并写了价格过期。
- [ ] E1105 按 2 间公寓计算，并提示请客人确认，没有照客人说的「一间就够」去报。
- [ ] 旺季加价只加在酒店上，门票和接送没有加。

## 6. 加分挑战

- 让 Claude 把每份草案再写成一封给客人的中文回复邮件，语气像顾问本人，标出项那里写「这部分我们的顾问会单独跟您确认」。
- 让它同时输出一张 CSV（邮件编号、客人、合计、定金、状态），每天贴进顾问的跟进表。
- 把价目表换成一份新季度的版本（自己改几个价格和有效期），看规则不改、只换文件时结果是否跟着变。

## 7. 简历 / 面试可以这样讲

> 为一家华人旅行社设计报价草案流程：用 Claude Project 固化价目表和报价规则，把客人的自然语言需求拆成酒店、门票、接送明细并计算合计与定金，自动处理旺季加价、儿童 / 婴儿价和房间人数上限；对价格过期、信息不全的需求单独标出，签证和保险问题一律转人工、不让 AI 作答（教学项目，数据和价格为教学假设）。
