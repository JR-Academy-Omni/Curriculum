# P21 · 记账 / 会计事务所：客户月度单据收集 → 缺件催收 → 会计复核

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 记账 / 会计事务所 | L2 Workflow | 150 分钟 | Claude + n8n + Google Sheets + Gmail + Slack |

## 1. 客户场景

明德会计在 Adelaide，两个会计 Helen 和 Mark，一个行政小许，每个月帮十几家小生意记账。每月初，小许要盯着每家客户把上个月的资料交齐：银行对账单、信用卡对账单、POS 报表、工资汇总、进货发票。现在全靠她脑子和一张 Excel：谁交了什么，谁还差什么，上次催过没有。结果每个月都有几家拖到会计要开工了还没齐；有客户传了 9 月的对账单当 10 月的，没人发现；有客户被连催了三封邮件，打电话来抱怨；还有一封不认识的邮箱发来「老街面馆的对账单」，差点被当成真的归档。

他们想要的是：**每天早上自动对一遍：谁的资料齐了就送给负责的会计复核；谁还差什么就起草提醒，小许点批准才发；催过两次还不交的不再发邮件，交给会计打电话；来路不明、期间不对、打不开的文件单独拦下来。**

## 2. 练习数据

都是练习数据，事务所、客户、邮箱（`.example`）和账号尾号都是为这个练习设计的。

| 文件 | 内容 |
|---|---|
| `data/clients.csv` | 12 家客户：客户编号、名称、联系人、登记邮箱、服务状态（active / paused）、银行账户（多个用分号隔开）、有没有信用卡 / POS / 工资、负责会计、沟通语言（中文 / English） |
| `data/doc-requirements.csv` | 5 类资料和什么时候需要（事务所自己的要求） |
| `data/received-2026-10.csv` | 截至 11 月 12 日收到的 33 个文件：收到时间、发件邮箱、资料类型、账户、期间、文件名、备注 |
| `data/reminder-log.csv` | 这个月已经发过的提醒：客户、期间、第几次、发送时间 |

资料要求（事务所内部规则）：每个银行账户一份对账单；有信用卡的要信用卡对账单；有 POS 的要 POS 销售报表；有员工的要工资汇总；所有客户都要当月的进货 / 费用发票包。

**教学假设**：交件日 11 月 7 日、补交日 11 月 17 日、「最多催两次」都是这家事务所自己定的规则。BAS、工资申报等的真实截止日期以 ATO 官方和事务所与客户的委托协议为准。这个流程只收资料，不判断任何一笔账怎么记。

数据里**故意藏了 5 处问题**：

1. **期间不对**：Coastal Tiles 的一份对账单是 9 月的，备注里客户还说是「十月的」；
2. **重复上传**：Harbour IT 的发票包传了两次；
3. **发件人不是客户**：一个不在客户表里的邮箱发来「老街面馆的对账单」，不能归档，可能是钓鱼邮件；
4. **文件打不开**：Golden Grain 的一份对账单有密码；
5. **已经催过两次**：Swift Couriers 11 月 3 日、7 日各收到过一封提醒，还是没交。

另外东方旅游是暂停服务的客户，不应该收到任何提醒。

## 3. 做法

**清单规则**（先在 Claude 里跑通，再搬进 n8n 的 Code 节点）：

- 每家客户应交的资料 = 按 `doc-requirements.csv` 和客户的设置算出来；
- 一个文件算「收到」，必须同时满足：发件邮箱是客户的登记邮箱、期间是 2026-10、文件能打开；同一类同一账户只算一次；
- 全部收到 → 送负责会计复核；
- 有缺的：已提醒 0 次 → 第 1 次提醒；已提醒 1 次 → 第 2 次提醒；已提醒 2 次及以上 → 不再发邮件，交给会计打电话；
- 暂停服务的客户不发任何东西。

**第一步：在 Claude 里把规则跑通。** 新建 Project「明德月度资料」，把 4 份 CSV 传进去，说明里写：

```
你是明德会计的资料收集助手。我会给你客户表 clients、资料要求 doc-requirements、收件记录 received、提醒记录 reminder-log。
按这个顺序处理：
1. 先过一遍收件记录，挡掉不算数的文件：发件邮箱不在客户表里的（写明「发件人不是客户，不归档」）；期间不是 2026-10 的；备注说打不开或有密码的；同一客户同一类资料同一账户重复的。每一条写进「文件异常」：编号、类型、怎么处理。
2. 每家 active 客户：列出应交资料（每个银行账户单独一项），对照剩下的有效文件，算出缺什么。
3. 按规则给出下一步：齐全 → 进会计复核（写负责会计）；缺件 → 第几次提醒，或「已催 2 次，转会计打电话」；paused → 跳过。
4. 给每家要发提醒的客户写一封邮件草稿：称呼联系人，列出缺的每一项和怎么准备，补交日期 11 月 17 日（周二），请对方直接回邮件附文件。按客户表的 language 用中文或英文写。第 2 次提醒要提一句上次是哪天发的。不超过 120 字（列表除外）。
不要在邮件里要求客户发密码、银行登录信息；不要评论客户的账；你只出草稿，不发任何邮件。
输出：① 客户状态表；② 文件异常清单；③ 提醒邮件草稿；④ 给小许的三行摘要。
```

发一句「对一下 10 月的资料」，拿结果跟第 4 节和 `expected/` 对。对不上先改规则，规则对了再进 n8n。

**第二步：把 4 份表放进 Google Sheets。** 一个表格 4 张工作表：`clients`、`doc_requirements`、`received`、`reminder_log`，再加一张 `review_log` 记会计复核结果。真实场景里 `received` 由另一个小流程自动写入（Email Trigger (IMAP) 收客户邮件 → Code 读附件名和发件人 → Google Sheets 追加一行），练习时直接用 CSV。

**第三步：按下面的节点搭 n8n。** 对清单、算催几次全放在 Code 节点里（确定、可复查），Claude 只负责写提醒邮件。

### n8n 搭建

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | Schedule Trigger | 每个工作日早上触发 | 周一到周五 09:00，时区 Australia/Adelaide |
| 2 | Google Sheets（读客户） | 读 `clients` | Operation: Get Row(s) |
| 3 | Google Sheets（读收件） | 读 `received`，只要期间相关的行 | 同上；节点设置打开 Always Output Data |
| 4 | Google Sheets（读提醒记录） | 读 `reminder_log` | 同上 |
| 5 | Code（对清单） | 按第 3 节规则先挡异常文件，再逐个客户算缺件和下一步；输出 `type = review / remind / call / skip / file_hold` | Run Once for All Items；用 `$('读客户').all()` 等取三张表 |
| 6 | Switch | 按 `type` 分五路 | review → 0；remind → 1；call → 2；file_hold → 3；skip → 不连线 |
| 7 | Basic LLM Chain + Anthropic Chat Model | remind 路：为每家客户写提醒邮件草稿 | 提示词见下；Temperature 0.2 |
| 8 | Slack · Send and Wait for Response（小许确认） | 把客户名、缺件清单、邮件草稿发到 #资料收集，等小许点 Approve / Decline | Response Type: Approval；超时 1 天按 Decline 处理 |
| 9 | If（小许是否批准） | 拒绝的写进 `reminder_log` 状态 declined，结束 | 条件：`approved` 为 true |
| 10 | Gmail（发提醒） | 批准后才发给客户 | To: 客户登记邮箱；正文用第 7 步草稿 |
| 11 | Google Sheets（记提醒） | 写入 `reminder_log`：客户、期间、第几次、几点发的、谁批的 | Operation: Append Row |
| 12 | Slack（转会计打电话） | call 路：@负责会计，写清缺什么、催过哪几天 | 不发任何客户邮件 |
| 13 | Slack（文件异常） | file_hold 路：Aggregate 后一条消息发到 #资料收集 | 发件人不是客户的那条写「不要打开附件，先核实」 |
| 14 | Slack · Send and Wait for Response（会计复核） | review 路：发给负责会计，等他选「复核通过 / 退回」并写备注 | Response Type: Custom Form；字段：结果、备注 |
| 15 | Google Sheets（记复核） | 写入 `review_log`：客户、会计、结果、备注、时间 | Operation: Append Row；退回的第二天会重新出现在清单里 |

第 7 步的提示词：

```
你在帮明德会计给客户写一封补交资料的提醒邮件。下面是这家客户的 JSON：联系人、客户名、沟通语言、缺的资料清单、第几次提醒、上次提醒日期。
要求：称呼联系人；先谢谢对方已经发来的资料；逐条列出缺的资料，每条写一句怎么准备（例如「在 POS 后台导出 10 月 1 日到 31 日的销售汇总」）；
补交日期写 11 月 17 日（周二）；第 2 次提醒要提一句上次提醒的日期，语气更直接但保持客气。
按 JSON 里的 language 用中文或英文写。不超过 120 字（列表除外）。
不要要求对方发密码或银行登录信息；不要写 JSON 里没有的资料；不要评论客户的账。
```

> 用 ChatGPT 也可以：第一步用 ChatGPT Project 跑同样的规则；n8n 里把 Anthropic Chat Model 换成 OpenAI Chat Model，其他节点不变。

## 5. 验收清单

- [ ] 进复核的正好是 C01、C02、C04、C05、C10，每家写了负责会计。
- [ ] C03 和 C07 被算作缺件（不是齐全），提醒邮件里分别写了「是 9 月的」和「有密码」。
- [ ] R028 没有被归到任何客户，Slack 异常消息里提醒「先核实、不要打开附件」。
- [ ] C09 没有收到第 3 封邮件，Helen 收到了打电话的 Slack 消息；C12 没有任何提醒。
- [ ] 小许点 Decline 时客户收不到邮件，`reminder_log` 记为 declined；批准后才写入新的提醒记录。
- [ ] 邮件草稿里的缺件跟 `decisions.csv` 一致，补交日期都是 11 月 17 日，没有要求客户发密码。

## 6. 加分挑战

- 会计复核时选「退回」并写原因（比如「对账单少了一页」），让第二天的清单把这条当缺件重新催，提醒里引用会计的原话。
- 给每家客户算「平均晚交几天」，每季度给 Helen 和 Mark 一份表，找出最需要换收集方式（比如直接连银行数据）的客户。
- 把发件人校验做严一点：客户登记了多个邮箱（老板和他的簿记员）时怎么办？加一列 `other_emails`，改 Code 节点，再跑一遍。

## 7. 简历 / 面试可以这样讲

> 为一家小型记账事务所搭建月度资料收集流程：用 n8n 每天按客户设置算出应交资料，自动挡掉期间不对、打不开、重复和来路不明的文件；缺件客户由 Claude 起草提醒、行政在 Slack 批准后才发出，催满两次自动转会计电话跟进；资料齐全的客户自动送负责会计复核并记录结果（教学项目，事务所和数据为练习设计）。
