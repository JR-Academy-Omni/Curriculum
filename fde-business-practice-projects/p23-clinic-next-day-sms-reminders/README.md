# P23 · 诊所 / 牙医：预约表生成次日提醒短信草稿

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 诊所 / 牙医 | L1 自动化 | 45 分钟 | Claude（Projects）+ Excel / Google Sheets |

## 1. 客户场景

佳美牙科在悉尼 Burwood，两位医生，前台 Linda。每天下午四点，Linda 要从预约系统导出第二天的预约表，一条条复制名字和时间，给病人发提醒短信。一天二十来个预约，发完要半小时，还老出错：发给了已经取消的病人；给 9 岁的孩子手机发了短信，家长反而不知道；有位病人去年明确说过不要发短信，又收到了；最让诊所经理紧张的一次，是有同事在短信里写了「明天上午 10 点拔智齿」，病人的手机是和家人共用的。

她想要的是：**导出的预约表丢进去，几分钟拿到一份能直接批量发的短信草稿表：该发谁、发到哪个号码、发什么，一条不多一条不少；不能发短信的单独列成电话清单。短信里只有时间，不出现任何治疗内容。**

## 2. 练习数据

都是练习数据，诊所、医生、病人、电话（`04xx xxx 000`）都是为这个练习设计的。

| 文件 | 内容 |
|---|---|
| `data/appointments-2026-11-13.csv` | 11 月 13 日（周五）的 21 个预约 |
| `data/sms-templates.md` | 诊所批准的四种短信模板（中文 / English，本人 / 发给监护人） |

预约表字段：

| 字段 | 含义 |
|---|---|
| appt_id / start / dentist | 预约编号、开始时间、医生 |
| patient_name / dob | 病人姓名、出生日期 |
| mobile | 病人本人手机 |
| sms_consent | 是否同意接收短信提醒：Y / N / 空白（未成年人这一栏记的是监护人的意思） |
| language | 中文 / English |
| status | booked 已约 / cancelled 已取消 / rescheduled 已改到别的日子 |
| treatment | 治疗项目（只给诊所内部看，**不能进短信**） |
| guardian_name / guardian_mobile | 监护人姓名、手机（未成年病人） |
| notes | 前台备注 |

数据里**故意藏了这几类问题**：

1. **没有短信同意**：一位病人是 N（备注「去年说过不要发短信」），一位是空白；
2. **不该提醒的预约**：一个已取消，一个已改到下周；
3. **未成年病人**：一对兄妹同一位家长，要发给家长、合成一条；一位 16 岁的病人有自己的手机，但家长没留手机号——不能因此改发给孩子；还有一位病人就诊当天刚满 18 岁，按成年人处理；
4. **没有手机号**：一位病人手机号是空的；
5. **治疗内容**：每一行都有 treatment，拔智齿、根管治疗、种植牙复查……短信里一个字都不能出现。

**教学假设**：本练习里「18 岁以下发给监护人」「同意栏必须是 Y 才发」是这家诊所自己的规则；短信里不写治疗内容，是因为手机可能被家人或旁人看到。真实的同意、隐私和电子信息规则，以澳洲隐私法（Australian Privacy Principles）、《Spam Act 2003》和诊所的隐私政策为准，拿不准就问诊所的隐私负责人。

## 3. 做法

**第一步：在 Claude 里建一个 Project。** 名字叫「佳美次日提醒」，把 `sms-templates.md` 放进项目文件，项目说明写：

```
你是佳美牙科的短信提醒助手。我每天下午会上传第二天的预约表 CSV。请按下面规则出短信草稿：
1. 只处理 status = booked 的预约；cancelled、rescheduled 列进「不发」，写原因。
2. 按就诊当天算年龄。未满 18 岁：收件人是监护人（guardian_name、guardian_mobile）；监护人没有手机号，列进「电话提醒清单」，不要改发到孩子本人的手机。满 18 岁：收件人是病人本人。
3. sms_consent 不是 Y（N 或空白）→ 不发短信，列进「电话提醒清单」，写清是 N 还是空白。
4. 收件手机号去掉空格后必须是 04 开头的 10 位数字，否则列进「电话提醒清单」。
5. 同一个收件手机号有多个预约（例如兄弟姐妹），合成一条短信，名字和时间按先后列出。
6. 短信只能用 sms-templates.md 里的模板，按 language 选中文或英文；中文称呼用全名，英文用名（first name）；时间写成「上午10:15」或「10:15am」。
7. 短信里绝对不能出现 treatment 的任何内容、医生的诊断或任何病情信息；也不写医生名字。
8. 输出三张表：① 短信草稿（预约编号、收件人、手机、语言、是否发给监护人、字数、短信内容），同时给一份 CSV；② 电话提醒清单（预约编号、病人、时间、原因）；③ 不发清单。最后一行写数字小结。
不确定的写出来，不要猜；你只出草稿，不发任何短信。
```

**第二步：上传当天导出的预约表，发一句：**「出明天 11 月 13 日的提醒短信。」

**第三步：核对。** 用第 5 节的清单逐条对。至少手工抽查两处：在 Excel 里筛 `status = booked` 且 `sms_consent = Y`，再看出生日期在 2008-11-13 之后的几行是不是都发给了监护人；再在短信草稿 CSV 里搜「拔」「根管」「种植」，必须一个都搜不到。

**第四步：变成每天的流程。** 规则存在 Project 里以后，Linda 每天下午只要上传导出表。短信草稿 CSV 粘进诊所短信平台的批量发送页面，电话清单打印出来，打完一个勾一个。

> 用 ChatGPT 也可以：建一个 ChatGPT Project 或自定义 GPT，把同样的规则和模板放进去，上传 CSV 即可。

## 4. 应该做出的结果

`expected/answer.json` 是脚本按同样规则算出来的标准答案，`expected/sms-drafts.csv` 是 14 条短信的标准文本，`expected/decisions.csv` 是 21 个预约每一个的处理结论。

| 结果 | 数量 | 预约 |
|---|---|---|
| 发短信 | **14 条，覆盖 15 个预约** | 兄妹 A016、A018 合成一条发给林美华 |
| 电话提醒 | 4 个 | A001 郑凯（同意 = N）、A004 Ethan Brooks（16 岁，家长没留手机号）、A007 Chloe Evans（没有手机号）、A014 Grace Walker（同意是空白） |
| 不发 | 2 个 | A003 何静（已取消）、A006 Liam Turner（已改约） |

- 21 = 15 + 4 + 2，每个预约都有去处。
- A008 Mia Santos 出生于 2008-11-13，就诊当天刚满 18 岁，按成年人发给她本人。
- 中文短信 59–60 字，英文 151–154 个字符，都在一条短信以内；只有兄妹那条合并短信是 73 字，超过 70 字会按两条计费（见加分挑战）。
- 合并那条的标准文本：

```
【佳美牙科】林美华您好，提醒林子涵、林子轩明天11月13日（周五）下午3:00、下午3:30有预约。改约请回复本短信或致电前台。回复STOP退订。
```

## 5. 验收清单

- [ ] 短信草稿是 14 条，不是 21 条，也不是 15 条（兄妹合成了一条）。
- [ ] 所有短信里都搜不到 treatment 里的任何词（拔、根管、种植、补牙、涂氟、牙周、牙套、洁牙），也没有医生名字。
- [ ] A016、A018 发给的是林美华的手机，不是孩子；A004 在电话清单里，没有发到 Ethan 自己的手机。
- [ ] A001（N）和 A014（空白）都在电话清单里，原因写得不一样。
- [ ] 已取消的 A003、已改约的 A006 没有短信，也不在电话清单里。
- [ ] 手机号都是 04 开头的 10 位数字，没有空格。

## 6. 加分挑战

- 合并短信超过 70 字会被拆成两条。让 Claude 想一个更短的合并写法（比如「林子涵 3:00、林子轩 3:30」），控制在 70 字以内，并确认没丢信息。
- 第二天让 Claude 再读一份「短信回复」表（病人回了「改约」「STOP」「好的」），把要改约的列给 Linda，把回 STOP 的人标出来，提醒她在系统里把 sms_consent 改成 N（由 Linda 改，不是 Claude）。
- 把电话清单按医生分开，各自附上「打电话时怎么说」的一句话，同样不提治疗内容。

## 7. 简历 / 面试可以这样讲

> 为一家牙科诊所把每天的预约表变成次日提醒短信草稿：用 Claude Project 固化规则，只提醒有效预约，按就诊当天年龄把未成年人的提醒改发给监护人并合并兄弟姐妹，没有短信同意或没有手机号的进电话清单；短信严格套用诊所模板，不出现任何治疗内容，并用关键词检查兜底（教学项目，诊所和数据为练习设计）。
