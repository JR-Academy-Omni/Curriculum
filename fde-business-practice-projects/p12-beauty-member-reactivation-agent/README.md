# P12 · 美业：会员运营 Agent

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 美业 / 美容院 | L3 Agent | 240 分钟 | Claude（Projects）+ n8n + Google Sheets / Gmail / Slack |

## 1. 客户场景

悦颜美学是布里斯班 Sunnybank 的一家美容院，做面部护理、睫毛、眉形和美甲，会员三十来位，很多人卡里还有预充值。店长 Coco 知道有不少老会员两三个月没来了，但每次想做回访，都要在会员表里一行行翻：谁多久没来、喜欢做什么、卡里还剩多少钱，再一条条手打短信。一忙就拖到下个月。更让她紧张的是：去年有个店员把推广短信发给了一位明确说过「别再发」的客人，客人直接在点评网站上留了差评。

她想要的是：**每周一自动找出久没来的会员，按每个人的喜好起草一条邀约；该跳过的人（退订、不打扰、刚联系过、有投诉没处理完）一个都不碰；她在手机上看一遍、点批准，才发出去。**

## 2. 练习数据

全部是练习数据：会员姓名、电话、邮箱都是编的；活动和规则是教学假设。

| 文件 | 内容 |
|---|---|
| `data/members.csv` | 32 条会员档案 |
| `data/offers-2026-11.md` | 店长确认过的 11 月回店活动（OF-1 到 OF-3）和发信规则 |

`members.csv` 字段：

| 字段 | 含义 |
|---|---|
| member_id / name / phone / email | 会员编号、姓名、电话、邮箱 |
| preferred_channel | 偏好渠道：sms / email / wechat |
| tier / prepaid_balance | 卡级（银卡 / 金卡）、卡内余额（澳元） |
| last_visit_date | 最后到店日期 |
| favourite_service / visits_12m | 最常做的项目、近 12 个月到店次数 |
| marketing_consent | 是否同意接收推广（yes 才能发） |
| unsubscribed_at | 退订日期，有值就是已退订 |
| do_not_disturb | 是否标了不打扰 |
| last_contacted_at | 上次推广联系日期 |
| open_issue / staff_note | 是否有未处理的问题、店员备注 |

运行日期按 **2026-11-11** 算。规则（教学假设）：最后到店 ≥ 60 天算久未到店；30 天内联系过的不再联系。

数据里**故意藏了 5 类问题**：

1. **已退订的会员**：M1007 九十多天没来，但 9 月已经退订。
2. **标了不打扰**：M1013 130 天没来，备注写「本人要求不要发任何推广」。
3. **重复档案**：M1004 和 M1021 是同一个人（同一电话）。只看 M1004 是 110 天没来，合并后她 18 天前刚来过——不该发。
4. **日期错误**：M1026 的最后到店日期是 2026-12-03，在未来。
5. **有投诉没处理完**：M1018 75 天没来，备注写着上次护理后脸部发红、投诉未处理。这时候发推广只会火上浇油，要转给店长亲自联系。

另外还有两个规则要卡住的情况：M1010 没有营销同意，M1029 12 天前刚联系过。M1015 备注里写了孕期——她符合邀约条件，但邀约里一个字都不能提。

教学假设：澳洲的 Spam Act 要求商业电子信息要有对方同意、写明发送方、带可用的退订方式；会员健康相关信息属于敏感信息，按隐私原则不能用在推广里。以官方信息和法律意见为准。

## 3. 做法

**第一步：先用 Claude 把规则和写法跑通。** 建 Project「悦颜会员回访」，上传 `offers-2026-11.md`，把下面的系统提示词放进项目说明，再上传 `members.csv`，说：「按今天 2026-11-11 出本周回访清单和草稿。」跟 `expected/decisions.csv` 对：32 行的状态必须一致，草稿至少满足验收清单里的每一条。

**第二步：搭 n8n。** 天数、排除规则、合并重复这些能算的，交给 Code 节点；Agent 只负责写邀约。

### n8n 搭建

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | Schedule Trigger | 每周一 10:00 跑 | Trigger Interval：Weeks；周一；Hour 10 |
| 2 | Google Sheets | 读会员表 | Operation：Get Row(s)，读全表 |
| 3 | Date & Time | 取今天日期 | Operation：Get Current Date；时区 Australia/Brisbane |
| 4 | Code | 算距上次到店天数；按电话合并重复档案（取最近一次到店）；日期为空或在未来标「数据异常」 | 只加字段，不改原始数据 |
| 5 | Switch | 按顺序分流：数据异常 → 店员核对；近期到过 → 结束；已退订 / 不打扰 / 无同意 / 30 天内联系过 → 结束；有未处理投诉 → 店长；其余 → 起草 | 规则顺序就是 README 第 2 节的顺序 |
| 6 | Slack | 「数据异常」和「有未处理投诉」推给店长，附原因和备注 | Channel：#前台；不发给会员 |
| 7 | Limit | 每周最多起草 20 条，防止一次群发太多 | Max Items：20 |
| 8 | AI Agent | 给每位会员写一条邀约 | 模型：Anthropic Chat Model；System Message 用下面的提示词；Require Specific Output Format 打开 |
| 8a | Anthropic Chat Model | Agent 的模型 | 选 Claude 模型；Temperature 0.5 |
| 8b | Structured Output Parser | 固定输出 | 字段：member_id、channel、offer_id、message |
| 8c | 工具：Notion（或 Google Sheets） | 读本月活动 | 只读；只返回 OF-1 到 OF-3 |
| 8d | 工具：Code Tool | 检查字数、退订语、禁用词 | 不通过就让 Agent 重写一次 |
| 9 | Aggregate | 把所有草稿合成一张审批清单 | All Item Data |
| 10 | Gmail（Send and Wait for Response） | 清单发给店长审批 | Response Type：Free Text 或 Custom Form（每条可勾选「批准 / 不发」） |
| 11 | Split Out | 拆回一条一条 | 只保留店长批准的 |
| 12 | Switch | 按渠道分三路 | sms / email / wechat |
| 13 | HTTP Request | 短信：调用店里签约的短信服务商接口发送 | 接口、鉴权以服务商文档为准；正文末尾必须有「回复 TD 退订」 |
| 14 | Gmail | 邮件：发送 | 正文末尾带退订链接 |
| 15 | Google Sheets | 微信：写入「店员手动发送清单」 | 店员复制发送，不自动加好友、不群发 |
| 16 | Google Sheets | 回写 last_contacted_at、审批人、发送结果 | Operation：Update Row；匹配 member_id |
| 17 | Webhook | 接短信「TD」回复或邮件退订点击，写入 unsubscribed_at | 单独一条小工作流；收到即生效 |

**Agent 的系统提示词：**

```
你是悦颜美学 Sunnybank 店的会员回访助手，只负责起草邀约，不负责发送。你写的每一条都要经过店长批准。

你收到的会员都已经过规则筛选（久未到店、有营销同意、没退订、没标不打扰、30 天内没联系过、没有未处理投诉）。不要自己再加人或删人；如果你觉得某位会员不该收到，在 message 里写「建议不发」并说明原因。

写法：
1. 开头写「【悦颜美学 Sunnybank】」，然后用名字打招呼（不带姓也可以），语气像熟悉的店员，不要像广告。
2. 根据 favourite_service 选活动：面部或身体护理、肩颈按摩用 OF-1；睫毛、眉形、美甲用 OF-2；金卡会员可以再加一句 OF-3。只能用本月活动里的内容，不许自己加折扣、送项目或改有效期。
3. prepaid_balance 大于 0 时，可以提醒一句「卡里还有 $X 余额可以用」；等于 0 就不提。
4. 不写任何功效承诺（去皱、美白、祛痘、根治之类），不提客人的健康、孕期、皮肤问题、投诉或任何店员备注，不说「你很久没来是不是不满意」这类话。
5. 每条不超过 120 个汉字（不算退订语）。
6. 结尾按渠道加退订方式：sms 加「回复 TD 退订」；email 加一行「不想再收到这类邮件：{{unsubscribe_link}}」；wechat 加「不想再收到可以直接告诉我们。」
7. 让客人用回复的方式约时间，不要在消息里写具体预约时段。

输出：member_id、channel、offer_id、message。
```

**Agent 能用的工具：** 读本月活动（Notion 或 Google Sheets，只读）、检查草稿（Code Tool）。它没有发短信、发邮件、改会员表的工具——这些都在店长批准后由普通节点完成。

**Agent 绝对不能做的事：**

- 不经店长批准发出任何消息。
- 给已退订、不打扰、没有营销同意、30 天内联系过的会员起草或发送推广。
- 给有未处理投诉的会员发推广（这类交店长亲自联系）。
- 在消息里使用健康、孕期、皮肤问题等档案备注，或写功效承诺。
- 自己编活动、加折扣，或修改会员档案。

> 用 ChatGPT 也可以：把 AI Agent 的模型换成 OpenAI Chat Model，提示词、工具和审批节点不变。
