# P37 · 通用：会议录音 → 纪要 → 待办表

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 通用 | L1 自动化 | 45 分钟 | Claude（Projects）+ Excel / Google Sheets |

## 1. 客户场景

拾光家居是墨尔本 Richmond 一家做家具进口和网店的小公司，五六个人。每周二上午开周会，一半人在办公室、一半人在 Zoom 上，Zoom 自动出一份转写稿。行政林晓负责写纪要：她要从三十多句口语里挑出「定了什么」「谁做什么、什么时候做完」，再发到群里。问题是转写稿里都是「周五前」「下周三」「月底」这种说法，她得自己换算成日期；有的事老板问了一句「谁有空弄一下」就过去了，最后谁也没做；还有同事说「这段别记」，她偶尔忘了删，差点把不该外传的话发进全员群。

她想要的是：**会一开完就把转写稿丢进去，十分钟拿到一份能直接发的纪要和一张待办表，没人认领的事、日期说不清的事单独标出来让老板定。**

## 2. 练习数据

`data/meeting-2026-11-10-transcript.txt`：一次周会的自动转写，开头 4 行是会议信息，后面 33 句发言（练习数据，公司、人名、客户名都是为这个练习设计的）。

| 内容 | 说明 |
|---|---|
| 会议信息 | 日期 2026-11-10（周二）、地点、参会 5 人、记录人 |
| 每句发言 | `[时间] 发言人：内容`，例如 `[10:03:44] 周婷：李强，你周五前把那批全部清点完……` |

数据里**故意藏了 4 类问题**，真实会议里天天有：

1. **没人认领的待办**：官网 FAQ 退货政策要改，老板问「谁有空弄一下」，没人接话就换了话题。
2. **截止日期冲突**：面料样品，销售说「这周五前寄」，老板后来转述客户说「下周二前寄出就行」，会上没定。
3. **不能进纪要的私下话**：有人说「这个别记进纪要啊」，接着说了客户那边的人事传闻，老板也说这段不记。
4. **讨论了但没决定**：要不要换快递公司，「之后再看」，不能写成待办。

另外：所有日期都是口头说法，要按规则换成具体日期；保险能不能赔要以保险公司的书面答复为准，纪要里不能替人下结论。

## 3. 做法

**第一步：在 Claude 里建一个 Project。** 名字叫「拾光家居 周会纪要」。项目说明里写清规则，以后每周都用这一份：

```
你是拾光家居的会议纪要助手。我会上传一份周会转写稿（每行 [时间] 发言人：内容）。
请按下面规则输出：
1. 先找「不记录」的段落：有人说「别记」「不记」「私下说」，从这句开始到话题回到正事为止，整段不进纪要，
   也不要在纪要里暗示或概括这段内容。只在最后告诉我「第 x–y 句按要求未记录」。
2. 决定：只写会上明确拍板的（「就这么定」「同意」「先别卖了」）。「之后再看」「再说吧」放进「未决定」。
3. 待办：每条写 事项 / 负责人 / 截止日期 / 原文出处（第几句）。
   - 负责人必须是会上有人明确接下或被点名的；没人认领，负责人写「待指派」，不要猜。
   - 日期换算规则：会议日 2026-11-10（周二）。「周X / 这周X」= 会议所在那一周（周一开始）的周X；
     「下周X」= 下一周的周X；「明天」= 会议日 + 1；「月底」= 当月最后一天。换算后写成 2026-11-13（周五）这种格式。
   - 同一件事出现两个不同的截止日期、会上没定下来：两个都写上，状态写「待确认」，不要替他们选。
4. 涉及保险、法律、合同能不能、该不该的，只记「去问谁、要什么答复」，不写结论。
5. 输出三块：① 可以直接发群的纪要（Markdown）；② 待办表 CSV（id,task,owner,due_date,status,source_lines,note）；
   ③ 给记录人看的「需要老板定的事」清单。
```

**第二步：上传转写稿，发一句：**「出 11 月 10 日周会的纪要和待办表。」

**第三步：核对。** 用第 5 节逐条对。最容易错的两处：周五是 11-13 不是 11-14（会议日是周二）；私下那段不光要删，连「有客户可能换供应商」这种概括也不能出现。

**第四步：发出去之前给人看一眼。** 纪要由林晓确认后再发群；「待指派」「待确认」两条单独私信老板周婷，让她拍板后再补进待办表。待办表 CSV 粘进团队的 Google Sheets，每周会前按「截止日期」排序看一遍。

> 用 ChatGPT 也可以：建一个 Project（或自定义 GPT），把同样的规则放进说明，上传转写稿即可。

## 4. 应该做出的结果

`expected/answer.json` 是标准答案（日期按规则由脚本换算），`expected/action-items.csv` 是待办表，`expected/minutes.md` 是纪要的参考写法。

转写稿 33 句，参会 5 人；决定 2 条，待办 6 条（4 条正常、2 条要老板定），未决定 1 条，第 27–29 句不记录。

| # | 事项 | 负责人 | 截止 | 状态 |
|---|---|---|---|---|
| A1 | 清点受潮的橡木餐椅，每箱拍照发群 | 李强 | 2026-11-13（周五） | ok |
| A2 | 联系保险公司问能否理赔，要书面回复 | 林晓 | 2026-11-12（周四） | ok |

- 决定：D1 受潮餐椅暂停销售、网店下架；D2 黑五全场 85 折，沙发和床架不参加。

- 纪要里不能出现 Kevin、跳槽、换供应商这几个词。

## 5. 验收清单

- [ ] 待办 6 条，每条都有原文出处；日期跟上表一致（特别是周五 = 11-13）。
- [ ] A5 的负责人是「待指派」，不是随便塞给某个人。
- [ ] A6 两个日期都列出来、标了「待确认」，没有替他们二选一。
- [ ] 第 27–29 句的内容在纪要里一个字都没有，连概括都没有。
- [ ] 「换快递公司」在「未决定」里，不在待办里；保险那条只写去问，没写能赔或不能赔。

## 6. 加分挑战

- 再给 Claude 一份上周的待办表，让它对照这周的转写稿，标出上周哪些事有人汇报了进展、哪些没人提。
- 让它给每位负责人各写一条私信版的待办提醒（只含他自己的事），看看是否没把别人的事和私下内容带进去。
- 把规则搬进 n8n：Google Drive 新转写稿 → Basic LLM Chain 出纪要 → Slack · Send and Wait for Response 让林晓确认后再发群。

## 7. 简历 / 面试可以这样讲

> 为一家小型进口家具公司设计周会纪要流程：用 Claude Project 固化规则，从自动转写稿里提取决定、待办和未决事项，把口头日期按统一规则换算成具体日期；没人认领的待办、互相冲突的截止日期单独列给负责人拍板，标注「不记录」的段落整段排除，纪要经记录人确认后才发出（教学项目，公司和会议内容都是为练习设计的）。
