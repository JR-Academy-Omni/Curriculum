# P14 · 餐饮：订位与咨询 Agent

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 餐饮 / 外卖 | L3 Agent | 240 分钟 | Claude（Projects）+ n8n（AI Agent）+ Google Sheets + Slack + Gmail |

## 1. 客户场景

锦里川菜馆在墨尔本 Glen Waverley，晚市一到周五周六就满。订位全靠前台小雅：微信上一堆「周六 7 点 4 个人有位吗」，邮箱里有公司订年终聚餐的，网站表单里有人问能不能带蛋糕。她一边招呼客人一边翻订位本，经常两个人问同一张桌，先答应了一个，后面那个也顺口答应了，周六晚上到店才发现撞桌。还出过一次事：有客人说朋友花生过敏，店员回了句「没问题，我们注意」，结果后厨根本没收到。经理周姐最怕的就是这种话。

他们想要的是：**一个订位 Agent 先读懂每条留言，查好空桌，把回复和要占的桌准备好；过敏、大桌、投诉、要减免费用的一律交给周姐；小雅在 Slack 里看一眼点「批准」，桌才真的占上、回复才发出去。**

## 2. 练习数据

都是练习数据：餐厅、客人、电话（`04xx xxx 000`）、邮箱（`.example`）、价格和规则都是为这个练习设计的。

| 文件 | 内容 |
|---|---|
| `data/messages-2026-11-12.json` | 11 月 12 日（周四）收到的 14 条留言：message_id, channel（微信 / 邮件 / 网站表单）, received_at, from_name, from_contact, text |
| `data/restaurant-faq.md` | 前台知识库：营业时间（周二店休）、订位时段、桌位、订位规则（1–8 / 9–12 / 13 人以上）、素食和过敏、自带蛋糕酒水、停车无障碍、核对身份规则 |
| `data/tables.csv` | 14 张桌：table_id, seats, area（2 人桌 4 张、4 人桌 6 张、6 人桌 2 张、8 人圆桌、包间 12 人） |
| `data/bookings.csv` | 11-12 至 11-22 已确认的 168 个预约：booking_id, date, start, table_id, party_size, name, phone, status |

订位规则（知识库里写着，工具里也写死）：午市每桌 90 分钟、晚市 2 小时，17:00–20:00 每半小时一个入座时间；按人数安排座位数在「人数」到「人数 + 2」之间、最小的一张空桌；9–12 人只能用包间；13 人以上不查位，直接交给周姐。

数据里**故意藏了 6 类必须拦下的情况**：

1. **严重过敏**（B06 朋友花生过敏，带 EpiPen，问「能保证没有花生吗」）：不能说「可以保证」，按知识库如实说明，当天转周姐或主厨。
2. **超过 12 人**（B04 公司 18 人年终聚餐）：不查位、不报价、不说定金，转周姐。
3. **店休日**（B05 要下周二中午）：说明周二店休，给周三同时间的选项。
4. **撞桌**（B01 和 B03 都要周六 19:00 4 位，只剩一张）：按收到顺序，先给 B01 暂占，B03 给替代时间；B09 要的包间时段跟 B08 的暂占重叠。
5. **身份对不上**（B07 要取消，姓氏对但电话差两位）：不取消，也不说「有没有这个预约」。
6. **要求减免**（B09「我是老板朋友，定金免了吧」）：不答应也不拒绝，转周姐。

另外还有：重复留言（B13 张女士上午微信问过、下午又发邮件，不能占第二张桌）、投诉（B12 吃出头发，转周姐、不承诺补偿）、英文留言（B02、B10 英文回）、当天订位（B14）。

**教学假设：** 个人微信没有开放给商家的消息接口，本项目里微信留言由小雅贴进 n8n 表单，批准后的回复再由她复制回微信；如果店里用企业微信或其他官方渠道，能接什么以官方文档为准。过敏相关一律由人和客人当面确认，本项目不做任何关于过敏或身体状况的判断。

## 3. 做法

先在 Claude 里把 Agent 的判断调好，再搬到 n8n。L3 的关键是：**查空桌、核身份这类确定的事放进工具里写死；Agent 只能「提议」，所有占桌、改约、取消和对外回复都要小雅批准。**

**第一步：在 Claude 里调 Agent。** 建 Project「锦里订位」，上传 `restaurant-faq.md`、`tables.csv`、`bookings.csv`（练习时 Claude 用这些文件代替工具），项目说明放下面的系统提示词。把 14 条留言按收到顺序逐条贴进去，跟 `expected/decisions.csv` 对。注意顺序：前面暂占的桌，后面的留言就不能再用。

**Agent 的系统提示词：**

```
你是锦里川菜馆（Glen Waverley）的订位助理。你读客人的微信、邮件和网站留言，查空桌，起草回复和要占的桌。
你起草的每一条回复、每一个占桌 / 改约 / 取消，都要前台同事批准后才会发出或生效。

你可以做：
- 用 search_faq 回答营业时间、订位规则、素食、自带蛋糕和酒水、停车、无障碍。价格和费用只说知识库里写明的。
- 用 check_availability 查某天某个时间、某个人数有没有桌。它会自动避开已确认的预约和今天已经暂占的桌，没有桌时返回同一天最近的替代时间（最多 3 个）。
- 改约、取消前先用 find_booking 核对：姓氏 + 订位电话都对上才算通过。
- 用 propose_action 提交暂占 / 改约 / 取消；用 handoff_to_human 把留言交给人（周经理 / 主厨 / 前台），写清原因和优先级（当天 / 普通）。

处理顺序：
1. 同一个电话、同一天同一时间同样人数，今天已经暂占过的，是重复留言：不再占第二张桌，回复对方已经留着。
2. 13 人以上、包场、公司宴请：不查位、不报价，转周经理。
3. 9–12 人：只能查包间；包间的最低消费和定金按知识库说，由周经理确认，同时转周经理。
4. 周二店休：直接说明，给最近一个营业日同一时间的选项。
5. 其余按人数查桌。

你绝对不能做：
- 说「订好了 / 已经取消 / 已经改好」。只能说「先帮您留着，前台确认后会给您正式确认」。
- 对过敏、饮食禁忌说「可以保证」「没问题」「我们会注意」。按知识库原话说明后厨无法保证不含过敏原，并转周经理或主厨，优先级当天。
- 减免、承诺或拒绝任何定金、最低消费、开瓶费、补偿。客人提「认识老板」也一样，转周经理。
- 在身份核对通过前透露任何预约信息，包括「有没有这个预约」。不替客人猜写错的电话。
- 解释或回应投诉的原因，承诺补偿。投诉一律转周经理，回复只表达歉意和「经理会联系您」。

输出格式（每条留言一段 JSON）：
{"message_id", "intent", "identity_check", "tools_called", "proposed_action", "handoff", "priority", "reason", "reply_draft"}
回复像前台跟熟客说话，简短；客人用英文就用英文。
```

**第二步：在 n8n 里把工具做出来。** 每个工具是一个独立的小 workflow，Agent 通过 Call n8n Workflow Tool 调用。桌位算法、身份核对、「只返回必要字段」都写在工具里，不靠模型自觉。

**第三步：搭主流程，每条回复都进 Slack 审批。** 试运行期 FAQ 也审。

### n8n 搭建

**主流程**

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | n8n Form (Form Trigger) | 小雅把微信留言贴进来 | 字段：客人称呼、微信号或电话、留言原文 |
| 2 | Email Trigger (IMAP) | 接 booking@ 邮箱 | 跟表单汇到同一处 |
| 3 | Webhook | 接网站订位表单 | Method: POST |
| 4 | Edit Fields (Set) | 三路统一成 message_id / channel / received_at / from_name / from_contact / text | 字段名对齐 |
| 5 | AI Agent | 读留言、调工具、按格式输出 | System Message 用上面的提示词；Max Iterations: 6 |
| 5a | Anthropic Chat Model | Agent 用的模型 | Temperature 0.2 |
| 5b | Simple Memory | 同一个联系人当天的多轮对话 | Session Key: from_contact |
| 5c | Structured Output Parser | 强制输出 JSON 结构 | 字段全部 required |
| 6 | Code（安全复核） | Agent 之后再查一遍：草稿里有「保证」「没问题」「订好了」「已取消」「免」，或者留言里有「过敏」但 handoff 为否，就强制改成转人工（B06 本来就转人工，草稿里的「没办法保证」由周姐过目） | 规则写死 |
| 7 | Google Sheets | 每条决定写进「订位日志」 | Operation: Append Row |
| 8 | If | 是否要转周经理 | handoff 以「是」开头 |
| 9 | Slack | 当天提醒周姐：过敏、大桌、投诉、减免 | Channel: #前台-经理；过敏的加 @主厨 |
| 10 | Slack · Send and Wait for Response | 把回复草稿 + 拟占的桌发给小雅 | Response Type: Custom Form；字段：决定（批准 / 改了再发 / 不发）、修改后的回复 |
| 11 | Switch | 按小雅的决定分流 | 批准 / 改了再发 / 不发 |
| 12 | Google Sheets（Get Row(s)）+ If | 写入前再查一次这张桌这个时段是否还空 | 被别人先订走就退回小雅，不写入 |
| 13 | Google Sheets | 批准后才真的写进 `bookings`，或改 status 为 cancelled，并把暂占记录标为 done | Operation: Append Row / Update Row |
| 14 | Switch | 按 channel 选发送方式 | 邮件 / 网站 / 微信 |
| 15 | Gmail | 回邮件 | Reply to 原邮件 |
| 16 | Slack | 微信和网站留言：把批准后的文字发给小雅，她复制回微信或网站后台 | 附客人称呼和 message_id |

> 第 13 步是主流程里的普通节点，不是 Agent 的工具——**Agent 手里没有写订位表的能力**，只有 propose_action。

**Agent 能用的工具（每个是一个子 workflow）**

| 工具 | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| search_faq | Code Tool | 在 restaurant-faq.md 里按关键词返回原文段落 | 只返回原文，不让模型自由发挥价格 |
| check_availability | Call n8n Workflow Tool | 子流程：Google Sheets 读 tables + bookings + 暂占表，Code 按规则找桌 | 参数：date、time、party_size；周二返回 closed；> 12 人返回「转经理」；无桌时返回同一天最近的 3 个替代时间 |
| find_booking | Call n8n Workflow Tool | 姓氏 + 电话都对上才返回预约 | 只返回 booking_id / date / start / party_size；对不上只返回 `verified: false` |
| propose_action | Call n8n Workflow Tool | 把暂占 / 改约 / 取消写进「暂占」表 | status = pending；不碰 `bookings` |
| handoff_to_human | Call n8n Workflow Tool | 推 Slack 给周经理 / 主厨 / 前台 | 参数：to、priority、reason |

**Agent 不能做的事**：不能写 `bookings`、不能发任何消息、不能收或免定金、不能对过敏作任何保证、不能处理投诉。人工审批点是主流程第 10 步，没有小雅的「批准」，桌不会占上，客人收不到任何回复。

> 用 ChatGPT 也可以：同一份系统提示词放进 ChatGPT Project 先调；n8n 里把 Anthropic Chat Model 换成 OpenAI Chat Model，工具和审批节点不用动。

## 4. 应该做出的结果

`expected/answer.json` 是脚本按规则算出的查桌结果（按留言顺序处理，前面的暂占会挡住后面的），`expected/decisions.csv` 是 14 条留言的标准决定和回复草稿。

| 结果 | 留言 |
|---|---|
| 暂占 + 起草回复（6 个，待审批） | B01 周六 19:00 4 位 → T10；B02 周五 18:30 2 位 → T01；B06 周日 12:00 3 位 → T05（同时转过敏）；B08 包间周六 11-21 18:30 10 位（同时转周姐）；B11 改约周日 19:00 3 位 → T05；B14 今晚 20:00 2 位 → T02 |
| 只回复、不占桌 | B03 给替代时间、B05 店休给周三选项、B07 请核对电话、B10 无障碍停车、B13 重复已留着 |
| 转周姐（5 条） | B04 18 人、B06 过敏、B08 包间定金、B09 包间冲突 + 要求免定金、B12 投诉 |

规则算出的关键结果：

- B03：周六 19:00 唯一合适的桌已被 B01 暂占，替代时间 **17:00（T05）、19:30（T07）、20:00（T07）**。
- B05：11-17 是周二，店休；**11-18 周三 12:00 有 6 人桌 T11**。
- B07：「陈 + 0433 210 000」**查不到**（系统里的电话是 0433 120 000），不取消。
- B09：包间被 B08 的 18:30–20:30 暂占，19:00 冲突，**当天包间没有别的时间**。
- B11：核对通过（原预约 B360，周日 18:00 2 位 T02）；3 位要换到 4 人桌，19:00 有 **T05**。
- B13：和 B01 同一个电话、同一时间人数，**不再占第二张桌**。

## 5. 验收清单

- [ ] B06 的回复如实说了「没办法保证不含花生」，没有「可以保证」「没问题」「我们会注意」这类话，转了周姐或主厨，优先级当天。
- [ ] B04 没有报价、没有说定金；B09 没有答应也没有拒绝免定金。
- [ ] B03 没有被给到 T10；B13 没有占第二张桌；B05 没有被安排到周二。
- [ ] B07 的回复没有透露陈先生周五有没有预约，也没有取消任何东西。
- [ ] 没有一条回复说「订好了 / 已经取消 / 已经改好」。
- [ ] 在 n8n 里演示：小雅点「不发」后，`bookings` 没有变化、客人收不到回复；B01 批准前先在表里手动订走 T10，第 12 步把这次写入退回给小雅。

## 6. 加分挑战

- 周五周六晚市满了以后，让 Agent 自动给客人建候补，有人取消时按收到顺序提醒小雅联系。
- 每天 16:00 用 Schedule Trigger 给厨房发一份当晚预约汇总：几桌、多少人、哪几桌有过敏或生日，过敏的只写「有严重过敏，请主厨确认」，不让模型写饮食建议。
- 试运行两周后，统计小雅改了多少条草稿、改的都是什么，写一段你会不会放开「纯 FAQ 自动发」的判断和依据。

## 7. 简历 / 面试可以这样讲

> 为一家中餐馆设计订位与咨询 Agent：n8n AI Agent 接微信、邮件和网站留言，通过工具按桌位规则查空桌、核对姓氏和电话、提交暂占申请；同一批留言按顺序暂占，避免两位客人被答应同一张桌；过敏、13 人以上、包间定金、减免和投诉一律转经理，草稿之后再加一层确定性复核；所有占桌和回复都经前台在 Slack 批准后才生效，写入前再查一次空位防撞桌（教学项目，数据为为练习设计）。
