# P01 · 餐饮：外卖订单汇总成每日销售日报

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 餐饮 / 外卖 | L1 自动化 | 45 分钟 | Claude（Projects）+ Excel / Google Sheets |

## 1. 客户场景

明月小馆是悉尼 Chatswood 的一家中餐馆，同时在 Uber Eats、DoorDash、Menulog 三个平台接外卖。老板陈姐每天打烊后，要把三个平台的订单导出来，在 Excel 里一张张对：今天卖了多少、哪个平台抽成最多、哪些菜卖得好、哪个时段最忙。她一个人对，常常对到半夜，还经常把取消的单、重复导出的单也算进去。

她想要的是：**每天打烊后，把三份导出丢进去，十分钟拿到一份对得上的日报。**

## 2. 练习数据

`data/orders-2026-11-10.csv`：三个平台一天的订单合并导出，共 79 行（练习数据，店名、订单号都是为这个练习设计的）。

| 字段 | 含义 |
|---|---|
| platform | 平台：Uber Eats / DoorDash / Menulog |
| order_id | 订单号 |
| order_time | 下单时间 |
| items | 菜品和数量，如「牛肉面 x2; 酸辣汤 x1」 |
| subtotal | 菜品小计（澳元） |
| discount | 平台活动折扣（澳元） |
| status | completed / cancelled / refunded |

数据里**故意藏了 4 处问题**，真实导出也常见：取消的单、退款的单、同一单被导出了两次、有一单金额是空的。日报必须把它们拦下来，不能算进收入。

平台抽成按教学假设计算：Uber Eats 30%、DoorDash 28%、Menulog 25%。真实费率以商家和平台签的合同为准。

## 3. 做法

**第一步：在 Claude 里建一个 Project（项目）。** 名字叫「明月小馆日报」。在项目说明（Instructions）里写清规则，以后每天直接用：

```
你是明月小馆的日报助手。我每天会上传一份外卖订单 CSV。请按下面规则出日报：
1. 只统计 status = completed 的订单；cancelled、refunded 不计入收入。
2. 同一个 order_id 出现多次，只算一次。
3. subtotal 为空的订单不计入，列进「需要核对」。
4. 净销售额 = subtotal - discount；平台抽成按 Uber Eats 30%、DoorDash 28%、Menulog 25% 估算；到手 = 净销售额 - 抽成。
5. 输出：① 分平台表（单数、小计、折扣、净销售额、预计抽成、预计到手）和合计；② 销量前 5 的菜（按份数）；③ 最忙的 3 个小时段；④ 需要核对的订单清单（订单号 + 原因）。
6. 所有数字保留两位小数。不确定的地方写出来，不要猜。
```

**第二步：上传 CSV，发一句话：**「出 11 月 10 日的日报。」

**第三步：核对。** 用下面的验收清单逐条对。至少手工抽查一个平台的合计：在 Excel 里筛选 completed、去掉重复订单号，再求和，看跟日报是否一致。

**第四步：做成每天的流程。** 把规则存在 Project 里以后，陈姐每天只要上传当天的导出。也可以让 Claude 同时输出一份 CSV 版的分平台表，粘进她的月度汇总表。

> 用 ChatGPT 也可以：建一个自定义 GPT（或 Project），把同样的规则写进说明，上传 CSV 即可。

## 4. 应该做出的结果

`expected/answer.json` 是标准答案（用脚本按同样规则算出来的）。核心数字：

| 平台 | 单数 | 净销售额 | 预计抽成 | 预计到手 |
|---|---|---|---|---|
| Uber Eats | 33 | 1,164.76 | 349.43 | 815.33 |
| DoorDash | 25 | 901.02 | 252.29 | 648.73 |
| Menulog | 17 | 500.60 | 125.15 | 375.45 |
| **合计** | **75** | **2,566.38** | **726.87** | **1,839.51** |

- 文件共 79 行，计入 75 单，有 4 单进了「需要核对」。
- 销量前 5：蒜蓉炒青菜 28 份、酸辣汤 23 份、扬州炒饭 23 份、牛肉面 21 份、小笼包（6 只）19 份。
- 最忙时段：12 点（21 单）、19 点（12 单）、20 点（11 单）。

## 5. 验收清单

- [ ] 合计计入 75 单，不是 79 单。
- [ ] 取消单、退款单、重复导出、金额为空这 4 处都出现在「需要核对」里，并且写了原因。
- [ ] 分平台净销售额和合计，跟标准答案的差距在 0.01 以内。
- [ ] 抽成是按「净销售额 × 费率」算的，不是按小计。
- [ ] 日报里写明了抽成是估算、真实费率以合同为准。

## 6. 加分挑战

- 加一列「客单价」（净销售额 ÷ 单数），看哪个平台的客人花得多。
- 让 Claude 再写三句给老板的结论，比如「Menulog 抽成最低但单量最少，可以考虑在 Menulog 做一次满减」，并标明哪些是数据、哪些是建议。
- 把第二天的数据也做一份，对比两天的变化。

## 7. 简历 / 面试可以这样讲

> 为一家多平台外卖餐厅设计每日销售日报流程：用 Claude Project 固化统计规则，自动排除取消、退款、重复导出和缺失金额的订单，按平台输出净销售额、抽成估算和到手金额；用手工抽查核对结果，把老板每晚的对账从约一小时缩到十分钟左右（教学项目，时间为场景假设）。
