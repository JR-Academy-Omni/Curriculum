# P19 · 房产 / 物业：看房登记表整理成客户名单

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 房产 / 物业 | L1 自动化 | 45 分钟 | Claude（Projects）+ Excel / Google Sheets |

## 1. 客户场景

嘉禾地产在悉尼 Epping，销售经纪 Sophie 每个周六连着跑三四场 open home。来看房的人扫二维码或者在 iPad 上登记，三场下来四十来条。周一早上她要把这些登记整理进客户名单，再按名单发跟进短信和新盘推送。麻烦在于：同一个人在两场都登记了，一次写 Jenny Zhang、一次写 Jenny Chang，电话一次带 +61 一次不带；有人扫码扫了两次；有人明确没勾「接收营销信息」，上个月还是被群发了一次新盘，对方打电话来投诉；同事 Kevin 去帮忙看场时自己也登了一条，结果收到了公司的跟进短信。

她想要的是：**三场的登记丢进去，十分钟拿到一份干净的客户名单：一人一行，看过哪几套写清楚，哪些人不能发营销标出来，拿不准的单独列出来给她看。**

## 2. 练习数据

都是练习数据，中介公司、房源地址、看房人、电话（`04xx xxx 000` 这种明显不真实的号码）和邮箱（`.example`）都是为这个练习设计的。

| 文件 | 内容 |
|---|---|
| `data/open-home-signins-2026-11-08.csv` | 11 月 8 日（周六）三场看房的登记，共 41 行 |
| `data/properties.csv` | 三套房源：H1 Epping 4 卧独立屋、H2 Eastwood 2 卧公寓、H3 Carlingford 3 卧联排 |
| `data/team-roster.csv` | 公司 3 位同事的姓名、职位、工作邮箱、手机 |

登记表字段：

| 字段 | 含义 |
|---|---|
| row_no | 行号 |
| property_id | 哪一场看房（H1 / H2 / H3） |
| sign_in_time | 登记时间 |
| name | 看房人填的名字（中文、英文、拼音都有） |
| phone / email | 手机、邮箱，格式五花八门，可能只填了一个 |
| buyer_type | 自住 / 投资 / 首次置业 / 邻居 / 其他 |
| how_heard | 从哪里知道这套房 |
| marketing_opt_in | 是否同意接收营销信息：Y / N / 空白 |
| comments | 看房人留的话 |

数据里**故意藏了这几类问题**，真实的登记表每周都会有：

1. **同一个人登记了多次**：拼写不同（Jenny Zhang / Jenny Chang、王磊 / Lei Wang），电话格式不同（`+61 412 506 000` 和 `0412 506 000`），邮箱大小写不同；还有一个人扫码扫了两次。
2. **名字一样但不是同一个人**：李娜和 Li Na 名字对得上，电话和邮箱都不一样，不能因为名字像就合并。
3. **没有联系方式**：有一条只留了个称呼，电话邮箱都空着；还有一条电话只有 6 位数字。
4. **没同意接收营销**：好几个人 `marketing_opt_in` 是 N 或空白，其中一个人第一次勾了 Y、第二次勾了 N。
5. **自己公司的同事**：有一条用的是私人邮箱，但手机号和花名册里的同事一致。

**教学假设**：本练习里，没同意接收营销的人照样进客户名单（他来看过房，Sophie 可以回复他本人主动问的事），但不进新盘推送和任何群发。真实规则以《Spam Act 2003》、隐私法和公司自己的合规要求为准，拿不准就问公司负责合规的人。

## 3. 做法

**第一步：在 Claude 里建一个 Project。** 名字叫「嘉禾看房登记」，把 `team-roster.csv` 和 `properties.csv` 放进项目文件（这两份不常变），项目说明写：

```
你是嘉禾地产的客户名单助手。我每周会上传一份 open home 登记表 CSV。请按下面规则整理：
1. 先规范联系方式：手机号去掉空格和符号，+61 开头改成 0，必须是 04 开头的 10 位数字，否则当作无效电话；邮箱一律转小写。
2. 判断是不是同一个人：规范后的手机号相同，或邮箱相同，就是同一个人，合并成一行。只是名字像、联系方式不同的，不要合并，列进「需要核对」。
3. 合并时：名字用第一次登记的写法，其他写法放进「其他写法」；看过的房源全部列出来。
4. 电话或邮箱出现在 team-roster.csv 里，或者邮箱是 @jiahe-realty.example，是公司同事，不进客户名单。
5. 电话和邮箱都没有（或电话无效又没有邮箱），不进名单，列进「需要核对」。电话无效但有邮箱的，进名单，只留邮箱，并列进「需要核对」。
6. 能不能发营销：这个人所有登记都勾了 Y 才算「是」；只要有一次 N 或空白，就是「否」。
7. 优先级：看了 2 套及以上，或备注提到合同、出价（contract / offer）→ 高；邻居 → 低；其他 → 普通。
8. 输出：① 客户名单表（客户编号、名字、其他写法、手机、邮箱、看过的房源、买家类型、能否发营销、优先级、备注），也给一份 CSV；② 需要核对清单（行号、名字、问题、建议怎么处理）；③ 一行数字小结：原始行数、客户数、合并掉几行、排除几行、能发营销几人。
不确定的写出来，不要猜；不要替我起草任何营销短信。
```

**第二步：上传当周的登记表，发一句：**「整理 11 月 8 日三场 open home 的客户名单。」

**第三步：核对。** 用第 5 节的清单逐条对。至少手工抽查两处：在 Excel 里按手机号排序，看合并的那几行对不对；再筛 `marketing_opt_in` 不是 Y 的行，看这些人在名单里是不是都标了「否」。

**第四步：变成每周的流程。** 规则存在 Project 里以后，Sophie 每周一只要上传新的登记表。导出的 CSV 先粘进她的客户表；发新盘推送前，用「能否发营销 = 是」筛一遍再发。

> 用 ChatGPT 也可以：建一个 ChatGPT Project 或自定义 GPT，把同样的规则和花名册放进去，上传 CSV 即可。

## 4. 应该做出的结果

`expected/answer.json` 是脚本按同样规则算出来的标准答案，`expected/client-list.csv` 是整理好的客户名单，`expected/decisions.csv` 是 41 行登记每一行的处理结论。

| 项目 | 数字 |
|---|---|
| 原始登记 | 41 行（H1 15 行、H2 14 行、H3 12 行） |
| 客户名单 | **36 人** |
| 合并掉的重复登记 | 3 行（Jenny Chang → C05 Jenny Zhang；Lei Wang → C09 王磊；Michael Tran 第二次扫码 → C18） |
| 排除 | 2 行（Mr Zhou 没有联系方式；Kevin L 是公司同事） |
| 能发营销 | 26 人；**不能发 10 人**：C02、C04、C05、C12、C15、C21、C23、C28、C29、C33 |
| 优先级高 | C05 Jenny Zhang（看了 H1 和 H3，想要合同）、C09 王磊（看了 H1 和 H2）、C15 Peter Nguyen（问合同） |
| 优先级低 | C33 陈阿姨（邻居） |

需要 Sophie 核对的 4 条：

| 行号 | 名字 | 问题 | 怎么处理 |
|---|---|---|---|
| 24 | Mr Zhou | 没有联系方式 | 不进名单，请 Sophie 回忆是否认识 |
| 27 | Kevin L | 公司同事（手机和 Kevin Liu 一致） | 不进名单，不发任何跟进 |
| 36 | Amanda Kerr | 电话 `0412 33` 位数不对 | 进名单，只用邮箱联系 |
| 31 | Li Na | 和 C11 李娜同名，但电话邮箱都不同 | 按规则不合并，请 Sophie 看一眼 |

注意 C05 Jenny Zhang：她第一次登记勾了 Y，第二次（写成 Jenny Chang）勾了 N，合并后按规则是「不能发营销」。她又是优先级最高的客户之一，所以 Sophie 可以回复她问的合同，但不能把她放进新盘推送。

## 5. 验收清单

- [ ] 名单是 36 人，不是 41 行，也不是只按名字去重后的数字。
- [ ] Jenny Zhang / Jenny Chang、王磊 / Lei Wang、两次 Michael Tran 各合并成一行；李娜和 Li Na 是两个人，并且出现在「需要核对」里。
- [ ] Kevin L 不在客户名单里，原因写的是「公司同事」。
- [ ] Mr Zhou 不在名单里；Amanda Kerr 在名单里但没有电话。
- [ ] 10 个「不能发营销」的人都标了「否」，包括合并后的 C05。
- [ ] 手机号全部是 04 开头 10 位的统一格式，邮箱全部小写。

## 6. 加分挑战

- 让 Claude 再按优先级给 Sophie 写一份周一跟进顺序：先联系谁、为什么，只写给她自己看，不起草群发。
- 拿下一周的登记表再跑一次，并把这周的客户名单也上传，让 Claude 判断哪些是「老客户又来看了」，在名单里加一列「第几次来看房」。
- 把规则改成先在 Google Sheets 里用公式规范手机号（`REGEXREPLACE`），再交给 Claude 去重，比较两种做法哪种更容易被同事接手。

## 7. 简历 / 面试可以这样讲

> 为一家房产中介把每周 open home 登记表整理成客户名单：用 Claude Project 固化规则，统一手机号和邮箱格式后按联系方式去重（不按名字），合并同一人的多次登记并保留看过的房源；自动排除公司同事和没有联系方式的登记，对没同意接收营销的人统一标记、不进群发；同名不同联系方式的情况列给经纪人确认（教学项目，数据为练习设计）。
