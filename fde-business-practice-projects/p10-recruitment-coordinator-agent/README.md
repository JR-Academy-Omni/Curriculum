# P10 · 招聘 / 人力外包：招聘协调 Agent

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 招聘 / 人力外包 | L3 Agent | 240 分钟 | Claude（Projects）+ n8n + Google Sheets / Gmail / Google Calendar |

## 1. 客户场景

桥联人力在墨尔本东南区，帮仓库、餐馆、会计事务所这些中小客户招人，两个顾问手上常年同时挂着十来个岗位。现在的做法是：顾问 Joyce 每天早上打开邮箱看新简历，对着岗位要求一份份看，再跟候选人和客户主管三方来回发邮件约时间，面试完还要追面试官要反馈、整理成一段话发给客户。最花时间的是约时间和追反馈；最怕的是两件事：一是新同事照着客户随口一句「最好要年轻男生」去筛人，二是拒信、录用通知没看清楚就发出去了。

她想要的是：**一个 Agent 每天先把新投递按岗位必备条件过一遍、把能约的面试时间排好、把面试反馈汇总好；所有要发给候选人的邮件，都先停在她这里点「批准」才发。**

## 2. 练习数据

全部是练习数据：客户、候选人、电话、邮箱都是编的，岗位要求和工时为教学假设。

| 文件 | 内容 |
|---|---|
| `data/job-orders.json` | 3 个岗位：JO-01 仓库拣货员、JO-02 中餐炒锅厨师、JO-03 行政助理。含必备条件、加分项、工时、面试官、客户备注 |
| `data/applications.csv` | 12 份投递：编号、姓名、邮箱、电话、岗位、投递时间、简历文件 |
| `data/resumes/A01.txt` … `A12.txt` | 简历正文（纯文本） |
| `data/candidate-availability.csv` | 候选人可面试时间段 |
| `data/interviewer-slots.csv` | 面试官下周（11 月 16–20 日）的 30 分钟空档 |
| `data/interview-feedback.csv` | 上一轮 5 位候选人（B01–B05）的面试反馈，每人应有 2 位面试官打分 |

数据里**故意藏了 5 类问题**：

1. **歧视性要求和无关个人信息**：JO-01 客户备注写「最好还是要 35 岁以下的男生」；好几份简历里写了性别、年龄、婚姻、出生年份、国籍、孩子。这些都不能参与判断。
2. **重复投递**：A10 和 A12 是同一个人（同一电话、不同邮箱）。
3. **工作权利需要人工确认**：A04 是学生签证，岗位每周约 38 小时。（A07 是 485 签证、工作无限制，属于合法工作权利，不能被筛掉——这是反过来的陷阱。）
4. **没有共同面试时间**：A11 条件都符合，但只能晚上面试，面试官没有晚间空档。
5. **面试反馈有问题**：B02 两位面试官意见相反；B04 反馈只收到 1 份；B05 有一条反馈提到口音和年纪。

教学假设：澳洲的反歧视法规不允许以年龄、性别、种族 / 国籍、婚姻、家庭责任、残障等因素做招聘决定；具体适用范围以官方信息和法律意见为准。候选人个人信息按隐私原则只用于本次招聘。

## 3. 做法

先在 Claude 里把判断规则跑通，再搬进 n8n。

**第一步：在 Claude Project 里跑一遍。** 建 Project「桥联招聘协调」，上传 `job-orders.json`，把下面的系统提示词放进项目说明，然后把 12 份简历和两个时间表贴进去，让它输出筛选表；再贴面试反馈，让它输出反馈汇总。跟 `expected/decisions.csv` 对，对不上就改提示词，直到 17 行全部一致。

**第二步：搭 n8n。** 两条工作流：每天早上的「新投递初筛 + 约面试」，和每天下午的「面试反馈汇总」。

### n8n 搭建

工作流 A：新投递初筛 + 约面试

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | Schedule Trigger | 每个工作日 8:30 跑一次 | Trigger Interval：Days；Hour 8，Minute 30 |
| 2 | Google Sheets | 读投递表里 status 为空的行 | Operation：Get Row(s)；Filter：status 为空 |
| 3 | Google Drive | 按 resume_file 下载简历 | Operation：Download |
| 4 | Extract from File | 把简历变成文本 | Operation：Extract From Text File |
| 5 | Code | 按电话号码标出重复投递，保留最早一份 | 只标记 `duplicate_of`，不删行 |
| 6 | If | 重复的走「标记重复」分支，直接回写表格，不进 Agent | 条件：`duplicate_of` 不为空 |
| 7 | AI Agent | 对每份投递按岗位必备条件初筛，并找面试时间 | 模型：Anthropic Chat Model；System Message 用下面的提示词；Require Specific Output Format 打开 |
| 7a | Anthropic Chat Model | Agent 的模型 | 选 Claude 模型；Temperature 0.2 |
| 7b | Structured Output Parser | 固定输出字段 | 字段：application_id、decision、failed_must_have、proposed_slot、needs_human、reason |
| 7c | 工具：Google Sheets | 读岗位表 job-orders | 只读 |
| 7d | 工具：Google Calendar | 查面试官下周空档 | Operation：Get Availability / Get Many，只读 |
| 7e | 工具：Code Tool | 找候选人时间和面试官空档的第一个共同 30 分钟 | 输入两组时间段，输出 slot 或 null |
| 8 | Switch | 按 decision 分三路：约面试 / 不符合 / 转人工 | Rules 按 decision 文字匹配 |
| 9 | Gmail（Send and Wait for Response） | 把邀约或拒信草稿发给顾问审批 | 收件人：顾问邮箱；Response Type：Approval；Approve 和 Disapprove 两个按钮 |
| 10 | If | 顾问是否批准 | 条件：`data.approved` 为 true |
| 11 | Google Calendar | 批准的邀约：建面试日程 | Operation：Create；邀请面试官和候选人 |
| 12 | Gmail | 批准后才发邮件给候选人 | Operation：Send；正文用审批过的草稿 |
| 13 | Slack | 转人工的条目推给顾问，附原因 | Channel：#招聘协调；不发给候选人 |
| 14 | Google Sheets | 回写 status、slot、审批结果、审批人、时间 | Operation：Update Row；匹配 application_id |

工作流 B：面试反馈汇总

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | Schedule Trigger | 每个工作日 16:00 | — |
| 2 | Google Sheets | 读反馈表 | Get Row(s) |
| 3 | Aggregate | 按 candidate_id 把多位面试官的反馈合成一条 | Aggregate：Individual Fields；分组用 Code 也行 |
| 4 | Code | 算平均分、收到几份、意见是否一致 | 应收份数 2；输出 rule_status |
| 5 | Basic LLM Chain | 写给顾问的一段汇总，并检查反馈里有没有无关个人特征 | 模型：Anthropic Chat Model；提示词同下方第 6、7 条 |
| 6 | Switch | 一致录用 / 一致不录用 / 反馈未齐 / 需要人工 | — |
| 7 | Gmail（Send and Wait for Response） | 录用通知草稿、拒信草稿交顾问审批 | Response Type：Approval |
| 8 | Gmail | 反馈未齐：提醒还没交的面试官 | 只发给面试官，不发候选人 |
| 9 | Slack | 意见不一致、含无关特征的条目推给顾问 | — |

**Agent 的系统提示词：**

```
你是桥联人力的招聘协调助手。你只做三件事：按岗位必备条件初筛简历、找面试时间、汇总面试反馈。你写的任何给候选人的邮件都只是草稿，必须交顾问批准。

初筛规则：
1. 只按岗位表里的 must_have 逐条判断，每条写「满足 / 不满足 / 简历没写清」。nice_to_have 只写在理由里，不决定通过与否。
2. 绝对不使用以下信息做判断，也不在理由里提及：年龄、出生年份、性别、婚姻、怀孕、孩子或家庭责任、种族、国籍、口音、宗教、残障、照片外貌。简历里出现了就当没看见。
3. 客户备注里如果有基于上述因素的要求（比如年龄、性别），不执行，单独标「转人工：客户要求不合规」。
4. 工作权利：公民、PR、写明工作无限制的签证 = 满足；学生签证或简历没写清 = 「转人工：工作权利」，不能直接拒。临时签证本身不是拒绝理由。
5. 有任何一条 must_have 明确不满足 = 「不符合」，起草拒信，拒信只写与岗位相关的原因。
6. 全部满足：用 Code Tool 找候选人可面试时间和面试官空档的第一个共同 30 分钟；找到就起草邀约，找不到就「转人工：无共同时间」。
7. 同一电话号码的多份投递只处理最早一份，其余标重复。

反馈汇总规则：
8. 每位候选人应收 2 份反馈。不齐就写「等待」，提醒面试官，不给候选人任何结果。
9. 两份都建议录用：起草录用通知交顾问，不写薪资和合同条款；两份都不录用：起草拒信交顾问；意见不一致：转人工。
10. 反馈里出现第 2 条列出的无关个人特征，把那句话剔出汇总，标「转人工：反馈含无关个人特征」。

输出：每份投递或每位候选人一行，字段为 application_id、decision、failed_must_have、proposed_slot、needs_human、reason。reason 用一两句中文说清楚。
```

**Agent 能用的工具：** 读岗位表（Google Sheets，只读）、查面试官空档（Google Calendar，只读）、找共同时间（Code Tool）。它没有发邮件、建日程、改表格的工具——这些都在审批之后由普通节点完成。

**Agent 绝对不能做的事：**

- 不经顾问批准，给候选人发任何邮件（邀约、拒信、录用通知）或建日程。
- 因为年龄、性别、国籍、口音、家庭、残障等因素筛人或打分，或者执行客户的这类要求。
- 写薪资、合同条款，或向候选人承诺录用。
- 回答签证政策问题，或者因为签证类型直接拒人。
- 修改岗位要求或面试反馈原文。

> 用 ChatGPT 也可以：在 n8n 里把 Anthropic Chat Model 换成 OpenAI Chat Model，提示词和工具不变；先在 Claude Project 里跑通的那一步，也可以换成 ChatGPT 的 Project。

## 6. 加分挑战

- 候选人回复「这个时间不行」时，用 Email Trigger (IMAP) 接住回信，让 Agent 重新找时间，再走一次审批。
- 加一张「人才库」表：拒掉的人按岗位类别存进去，下次有合适岗位先查这张表（注意只存与岗位相关的信息）。
- 每周五自动出一份给客户的进度表：各岗位投递数、面试数、待反馈数。

## 7. 简历 / 面试可以这样讲

> 为一家人力外包公司搭建招聘协调 Agent（n8n + Claude）：按岗位必备条件初筛简历、自动匹配候选人和面试官的共同时间、汇总多位面试官的反馈；所有邀约、拒信和录用通知都经顾问在 Gmail 审批后才发出。设计时明确排除年龄、性别、国籍、家庭等无关因素，客户的不合规要求和工作权利不清的情况自动转人工（教学项目，数据为教学构造）。
