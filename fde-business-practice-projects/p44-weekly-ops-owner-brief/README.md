# P44 · 通用：每周经营数据自动汇总成老板简报

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 通用（14 人的上门清洁公司） | L2 Workflow | 150 分钟 | Claude（Projects）+ n8n + Google Sheets + Slack + Gmail |

## 1. 客户场景

蓝湾清洁在布里斯班 Mount Gravatt，四个清洁小组，做住宅保洁、办公室保洁、退租清洁和地毯清洗。老板黄总每周一想知道上周到底赚没赚钱，但数据散在四个地方：排班软件导出的工单、Xero 的发票、公司卡和收据录的支出、客户回访的评分。行政小林每周一花一上午把它们拼成一张表发给黄总，常常出错：重复开的发票算进了收入，上周的保险费算进了本周，客户投诉被压在一堆五星好评下面，黄总周三才看到。

黄总想要的是：**每周一早上八点前，收到一封一页纸的简报：上周做了多少、收了多少、估算赚了多少、谁欠钱、哪单亏工时、哪条投诉要他亲自处理；数字要对得上，发出前小林看一眼。**

## 2. 练习数据

公司、客户编号、金额都是为这个练习设计的。

| 文件 | 内容 |
|---|---|
| `data/jobs-2026-11-02-to-08.csv` | 一周 41 张工单：job_id, date, customer_id, service_type, crew, hours_booked, hours_actual, price_ex_gst, status |
| `data/invoices-xero-export.csv` | Xero 发票导出 43 行（本周开的 + 之前没收回的）：invoice_no, customer_id, job_id, issue_date, due_date, amount_ex_gst, gst, status（PAID / AUTHORISED / VOIDED） |
| `data/expenses.csv` | 12 条支出：date, category, supplier, amount_ex_gst, note |
| `data/feedback.csv` | 10 条客户反馈：date, customer_id, channel, rating（1–5）, text |
| `data/last-week-summary.json` | 上周的几个关键数字，用来做对比 |

统计周是 **2026-11-02（周一）至 11-08（周日）**，报告日 **2026-11-09**。

数据里**故意藏了 5 类问题**：

1. **重复发票**：同一张工单 J1140 在 Xero 里开了两张发票，只能算一次。
2. **作废发票**：取消的工单 J1118 之前预开过发票，已经 VOIDED，不能算。
3. **做完没开票**：有一单 completed 的工单找不到发票。
4. **支出混进来**：一条耗材是重复录入（收据录过一次、刷卡记录又录一次）；一条保险费是上周的日期。
5. **投诉埋在好评里**：有一条 1 分反馈说清洁时打碎了客户的花瓶、要求赔偿。简报必须放在最前面，交给老板，不能只变成「平均分 4.0」。

另外还有两单固定价的退租清洁工时严重超了。

教学假设：人工成本按每人工小时 38 澳元估算（含 super、保险的粗估），只用于看趋势；真实成本以工资单和会计为准。毛利 = 营业额 − 人工估算 − 本周支出，是管理口径的估算，不是会计报表，也不是报税依据。赔偿和保险理赔以保单和保险公司答复为准，简报不下结论。

## 3. 做法

**统计规则**（先在 Claude 里跑通，再搬进 n8n 的 Code 节点）：

- 营业额 = 本周 status = completed 的 price_ex_gst 合计（按完成算，不按收款算）
- 人工 = completed 工单的 hours_actual 合计 × 38
- 支出：只算日期在本周内的；同供应商、同类别、同金额在本周出现两次的，第二条不算
- 估算毛利 = 营业额 − 人工估算 − 本周支出
- 本周开票：issue_date 在本周、不是 VOIDED、同一 job_id 只算第一张
- 做完没开票 = completed 工单里找不到任何非作废发票的
- 逾期未收：status = AUTHORISED、不是重复发票、due_date 早于报告日
- 超时单：hours_actual ≥ hours_booked × 1.25
- 反馈：平均分；2 分及以下全部原文列出

**第一步：在 Claude 里把规则跑通。** 建 Project「蓝湾周报」，上传 5 个文件，说明里写：

```
你是蓝湾清洁的周报助手。统计周 2026-11-02 至 2026-11-08，报告日 2026-11-09。
先按规则算数，再写简报。规则：
1. 营业额 = status 为 completed 的工单 price_ex_gst 合计；人工成本 = 这些工单 hours_actual 合计 × 38（教学假设）。
2. 支出只算日期在统计周内的；同供应商、同类别、同金额在本周出现两次，第二条不算，并写进「没算进来的支出」。
3. 估算毛利 = 营业额 − 人工成本 − 支出。
4. 发票：VOIDED 不算；同一个 job_id 有两张发票，第二张标为重复；本周开票只算 issue_date 在统计周内的。
5. 找出 completed 但没有任何有效发票的工单。
6. 逾期未收 = AUTHORISED、非重复、due_date 早于报告日；写出客户、金额、逾期天数。
7. hours_actual ≥ hours_booked × 1.25 的工单列为超时。
8. 跟 last-week-summary 对比：完成单数、营业额、毛利、平均分、逾期金额。
简报格式：
- 最上面一段「先看这件事」：2 分及以下的反馈里，涉及损坏、赔偿、安全的，原文要点 + 需要谁处理。不判断该不该赔。
- 然后：本周数字 / 需要处理的账 / 超时的单 / 建议。
- 「建议」和数据分开写，写明是建议。所有金额不含 GST，保留两位小数。不确定就写出来，不要猜。
```

发一句「出上周的周报」，跟第 4 节和 `expected/answer.json` 对。对不上的地方多半是：重复发票算了两次、上周的保险费算进来了、做完没开票那单被漏了。

**第二步：把数据接进 Google Sheets。** 实际用的时候，工单从排班软件、发票从 Xero 每周导出（或用 HTTP Request 调它们的接口，接口和鉴权以各自官方文档为准），练习时直接把 CSV 导进一个表格的四张工作表：`jobs`、`invoices`、`expenses`、`feedback`，再加一张 `weekly_metrics` 存每周结果（下周就从这里读「上周」）。

**第三步：按下面的节点搭 n8n。** 所有数字都由 Code 节点算，Claude 只拿算好的 JSON 写成人话，不让它自己加总。

### n8n 搭建

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | Schedule Trigger | 每周一早上跑 | 每周一 07:00，时区 Australia/Brisbane |
| 2 | Date & Time | 算出统计周的开始和结束日期 | 报告日减 7 天到减 1 天 |
| 3 | Google Sheets（读工单） | 读 `jobs` | Operation: Get Row(s)；加过滤：date 在统计周内 |
| 4 | Google Sheets（读发票） | 读 `invoices` 全部行 | 逾期要看旧发票，所以不按日期过滤 |
| 5 | Google Sheets（读支出） | 读 `expenses` | 先读全部，日期过滤在 Code 里做，这样被排除的能列出来 |
| 6 | Google Sheets（读反馈） | 读 `feedback` | 按日期过滤到统计周 |
| 7 | Google Sheets（读上周） | 从 `weekly_metrics` 取最后一行 | Operation: Get Row(s)，配合 Sort + Limit 1 |
| 8 | Code（算周报数字） | 按第 3 节规则算所有数字，输出一个 JSON：metrics + 要处理的账 + 超时单 + 低分反馈 | Run Once for All Items；用 `$('读工单').all()` 等取各路数据 |
| 9 | If（有没有低分反馈） | 有 2 分及以下的，先单独推一条给黄总和小林 | 条件：`low_ratings` 数量 > 0 |
| 10 | Slack（低分提醒） | 低分原文立刻发到 #客户反馈，@黄总 @小林 | 不等周报，先让人知道 |
| 11 | Basic LLM Chain + Anthropic Chat Model | 把第 8 步的 JSON 写成简报 | 提示词见下；Temperature 0.2 |
| 12 | Slack · Send and Wait for Response（小林核对） | 简报 + 关键数字表发给小林，选「发送 / 改了再发 / 先不发」 | Response Type: Custom Form；字段：决定、修改后的正文 |
| 13 | Switch | 按小林的决定分流 | 发送 / 改了再发 → 第 14 步；先不发 → 结束并记录 |
| 14 | Gmail | 把简报发给黄总 | Subject：「蓝湾周报 11-02 至 11-08」；正文用小林确认的版本 |
| 15 | Google Sheets（写 weekly_metrics） | 把本周数字存一行，下周对比用 | Operation: Append Row |

人工审批点：第 12 步。小林没点发送，黄总收不到简报。第 10 步的低分提醒是内部通知，不发给客户。

第 11 步的提示词：

```
你在帮蓝湾清洁写给老板黄总的周报。下面的 JSON 是已经算好的数字，你只负责写成一页纸。
要求：
1. 第一段「先看这件事」：low_ratings 里涉及损坏、赔偿、安全的，写要点和谁要处理。不说该不该赔，不估赔多少。
2. 然后四块：本周数字 / 需要处理的账（没开票、重复发票、没算进来的支出）/ 超时的单 / 建议。
3. 数字一律照抄 JSON，不重新计算，不四舍五入成别的数。金额写明不含 GST。
4. 「建议」最多两条，写明是建议；没有数据支撑的话不写。
5. 中文，像跟老板当面汇报，不用「综上所述」之类的话。
```

> 用 ChatGPT 也可以：第一步用 ChatGPT Project 跑同样的规则；n8n 里把 Anthropic Chat Model 换成 OpenAI Chat Model，其他节点不变。

## 6. 加分挑战

- 加一个「每组表现」：按 crew 统计完成单数、平均评分和超时单数，看是不是某个小组特别容易超时。
- 让周报同时生成一张 CSV 附件（逾期发票清单 + 联系方式），小林可以直接拿去催款；催款邮件要另走审批，不要自动发。
- 连续两周毛利率低于 15% 时，在简报标题里加一句提醒，并写清触发的规则。

## 7. 简历 / 面试可以这样讲

> 为一家上门清洁公司搭建每周经营简报：用 n8n 每周一汇总工单、Xero 发票、支出和客户反馈，在 Code 节点里按固定口径计算营业额、人工估算、毛利、逾期应收和超时工单，排除重复与作废发票、重复和跨周支出，并找出做完未开票的工单；Claude 只负责把算好的数字写成一页简报，投诉放在最前面并先行提醒，行政确认后才发给老板（教学项目，公司和数据都是为这个练习设计的）。
