# P18 · 留学移民中介：签证进度表 → 到期提醒 → 顾问跟进待办

| 行业 | 难度 | 时长 | 工具 |
|---|---|---|---|
| 留学移民中介 | L2 Workflow | 150 分钟 | Claude（Projects）+ n8n + Google Sheets + Slack + Gmail |

## 1. 客户场景

还是 P03 里的启航留学移民。注册移民代理 Michael Tan 手上同时跟着十几个签证案子，进度全记在一张 Google 表里：哪个递交了、哪个在补件、补件截止是哪天、客户护照什么时候到期。表是前台小林在维护，Michael 每周想起来翻一次。上个月一个客户的补件截止日过了三天才被发现；还有一次小林看到客户问「能不能保证批下来」，好心回了句「一般都没问题的」——这种话在澳洲只能由注册移民代理说，而且谁都不该说「保证」。

他们想要的是：**每天早上自动扫一遍进度表，按公司的跟进规则排出今天的待办，紧急的直接 @Michael；能发的事务性提醒（交补件、约体检、换护照）先写好草稿，Michael 点批准才发；任何签证会不会批的问题，系统和前台都不碰。**

## 2. 练习数据

都是练习数据：公司沿用 P03，客户、案子、邮箱（`.example`）和日期都是为这个练习设计的。所有日期以 **2026-11-12** 为「今天」。

| 文件 | 内容 |
|---|---|
| `data/visa-tracker.csv` | 签证进度表，17 行 |
| `data/followup-rules.md` | 公司内部的跟进规则：范围、触发条件和优先级、不能自动处理的情况、提醒怎么写 |

`visa-tracker.csv` 的字段：

| 字段 | 含义 |
|---|---|
| case_id / client_name / client_contact | 案子编号 / 客户 / 联系邮箱 |
| case_owner | 负责的注册移民代理 |
| visa_type | 签证类型，只是个标签 |
| stage | 材料收集 / 已递交 / 补件中 / 已获批 / 已结案 / 已撤回 |
| lodged_date | 递交日期 |
| current_visa_expiry | 表里记的客户当前签证到期日 |
| passport_expiry | 护照到期日 |
| rfi_due / health_check_due | 部门来信里的补件截止 / 体检截止 |
| last_contact | 上次联系客户的日期 |
| contact_ok | 能不能直接给客户发消息 |
| notes / updated_at | 备注 / 这行最后更新时间 |

跟进规则的核心（全文见 `followup-rules.md`）：补件和体检截止「已过期或 7 天内」是紧急、「8–14 天」是高；当前签证到期日已过是紧急，60 天内按 stage 分高或中；护照 6 个月内到期是中；超过 30 天没联系是低；客户问到批不批是中，只由 Michael 回。

数据里**故意藏了 6 类问题**：

1. **重复行**：C112 有两行，旧的一行还是「已递交」，新的一行已经「补件中」，有补件截止日。要用 updated_at 最新的那行，否则会漏掉补件。
2. **负责人为空**：C110 没有 case_owner。
3. **日期格式不对**：C110 的护照到期写的是「03/04/2027」，看不出是 3 月 4 日还是 4 月 3 日，不能猜。
4. **截止日已过**：C105 的补件截止 11-08 已经过了；C108 表里的当前签证到期日 11-05 也过了。系统不判断这意味着什么，只让 Michael 今天亲自核实。
5. **不能直接联系**：C109 的客户要求只跟她女儿联系，不能起草给她本人的消息。
6. **客户问「能不能保证批下来」**：C111 只生成给 Michael 的待办，不起草任何回答。

另外还有已获批、已结案、已撤回的三个案子，不在提醒范围里。

**教学假设：** 这套规则只是公司内部的跟进节奏，决定「谁、什么时候、做什么事」，不对任何签证结果、等待时间、是否合法在留作判断。签证和移民建议只能由注册移民代理给出，以 OMARA、Department of Home Affairs 的官方说明和相关法规为准。

## 3. 做法

规则全部能算，放在 Code 节点里；Claude 只做两件事：把待办写成 Michael 一眼看懂的话，起草事务性提醒。

**第一步：在 Claude 里把规则跑通。** 建 Project「启航签证跟进」，上传 `followup-rules.md`，项目说明写：

```
你是启航留学移民的签证跟进助手。今天是 2026-11-12。我会上传签证进度表 visa-tracker.csv，请严格按 followup-rules.md 处理。
1. 同一个 case_id 多行，只用 updated_at 最新的一行。
2. 只处理 stage 为 材料收集 / 已递交 / 补件中 的案子。
3. 逐个案子按触发规则列出所有触发项，每项写：优先级、触发了什么（带日期和还剩几天）、待办。案子的优先级取最高的一项。
4. case_owner 为空、日期不是 YYYY-MM-DD 格式的，单独标出来，不要猜日期。
5. 能起草客户提醒的条件：contact_ok = yes、有负责人、没有待核实的问题、优先级不是紧急，而且触发项里有「提醒客户」或「例行跟进」。
   提醒只写事务：截止日期（照抄表里的日期）、要交什么、请联系谁。用前台小林的口吻，三四句。
6. 你绝对不能写：签证会不会批、要等多久、有没有影响、该不该换签证、「一般没问题」「应该可以」。客户问到这些，只给 Michael 生成待办。
输出：① 今天的待办表（按优先级排序：紧急 → 高 → 中 → 低），列 case_id、客户、负责人、优先级、触发项和待办、标记；② 每条可以发的客户提醒草稿；③ 给 Michael 的三行摘要。
你不发任何消息，只出草稿。
```

上传 `visa-tracker.csv`，发一句「出今天的签证跟进待办」，拿结果跟第 4 节对。对不上先改规则。

**第二步：把进度表放进 Google Sheets。** 一个表格三张工作表：`tracker`（就是这份 CSV）、`todos`（每天生成的待办）、`reminder_log`（每条提醒的审批和发送记录）。

**第三步：按下面的节点搭 n8n。**

### n8n 搭建

| # | 节点 | 做什么 | 关键设置 |
|---|---|---|---|
| 1 | Schedule Trigger | 每个工作日早上触发 | 周一到周五 08:30，时区 Australia/Sydney |
| 2 | Google Sheets（读进度表） | 读 `tracker` 全部行 | Operation: Get Row(s) |
| 3 | Sort | 按 case_id、updated_at 降序排 | 为下一步去重做准备 |
| 4 | Remove Duplicates | 同一个 case_id 只留第一行（也就是最新的一行） | Compare: Selected Fields → case_id |
| 5 | Filter | 只留 材料收集 / 已递交 / 补件中 | stage 在这三个里 |
| 6 | Code（跟进规则） | 按 `followup-rules.md` 逐案算触发项、优先级、标记、能不能发提醒 | 日期先用正则校验 YYYY-MM-DD，不合格的不参与计算、写进 flags；规则跟 Claude Project 里一字不差 |
| 7 | Filter | 去掉没有任何触发项和标记的案子 | |
| 8 | Google Sheets（写待办） | 写进 `todos` | Operation: Append Row；列 case_id、owner、priority、todos、flags、日期 |
| 9 | If（紧急） | priority = 紧急 | 是 → 第 10 步 |
| 10 | Slack（紧急提醒） | @Michael，列出紧急案子和待办 | Channel: #签证-紧急；只写触发项，不写任何判断 |
| 11 | Aggregate + Slack（早报） | 全部待办合成一条，发给 Michael 和小林；未分配、日期待核实的 @小林 | Aggregate: All Item Data |
| 12 | Filter（可以发提醒的） | client_reminder = 起草，待 Michael 批准 | |
| 13 | Basic LLM Chain + Anthropic Chat Model | 按第一步的提示词第 5、6 条起草提醒 | Temperature 0.2；只传这个案子的触发项和日期 |
| 14 | Code（安全复核） | 草稿里出现「批」「拒」「保证」「没问题」「应该可以」「影响」「等多久」就退回，不进审批 | 规则写死，不靠模型 |
| 15 | Slack · Send and Wait for Response（Michael 审批） | 每条提醒发给 Michael：案子、触发项、草稿 | Response Type: Custom Form；字段：决定（批准 / 改了再发 / 不发）、修改后的内容；超时 1 天按「不发」处理 |
| 16 | Switch | 按 Michael 的决定分流 | 批准 / 改了再发 / 不发 |
| 17 | Gmail | 发给客户 | To: client_contact；落款小林 |
| 18 | Google Sheets（写 reminder_log） | 记 case_id、谁批的、几点发的、最终内容 | Operation: Append Row |

人工审批点是第 15 步：没有 Michael 的「批准」，客户收不到任何消息。紧急的案子在第 12 步就被挡下，不走模板提醒。

> 用 ChatGPT 也可以：第一步用 ChatGPT Project 跑同样的规则；n8n 里把 Anthropic Chat Model 换成 OpenAI Chat Model，其他节点不变。

## 5. 验收清单

- [ ] C112 用的是 updated_at 为 11-09 的那行，出现了补件截止的高优先级待办；旧的那行没有单独生成待办。
- [ ] C110 被标出负责人为空和日期待核实，系统没有把 03/04/2027 猜成任何一个日期，也没有起草提醒。
- [ ] 三个紧急案子都 @了 Michael，都没有生成模板提醒。
- [ ] C109 没有任何给客户的草稿；C111 没有任何回答客户问题的文字。
- [ ] 4 条提醒草稿里没有「批」「拒」「保证」「没问题」「应该可以」「影响」「等多久」这类字眼，日期跟表里一致。
- [ ] 在 n8n 里演示：Michael 点「不发」后客户收不到邮件，`reminder_log` 记为不发；故意让模型写一句「应该没问题」，第 14 步把它拦了回去。

## 6. 加分挑战

- 每周一多发一份给 Michael 的周视图：未来 30 天内所有截止日，按日期排成一张表。
- 小林改了进度表以后（比如把 C105 标成已补件），第二天的待办自动消失；想想你用哪个字段判断「这件事已经做完了」。
- 加一个「提醒发出后 3 天客户没回」的检查，自动给小林生成一条电话跟进的待办。

## 7. 简历 / 面试可以这样讲

> 为一家留学移民中介搭建签证进度跟进流程：n8n 每个工作日读取进度表，按最新更新去重，用确定性规则算出补件、体检、签证和护照到期的跟进优先级，生成每位注册移民代理的待办，紧急案子即时提醒；负责人缺失和格式不明的日期单独标出、不做猜测；只起草事务性客户提醒，经注册移民代理审批后发送，任何签证结果相关的问题都不由系统回答（教学项目，数据为为练习设计）。
