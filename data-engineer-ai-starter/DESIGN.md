> 本文件是该课的设计 SoT。课时、步骤、价格只写在 `public/outline.json`，本文件不复述大纲。销售预览在 `public/curriculum.html`，它的课时代码、标题、时长必须和 outline.json 一致。

> 取代旧目录 `data-engineer-ai-advanced/` 里早期的入门设计（交通视频加爬虫项目）。保留的决策：数据工程做骨架、AI 做方法；每节课带走一样东西；每个翻车点要实跑验证。放弃的：交通视频和爬虫项目、$788 进阶定价、Airflow 作为入门内容。

## 定位

- **学员**：转入数据工程的人：分析师、测试、客服、其他方向的开发、应届毕业生。
- **先修**：基础 SQL（select、join、group by），能读简单的 Python，会用终端和 Git。其余（dbt、数据仓库、数据质量测试）课上边做边学。
- **买到什么**：10 小时直播带做（L00 30 分钟准备不直播，L01 到 L05 各 120 分钟）；一个作品集项目；一段能面对面讲清楚的讲解。价格 $599 含 GST，满 15 人开班，同一时间只开一个班，讲师亲自带。
- **不是什么**：不是 AI 工程课，不教 Airflow、Spark、云上仓库；不承诺工作、薪资、晋升、签证或收入；不是看讲座的课（概念每节最多 10 分钟）。

## 决策记录

- 2026-10-11 Lightman 定：入门与进阶各 $599 含 GST；满 15 人开班；同一时间只开一个班；全部由 Lightman 亲自授课。

- 不教 Airflow 和 Spark：初级广告样本里这两项都是 0 次（见 JD 证据）。
- 每节课固定节奏：先看终点（10 到 15 分钟演示），最多 10 分钟概念并做成清单，其余动手，最后一项是“带走：”。
- 四条规则从 L00 起教：先说清要什么再让 AI 写；让 AI 解释每一段；自己运行验证；讲不清的不提交。每节结尾做讲解。
- 数字纪律：任何节省时间或成本的数字，没有实测前不写进销售页和 outline.json。

## AI 关系

**原则**：AI 在这门课里是结对搭档，也是老师。它负责快：读文件、提方案、写初稿。学员负责对：每一次都要先说清自己要什么，运行它的输出，数行数，找它漏掉的假设，并用自己的话讲出来。判断标准只有一条：拿掉 AI，学员还能讲清这个结果为什么对。样本里 4 条真正的初级数据工程广告都提到 AI，多数是 AI 辅助编码或兴趣（样本很小，见 JD 证据）。课程训练的用法是：快，但粒度、主键和测试你说得清。

| 课 | AI 做什么 | 你做什么 | 你要能讲清或判断什么 | AI 容易错在哪 |
|---|---|---|---|---|
| L00 开课前准备 | 解释环境检查脚本的报错 | 装好环境，跑通第一条查询 | 四条规则是什么、为什么这样定 | 给出的修复命令和你的系统不匹配 |
| L01 读懂数据再装载：AI 提表和主键，你说清一行是什么 | 读 5 个原始文件（orders、order_items、customers、products、payments），提出表结构、主键和外键，并写装载脚本。 | 先自己写下每张表一行代表什么，再对照 AI 的提案；用 count(*) 和 count(distinct 主键) 验证它的主键；改正后装载进 DuckDB。 | 能用一句话说清每张表的粒度；能说出为什么 order_id 不能直接当 payments 的主键。 | 看到 order_id 就当主键，不检查导出文件里的重复行；把一单多笔付款当成一对一。 |
| L02 用 dbt 清洗建模：从 staging 到 marts | 按数据字典写 staging 模型（改名、转类型、统一单位和状态值）和 marts 初稿。 | 拿数据字典逐行对照 AI 写的 SQL；在 staging 里修正金额单位和时间格式；给 fct_orders 写粒度注释。 | 能说清 staging 和 marts 各自该做什么、不该做什么；能说清 fct_orders 一行是什么。 | 两个来源的金额一个是美分一个是美元，AI 直接相加；时间字符串格式混用，按字符串排序；状态值大小写不统一，分组被拆成两组。 |
| L03 数据质量：测试、去重，跑两遍结果一样 | 为每个模型写 dbt 测试，提出去重和增量加载的写法。 | 判断 AI 的测试覆盖了什么、漏了什么，补上 relationships 测试和业务规则测试；复现重复加载并改成可重跑；写行数对账查询。 | 能说清每个测试在保护哪条假设；能说清幂等是什么、你怎么证明它成立。 | 只写 unique 和 not_null，业务规则（如退款金额不能大于付款金额）一条没有；用 insert into 追加却不设唯一键；去重时随手 distinct，把本该保留的行也去掉。 |
| L04 三个业务问题：审 AI 写的 SQL | 为三个业务问题写 SQL：悉尼时间的日销售额、首单月的复购率、品类退款率。 | 先用一句话写下答案的粒度，再审 AI 的 SQL：数 join 前后的行数，查 NULL 去了哪里，核对时区；改错并留下审查记录。 | 能说清为什么 join 之后求和会变大；能说清 where region <> 'AU' 会丢掉哪些行；能说清“一天”按哪个时区算。 | orders join payments 后对订单金额求和，一单多笔付款就重复计算；NULL 与 <> 比较结果是未知，被 where 悄悄丢掉；用 UTC 日期切“一天”。 |
| L05 作品集：README、血缘图、面试讲解和审查清单 | 起草 README 和血缘图说明，整理面试讲解提纲。 | 逐条核对 AI 写的内容和仓库实际是否一致，删掉做不到的声明；和同学互相模拟追问；写出自己的 AI 代码审查清单。 | 能不看稿讲清整条管线的粒度、测试、重跑，以及你改过 AI 的哪三处。 | README 写“覆盖全部数据质量测试”，仓库里只有两条；血缘图画的是理想结构，不是 dbt 实际依赖。 |

## 项目与环境

- **学员做的项目**：课程提供的电商模拟数据（orders、order_items、customers、products、payments 五个文件），本地 DuckDB，dbt 做 staging 和 marts，写测试与重跑脚本，回答三个业务问题，最后整理成作品集仓库。
- **工具**：Python、DuckDB、dbt（DuckDB 适配器，是假设，见待核实）、Git、学员自带的 AI 编程助手。
- **谁出钱**：云费用为零（本地运行）。AI 编程助手由学员自备，支持哪些工具和费用如何说明：待定，开班前写入报名页。课程方不在课上调用任何付费模型接口。
- **和云仓库的对应**：DuckDB 里练到的是 SQL 建模、粒度、dbt 分层、测试、幂等，这些思路可以带到 Snowflake、Databricks、BigQuery。不等同：云仓库有自己的计费、权限、分区聚簇、性能调优和语法差异，这些入门课不教，也不声称学会了 DuckDB 就等于会了云仓库。

## 常见翻车点

每一条都必须用 Claude Code 或学员会用的助手实跑出来才成立：给 AI 一个中性的提示，看它是不是真的这样写。**目前全部未实跑**，下表的“预期”是设计假设，不是结论；AI 不踩的雷要换掉。

| 课 | 翻车点 | 怎么埋 | 实跑验收（未做） |
|---|---|---|---|
| L01 | 把 order_id 当主键，漏掉导出里的重复行 | orders 文件里放同一 order_id 的两行，updated_at 不同 | 默认提示下，AI 的装载脚本主键约束失败或静默保留两行 |
| L01 | payments 当成和订单一对一 | 部分订单有两笔付款 | AI 的数据字典把 order_id 写成 payments 的唯一键 |
| L02 | 美分和美元直接相加 | orders 金额存美分，payments 存美元 | staging 模型里没有单位转换 |
| L02 | 混合日期格式按字符串处理 | 同一列有两种日期格式 | AI 用单一格式转换，部分行变 NULL |
| L03 | 追加加载，第二次运行行数翻倍 | 装载不设唯一键 | 连跑两遍，行数 = 2 倍 |
| L03 | 测试只有 unique 和 not_null | 不给业务规则提示 | AI 生成的测试里没有 relationships 或业务规则 |
| L04 | join 付款后求和重复计算 | 一单多笔付款 | 品类退款率比对照结果偏高 |
| L04 | where 不等于条件丢掉 NULL 行 | customers 的 region 有 NULL | 行数比预期少 |
| L04 | 用 UTC 日期切一天 | 时间戳存 UTC，业务按悉尼时间 | 凌晨订单落在前一天 |
| L05 | README 声明与仓库不一致 | 让 AI 只看 outline 写 README | README 声称的测试数多于仓库实际 |

## 报名前自测

五个是或否的问题，写在销售页：

1. 你能不查资料写出一条 select + join + group by 的查询吗？否：先补 SQL 基础再报名。
2. 给你一个 20 行左右的 Python 函数，你能说出它返回什么吗？否：先补 Python 读码再报名。
3. 你会在终端里切换目录、运行 Python 脚本并用 Git 提交吗？否：先补命令行与 Git 再报名。
4. 你已经写过 dbt 模型或维护过每天定时跑的管线吗？是：看进阶课，不报入门。
5. 你愿意在课上解释 AI 写的每一段代码吗？否：这门课不适合你。
