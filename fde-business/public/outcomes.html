Finance Operations

客户问题与边界

Create a review-ready invoice register and an exception queue. Preserve the source of every field; leave approval, GST eligibility and payment decisions with finance.

  • A$8,000 project setup ceiling and A$500 monthly operating ceiling. These are client-brief budgets, separate from course tuition.
  • No supplier payments, bank-detail changes or tax-credit claims are automated.
  • Amounts are AUD. Only rows explicitly marked standard-taxable and GST-inclusive use a total/11 arithmetic check. Missing tax status is reviewed.
  • The same supplier/invoice reference must not create two payable records. A duplicate is reported, not silently merged.

方案与交付判断

  • Use a controlled intake → extract fields → validate → check duplicates → human review → approved register workflow.
  • INV-101 is review-ready with an arithmetic GST component of A$100; this does not establish a tax-credit entitlement.
  • INV-201 has a mismatch: the standard-taxable inclusive arithmetic check is A$50, but the supplied field is A$60. Keep the original field and request review.
  • The forwarded INV-101 is a duplicate. The invoice-c record lacks currency and tax status and remains in review.
  • Planning at 80% accepted coverage and five minutes saved per accepted invoice gives 20 hours of monthly capacity. Measure both extraction and review time before claiming an improvement.

"""Business workflow reference: field checks and routing, no external actions or model calls."""
from decimal import Decimal, ROUND_HALF_UP, InvalidOperation
from pathlib import Path
import json

def invoice_register(records):
    seen=set();results=[]
    for row in records:
        key=(row.get('supplierRef'),row.get('invoiceRef'))
        issues=[]
        if not all(key):issues.append('missing-identity')
        elif key in seen:issues.append('duplicate')
        else:seen.add(key)
        if row.get('currency')!='AUD':issues.append('review-currency')
        expected=None
        if row.get('taxStatus')!='standard-taxable-inclusive':issues.append('review-tax-status')
        else:
            try:
                total=Decimal(row['total']); gst=Decimal(row['gst'])
                if not total.is_finite() or not gst.is_finite() or total<0 or gst<0:raise ValueError('invalid amount')
                expected=(total/Decimal(11)).quantize(Decimal('0.01'),rounding=ROUND_HALF_UP)
                if abs(gst-expected)>Decimal('0.01'):issues.append('gst-arithmetic-mismatch')
            except (ValueError,TypeError,KeyError,InvalidOperation):issues.append('review-amount')
        results.append({'source':row['source'],'invoiceRef':row.get('invoiceRef'),'originalTotal':row.get('total'),'originalGST':row.get('gst'),'expectedGST':str(expected) if expected is not None else None,'status':'review-ready' if not issues else 'exception','issues':issues,'approvalOwner':'finance','paymentExecuted':False})
    return results

def customer_queue(events):
    leads={};notes=[]
    for event in events:
        key=event.get('enquiryId')
        if not key:notes.append({'eventId':event['eventId'],'status':'missing-information'});continue
        current=leads.get(key)
        if current and event['revision']<=current['revision']:
            notes.append({'eventId':event['eventId'],'status':'duplicate-or-stale'});continue
        leads[key]={'enquiryId':key,'revision':event['revision'],'preferredWindow':event['preferredWindow'],'draftApproval':'required','draftText':'Thanks for your request. We have noted '+event['preferredWindow']+' as your preferred window. Our team will check availability before confirming a visit.','messageSent':False}
        notes.append({'eventId':event['eventId'],'status':'updated-review-required' if current else 'draft-review-required'})
    return {'leads':list(leads.values()),'events':notes}

def onboarding(row):
    if not row['contractConfirmed']:status='HR-confirmation-required'
    elif not row['managerAssigned']:status='manager-required'
    elif row['accessApprovedRevision']!=row['roleRevision']:status='IT-reapproval-required'
    elif not row['accessFulfilmentEvidence']:status='IT-fulfilment-evidence-required'
    else:status='ready-for-owner-review'
    return {'starterRef':row['starterRef'],'status':status,'accessGranted':False}

def run():
    cases={c['id']:c for c in json.loads(Path(__file__).with_name('outline.json').read_text())['cases']}
    rows=invoice_register(cases['finance']['records']);customers=customer_queue(cases['customer']['records']);people=[onboarding(r) for r in cases['people']['records']]
    assert rows[0]['status']=='review-ready' and rows[0]['expectedGST']=='100.00'
    assert 'gst-arithmetic-mismatch' in rows[1]['issues'] and rows[1]['expectedGST']=='50.00'
    assert 'duplicate' in rows[2]['issues']
    assert 'review-currency' in rows[3]['issues'] and 'review-tax-status' in rows[3]['issues']
    assert len(customers['leads'])==1 and customers['leads'][0]['revision']==2 and not customers['leads'][0]['messageSent']
    assert people[0]['status']=='IT-fulfilment-evidence-required' and people[1]['status']=='HR-confirmation-required' and people[2]['status']=='IT-reapproval-required'
    return {'invoiceRegister':rows,'customerFollowUp':customers,'onboarding':people,'planning':{'monthlyCapacityHours':300*.8*5/60,'capacityValueAUD':300*.8*5/60*60,'operatingAssumptionAUD':200+2*80}}
if __name__=='__main__':print(json.dumps(run(),indent=2))

Customer Follow-up

客户问题与边界

Prepare a clean lead list, identify missing information, propose an owner and draft the next response for staff approval.

  • A$6,000 setup ceiling; one approved shared workspace.
  • No message, quote or appointment is sent or confirmed automatically.
  • A customer asking for a discount does not approve a new price.
  • Use source enquiry IDs to find duplicates; missing IDs require review.

方案与交付判断

  • Keep one lead per source enquiry ID and preserve the incoming revision history.
  • Prepare a response draft and owner; retain staff approval before any outbound message.
  • The email event for ENQ-17 revision 1 does not create a second lead.
  • Revision 2 invalidates approval of the Tuesday draft. Use the new preferred window and request confirmation.
  • An incomplete request goes to a missing-information queue, not an invented customer profile or promised booking.

Employee Onboarding

客户问题与边界

Create an ownership-based onboarding checklist and a progress brief, with evidence for every completed step.

  • A$5,000 setup ceiling.
  • HR confirms employment details; IT owns access approval and provisioning.
  • No account is created or permission granted by the course workflow.
  • A checked box without supporting evidence is not accepted as completion.

方案与交付判断

  • Use a checklist with task owner, prerequisite, evidence and escalation date. Keep HR, IT and manager responsibilities distinct.
  • START-01 can have an approved access request but is not provisioned without fulfilment evidence.
  • START-02 stays with HR while contract confirmation is missing.
  • START-03 needs a new IT decision for role revision 2; evidence for the prior role does not establish current access.
  • The handover includes unresolved items and their owners. A green dashboard does not substitute for the supporting records.

Pilot plan

  • Track complete outputs, review minutes, exception backlog and duplicate reports over the agreed pilot period.

Runbook

  • Start: place new inputs in the approved intake location and retain their original filenames or source IDs.
  • Prepare: generate candidate fields, run the defined checks and open the exception queue.
  • Review: finance resolves amount, tax-status and approval questions; record the owner and evidence.
  • Duplicate: preserve both source references, link the duplicate to the existing record and stop repeated downstream work.
  • Change: version the workflow rule and rerun affected pending records; old approvals do not apply to changed content.
  • Handover: another participant must reproduce the register, explain an exception and identify the responsible finance, sales or IT owner.
