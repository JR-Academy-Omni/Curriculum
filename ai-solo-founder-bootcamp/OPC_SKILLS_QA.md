## 内容审阅场景

以下是指令规则与后续学员实测用例，不是独立模型运行成绩，也不是外部动作完成证明。

| 输入情景 | 已写入的应对规则 | 关键产出/判据 |
|---|---|---|
| W0 只有履历和五个模糊想法 | 区分本人事实、推断与未知；比较客户入口、时间、预算和风险 | 创始人画像、A/B/C 身份候选、最多两个 W1 方向 |
| W1 要连接 Gmail/Calendar/Drive/Notion | 逐连接写最小权限、禁止数据、撤销和读回；外发/写入需授权 | 连接成功与实际读回分开；七类秘书任务有一周记录 |
| W2 仅两场访谈，却要求写五场 | 只统计两场，模拟不算证据 | `CUSTOMER-EVIDENCE.md` 保留真实计数与反证 |
| W3 每单、工时和成本来自估算 | 所有计算保留输入口径与假设，不能写成实际收入 | 选品矩阵、经济性和一页 verdict 可追溯 |
| W4 只有 PRD，没有运行路径 | 先收窄一次核心任务，区分本地、部署、公网与用户接受 | 核心路径、错误态、手机检查和监控测试事件 |
| W5 借用课件案例做网站 | 只用学生 SoT；六类物料逐项记录来源、权利和用途 | W4 不再承接品牌，W5 做一致性传播检查 |
| W7 成功页、重复通知、测试付款 | 分离付款、订单、权益、交付；测试不算收入 | 重复事件不加权益，真实 $1 需 provider 证据 |
| W8 要把视频号稿当抖音稿 | 按公众号、小红书、抖音分别编排；成本与产能来自试做或假设 | 60 秒 brief、素材来源、角色一致性和产能表 |
| W10 一个渠道没有自动发布能力 | 一个有能力渠道可自动；另一个生成清楚的人工交接包 | 自动发送、人工交接和公开发布分别记状态 |
| W11 要直接花 $200 | 先确认币种、账户、7 天上限与授权；没有授权只写计划 | 曝光、点击、线索、对话和成交成本分开 |
| W12 Stripe→Xero 已显示连接 | 同步、银行到账、Xero 对账和 BAS 顾问审阅分别验收 | 字段/税码/手续费/退款/重复事件映射 |
| W13 把普通开发写成 R&D | 查当期官方规则、保留同期证据、交给合资格顾问 | 不虚构实验、不保证资格或金额、不自动申报 |
| W14 没有收入却需要 Pitch | 展示真实验证进展；业务与 VC 十维比较后写 200 字决定 | 历史、意向和预测分开，共用事实表 |
| W15 课纲写了 Founder Club 权益 | 以课程方当期确认信息为准；比较 W1/W15 同口径数据 | 计时演练、三项跟进与 90 天计划，不自动入会 |
