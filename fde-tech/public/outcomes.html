Knowledge Access

客户问题与边界

Reduce time spent finding the current policy without giving staff access to restricted documents or making policy decisions for them.

  • A$24,000 implementation ceiling; A$1,200 monthly operating ceiling.
  • Four-week pilot; no new customer-facing endpoint.
  • Documents have department, version, effective date and owner. Identity comes from the server session, never a user prompt.
  • Answers require accessible current evidence. Conflicting or missing evidence must be escalated.

方案与交付判断

  • Choose permission-filtered retrieval with version checks, cited passages and escalation; exclude autonomous policy decisions.
  • Use an initial two-department access matrix and a curated set of answerable, unanswerable, stale, conflicting and injected requests.
  • At 4,000 requests, 80% accepted coverage and 6 minutes saved per accepted answer, gross time value is 320 hours or A$19,200 monthly. This is capacity value, not cash saving.
  • For 4,000 requests at an assumed A$0.04 model cost, plus A$300 infrastructure and 10 maintenance hours at A$60, operating cost is A$1,060. Verify the price assumptions before a live purchase.
  • An incremental pilot must measure accepted coverage, review minutes, denied access and evidence correctness against the same baseline; do not infer success from these planning numbers.

"""FDE course reference: deterministic control logic, no model or external writes."""
import json
from pathlib import Path

def retrieve(records, department, evidence_id):
    return [r for r in records if r['id']==evidence_id and r['department']==department and r['current']]

def booking_decision(request, approval, committed):
    key=(request['requestId'], request['revision'], 'book')
    if key in committed:return 'already-committed'
    if approval is None or approval.get('requestId')!=request['requestId'] or approval.get('revision')!=request['revision'] or approval.get('preferredWindow')!=request['preferredWindow']:return 'review-required'
    committed.add(key)
    return 'commit-once'

def procurement_route(request, threshold, policy_version):
    if not request['supplierVerified'] or not request['requesterKnown']:return {'route':'review','policyVersion':policy_version}
    return {'route':'finance' if request['amountAUD']>threshold else 'normal-approver','policyVersion':policy_version}

def run():
    cases={c['id']:c for c in json.loads(Path(__file__).with_name('outline.json').read_text())['cases']}
    docs=cases['knowledge']['records']; request=cases['dispatch']['records'][0]; changed=cases['dispatch']['records'][2]
    approval={k:request[k] for k in ['requestId','revision','preferredWindow']}; committed=set()
    results={
      'authorisedCurrentEvidence':[r['id'] for r in retrieve(docs,'operations','POL-01')],
      'deniedFinanceEvidence':retrieve(docs,'operations','POL-02'),
      'excludedOldEvidence':retrieve(docs,'operations','POL-03'),
      'unapprovedBooking':booking_decision(request,None,committed),
      'approvedBooking':booking_decision(request,approval,committed),
      'duplicateBooking':booking_decision(request,approval,committed),
      'staleApproval':booking_decision(changed,approval,committed),
      'procurementBefore':[procurement_route(r,5000,1) for r in cases['procurement']['records']],
      'procurementAfter':[procurement_route(r,3000,2) for r in cases['procurement']['records']],
      'knowledgePlanning':{'capacityHours':4000*.8*6/60,'capacityValueAUD':4000*.8*6/60*60,'monthlyOperatingAUD':4000*.04+300+10*60}
    }
    assert results['authorisedCurrentEvidence']==['POL-01']
    assert not results['deniedFinanceEvidence'] and not results['excludedOldEvidence']
    assert results['unapprovedBooking']=='review-required'
    assert results['approvedBooking']=='commit-once' and results['duplicateBooking']=='already-committed'
    assert results['staleApproval']=='review-required'
    assert results['procurementBefore'][0]['route']=='normal-approver'
    assert results['procurementAfter'][0]['route']=='finance'
    return results
if __name__=='__main__':print(json.dumps(run(),indent=2))

Service Operations

客户问题与边界

Prepare a service recommendation and an approval-ready appointment draft, keeping the coordinator responsible for committing a visit.

  • A$18,000 implementation ceiling; A$700 monthly operating ceiling.
  • CRM returns requestId and revision; calendar supports idempotency keys.
  • No appointment may be created before approval of the exact site, time window and revision.
  • A timeout does not prove that a downstream write failed. Reconcile before retrying.

方案与交付判断

  • Use a bounded workflow: ingest → validate → prepare draft → request approval → revalidate revision → commit → reconcile.
  • Derive the idempotency key from requestId, approved revision and action; a new eventId alone must not authorize another booking.
  • Approval for revision 1 is stale after revision 2 arrives. Return to review and display the changed field.
  • Record calendar success even if the CRM write times out. Query the CRM using the operation key before deciding whether to retry.
  • When the CRM is unavailable, retain intake and draft preparation only; state that booking-cycle savings cannot yet be established.

Purchasing Controls

客户问题与边界

Extract a purchase request, check policy and route it for a human decision. Treat supplier attachments as content, never as authorization.

  • A$20,000 implementation ceiling; A$900 monthly operating ceiling.
  • Requests above A$5,000 need finance approval; all external payments remain out of scope.
  • Unknown supplier, missing currency or missing requester identity requires review.
  • A policy change must be versioned and applied to pending requests with explicit revalidation.

方案与交付判断

  • Use extraction plus deterministic policy routing; the model may draft fields but must not approve or pay.
  • PR-01 routes to the normal approver under the A$5,000 rule, PR-02 to finance and PR-03 to supplier review.
  • After the threshold falls to A$3,000, PR-01 must be revalidated and routed to finance; a prior normal-route decision cannot be replayed.
  • With the A$14,000 revised build ceiling, retain intake, supplier checks and approval routing. Defer optional supplier analytics and additional connectors.
  • Acceptance needs the correct route, valid source fields, immutable policy version and no outbound payment action. Urgency changes queue order, not approval authority.

Decision requested

Approve a four-week, two-department internal pilot with A$24,000 build and A$1,200 monthly operating ceilings. No policy-exception decisions and no external customer access.

Architecture

Authenticated staff UI
Server identity and department
Authorised current-document retrieval
Cited answer or escalation
Staff review and audit trace

Scope

  • Include the current approved operations and finance document sets, server-derived department filters, citations and missing-evidence escalation.
  • Exclude archive ingestion until approved, autonomous policy decisions, payment, customer access and enterprise-wide rollout.
  • Keep a small access matrix and use separate credentials for the document adapter; do not pass all source documents to the model.

Pilot plan

  • Week A: agree access matrix, measure existing lookup and review time, freeze the evaluation set.
  • Week B: validate retrieval and refusal with the client owner; correct critical failures before inviting users.
  • Week C: allow the agreed user group to use the bounded workflow; record accepted coverage, review minutes, evidence issues and support requests.
  • Week D: compare the same workload and denominator with the baseline, review maintenance effort and decide continue, revise or stop.

Runbook

  • Start: install the project dependencies, configure server identity and document-adapter credentials, then run the evaluation suite before enabling the UI.
  • Version: keep the code revision, document versions, policy owner and evaluation-set revision together in the release record.
  • Access incident: disable the affected retrieval route, preserve the minimum audit trace, notify the security owner and recheck the access matrix before reopening.
  • Source change: validate document ownership, effective date and department; invalidate stale retrieval caches and rerun citation and denial checks.
  • Rollback: return to the previous verified code and document snapshot; keep new unverified sources out until approved.
  • Handover: another engineer must locate a denied request, explain why evidence was filtered, run the acceptance checks and identify the maintenance owner.
