# AI DevOps 实战课 · 项目班 — 设计说明

> SoT：课程内容（课时、步骤、文案、价格）只写在 public/outline.json，销售预览页是 public/curriculum.html。本文件只记录定位、决策、AI 关系、JD 证据、环境、翻车点和待核实事项，不复述大纲。主题色 #2B8A6E（绿色，运维里「系统正常」的颜色，与同系列高级班区分）。

## 定位

- **学员**：想转进 DevOps 的人，来自技术支持、测试、系统管理、其他 IT 岗位，以及应届毕业生。
- **前置**：Linux 命令行基础、Git 基础、能读简单代码。AWS、Terraform、CI/CD 从零开始，边做边学。
- **买到什么**：10.5 小时（L00 自学 30 分钟加 L01 到 L05 各 120 分钟直播）。从第一节起就是 AI DevOps：搭一个只读的 AI 工作台，用它读陌生的 AWS 账号、把一句话需求变成 Terraform、搭流水线并诊断红灯、只读调查故障，最后固化成 skill 加一个 hook，整理成作品集仓库和面试讲解。
- **价格与开班**：$599 含 GST；不少于 15 人才开班；同一时间只开一个班；讲师由 Lightman 本人担任。
- **不是什么**：不是已在运维生产环境者的课（请看高级班）；不教 Kubernetes（本课用 ECS，倾向，未最终定）；不教部署或训练模型，不教做 AI 应用；不教 MCP、子代理、云端代理和团队插件；不承诺工作、薪资、签证或晋升。交付物是作品集仓库（AI 工作台加用它做出的东西）加一份能面试用的讲解。

## 与高级班的区别

| 维度 | 项目班（本课） | 高级班 |
|---|---|---|
| 学员 | 转行者，没有 DevOps 基础 | 已在做 DevOps，有领域判断力 |
| AI 的角色 | 结对搭档和老师 | 团队成员或流水线里的一个组件 |
| 学员的角色 | 一边学领域，一边审 AI | 用领域经验审 AI 的输出 |
| 主要风险 | 信任自己读不懂的基础设施代码，以及把规则当成安全边界 | 把 AI 接入团队流程后的权限、安全和治理 |
| 内容 | 一个个人 AI 工作台走完读账号、写 Terraform、搭流水线、排障、skill 加一个 hook、作品集 | MCP、hooks 体系、子代理、云端代理、团队插件，团队落地与治理 |

MCP、子代理、云端代理、团队插件不进本课，销售页只作为「高级班内容」提及。本课只做一个很小的 hook（拦 apply 和 destroy），目的是让学员亲手试出它拦不住什么，不是教 hooks 体系。

## 决策记录

- 2026-10-11 Lightman 定：不再叫「入门」（没人愿意报），入门版改称「项目班」；进阶版改称「高级班」（可以叫）。目录名里的 starter 和 advanced 是内部标识，保持不变。
- 2026-10-11 重定位为 AI 优先：Lightman 反馈「不是 devops 入门，是 AI DevOps」，此前一版「这就是普通的过去的项目了，不够 AI，我想前面都是可以很 AI」。旧版是传统的初学项目（Docker、Terraform、流水线、监控、故障），AI 只是旁边的搭档。新版从 L01 起让 AI 代理做事：搭工作台、读账号、写 Terraform、搭流水线、只读排障、固化成 skill 加 hook；项目班和高级班的分界保留（项目班是单人工作台，高级班是团队级接入）。Docker 和监控告警两节被拿掉，换成 AI 工作台和 AI 排障；监控告警不再单独成课（销售页不得再说教监控），这是有意的取舍。
1. **AI 在场的方式是「划范围、再干活、再验证」**：每节固定写明 AI 做什么、学员做什么、学员要能讲清什么；学员的判断力是交付物，不是 AI 的速度。
2. **真正的边界是 IAM 只读角色和沙箱账号**：规则文件、Claude Code 的权限设置、hook 都是便利，它们的实际拦截行为未核实（见待核实），课件和销售页不得称它们为安全边界，也不写「有了护栏不会也能安全地用」之类的话。L01 当场演示 IAM 拒绝写入，L05 当场试 hook 能被怎样绕过。
3. **AWS 只读靠命令白名单，不用 AWS MCP**：能读实时账号状态的 AWS MCP 是否可用、权限如何未核实，所以本课用只读 profile 加只读命令白名单；MCP、子代理、云端代理、团队插件全部留在高级班。
4. **所有写入动作由学员本人执行**：apply、destroy、回滚、止血都是学员用自己的写入凭据做，凭据不放进 AI 会话。AI 在 GitHub 上只能开 pull request，靠 main 分支保护强制，不靠 AI 自觉。
5. **故障演练：先自己查，再让 AI 只读查，再重跑它的命令验证，再对比**：不先让 AI 查，否则学员没有可对比的基线；产出是 runbook，不只是复盘。
6. **运行环境用 ECS（倾向，未最终定），不用 Kubernetes**：EKS 集群创建慢、控制面有固定费用（金额待实测）；本课时间用在 AI 工作台上。代价：JD 抽样里 Kubernetes 和 EKS 出现很多，销售页必须直说本课不教 Kubernetes。
7. **一个很小的 hook**：只拦 terraform apply 和 destroy，且课上故意换写法去试，记录拦住与放过，写成「护栏试验记录」。
8. **不承诺项**：不写金钱、岗位、签证类承诺；任何省时或成本数字在实测前不进销售页和 outline.json。
9. **继承自旧稿的决定**：AWS 预置沙箱账号并设预算上限、课后回收；代码托管用学员自己的 GitHub 仓库；通知类（SNS 邮件）本版不再使用。

## AI 关系

**一段话的原则**：AI 是被划了范围的同事，不是替学员完成作业的人，更不是不受约束的管理员。它在只读权限内读账号、画图、写 Terraform 和流水线、读日志、查故障、起草 runbook 和 README，还当追问的面试官；学员先把要什么写清楚，给它划范围，自己审查、自己验证、自己执行所有写入动作，并在每节课结束前讲回。每节课的标准是：学员能说出 AI 做了什么、自己判断了什么、凭什么判断它对。解释不了的东西不提交。

**边界的真话**：真正的安全边界是 AWS 的 IAM 只读角色和隔离的沙箱账号。规则文件、Claude Code 权限设置、hook 是便利，实际拦截行为未核实（见待核实），课件不得称它们为安全边界。学员的写入凭据不放进 AI 会话，是降低失误的做法，不是技术上的强制；能强制的只有两处：只读角色本身没有写权限，GitHub 的 main 分支保护拒绝直接推送。

四条规则从第一节课起执行：先说清要什么再让 AI 写；让 AI 解释每一段；自己运行并核对；解释不了的不提交。

| 课 | AI 做什么 | 你做什么 | 你要能讲清或判断什么 | AI 容易错在哪（写课时的假设） |
|---|---|---|---|---|
| L01 搭 AI 工作台，读陌生账号 | 只读读完沙箱账号和仓库，列资源，画架构图，标明读到的和推测的。 | 装 Claude Code，写规则文件；配 IAM 只读角色和只读命令白名单；把图对着控制台逐项核对。 | 账号里有什么、各自干什么；真正的边界是什么，规则和白名单又只是什么。 | 把推测画成事实；漏掉控制台里的资源；画出不存在的组件。 |
| L02 一句话需求到 Terraform | 把需求写成 Terraform 并逐段解释；apply 后用只读权限核对结果。 | 先写一页需求和验收标准；用三件事审 plan（权限过宽、对公网暴露、成本）；自己 apply。 | plan 里每个资源的用途、谁能访问、删掉的后果；为什么这条权限可以这么给。 | 权限写成星号；对公网开放；日志保留或 NAT 带来费用。 |
| L03 AI 搭流水线，诊断红灯 | 起草 GitHub Actions；读失败日志给原因；把修复开成 pull request。 | 先写流水线需求；设 main 分支保护；审凭据用法；先自己读红灯再对比 AI；审并合并 pull request。 | 每个阶段在做什么；长期密钥还是 OIDC 临时角色；AI 为什么改不了 main。 | 长期密钥存进 secrets；OIDC 信任条件和仓库名对不上；漏掉镜像仓库登录。 |
| L04 故障，AI 只读调查，写 runbook | 只读查日志和指标，给时间线、根因，写明每条结论依据的命令；起草 runbook。 | 先自己查；再让 AI 查；重跑它的命令标证据或猜测；自己止血；写 runbook。 | 哪些结论有证据；先止血还是先找根因；AI 的结论为什么可信或不可信。 | 把相近的事当原因；日志被截断仍下定论；没有证据说得很肯定。 |
| L05 skill、hook、作品集 | 用学员的 skill 审新草稿；起草 README 和架构图；扮演面试官。 | 写 skill；写一个拦 apply 和 destroy 的 hook，换写法试它；整理仓库；自己 destroy。 | hook 拦得住什么、拦不住什么，所以为什么边界仍是 IAM；整套工作台每部分的用途。 | 对换了写法的命令放行；架构图画了不存在的组件。 |

补充：L00 AI 不参与；L01 到 L05 每节最后一步是「带走」，结束前互相讲回。「AI 容易错在哪」一列是写课时的假设，需要在 starter 仓库里用真实运行逐条验证，见待核实。

## 常见翻车点

下面每一条都给出复现办法。现在只是课程设计阶段，还没有人在 starter 仓库上实跑过，实跑记录见待核实。

1. **AI 把推测画成事实**：让 AI 读沙箱账号并画图，不要求它标注来源，把图对照控制台，找出控制台里没有的组件。
2. **IAM 只读角色下命令被拒的表现**：用只读 profile 运行一条创建资源的命令，记录真实报错，作为 L01 演示的依据。
3. **数据库端口或存储桶对公网开放**：让 AI 起草需求里没提的网络规则，对 plan 输出 grep 0.0.0.0/0 和公开访问设置。
4. **IAM 权限写成星号**：对 AI 起草的角色策略 grep 星号。
5. **OIDC 无法扮演角色**：把角色信任条件里的仓库名故意写错，看 Actions 日志里 AssumeRoleWithWebIdentity 的授权错误。
6. **docker push 被拒**：没有先执行 aws ecr get-login-password 登录就推送，看错误信息。
7. **AI 推送 main 被拒**：开启分支保护后，让 AI 直接推送 main，记录 GitHub 返回的信息；管理员是否也被拦要看保护规则里的设置。
8. **hook 被换写法绕过**：写一个匹配 terraform apply 的 hook，再用带参数、带目录、放进脚本、换别名的写法运行，记录哪些被拦、哪些放过。
9. **AI 对被截断的日志仍下定论**：给 AI 一份被截断的日志，看它是否仍给出确定的根因。
10. **区域不一致**：命令行默认区域不是悉尼，资源建到别的区域，控制台里看不到。

## 报名前自测

页面上的 5 题（是或否），与此处一致：

1. 能不看教程，在 Linux 终端里找到日志文件并看最后 50 行吗？否：先补 Linux 命令行。
2. 用过 git clone、add、commit、push，并能说清分支吗？否：先补 Git。
3. 能说出一段 20 行左右 Python 或 JavaScript 在做什么吗？否：先补入门编程。
4. 有 GitHub 账号，并愿意把代码放进自己的仓库吗？否：课前注册即可，不影响报名。
5. 现在的工作是否已经在维护生产环境的 AWS、Terraform 或流水线？是：看高级班。
