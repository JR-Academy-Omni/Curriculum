# AI DevOps 实战课 · 入门 — 设计说明

> SoT：课程内容（课时、步骤、文案、价格）只写在 public/outline.json，销售预览页是 public/curriculum.html。本文件只记录定位、决策、AI 关系、JD 证据、环境、翻车点和待核实事项，不复述大纲。主题色 #2B8A6E（绿色，运维里「系统正常」的颜色，与同系列进阶课区分）。

## 定位

- **学员**：想转进 DevOps 的人，来自技术支持、测试、系统管理、其他 IT 岗位，以及应届毕业生。
- **前置**：Linux 命令行基础、Git 基础、能读简单代码。AWS、Terraform、CI/CD 从零开始，边做边学。
- **买到什么**：10.5 小时（L00 自学 30 分钟加 L01 到 L05 各 120 分钟直播），把一个现成的订单系统（前端、API、Postgres）从笔记本放到 AWS，配流水线和监控，演练一次故障，整理成作品集项目和面试讲解。
- **价格与开班**：$599 含 GST；不少于 15 人才开班；同一时间只开一个班；讲师由 Lightman 本人担任。
- **不是什么**：不是已在运维生产环境者的课（请看进阶课）；不教 Kubernetes；不教部署或训练模型，不教做 AI 应用；不承诺工作、薪资、签证或晋升。交付物是作品集项目加一份能面试用的讲解。

| 维度 | 入门（本课） | 进阶 |

## 决策记录

1. **一个项目做到底，AI 全程在场**：入门学员没有领域基础，没有一个贯穿的成果就说不出买了什么。这与进阶课「给团队搭工具箱」的方向不同，两课刻意不共用主线。
2. **每节练一种读法**：学员此刻最大的风险是信任自己读不懂的东西，所以每节固定训练一种读法：Terraform plan、流水线日志、指标、事故时间线、权限。
3. **先写需求再让 AI 动手**：四条规则从 L00 起执行，L01 就把「只读规则」落成实际的权限设置，让规则不只是口号。
4. **故障演练固定顺序：先自己，后 AI，再对比**：不先让 AI 查，否则学员没有可对比的基线。
5. **运行环境用 ECS Fargate，不用 EKS（倾向，未最终定）**：理由是课上创建 EKS 集群慢，并且集群有固定控制面费用（金额待实测）；10 小时只够做完一个项目，再加 Kubernetes 对象会把时间占满。代价：JD 抽样里 Kubernetes/EKS 出现很多，销售页必须直说本课不教 Kubernetes。若改用 EKS，L04 要重排。
6. **通知用 SNS 邮件**：不要求学员有 Slack 工作区。Slack 是否作为补充，待定。
7. **不承诺项**：不写金钱、岗位、签证类承诺；任何省时或成本数字在实测前不进销售页和 outline.json。
8. **继承自旧稿的决定**：AWS 预置沙箱账号并设预算上限、课后回收；代码托管用学员自己的 GitHub 仓库。

## AI 关系

**一段话的原则**：AI 是结对搭档兼老师，不是替学员完成作业的人。它起草基础设施代码、解释每一段、在只读权限内查日志和指标、画图、整理复盘，还当追问者；学员先把要什么写清楚，自己运行，自己核对，自己在每节课结束前讲回。每节课的标准是：学员能说出 AI 做了什么、自己判断了什么、凭什么判断它对。解释不了的东西不提交。

四条规则从第一节课起执行：先说清要什么再让 AI 写；让 AI 解释每一段；自己运行并核对；解释不了的不提交。AI 的写入类动作（apply、destroy、删除）一律由学员本人执行，这一点在 L01 通过权限设置落地。

| 课 | AI 做什么 | 你做什么 | 你要能讲清或判断什么 | AI 容易错在哪 |
|---|---|---|---|---|
| L01 本机用 Docker 跑起订单系统，再用 Terraform 放上 AWS | 起草 Dockerfile 的解释、起草 Terraform（ECS Fargate、负载均衡、Postgres、镜像仓库）；只在你立的只读规则内行动。 | 先写下一页需求，再给 AI 立规则；自己跑 docker compose；自己读 plan，决定能不能 apply。 | plan 里每个资源是干什么的、谁能从公网访问它、删掉它会发生什么。 | 安全组把数据库端口对 0.0.0.0/0 打开；健康检查路径写错导致任务反复重启；在 Apple 芯片上构建的镜像在 x86 的 Fargate 上起不来。 |
| L02 GitHub Actions 流水线：推一次代码，自动构建并部署到 ECS | 起草 GitHub Actions 的工作流文件，并解释每一段；在你读完日志之后，给出它对失败原因的判断。 | 先写下流水线的阶段和触发条件；逐段解释草稿；自己读失败日志并写出原因，再去问 AI；自己执行一次回滚。 | 流水线的每个阶段在做什么；失败时去哪里看第一个红色步骤；部署用的凭据是长期密钥还是临时角色，为什么。 | 草稿把 AWS 长期密钥存进 secrets，而不是用 OIDC 临时角色；角色的信任条件和仓库名对不上导致无法扮演角色；忘记登录镜像仓库导致推送被拒。 |
| L03 监控与告警：CloudWatch 指标、日志和第一条告警 | 在你写完自己的关注清单之后，给出它认为该监控什么；起草 CloudWatch 仪表盘和告警的 Terraform。 | 先在纸上写下订单系统出什么事你必须知道；审 AI 起草的告警；跑压测，对着曲线说出含义；删掉没有动作可做的告警。 | 每条曲线的含义；为什么看 p99 而不是平均值；每条告警触发后你具体要做什么。 | 告警一直显示数据不足，因为没有流量或缺失数据的处理方式不对；把 CPU 平均值当成唯一指标；起草的四条告警里有的半夜会吵醒你却没有任何可做的动作。 |
| L04 故障演练：先自己查，再让 AI 查，对比各找到了什么 | 在只读权限内查日志和指标，给出时间线与根因判断；帮你整理复盘文档。 | 先不用 AI，自己写出时间线；再让 AI 查，记录它每个结论所依据的证据；逐条标注哪些是证据、哪些是猜测。 | 哪些结论有证据、哪些只是猜测；先止血还是先找根因；AI 的结论为什么可信或不可信。 | 把时间上靠得近的事当成原因；只看最近一次部署；日志被截断后仍给出确定的结论；没有证据却说得很肯定。 |
| L05 作品集：README、架构图、面试讲解和 AI 基础设施审查清单 | 起草 README 和 mermaid 架构图；用只读权限按清单审查你的仓库；扮演面试官追问。 | 核对架构图的每个箭头；自己按清单审查，再和 AI 的结果对比；用自己的话讲解，追问答不上来就回去改代码或改说明。 | 权限有没有过宽；有没有不该对公网暴露的东西；有没有会让账单意外变大的配置；自己的项目每一部分能不能讲清。 | 架构图里画了仓库里并不存在的组件；README 里的命令没人试过；审查时漏掉对公网开放的端口和过宽的权限；NAT 网关或日志保留时间带来意外费用。 |

补充：L00 AI 不参与；L01 到 L05 每节最后一步是「带走」，结束前互相讲回。「AI 容易错在哪」一列是写课时的假设，需要在 starter 仓库里用真实运行逐条验证，见待核实。

## 常见翻车点

下面每一条都给出复现办法。现在只是课程设计阶段，还没有人在 starter 仓库上实跑过，实跑记录见待核实。

1. **Apple 芯片上构建的镜像在 Fargate 上起不来**：在 M 系列 Mac 上不带平台参数构建并推送镜像，用 x86 的 Fargate 任务运行，看 ECS 任务的停止原因，应出现 exec format error。修法：构建时指定 linux/amd64，或把任务架构设成 ARM64。
2. **健康检查路径写错，任务反复重启**：把负载均衡的健康检查路径改成不存在的路径，apply 后看 ECS 服务事件。
3. **数据库端口对 0.0.0.0/0 打开**：让 AI 起草 RDS，对 plan 输出 grep 0.0.0.0/0。
4. **docker push 被拒**：没有先执行 aws ecr get-login-password 登录就推送，看错误信息。
5. **OIDC 无法扮演角色**：把角色信任条件里的仓库名故意写错，看 Actions 日志里 AssumeRoleWithWebIdentity 的授权错误。
6. **destroy 删不掉镜像仓库**：仓库里还有镜像时 destroy，看报错；解决是在 Terraform 里设 force_delete，学员要能说出为什么这样设。
7. **告警一直显示数据不足**：创建告警后不打流量，看告警状态；再调整缺失数据的处理方式。
8. **区域不一致**：命令行默认区域不是悉尼，资源建到别的区域，控制台里看不到。

## 报名前自测

页面上的 5 题（是或否），与此处一致：

1. 能不看教程，在 Linux 终端里找到日志文件并看最后 50 行吗？否：先补 Linux 命令行。
2. 用过 git clone、add、commit、push，并能说清分支吗？否：先补 Git。
3. 能说出一段 20 行左右 Python 或 JavaScript 在做什么吗？否：先补入门编程。
4. 有 GitHub 账号，并愿意把代码放进自己的仓库吗？否：课前注册即可，不影响报名。
5. 现在的工作是否已经在维护生产环境的 AWS、Terraform 或流水线？是：看进阶课。
