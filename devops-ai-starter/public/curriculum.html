AI DevOps 实战课 · 项目班
让 AI 动手做 DevOps，你来把关

第一节课就搭起自己的 AI 工作台，然后让 AI 代理读 AWS 账号、写 Terraform、搭流水线、查故障。它只有只读权限，每一步你来审查、验证，并说清它凭什么对。最后把整套工作台整理成作品集。

10 小时直播带做$599 含 GST适合想转进 DevOps 的人

这门课和 AI 的关系

这不是一门先学传统 DevOps、AI 顺便帮忙的课。从第一节开始，工作就是你和 AI 代理一起做：它读、写、查，你划范围、审查、验证。AI 能在几分钟里写出像样的 Terraform 和流水线，风险在于你读不懂它，却让它碰了你的账号。所以这门课先搭护栏，再让它干活，再练你把关的本事。

AI 做

读账号和仓库、画架构图、写 Terraform 和流水线、读失败日志、只读调查故障、起草 runbook 和 README，还扮演追问的面试官。

你做

先写清要什么；给 AI 划范围；审 plan 和 pull request；重跑它引用的命令验证结论；自己执行所有写入动作；每节课结束前讲回。

你要能讲清

账号里每个资源是什么；plan 里哪一行最危险；一次部署经过了哪些步骤；一个故障结论凭什么成立；护栏拦得住什么、拦不住什么。

先说清楚：什么才是真正的边界

AI 的规则文件、权限设置、hook，都是便利，能减少失误，但课上不把它们当作安全保证，它们实际能拦住哪些写法，课上会当场试，结果以实测为准。真正挡住 AI 改动账号的，是你给它的那个 AWS 只读角色：角色没有写权限，AI 说什么都写不进去。这个差别，第一节课就当场演示。

从第一节课就执行的四条规则

  1. 先说清你要什么，再让 AI 写。
  2. 让 AI 解释每一段，听不懂就追问。
  3. 自己运行，自己核对输出。
  4. 你用自己的话解释不了的，不提交。

L01

搭起你的 AI 工作台，让它读懂一个陌生的 AWS 账号

120 分钟 · 直播
先看终点
AI 在只读权限下读完一个陌生的沙箱账号和代码仓库，画出架构图；接着老师让它执行一条创建资源的命令，AWS 返回拒绝信息。你看清楚这套工作台要搭成什么样。
AI 做
只用只读权限，读完陌生账号和仓库，列出资源，画出架构图，并标明哪些是读到的、哪些是推测的。
你做
安装并配置 Claude Code，写规则文件；用 IAM 只读角色加只读命令白名单划出范围；把 AI 的图逐项对着 AWS 控制台核对。
你要能讲清
这个账号里有哪些资源、各自是干什么的；真正挡住 AI 改动账号的是什么，规则文件和权限设置又只是什么。
要练着抓的问题
把推测当成读到的事实；漏掉控制台里存在的资源；画出账号里并不存在的组件。
带走
一个 AI 工作台仓库（规则文件、命令白名单、只读角色的配置说明）、一张你核对过的架构图、一页「这张图里 AI 猜了什么、错了什么」的笔记。

这节练的判断：AI 画的架构图对不对

L02

一句话需求变成 Terraform：审 plan 的三件事，再在沙箱里 apply

120 分钟 · 直播
先看终点
一句需求交给 AI，得到一份 Terraform；老师用三件事审 plan，抓出一处过宽的权限，改完 apply，最后一条命令全部拆除。
AI 做
把你写好的需求变成 Terraform，逐段解释，并在你 apply 之后用只读权限核对结果。
你做
先把一句话写成一页需求和验收标准；用三件事审 plan：权限是不是太宽、有没有对公网暴露、会不会带来意外费用；确认后由你本人在沙箱里 apply。
你要能讲清
plan 里每个资源是干什么的、谁能访问它、删掉它会怎样、为什么这条权限可以这么给。
要练着抓的问题
权限写成星号；存储或数据库对 0.0.0.0/0 或公开访问开放；日志保留时间或 NAT 网关带来意外费用。
带走
一个能 apply 也能 destroy 的 Terraform 仓库、一份「审 plan 三件事」检查表、一份写给自己的「AI 这次写错了什么」笔记。

这节练的判断：审 plan 的三件事

L03

让 AI 搭 GitHub Actions 流水线，并诊断一次红灯

120 分钟 · 直播
先看终点
AI 起草的流水线第一次跑红，AI 读日志给出原因并把修复开成 pull request，你审后合并，流水线变绿并部署；再看 AI 想直接推送 main，被 GitHub 拒绝。
AI 做
起草工作流，读失败日志并给出原因判断，把修复作为 pull request 提交。
你做
先写下流水线需求；设置 main 分支保护，让任何改动都必须经过 pull request；逐段解释工作流并审它的凭据用法；先自己读红灯日志，再与 AI 的判断对比；审并合并 pull request。
你要能讲清
流水线每个阶段在做什么；部署用的是长期密钥还是临时角色，为什么；AI 为什么改不了 main。
要练着抓的问题
草稿把 AWS 长期密钥存进 secrets，而不是用 OIDC 临时角色；角色的信任条件和仓库名对不上；忘记登录镜像仓库导致推送被拒。
带走
一个在你自己仓库里能跑通的部署流水线、一页「读红灯日志三步」笔记、一份 main 分支保护的设置截图和说明。

这节练的判断：AI 搭的流水线，和它对红灯的判断

L04

故障演练：AI 只读调查，你验证结论，写成 runbook

120 分钟 · 直播
先看终点
老师注入一个故障，AI 只读调查并给出时间线；老师逐条重跑它引用的命令，指出一条有证据的结论和一条没有证据的结论；最后展示由此写出的 runbook。
AI 做
只用只读权限查日志和指标，给出时间线、根因判断和每条结论依据的命令；起草 runbook。
你做
先不用 AI，自己查并写下判断；再让 AI 查；重跑它引用的命令，把每条结论标成证据或猜测；与自己的结果对比；自己执行止血，写成 runbook。
你要能讲清
哪些结论有证据、哪些只是猜测；先止血还是先找根因；AI 的结论为什么可信或不可信。
要练着抓的问题
把时间上靠得近的事当成原因；只看最近一次部署；日志被截断后仍给出确定的结论；没有证据却说得很肯定。
带走
一份你自己的 runbook（症状、排查步骤、证据、止血办法、预防）和一页「我和 AI 各发现了什么」对比。

这节练的判断：区分证据和猜测

L05

把规则变成 skill，加一个 hook，把工作台做成作品集

120 分钟 · 直播
先看终点
AI 想执行 terraform apply，被你写的 hook 拦下；然后打开一个完成的作品仓库，做一次被追问的三分钟讲解。
AI 做
用你写的 skill 审查新的 Terraform，起草 README 和架构图，扮演面试官追问。
你做
把审 plan 三件事写成 skill；写一个很小的 hook 拦住 apply 和 destroy，并故意换几种写法试它拦不拦得住；整理仓库，写一份能面试用的讲解；自己 destroy 并核对沙箱没有残留。
你要能讲清
这个 hook 拦得住什么、拦不住什么，所以为什么真正的边界仍是 IAM；整套工作台里每一部分是干什么的。
要练着抓的问题
hook 对带参数、放进脚本或换了别名的命令放行；把规则文件当成安全边界；架构图里画了仓库里并不存在的组件。
带走
一个作品集仓库（README、架构图、skill、hook、各节笔记）、一页「护栏试验记录」、一份你自己的话写的三分钟讲解稿。

这节练的判断：护栏拦得住什么、拦不住什么

前置要求与 5 题自测

前置要求：会用 Linux 命令行，会用 Git，能读简单代码。AWS、Terraform、CI/CD 不需要提前学。

  1. 你能不看教程，在 Linux 终端里进入一个目录，找到一个日志文件，并看到它的最后 50 行吗？

    否：先补 Linux 命令行基础再报名。

  2. 你用过 git clone、add、commit、push，并能说清分支是什么吗？

    否：先补 Git 基础再报名。

  3. 给你一段 20 行左右的 Python 或 JavaScript，你能说出它大概在做什么吗？

    否：先补入门编程再报名。

  4. 你有 GitHub 账号，并愿意把课上的代码放进自己的仓库吗？

    否：课前注册一个账号即可，不影响报名。

  5. 你现在的工作里，是否已经在维护生产环境的 AWS、Terraform 或部署流水线？

    是：这门课对你偏浅，请看高级班。

我们不承诺什么

  • 不承诺工作、面试、薪资、晋升或签证结果。你带走的是一个工作台仓库和一份自己的话写的讲解。
  • 不承诺 AI 每次都对，也不承诺护栏万无一失。课上你会亲眼看到 AI 出错，也会亲手试出 hook 拦不住的写法，目的是让你练会发现，并知道真正的边界在哪里。
  • 不承诺覆盖 DevOps 的全部。这门课不教 Kubernetes，也不教 MCP、子代理和团队级的 AI 治理，那些在高级班。

常见问题

课程用 ECS，不教 Kubernetes，这样行吗？
不教。10 小时要覆盖工作台、Terraform、流水线、排障和作品集，Kubernetes 和 EKS 放进来会把时间占满。这些做法多数可以迁移，但具体的 Kubernetes 对象和命令这门课不覆盖。
我没用过 AWS 和 Terraform，跟得上吗？
课程前提是 Linux 命令行和 Git。AWS、Terraform、流水线都在课上边做边学：AI 先动手，你逐段让它解释，再自己核对。课前准备那一节会先让你把环境和沙箱账号跑通。
我可以用别的 AI 工具吗？
课上用 Claude Code 演示。你用同类的 AI 编程助手也行，但我们只排查课程用的那套环境里的问题，skill 和 hook 的写法也以 Claude Code 为准。AI 工具订阅费用的安排，与沙箱费用一起在报名前公布。
AI 都能做了，我还需要学什么？
需要学的是把关。AI 写的基础设施可能权限过宽、可能对公网开放、可能让账单意外变大，而且它说得很肯定。这门课每节练一种判断：图对不对、plan 能不能 apply、红灯的原因是什么、结论有没有证据、护栏拦不拦得住。
给了 AI 规则和 hook，是不是就安全了？
不是。规则和 hook 只是减少失误的便利，课上会让你试出它们拦不住的写法。真正的边界是 IAM 只读角色和隔离的沙箱账号；所有写入动作都由你自己执行。
学完会不会得到工作？
不承诺。你会得到一个能展示的作品集仓库和一份用自己的话写的讲解，能不能拿到面试和录用取决于很多课程控制不了的因素。
云资源的费用谁出？
AWS 沙箱账号由课程提供，费用与预算上限的具体安排在报名前公布。本课不要求使用你自己的 AWS 账号。
