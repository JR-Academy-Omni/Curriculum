Vibe Coding 大师课 · 第六节课 — Agent：会遇到的问题 · 怎么定位 · 怎么改

90 分钟诊断课（讲解 + 投屏演示 + 一段 10 分钟诊断练习，不做长任务实操，学员不需要环境）。立意是「懂原理不解决问题，会诊断才解决问题」，所以全课是一条诊断链：① 会遇到的问题 → ② 怎么定位 → ③ 怎么改。地基段只讲到够用：Agent = 模型 + 工具 + 循环、循环四拍与「它每一轮都重新读一遍 context 再决定、不是带着记忆往前走」、停止条件里的「它认为」，以及核心立论「它没有记忆，只有 context」——于是「它怎么又忘了 / 瞎编 / 不守规范」三句抱怨全都先当 context 问题查，前五节所有 SoT 的物理作用被重新解释成一件事：让它每轮重读 context 时读到的是对的东西（系列收束页）。① 问题（全课最长一段）讲五条跑偏机制，每条配一个学员认得出的症状：context 稀释（越到后面越不守规矩）/ 压缩丢细节（风格断层、重踩已解决的坑）/ 错误累积（每步都有道理但整体错）/ 目标漂移（diff 大三倍）/ 进度幻觉（总结全绿、自己跑全红——前四条骗的是它自己，这条骗的是你的验收环节）。② 定位给出可带走的两件工具：定位三问（这件事在它 context 里吗 · 它是在查还是在猜 · 这句「完成了」我自己验过吗）和症状 → 机制反查表（每行右边都是 30 秒内能做完的动作），并点破「『它今天不行』不是诊断，是放弃诊断」；随后老师投屏走一遍真实反查 + A/B 预录对照（裸交 vs 带任务交付单），揭穿「顺便该修的都修一修」就是目标漂移的许可证、而且是你自己发的。10 分钟现场诊断练习：学员对着预录的跑偏记录填诊断单前两栏，讲评只问「你依据哪条症状」、不判对错——练的是推理链。③ 怎么改把五条机制一一对应到五个具体处方：落盘（治稀释/压缩）· 计划先行 + 你审计划（治累积）· 交付单的「边界」格（治漂移）· 可执行验证 + 铁律「它说完成了不算完成，判据必须来自它之外」（治幻觉）· 打断三信号（事中兜底）；最后学员回填诊断单第三栏，带走一条完整的「症状 → 机制 → 处方」链。28 页，含反查表 / 定位三问 / 交付单模板三张可打印讲义 + 作业（含课后补做完整 A/B、交付单按 L5 判断线做成 Skill）。

Vibe Coding 大师课 · 第七节课 — Subagent：给 context 分家

120 分钟动手工作坊（两次实验：一次正收益，一次红灯；全程只读、不改真实代码）。承接 L6：上节课诊断出「探索噪音挤满一个 context」，L7 给出那个病的结构性解法——别把所有事塞进一个 context 里。全节立论只有一句：子 Agent 不是多一个人手，是多一个独立的 context；立住之后收益（脏活不污染主 context）、代价（冷启动 / 报告开销 / 它看不见你的对话）、铁律（不假设继承 / 不重叠所有权 / 不拿自述验收）全是它的推论。判断线是两层门：三项强收益（隔离噪音 / 并行分支 / 独立视角）至少命中一项，四条就绪条件必须全过——而且「独立视角」是唯一一个 1 个子 Agent 就能拿满的，这直接推出最小配置：1 个 verifier。课堂做两次实验且顺序不可调：动手 A 派三路只读调查、收口是一张证据可追溯、缺口已标记的汇总矩阵（不许把三份报告拼起来）；动手 B 是红灯——故意派一个两三步就能做完的小活并真的计时，让学员亲手测到冷启动 + 重新摸索 + 写回执 + 你再读回执比自己顺手做完慢得多。判断线放在两次实验之后，从学员自己的数据里长出来——延续 L4 CI 红灯 / L5 description 翻车 / L6 裸交跑偏一贯的「先撞墙，再给尺子」。操作层同样落地：六格 brief + 坏 brief 现场改写、三档调用的强制力差别（「我说了」不等于「它照做了」）、好指令逐句拆解（边界用否定句显式收窄、证据格式前置、以及最容易漏的「给『不知道』一个出口，不给出口它就编」）、按判断密度而非重要性选模型档（verifier 判断密集不能省，调查员执行密集便宜档够用；先调思考力度再动档）。收尾是三条底线：context 隔离 ≠ workspace 隔离、完成回执、以及「再找一个 Agent 看看不是 verifier」。全课收口：分派改变的是信息怎样流动，不会转移最终验收责任。

Vibe Coding 大师课 · 第八节课 — Agent Team：从「多开 context」到「共同完成任务」

120 分钟「先讲后做」工作坊（全程只读，不改课堂仓库任何代码）。课堂硬产物：每位学员亲手创建并验证一个真正的 Agent Team。课堂仓库 star-mansions，必须锁 commit。

🔁 2026-08-09 从零重写为 v1.0，旧版整体作废。 旧蓝图用「先撞墙、再解释」+ 浅题/深题双线，造成四个问题：学员还没建立 Team 心智就要同时管角色文件、三个会话、任务板、消息协议和两条根因线；角色 C 在 config 与唱反调之间换身份，任务板和讲稿对不上号；课堂把「发现某个预设答案」当成功，反而弱化了真正该学的结构与设置；大量概念靠课后解释，学员做的时候不知道自己在观察什么。新版不靠隐藏答案制造戏剧性——先把尺子讲清楚，再要求学员用尺子做出一个可验收的 Team。

🎬 两幕结构：第一幕先讲（0–50：定义 → 判断 → 最小单位 → 必要设置 → 角色与任务 → 通信 → Lead 验收）→ 过渡（50–60：老师 smoke test + 休息）→ 第二幕后做（60–113：环境预检 → 建最小 Team → 验证 → 扩成标准组合 → 跑案例 → Lead 收口）→ 结尾（113–120：组合选择 + Exit + 作业）。节奏铁律：0–55 分钟不让学员创建 Team；60 分钟后不再插入新概念；最小 Team 验证不过，不进正式 Lab。

🎯 全节立论：Agent Team 的价值，不是多开几个 Agent；是让一名成员的新证据，在任务结束前改变另一名成员的下一步。 配一条必须讲清的诚实边界——Team 并不会让某个结论「在结构上只有 Team 才能发现」，一个优秀的 Lead 也可以手动收集并转发证据；Team 真正提供的是独立 context、成员直接互发消息、共享任务状态、过程中处理发现与阻塞、Lead 不必充当每一条信息的人工中转站。所以选 Team 是收益与协调成本的比较，不是能力等级判断。

📐 选择 Team 的三问：① 值得开多个 context 吗（L7 的门）② 成员的中途信息会改变别人的下一步吗（本节核心）③ 协调收益大于协调成本吗。第三问的标准判断句：「如果我删掉成员间消息，任务会在哪一步变慢、变差或失去可验证性？」答不出来，不开 Team。

🧱 最小可用单位 = Lead + 2（不是 Lead + 1——只有一名 teammate，谁和谁直接协作？）。五条缺一不可：1 Lead、2 teammates、1 个共享任务、1 次 teammate → teammate 直接消息、1 次 Lead 决定与外部验收。成员名单和共享任务不是充分证据；只有 Lead ↔ 成员的往返，按 Subagent 处理，不算过关。正式 Lab 用 Lead + 3（两个边界调查员 + 一个 verifier），扩展顺序固定不得倒着来：最小 Team → 稳定角色 → 依赖与任务状态 → challenger → 写入所有权 → 模型档位 → plan approval → Hooks/MCP/Skills。

⚙️ 必须设置极少：功能已启用且账号可用、项目目录可读、至少 in-process 显示模式、权限模式明确、课堂只读。tmux、分屏、角色文件、skills、MCP、Hooks、不同模型一个都不是前提。 另标清一条易错边界：tools 是工具 allowlist，不是目录沙箱——「只读 frontend/」是角色指令，不是物理路径限制。四步 smoke test（成员名单 / 共享任务 / A→B 直接消息 / Lead 视角）中前三条全过才进正式 Lab。

🧪 正式 Lab（只有一个案例）：学员先建最小 Team、跑 smoke test、再新增 verifier 扩成标准组合，完成一次跨前后端的只读调查。角色从创建到结束不更名、不换身份（角色漂移是高频失败）。课堂不修代码；「找到根因」不替代「证明 Team 真实协作」，成员共识不替代 Lead 外部验收；成员回答「这条证据没有改变我的下一步」也算合格——真实协作记录比强行制造翻转更重要。

Vibe Coding 大师课 · 第十节课 — 四象限 AI 协作协议：信息在谁那里，决定谁该说什么

90 分钟框架课（不是讲座 —— 前 32 分钟学员在写、在卡住、在看老师翻车）。课堂硬产物：一段学员自己的「开场四问」，可复用、可做成 Skill。

🔀 系列首次从机制层转向理论层。 L1 到 L9 全是机制（SoT / 交付链路 / Skills / 诊断 / Subagent / Team / 老项目），九节课给了几十条规则，而规则只在教过的场景里有效。L10 换的是层次不是话题：前九节给你动作，第十节给你一张能自己推出动作的图。 蓝图 §0.1 把这个转向的代价写在了明面上，防止后面自我欺骗：这节课不会让学员多一项能力（四格里三格对应的动作学员已经会做），它唯一的价值是让学员在没教过的第十种情况下做对。所以全节只有一条成败判据：「一个学完的人，回去做下一个真实任务时，动作和没学的人不一样吗」。离场状态是「思路更清楚了」= 这节课失败。

🧱 核心不是四个格子，是四条搬运动作。 四格（开放区你和它都清楚 / 隐藏区你清楚它不知道 / 盲区它清楚你不知道 / 未知区都不知道）本身是一页纸，讲完加举例 30 到 35 分钟就见底，90 分钟必然注水。撑住时长的是格子之间的搬运：隐藏 → 开放 = 落盘（L1–L3 全部 SoT）· 盲区 → 开放 = 先让它说、你别先下结论（L6 诊断 / L9 Discovery 前九步不改文件）· 未知 → 盲/隐 = 设计实验，不是设计 prompt（L7 只读调查）· 开放 → 隐藏 = 退化。第四条是最值钱也最原创的一页：开放区不是你达成的状态，是你维护的状态，而且它退化的时候没有报错。Johari 原型里没有这条（人际关系里信息不会自己过期，代码库里会），所以它也是唯一一条学员在别处学不到的。

🔴 最重要的教学决定：四格图必须到第 32 分钟才第一次出现。 理论课只有一种死法 —— 图在第 8 分钟上屏，之后 80 分钟都在解释一张已经在屏幕上的图，学员从「我在想」变成「我在听」再也回不来。所以顺序是反的：0–20 学员回答四个并列问题（不给任何框架）→ 20–32 老师用自己那个无文档老项目现场暴露一次盲区 → 32 分钟图出现，台词固定「你们刚才填的东西有名字」。连带铁律写进 deck 检查：P00 到 P07 不许出现任何 2×2 布局、四格配色或「象限」二字，四问不许排成方阵，封面标题是「你以为它知道」而不是课名（真名首现在 P08，和图同时上屏）。

🤐 第三问（盲区）学员会卡住，卡住就是教学内容。 硬性要求 90 秒沉默、不举例、不换说法再问一遍（举例等于把答案给了），然后立刻切老师演示。老师承认的是「无知」，比 L9 承认「遗忘」更重一档，而且蓝图明写 那次调用不许提前跑（排练过的惊讶是假的）。但「不许排练」只约束当天那个模块，不豁免运维兜底：三级降级 = 换备用模块重跑 → 投第三个模块的预录并必须明说是预录、不许假装现场 → 只讲不演，用第三问填不出来的举手数当替代证据。

🩹 隐藏区不教「要落盘」，教「你以为你落盘了」。 学员学过三节 SoT，这一格最容易被敷衍过去。破法三步：用他们自己第二问的答案当反例（真正的隐藏区是理由和约束，不是事实 —— 事实它能读，理由只在你脑子里，直接接 L9 的 status == 7）→ 现场打开自己的 CLAUDE.md 数过期条目（这是退化反转页的引信，先埋不点；上限 15 条；学员只报数字，不许要求投屏或上交内容）→ 粒度问题（意图 / 规格 / 判据 / 实现，只给 L11 埋点，不展开）。另有独立一页 数据边界：隐藏区搬不过去时搬它的形状，不搬它的内容（「有一类客户走特殊结算路径，标记在 X 字段」而不是真实客户名）；四问不依赖任何特定工具，国内环境的能力差距只出现在盲区和未知区两格，只影响搬运效率，不改变协议。

🎯 收口是一个动作，不是一句总结。 硬产物是「一段你回去真会粘贴的话」，deck 只给骨架不给范文（给了范文四格就变成填空题），并配一页「为什么这么组词」原理层（四段分开写 / 有冲突以这里为准 / 先说结论不要直接改 / 提最小实验先别做 / 明确说不知道不要猜）。收口接 L5 那条判断线：同一段话说到第三次，它就该是个 Skill —— 第五节教的判断线，用来固化第十节自己。课堂规则两条也写进 deck：讲评只问「你这一条属于哪一格、依据是什么」，不判对错（一判对错学员就转向猜老师想要的答案，框架当场退化成考试题；而且学员的任务在他自己的隐藏区里，老师本来就没有判对错的信息）；边界争议一句话止住 —— 格子的边界不重要，搬运动作才重要；分不清就当隐藏区处理，因为四种错判代价不对称（错当开放区它会编且你不知道，错当盲区白问一轮，错当未知区白做一个实验，错当隐藏区只是啰嗦）。出处（Johari Window, Luft & Ingham 1955）放到第 87 分钟才说 —— 一开场说是 1955 年的模型，学员立刻归档成旧东西，注意力当场掉一半。

90 分钟框架课（前 22 分钟学员在写、在被打回；22–36 分钟看老师现场翻两次车）。课堂硬产物：一份学员自己的「无人值守任务书」，七段两块，可复用、可做成 Skill。

🕳 全节承接的是一个前十节从没说出口的前提：你在旁边看着。 L6 的打断信号要人看 · L7 的汇总是你的活 · L8 的 Lead 验收要你在 · L10 的开场四问是你开工前自己过一遍 —— 全都假设你在场。L11 第一次把这个前提抽掉：任务在凌晨三点跑，你在睡觉，它遇到需要拍板的地方没人拍。所以这节课不是「教一个工具怎么点」（设置本身十分钟讲完，写进 §4 非目标第一条），而是一件事在没人看着的时候交出去，你要提前把什么补上。收口立论：「你消灭的不是那个问题，是那次提问。」 提问被取消了，那个决定并没有消失 —— 它被交给 Agent 自己做了，而那笔债只能靠任务书提前还。

🚪 教学决定一：先让学员交一件不合格的任务。 讲「哪些适合、哪些不适合，来我给你四条判据」一定失败 —— 学员会点头、会记下，然后回去把一件不该自动化的事自动化了，因为他不觉得那四条说的是他。所以顺序是反的：先写下「我想让它每天替我做的那件事」（不给任何判据），再用四个问题逐个打回来，判断闸到第 36 分钟才出现（沿用 L10「图不许提前上屏」的铁律形态，deck 上锁死：P10 之前不许出现任何闸门图、四步图或「判断线」三个字，连封面标题和浏览器标签都不许出现「定时 / Schedule / Cron / 自动化」）。全课支点是第二问「它做错了，你多久会知道？」——多数人答不出，因为手工做的时候那一眼检查是免费且隐形的，自动化把它拿掉了；追问三句写死，至少 60 秒沉默不救场。

🎬 教学决定二：演示必须翻车两次，翻法不同。 学员进教室时只怕「它停下来等你批」，真正会伤人的是「它没停，它绕过去了，然后报告说做完了」——演示 A 现场跑（只给读权限做一件必须写文件的事，跑完当场打开文件让全场看见它没变，不许用截图），演示 B 展示一个前一天就挂住的会话（不是现场建，因为「它等了一夜也没人理」这件事在五分钟里物理上演不出来）。

⚙️ 第四幕把「卡住」和「断掉」明确切开——混着讲学员回去只会加超时、不会加契约。卡住（它还活着但不往前走）：卡权限 / 卡问题 / 卡等待 → 提前批 / 提前答 / 给边界，三条做法连代价一起讲（deck 上代价列的视觉权重高于做法列）。断掉（它没活到最后）五种：网络断 / 凭证过期（无人值守头号杀手，从某天起再也没跑成过而它不会尖叫）/ 环境没准备好 / 限流超时 / 额度用完（性质不同 —— 前四种是跑了没成，这种是压根没跑）。前四种的共同点是全都会给你一个「跑完了」的外观，第五种连外观都没有。

🔒 铁律（反转页）：宁可交回一句「我没做，因为 X」，也不要交回一个它猜着做完的结果。 机制是默认情况下 Agent 把「完成任务」排在「保护你的意图」前面，这句话是给它一个比完成任务优先级更高的合法退出——没有这个出口，它只剩绕道一条路。由此推出结果契约：绿灯只代表进程正常退出，不代表任务做成了，所以你需要一个你自己定的信号，状态写死成 done / skipped / needs-human 三档 + 一条来自它之外的证据 + 不是 done 时的原因，什么都没交回来 = 报警。第三档是关键 —— 只有成功 / 失败两档时它会把「我没做」也塞进成功里（它确实正常结束了），needs-human 是那条铁律的机器形态，也是给它说实话的余地。最后是重试与幂等（先契约后重试，顺序不能颠倒）：「重试不是勇气问题，是幂等问题」，判「不安全 → 第一版只提议不生效」在评分表里是满分答案。

📋 硬产物是七段两块，这是无人值守的真实架构：前五段写给它看（目标 / 判据 / 边界 / 预答 / 出口），后两段写给盯着它的那个脚本看（回执契约 / 重跑规则）——「无人值守从来不是一个 Agent 自己跑，是一个 Agent 加一个盯着它的东西」。每一段都能追溯到课上某个环节：目标←闸① · 判据←闸②+L6 铁律 · 边界←闸③ · 预答←闸④+L10 隐藏区（本节和上节的结构性接口：隐藏区就是它会来问你的地方，而定时任务不给它问的机会）· 出口←铁律 · 回执契约←绿灯不等于成功 · 重跑规则←幂等。

🌏 受限 / 国内环境不许砍：给了退让阶梯（云端托管 → 本机调度器 → CI 定时 → 只写任务书人工执行）并逐级标明失去哪一项能力维度，只讲能力维度不排名不点评产品；收口是「通道会变，会被墙，会改名，会涨价，任务书不会」。另配课前 72 小时通道自查（敲一次 /schedule → 有无桌面端 → 能否写系统调度），课堂按结果分流，硬产物与通道解耦，一条通道都用不了的人照样交得出任务书。

Vibe Coding 大师课 · 第十二节课《Claude Hook》— 把「我跟它说过」变成「它绕不过去」

96 分钟动手课（第 20 分钟学员就亲手挂上第一个 hook 并当场验证；40–58 分钟看着自己挂的东西咬自己三次）。课堂硬产物：一个学员自己写的、当堂拦截成功过一次的 hook——Exit ticket 现场只收拦截证据，没跑通的不算数。

🧾 这节课还的是系列自己写下的欠条。 L5 蓝图 §64 和 L6 蓝图 §82 的非目标里写着「不讲 MCP / Hooks / Schedule / Subagent（放后续）」——Subagent 由 L7 兑现、Schedule 由 L11 兑现，Hooks 欠了六节课（MCP 仍欠着，且 L9 蓝图有三处误写「学员已学过 MCP」，需另开票修）。

🔑 全节承接一个前十一节没说破的性质：交给学员的东西全都是「说给它听」的。 L1 的 PRD · L2 的 CLAUDE.md · L5 的 Skill · L7 的 brief · L11 的七段任务书 —— 它可以不读，读了可以不照做，这次照做了下次可以不照做。L12 第一次给一个它不能不照做的东西。支点是官方原文（逐字引用、标明出处）：「deterministic control: certain actions always happen rather than relying on the LLM to choose to run them.」 收口立论：「hook 挡得住的，只有你说得清的那部分。」说不清的那部分还在——而且现在你以为它被挡住了（与 L11「绿灯不等于成功」同构：一个让你安心的信号，和它实际保证了什么，中间有个缺口）。

🎯 教学决定一：先让它成功，再让它咬人 —— 不再用第三遍「先撞墙再给尺子」。 L10 图在第 32 分钟、L11 闸在第 36 分钟都用了这个形态，第三次学员会认出套路、戏剧性归零。而 hook 是这个系列里第一个能在 90 秒内跑给人看的东西，不用它是浪费。所以顺序是：数一数你说过几遍 → 演示「CLAUDE.md 里写着它照样犯」→ 全班一起挂上第一个，当场故意违反，看它被拦（全节高光，学员第一次看到「它绕不过去」）→ 然后那个东西开始咬他 → 判断线到第 58 分钟才出现。学员对 hook 的第一印象必须先是「太爽了」，否则后面的告诫他听不进去。

🩸 教学决定二：三次翻车形态不同，全部由学员改自己的 hook 触发（老师不演）。 ① 把 PROTECTED_PATTERNS 改成 "." → 它什么都干不了了（你回去三天内会关掉它，而一个被关掉的 hook 和没挂过是一回事）；② 把 PreToolUse 改成 PostToolUse ⭐⭐ 本幕支点——脚本跑了、判据判对了、它也收到了 Blocked，而那一行已经在文件里了（现场必须打开 .env 让全班看见）。官方依据：PostToolUse hooks can't undo actions since the tool has already executed，Can block? = No。这一次失败是没有声音的：红字照出、日志照写、监控正常，只有文件变了；③ exit 2 改 exit 1 → 冒红字然后照做（hook 挂上 ≠ 生效，你得看见它拦成功过一次）。

🧭 全 deck 视觉重心是时点二维图（拦得住 / 拦不住 × 它还没动手 / 已经动手了，右上角是个明确的大叉）：怕「它做了不该做的」→ 事前拦 PreToolUse；怕「它漏了该做的」→ 事后补 PostToolUse / Stop——挂反了都会失败，而第一种挂反了你还看不出来。第四格 Stop 单独讲，因为它结清了 L6 那笔账：Stop | Yes | Prevents Claude from stopping——「它说完成了不算完成」一直是一条原则，今天它有执行机构了（另一笔：SessionStart + compact 兑现 L6「压缩会丢东西」）。

🔐 接 L11 的接口是一整页：hook 压得过 --dangerously-skip-permissions。 L11 §8.2 那三条让它不卡住的做法，最大代价是「你放开的时候把该拦的也一起放开了」；官方两句原文各落一个「所以」——PreToolUse hooks fire before any permission-mode check… blocks the tool even in bypassPermissions mode（所以你可以放开权限跑得飞快，同时保证有三件事它永远碰不到）· Hooks can tighten restrictions but not loosen them（所以 hook 不是后门——这是设计，不是限制：一个能放宽的 hook 等于把安全边界交给每个能改配置文件的人）。

🏢 最值钱的一格是「挂在哪个文件 = 谁受它管」。 项目级 .claude/settings.json 能提交进仓库，克隆的人自动受管、不需要读 CLAUDE.md、也不需要同意——这是前十一节唯一一次跨过「你自己」。反面同样讲透：你克隆一个仓库，就接受了它每一条会在你机器上自动执行的 shell，于是送学员一个新习惯：克隆陌生仓库先敲 /hooks 看一眼。

💻 代码是本 deck 的一等公民（与 L10 / L11 不同）：25 个代码样例集中在 src/data/code.ts 作唯一事实源，每条都标「官方」还是「本课写法」（混着给，学员分不清哪些有权威背书）。附录三页（课上不讲、不带阶段徽章、投屏留最后拍照）：用法样例库（拦 / 补 / 灌上下文 / 验收 / 提醒 / 审计 / 团队 八类，含 L5·L6·L11 的回收点）· 脚本解剖与字段速查（六步骨架 · stdin 字段 · 三条输出路 · Can block? 全表 · 五种 type · 配置两层数组结构 · matcher 全表）· 排错八条（含「先把输入存进 /tmp/hook-input.jsonl 再触发一次，比查表快十倍」）。

🌏 受限 / 国内环境不许砍：先讲清 hook 依赖的能力维度——「宿主愿意在生命周期固定时点执行你的命令并听你的返回值」，再给退让阶梯（Claude Code hook → git pre-commit/pre-push → CI → CLAUDE.md + 人工 review）并逐级标明失去什么（拦得越晚，它已经做错的越多、返工越贵）；只用 git hook / CI 这类通用机制，不依赖也不点评任何具体产品的功能宣称。收口：「工具会变，会被墙，会改名，会涨价，『这条规矩机器判不判得出来』这个问题不会。」

📐 纪律：判断线四道（说过几遍 / 漏做还是做错 / 不动脑的脚本判不判得出来 / 拦错了还干不干得了活）与时点二维图、三行机制、六步骨架，deck 与讲义都写明是本课的教学设计，不是官方文档的分法；蓝图 §21.3 列了 9 条必须开课当天重新核对的项（含 PostToolUse 是否仍 Can block? = No——变了半节课要改）；讲稿附录 K 六个空里 K.6 要求讲师亲手试出 disableAllHooks 的实际行为，不许凭文档字面推断。deck 里不留任何待填空白、不出现绝对分钟数、任何一页都没有填好的样例 hook（给了范文，收上来全是它的变体）；不用本仓库自己的 .claude / Skill / hook 当例子。26 页全部经 1600×900 实机截图核对，无溢出、无裁字。

Vibe Coding 大师课 · 第十三节课《造一套让规矩成立的系统》— 把一条没人执行的规矩，变成一个会自己拦人的仓库

135 分钟线上直播动手课（无助教）。学员第 8 分钟开始敲，敲到第 130 分钟，仓库当堂从空目录长出来（不发 starter kit，只发 check.mjs 骨架 + 六个救生艇目录 —— 已做好并通过双向验收：六个原样跑全绿，六个被故意弄坏必须变红，只验绿等于没验，一个永远不会红的检查和一个不存在的检查是同一个东西）。课堂硬产物：一个规则仓库 + 6 条检查 + 4 次他自己造出来的红 + 1 个被 CI 挡住的 PR + 一段「拒绝编造」的生成器约束。

🔗 承接 L12：让一个 agent 绕不过去 → 让一整个团队绕不过去。 同一个立论，对象从一个 context 换成一群人。而「一群人」的最小单位比公司小得多 —— 一个项目组、一个三人小队，甚至只有你和你那几个 agent。判据只有一条：有没有超过一个动作者，会碰同一批东西。

🎯 教学决定一：脊椎是「造这套东西要依次回答的八个问题」，不是强制力阶梯。 阶梯在这条决定链里是第 6 个决定，把它提到第一位，学员学会的是「怎么给一条规则加强制点」，学不会「该有哪些规则、按什么顺序建」。八步：疼在哪 → 什么该进这个仓库 → 文件打架时谁赢 → 谁答应什么 → 我不知道的怎么办 → 该查什么不该查什么 → 怎么让它绕不过去 → 回去怎么复制这一套。每一步产出一个文件，每一步结束跑一次检查（这是把课从管理研讨拉回动手课的唯一手段）。

🩸 教学决定二（v3.2 讲师翻面）：正面给规矩，不赌学员会犯错。 早期版本是「这条检查我不解释，你先跑」—— 全部押在它会咬到学员自己刚写的名字上。讲师否掉了，理由是事实层面的：每个人的仓库不一样，这一下不一定咬得到。学员课堂上只写两个角色，角色模板那三段又不天然招人名，很多人跑出来就是绿的，那一格对他们完全是空的 —— 一个只在学员恰好犯过错时才成立的教学点，不是教学点，是抽奖。现在改成四层：正面给规矩（角色文件里只出现角色，人名只活在花名册里）→ 给理由（那个人离职的那天，你要改的应该只有一份文件；名字散进角色文件，离职就变成一次全仓搜索，而搜索总会漏）→ 才跑去验证，而且抓到和没抓到都有话说（「没抓到」那句是新增的那一半：两种可能，别急着高兴，你确实写对了，或者你今天只写了两个角色还没碰到 —— 回去写第十个的时候会碰到）→ 讲师投屏自己的例子，「检查从哪来」压在这一层（学员中没中是随机的，讲师中过是确定的）。连带拆掉了「本 deck 最大的自毁按钮」，同时消掉一条严重度「高」的结构性风险。 检测用花名册精确匹配而不是人名正则：正则版实测在中文最自然的写法上（「由某某审批」后面紧跟汉字）全部漏掉，还会把普通词误判成人名；花名册版中英文通吃、零误报，而且「先建花名册再写角色」这个动作本身就在教「人和角色是两张表」。

🔥 四次红，前三次必然发生、全部由学员自己造（第四次是条件红，见教学决定二）： ① 加了角色忘了登记；② 把一份文件标成 Status: approved，它红了，它说「你还没写完」⭐ 这是收口的地基（早期版本没有这一步，导致全节最重要的那条检查在课堂上从来没红过，学员只听过没见过）；③ 满屏红；④ 抓到自己的名字（⚠️ 条件红：取决于学员自己写了什么，不保证发生，所以 P18 已改成不依赖它）。

🦷 三次翻车形态不同，第二次最重要： ① 它给了你一段跑得通的代码（学员自选一条最该查的说给 agent 听，一大半说的是判断题；agent 不会拒绝，它给你一段跑得通、但查的不是那回事的代码，而你以为成了 —— 这一类失败没有声音，而且它在第三幕就埋下了 L14 的收口。这条边界要明着承认，一个声称能查判断题的检查器，只会在你最需要它的时候给你一个错误的绿灯）；② 全设成失败 ⭐⭐ 本幕支点 —— 索引里加三个还没建的角色，满屏红，而且红得有道理。三句一句都不能省：「这是错吗？（不是）/ 那你明天还会跑它吗？（不会）/ 一个天天红的检查，和一个不存在的检查，是同一个东西」，解药是一个词：bad 改 note；③ 全绿却早就违反了。

📐 三句话（v3 全部换过，因为全课主链从「勤勉」换成了「信任」）： 立论（阶梯页，全节唯一一次点明）「规矩的力量，不在它写了什么，在谁改得了它。」· 反转（第三幕末，不是第五幕 —— 前移是为了避免两个反转互相稀释）「检查挡得住的，只有你说得清的那部分。」说不清的能转化掉一部分，剩下的必须承认它只能靠人记得，不许假装它被守住了；生成器那句「看它留了多少空」降级成第五幕的回声，不再当新东西讲 · 收口（全程不许提前说）「留白在等的那个人，就是你该去谈的那场话。」链条：有强制点 → 强制点只挡得住你说得清的 → 说不清的必须留白 → 留白在等谁 → 那个人就是你一直没去谈的那个人。

📏 按规模选形态（附录 A0，一定会有人问「我们就三个人要不要做」）： 不要答「那你可以简化一下」，那等于说他不配做这套东西。 正确答案是「规模决定形态，不决定要不要做」，而且三个人的组收益最快 —— 小组最吃亏的是「只有一个人知道那件事怎么做」，那人请假整摊就停了，而规则文件正是这件事最直接的解药。课堂八步走的就是三人形态，所以那句「你不是做了个简版，你做完了」必须说出口。

💻 线上无助教是本节的结构性约束：所有信号走聊天框数字（翻车③ 改成「抓到打 1、没抓到打 0」，反而给了讲师一个精确的命中率读数）；每个动手点配一个救生艇目录，学员自己覆盖就能跟上；学员只贴终端输出，不贴文件内容（他们写的是自己那儿的真实情况，终端输出天然脱敏）；每个等待点讲稿都写好了话术，直播最致命的是空等。

🔒 脱敏纪律（约束的是讲师，不是学员）：讲师投屏、演示仓库、预录、deck 全部脱敏 —— 不能把自己那儿的信息泄露给一屋子人；学员没有这条约束，写真名真金额真客户全都是对的，因为系统在他们自己电脑上。而且让学员写真的是教学必需：编的公司永远答得上「这个数谁定的」，也永远不疼。deck 因此不出现任何产品名（顺带让国内班海外班共用一份课件）、不出现精确计数（文件数 / 提交数 / 缺口数组合起来是可反查的指纹）、不出现任何「原话」式引用（所有观点用本课自己的话说）。

📚 核心资产是检查样例库（七类十五条可跑的 Node 检查，每条标了能不能在课堂那个仓库上直接跑）。其中三条值得单说：C-1 派生值不许被手写第二遍 —— 它查的是动作不是值，那个值可能碰巧是对的，手写这个动作仍然是错的；E-1 标了生效的文件不许残留留白 —— 全节收口所依赖的那一条，它的作用不是找错，是堵住你；F 组八条不需要身份就能查的漂移不变式 —— 因为账号映射不入库、不能按人查，限制反而逼出了更强的检查（「一个不是组织成员的协作者」，不需要知道那是谁就能抓到离职残留）。另有 G 组「明确不该查的」，不假装，是这套东西能被信任的原因。

🧱 与 L14 的接口写死在倒数第二页（全景三仓图，一分钟，不展开）：今天造的是中间那块，上面还有一层 —— 谁给它权限、它接哪些系统、它会哪些技能、谁来维护，那一层下节课讲。「今天先把地基打对，因为地基错了，上面那层越强越危险」 —— 一个规则写得糊涂的仓库配上一个有写权限的 agent，比没有 agent 糟得多。学员一定会追问权限怎么给，一律答「下节课」，一开口讲权限模型收口就没时间了。

Vibe Coding 大师课 · 第十四节课《它能碰什么》— 给一个 agent 一套公司系统的权限、连接、技能与维护

120 分钟线上直播动手课（无助教）。课堂硬产物：一张自己公司的写权限表（四列）+ 一个当堂跑出 FAILED 而不是 0 的脚本 + 一份按十节写完的技能规范。

🔗 承接 L13：那节造了一个会自己拦人的仓库，但它现在没有消费者。 学员回去第一天就会撞上同一个问题：「我建好了。然后呢？AI 在哪？它凭什么读我这些文件？它能改吗？谁拦着它？」顺序是故意的，而且是这两节之间最重要的一句话：地基错了，上面那层越强越危险。一个规则写得糊涂的仓库，配上一个有写权限的 agent，比没有 agent 糟得多。

🦴 脊椎是交底五问，有顺序不能打乱：有哪些仓（东西放哪）→ 给它什么权限（谁能动）⭐ 核心产物在这 → 接哪些外部系统（够不够得着外面）→ 它有哪些技能（会干什么活）→ 怎么维护（怎么不烂掉）。

📐 三句话：立论（第二幕，全节唯一一次点明）「权限不是一个开关，是一张一行一行批出来的表。」· 反转（第五幕，学员刚给自己的表加完审批人、最有安全感的时候翻）「你加的那个人工审批，多半不是保障，是失效模式。」· 收口（全程不许提前说）「它最危险的时候，不是它做错了事，是它什么都没做，而你以为它做了。」

💎 全课最值钱的一格是写权限表的第三列「批准立在什么上面」，而且它反直觉：真正起作用的限制，不在「谁按那个按钮」，在这项批准立在什么上面 —— 后者读者可以核查，按钮不能。所以这张表允许出现强弱不同的两行，而且必须标出来：一行的依据是「一封任何人都能重新打开来读的邮件」，另一行是「一通电话，由提出这个需求的人转述」—— 把弱的那行标出来，比把它伪装成跟前者一样，安全得多。

🦷 三次翻车，第二次最重要，而且它就是收口的地基：① 把白名单放宽跑一条危险命令（形态「认知错位」：以为白名单是安全边界，其实它是省事边界，它减少确认弹窗，不阻止任何事）；② 造一次查询失败，看它报 0 ⭐⭐（形态「看不见」—— 全课唯一一个学员看完会后背发凉的时刻。三句一句都不能省：「它报了 0，这个 0 是什么意思 / 真的吗，它查到了吗 / 那它凭什么报 0」，答案是「0」和「我不知道」被写成了同一个字）；③ 挂一个会阻塞的钩子（形态「烦」：一个会阻塞会话的新鲜度警告，比它警告的陈旧本身更糟）。

⚠️ 这一节最大的风险是讲成管理课，比 L13 严重得多 —— 权限表、连接器清单、技能规范、维护制度，四样里三样是在写表格。解药只有一条铁律：每一幕结束前，学员的终端必须有新输出。没有就是这一幕讲飞了。

🔒 全程不出现学员公司那边的任何产品名（一律用「工单系统 / 聊天工具 / 邮箱 / 代码托管」）。这不只是脱敏，是三重收益：国内班海外班同一份课件（五问的结构对任何一套工具都成立，只换连接器清单）· 学员能把自己代入（学员公司用的东西跟讲师不一样是常态，讲产品名会让一半人觉得「这跟我没关系」）。本节比别节更要紧，因为它通篇在讲外部系统。

🚧 还没定的四件事（PRD §6）：时长 120 还是 dry run 后收到 105 · 第一幕让学员跑自己的配置还是讲师投屏 · ⚠️ 翻车② 用什么当查询目标（必须零依赖零网络、所有学员都能复现 —— 这一条不解决，全课高光那一页做不出来，而且要实测不能凭想象设计） · 入场券有人交不出来怎么办。

Vibe Coding 大师课 · 第十五节课《它碰过什么》— 从批准到证据：你凭什么敢在睡觉的时候让它跑

135 分钟线上直播动手课（无助教）· 第十四节《它能碰什么》的 Part 2。课堂硬产物：一张不可逆清单 + 一条可被重新打开来读的运行痕迹 + 一个真的开起来的定时任务 + 一条把当堂某次翻车写进 L13 仓库并跑红的检查。

🔗 为什么必须有这一节：L14 整套设计全是「批准」，没有一样是「证据」。 L14 文档里有六处写了没兑现：技能十节第 8 条审计记录（一行字）· 写权限表第四列「升级要什么证据」（开了列没内容）· 「受另一条留存规则管」（那条规则全文档不存在）· 「新检查从真发生过的错来」（事故→检查的路径没定义）· 收口指出了病没给药 · 以及「宁可全部由人触发」认了代价却没还的那笔债。而 L14 最值钱的那一格（写权限表第三列「批准立在什么上面」）讲的恰恰是能不能重新打开来读 —— L14 把这把尺子用在了批准上，没用在运行上。L15 把它推到运行那一侧。

🔧 结构性产出：这一节不是给 L14 加内容，是把 L14 的核心产物重排一遍。 写权限表按「写到哪」分行 → 不可逆清单按「撤不撤得回来」分行。前者答得出谁批的，后者才答得出出事怎么办。讲师必须明说「我在改上节课的东西」，不许把两张表讲成并列。同一句顺带修掉 L14 的一个误读风险：L14 说「人工审批往往是失效模式」，学员容易泛化成「审批没用全撤了」—— L15 给出那条精确的例外：人按的那一下，只在不可逆的前一秒有用。

⏰ 定时任务是本节终点，也是整个系列的分水岭（蓝图 §0.2b）：它是这套东西第一次在没有人在场的情况下工作。 L13–L15 把它建起来、接上手、放出去；L16–L17 是它跑起来之后怎么活下去。开场第一分钟就宣布终点，每一张表都因此有了理由：你要开那个东西，这些是开它的条件。

💡 冷启动回头证明了 L13，这是本节最漂亮的一格：定时任务跑的时候读不到你的会话、你的本机、你那次对话，所以它只有两条路 —— 抄规则全文（两份，必然漂移），或者第一步去拉那个远端（一份）。后者唯一成立的前提，就是 L13 整节课在造的那个你改不了的远端。「冷启动不是定时任务的缺点，它是检验你那个仓库建对没有的唯一一次考试。」

📐 三句话：立论（第二幕）「证据不是存在哪，是谁在什么时候会被它拦住。」· 反转（第三幕末，学员刚做完回滚最有安全感的时候翻）「你刚才撤回的是你的系统，不是外面的世界。」· 收口「一套系统上一次因为真出了事而改过规矩，离现在多久 —— 这个数，就是它真正的年龄。答不上来的，不是稳定，是没人在看。」收口和 L14 收口的关系要说出口：L14 讲一次运行骗了你，L15 讲整套系统骗了你 —— 同一个形状，高了一层。

🦷 三次翻车 + 两次自检，两套东西不要混：翻车是情绪设计（① 翻出它上次留下的东西，念出来的是作文不是事实；② 素材包三分钟找出改错那一次 ⭐⭐ 收口的地基 —— 「它什么都记了，它什么都没拦住，因为它在等人来找，而没有人会来找」；③ 真跑一次撤回，两种结局都对，讲师都要能接）。自检是开关前面的检查（A 冷启动，零依赖、进不砍清单；B 关掉会话再开列一下，一批人会是空的 —— 它看起来开着，它从来没跑过）。⚠️ 把自检讲成翻车，第四幕会变得很丧，而第四幕是全课唯一往上走的一幕。

🔄 产品名纪律在本节切了一刀：学员公司的系统绝对不说，Claude 自己的（定时任务 / 会话 / 技能 / 钩子）照常说。判据一句话：换一家公司还要用的，说；换一家公司就不用了的，不说。不切这一刀，第四幕根本没法做。另外定时任务只讲形状不讲参数（产品细节会变版本，具体值进讲师课前核对清单）。

🚨 Codex review 指出、尚待讲师拍板的四条（已写进讲稿第四幕的待决框）：① 课程契约断裂 —— 本节说「今天你会真的开一个」，但「真开」不在过关线、砍法允许降成讲师投屏，而 L16/L17 又把「已经开着」当硬前提；② 三道门与入场券死锁 —— 门要求连续成功若干次 + 一次被检查抓住的失败 + 撤回演练过，而入场券只保证「跑过一次」；③ 冷启动没有通过证据 —— 故意让它变红，但没安排改完重跑；④ 服务凭据无人接 —— L14 禁定时任务的理由是技术的，本节回答的全是治理资格。
